Объекты

В прошлом уроке мы научились хранить списки: покупки, оценки, города. Массив отлично подходит, когда вещей много и они однотипные. Но как описать одну вещь, у которой много разных свойств — студента, товар, заказ такси? Для этого в JavaScript есть объекты. Почти всё, что приходит с сервера и показывается на сайте, — это объекты и массивы объектов. Сегодня соберём всё вместе: функции, массивы и объекты — и научимся ставить ИИ точные задачи на этом языке.

  • Создавать объекты, читать, менять, добавлять и удалять их свойства
  • Работать с вложенными данными и массивами объектов — как в настоящих ответах сервера
  • Писать методы объекта и понимать, на что указывает this
  • Быстро доставать данные деструктуризацией и делать копии через ...
  • Превращать объекты в JSON и обратно, безопасно читать данные от сервера
  • Писать для ИИ точные промпты на языке JS и проверять его ответы

01 Что такое объект и зачем он нужен

Вспомним массив: ["нон", "чой", "самбуса"]. Это список однотипных вещей, и к каждой мы обращаемся по номеру — индексу. А теперь попробуем описать одного студента: имя, возраст, город, курс. Можно и массивом:

Массивом — неудобно

Что лежит в student[2]? Нужно помнить порядок. Перепутали местами — получили ошибку, которую трудно заметить.

const student = ["Фарход", 20, "Душанбе", "Frontend"];
console.log(student[2]); // а это что? город? курс?
Объектом — понятно

У каждого значения есть название. Читаешь код — и сразу понятно, что где лежит.

const student = { name: "Фарход", age: 20, city: "Душанбе", course: "Frontend" };
console.log(student.city); // сразу видно: город
Аналогия из жизни

Вспомните паспорт или анкету при поступлении в Ilmhona. Там нет «строки номер 3» — там есть поля с названиями: «Фамилия», «Дата рождения», «Город». У каждого поля есть название и содержимое. Объект устроен точно так же: это набор пар «название → значение».

Объект
Набор пар «ключ: значение» в фигурных скобках { }. Описывает одну вещь со многими свойствами.
Свойство
Одна пара внутри объекта, например city: "Душанбе". Как одно поле в анкете.
Ключ
Название свойства (city). Всегда строка, даже если пишем без кавычек.
Значение
То, что хранится под ключом ("Душанбе"). Может быть чем угодно: число, строка, массив, другой объект, функция.

Как создать объект

Объект пишут в фигурных скобках. Внутри — свойства через запятую. Каждое свойство: ключ, двоеточие, значение. Такая запись называется литерал объекта.

const student = {
  name: "Фарход",
  age: 20,
  city: "Душанбе",
  isStudent: true
};

console.log(student);        // → { name: "Фарход", age: 20, city: "Душанбе", isStudent: true }
console.log(typeof student); // → object

const empty = {};            // пустой объект — тоже объект
console.log(empty);          // → {}

Как прочитать свойство: точка и квадратные скобки

Есть два способа. Через точку — student.name — самый частый и короткий. Через квадратные скобки — student["name"] — нужен в двух случаях:

  • в ключе есть пробел или дефис: product["старая цена"], product["made-in"];
  • имя ключа лежит в переменной: product[field].
const product = {
  title: "Казан",
  price: 250,
  "made-in": "Таджикистан",
  "старая цена": 300
};

console.log(product.title);          // → Казан
console.log(product["price"]);       // → 250
console.log(product["made-in"]);     // → Таджикистан
console.log(product["старая цена"]); // → 300

// ключ лежит в переменной
const field = "title";
console.log(product[field]);  // → Казан
console.log(product.field);   // → undefined (ищет ключ с именем "field")

Последняя строка — частая ошибка. product.field ищет свойство, которое буквально называется field. А product[field] сначала берёт значение переменной ("title") и уже потом ищет такой ключ.

Нет такого свойства — получаем undefined

const user = { name: "Мадина" };

console.log(user.age);    // → undefined
console.log(user.length); // → undefined (у объекта нет length, как у массива)

Ошибки нет: JavaScript просто говорит «тут ничего нет». Ошибка будет, если попытаться взять свойство у самого undefined, например user.address.city. Как защититься — разберём в теме 02.

Изменить, добавить, удалить

Объект можно менять после создания. Присвоили значение существующему ключу — изменили. Новому ключу — добавили. Оператор delete удаляет свойство. А оператор in проверяет, есть ли ключ.

const order = { dish: "Оши палав", price: 30 };

order.price = 35;      // изменить: ключ price уже был
order.drink = "Чой";   // добавить: ключа drink не было
console.log(order);    // → { dish: "Оши палав", price: 35, drink: "Чой" }

delete order.drink;    // удалить
console.log(order);    // → { dish: "Оши палав", price: 35 }

console.log("price" in order); // → true
console.log("drink" in order); // → false
Важно: const и объекты

const запрещает переприсвоить переменную — положить в неё другой объект. Но менять содержимое объекта можно. Представьте: на коробке приклеена наклейка «card». Наклейку на другую коробку не переклеишь, а вот вещи внутри коробки менять можно.

const card = { owner: "Зарина", balance: 100 };

card.balance = 150;          // можно: меняем содержимое
console.log(card.balance);   // → 150

// card = { owner: "Зарина", balance: 0 };  // нельзя: TypeError, const не переприсваивается

Короткая запись свойств

Часто значения уже лежат в переменных с такими же именами. Тогда вместо { name: name, age: age } можно написать просто { name, age }. Это одно и то же.

const name = "Нилуфар";
const age = 18;
const city = "Бохтар";

const student = { name, age, city };
console.log(student); // → { name: "Нилуфар", age: 18, city: "Бохтар" }

// функция-«фабрика»: принимает данные, возвращает объект
const makeStudent = (name, city) => ({ name, city, course: "Frontend + ИИ" });
console.log(makeStudent("Далер", "Куляб")); // → { name: "Далер", city: "Куляб", course: "Frontend + ИИ" }
Ловушка: стрелочная функция возвращает объект

Обратите внимание на круглые скобки: () => ({ ... }). Без них JavaScript решит, что { — это начало тела функции, а не объект, и функция вернёт undefined.

Как перебрать все свойства

У массива есть for...of и методы. Объект напрямую так перебрать нельзя, но есть три помощника, которые превращают объект в массив:

  • Object.keys(obj) — массив ключей;
  • Object.values(obj) — массив значений;
  • Object.entries(obj) — массив пар [ключ, значение].
const grades = { html: 5, css: 4, js: 5 };

console.log(Object.keys(grades));    // → ["html", "css", "js"]
console.log(Object.values(grades));  // → [5, 4, 5]
console.log(Object.entries(grades)); // → [["html", 5], ["css", 4], ["js", 5]]

// сколько свойств в объекте
console.log(Object.keys(grades).length); // → 3

// средняя оценка: values + reduce из прошлого урока
const sum = Object.values(grades).reduce((total, g) => total + g, 0);
console.log(sum / Object.keys(grades).length); // → 4.666666666666667

Чаще всего перебирают пары через for...of по Object.entries. Запись const [subject, grade] раскладывает пару на две переменные — подробно разберём это в теме 05, а пока просто запомните форму.

const grades = { html: 5, css: 4, js: 5 };

for (const [subject, grade] of Object.entries(grades)) {
  console.log(`${subject}: ${grade}`);
}
// → html: 5
// → css: 4
// → js: 5

Есть и старый способ — цикл for...in. Он перебирает ключи, а значение берём через квадратные скобки:

const grades = { html: 5, css: 4, js: 5 };

for (const key in grades) {
  console.log(key, grades[key]);
}
// → html 5
// → css 4
// → js 5
Частые ошибки

1) grades.key внутри for...in — ищет ключ «key». Нужно grades[key].
2) obj.length — у объекта нет длины. Используйте Object.keys(obj).length.
3) { name = "Фарход" } — внутри литерала ставят двоеточие, а не =.
4) Забыли запятую между свойствами — SyntaxError.

02 Вложенность: объекты в объектах, массивы объектов

Значением свойства может быть что угодно — в том числе другой объект или массив. Так и выглядят настоящие данные: у пользователя есть адрес (объект), список навыков (массив), а у группы — массив студентов, каждый из которых — объект.

Аналогия из жизни

Папка «Группа FE-07» в шкафу. В ней лежит листок с именем ментора и ещё одна папка «Студенты». В папке «Студенты» — анкеты, каждая на своём листке. Чтобы найти город второго студента, вы открываете: группа → папка студентов → вторая анкета → поле «Город». В коде путь записывается точно так же: group.students[1].city.

const user = {
  name: "Шахром",
  age: 22,
  address: {               // объект внутри объекта
    city: "Худжанд",
    street: "ул. Камоли Худжанди"
  },
  skills: ["HTML", "CSS"]  // массив внутри объекта
};

console.log(user.address.city);   // → Худжанд
console.log(user.skills[0]);      // → HTML
console.log(user.skills.length);  // → 2

user.address.zip = "735700";      // добавили свойство во вложенный объект
user.skills.push("JavaScript");   // методы массива работают как обычно
console.log(user.skills);         // → ["HTML", "CSS", "JavaScript"]

Массив объектов — самая частая форма данных

Когда сайт запрашивает у сервера список товаров, студентов или заказов, почти всегда приходит массив объектов. Вот как выглядит группа студентов:

const group = {
  name: "FE-07",
  mentor: { name: "Далер" },
  students: [
    { name: "Фарход", city: "Душанбе" },
    { name: "Мадина", city: "Худжанд" }
  ]
};

console.log(group.mentor.name);       // → Далер
console.log(group.students[1].name);  // → Мадина
console.log(group.students.length);   // → 2

Как читать длинный путь

  1. group — берём весь объект группы.
  2. .students — достаём из него свойство students. Это массив.
  3. [1] — у массива берём элемент с индексом 1 — второй объект.
  4. .name — у этого объекта берём имя: "Мадина".
Совет

Если путь не работает, выводите его по частям: console.log(group), потом console.log(group.students), потом console.log(group.students[1]). Сразу увидите, на каком шаге данные не такие, как вы ждали.

Методы массивов + объекты

Всё, что вы выучили в прошлом уроке, отлично работает с массивом объектов. В колбэк приходит целый объект, и мы берём у него нужное свойство.

const products = [
  { id: 1, title: "Ковёр", price: 900, category: "дом" },
  { id: 2, title: "Казан", price: 320, category: "кухня" },
  { id: 3, title: "Пиала", price: 15, category: "кухня" },
  { id: 4, title: "Чайник", price: 120, category: "кухня" }
];

const titles = products.map(p => p.title);
console.log(titles); // → ["Ковёр", "Казан", "Пиала", "Чайник"]

const kitchen = products.filter(p => p.category === "кухня");
console.log(kitchen.length); // → 3

const cheap = products.find(p => p.price < 100);
console.log(cheap); // → { id: 3, title: "Пиала", price: 15, category: "кухня" }

const total = products.reduce((sum, p) => sum + p.price, 0);
console.log(total); // → 1355

const hasExpensive = products.some(p => p.price > 500);
console.log(hasExpensive); // → true

А теперь цепочка: «все товары для кухни дороже 100 сомони — в виде строк для витрины», и сортировка по цене. Сортируем копию (slice()), чтобы не испортить исходный массив.

const products = [
  { id: 1, title: "Ковёр", price: 900, category: "дом" },
  { id: 2, title: "Казан", price: 320, category: "кухня" },
  { id: 3, title: "Пиала", price: 15, category: "кухня" },
  { id: 4, title: "Чайник", price: 120, category: "кухня" }
];

const showcase = products
  .filter(p => p.category === "кухня" && p.price > 100)
  .map(p => `${p.title} — ${p.price} сомони`);
console.log(showcase); // → ["Казан — 320 сомони", "Чайник — 120 сомони"]

const byPrice = products.slice().sort((a, b) => a.price - b.price);
console.log(byPrice.map(p => p.title)); // → ["Пиала", "Чайник", "Казан", "Ковёр"]
console.log(products[0].title);         // → Ковёр (исходный порядок цел)
Ловушка: find возвращает тот же объект, а не копию

Если изменить то, что вернул find, изменится и объект внутри массива. Это не копия, а ещё одна «ссылка» на тот же объект.

const products = [{ title: "Казан", price: 320 }, { title: "Пиала", price: 15 }];

const kazan = products.find(p => p.title === "Казан");
kazan.price = 280;

console.log(products[0].price); // → 280 (изменился и в массиве!)

Безопасный доступ: ?.

Данные от сервера не всегда полные. У одного пользователя есть адрес, у другого — нет. Если взять свойство у undefined, программа упадёт с ошибкой TypeError, и весь код ниже не выполнится:

const users = [
  { name: "Далер", address: { city: "Куляб" } },
  { name: "Сабрина" }   // адреса нет
];

console.log(users[0].address.city); // → Куляб
console.log(users[1].address.city); // TypeError: адрес undefined, у него нет city
console.log("Эта строка уже не выполнится");

Оператор опциональной цепочки ?. говорит: «если слева undefined или null — дальше не иди, просто верни undefined». А оператор ?? позволяет подставить значение по умолчанию, если слева undefined или null. Их часто используют вместе.

const users = [
  { name: "Далер", address: { city: "Куляб" } },
  { name: "Сабрина" }
];

console.log(users[1].address?.city);  // → undefined (без ошибки)
console.log(users[1].address?.city ?? "город не указан"); // → город не указан

for (const u of users) {
  console.log(`${u.name}: ${u.address?.city ?? "—"}`);
}
// → Далер: Куляб
// → Сабрина: —

// ?. работает и с массивами
const empty = [];
console.log(empty[0]?.name); // → undefined
Не ставьте ?. везде подряд

?. нужен там, где данные по-настоящему могут отсутствовать (необязательное поле, пустой ответ). Если свойство обязательно должно быть, а его нет — лучше получить ошибку и найти баг, чем молча показать пустоту.

03 Методы объекта

Значением свойства может быть и функция. Такая функция внутри объекта называется методом. Свойства описывают, какой объект (имя, цена, город), а методы — что он умеет делать (поздороваться, посчитать сумму, применить скидку).

Аналогия из жизни

Чайник: у него есть свойства — цвет, объём, сколько воды налито. И есть кнопка «вскипятить» — это действие. В объекте свойства — это данные, а методы — это кнопки, которые что-то делают.

Метод
Функция, которая лежит в свойстве объекта.
Вызов метода
Запись объект.метод() — со скобками! Без скобок вы просто получите саму функцию, но не запустите её.
const chaikhana = {
  name: "Рохат",
  city: "Душанбе",
  greet: function () {
    console.log("Хуш омадед в чайхану!");
  }
};

chaikhana.greet();                  // → Хуш омадед в чайхану!
console.log(typeof chaikhana.greet); // → function

Короткая запись метода

Слово function и двоеточие можно опустить: greet() { ... }. Это современная запись, её вы будете видеть чаще всего. Методы, как обычные функции, принимают параметры и возвращают значения через return.

const calc = {
  add(a, b) {
    return a + b;
  },
  multiply(a, b) {
    return a * b;
  },
  percent(sum, p) {
    return sum * p / 100;
  }
};

console.log(calc.add(25, 17));      // → 42
console.log(calc.multiply(4, 12));  // → 48
console.log(calc.percent(300, 15)); // → 45

Вы уже давно пользуетесь методами

Каждый раз, когда вы ставили точку и скобки, вы вызывали метод встроенного объекта. console — это объект, а log — его метод! Math — объект с математическими методами. Строки и массивы тоже имеют методы.

console.log(typeof console);     // → object
console.log(typeof console.log); // → function

console.log(Math.round(4.6));    // → 5
console.log(Math.max(3, 9, 4));  // → 9

const city = "хорог";
console.log(city.toUpperCase()); // → ХОРОГ

const cart = ["нон"];
cart.push("чой");                // push — метод массива
console.log(cart);               // → ["нон", "чой"]

Так что arr.push(...) и calc.add(...) — одна и та же идея: у объекта есть свойство-функция, и мы его вызываем через точку.

Забыли скобки

Метод не запустился — вывелась сама функция.

console.log(calc.add);   // ƒ add() — это функция, а не результат
chaikhana.greet;         // ничего не произошло
Со скобками

Метод выполнился и вернул результат.

console.log(calc.add(2, 3)); // 5
chaikhana.greet();           // Хуш омадед в чайхану!

Метод, которому нужны данные объекта

Часто методу нужны другие свойства того же объекта. Пока можно обратиться к ним по имени переменной:

const chaikhana = {
  name: "Рохат",
  open: "07:00",
  info() {
    return `Чайхана «${chaikhana.name}», открыта с ${chaikhana.open}`;
  }
};

console.log(chaikhana.info()); // → Чайхана «Рохат», открыта с 07:00

Это работает, но неудобно: если переименовать переменную или захотеть такой же метод в другом объекте — всё сломается. Для этого есть специальное слово this — следующая тема.

Частые ошибки

1) Вызов без скобок: obj.method вместо obj.method().
2) Опечатка в имени: calc.Add() → TypeError: calc.Add is not a function. Регистр букв важен.
3) Забыли return — метод вернёт undefined, хотя внутри всё посчитал.

04 this — «этот объект»

Внутри метода часто нужно сказать: «возьми имя этого объекта». Для этого есть слово this. Правило, которое нужно запомнить:

Главное правило

this — это объект, который стоит перед точкой в момент вызова метода. Вызвали student.introduce() — значит внутри this равен student.

Аналогия из жизни

Слово «я». Когда Фарход говорит «я из Душанбе», «я» — это Фарход. Когда ту же фразу говорит Мадина, «я» — это Мадина. Фраза одна, а смысл зависит от того, кто говорит. this — это «я» для метода: зависит от того, у какого объекта метод вызвали.

const student = {
  name: "Манижа",
  city: "Истаравшан",
  introduce() {
    console.log(`Салом! Я ${this.name} из города ${this.city}`);
  }
};

student.introduce(); // → Салом! Я Манижа из города Истаравшан

student.city = "Душанбе"; // переехала
student.introduce(); // → Салом! Я Манижа из города Душанбе
  1. Вызов student.introduce(). JavaScript смотрит, что стоит слева от точки, — это student.
  2. this = student. На время этого вызова this указывает на объект student.
  3. this.name — это то же самое, что student.name, то есть "Манижа".
  4. Метод всегда берёт свежие данные. Поменяли city — следующий вызов уже покажет новый город.

Методы меняют объект через this

const counter = {
  count: 0,
  increment() {
    this.count++;
  },
  reset() {
    this.count = 0;
  },
  show() {

counter.increment();
counter.increment();
counter.increment();
counter.show();  // → Счётчик: 3

Одна функция — разные объекты

Вот где this по-настоящему полезен. Одну и ту же функцию можно положить в несколько объектов — и каждый раз this будет тем объектом, у которого её вызвали.

function sayHi() {
  console.log(`Ассалому алейкум, я ${this.name}`);
}

const farhod = { name: "Фарход", sayHi };
const zarina = { name: "Зарина", sayHi };

farhod.sayHi(); // → Ассалому алейкум, я Фарход
zarina.sayHi(); // → Ассалому алейкум, я Зарина

Ловушка 1: стрелочная функция как метод

У стрелочной функции нет своего this. Она берёт this снаружи — оттуда, где её написали, а не от объекта перед точкой. Поэтому как метод с this она не работает:

const user = {
  name: "Рустам",
  hello: () => {
    console.log(this === user); // стрелочная: this взят снаружи объекта
  },
  hi() {
    console.log(this === user); // обычный метод: this — объект перед точкой
  }
};

user.hello(); // → false
user.hi();    // → true

Если бы внутри hello было this.name, вы получили бы не «Рустам», а пустоту или undefined. Зато стрелочная функция идеальна внутри метода — например, как колбэк для map: она возьмёт this у метода, а значит, у объекта.

const shop = {
  discount: 10,
  prices: [100, 250, 40],
  withDiscount() {
    // стрелочный колбэк берёт this из метода withDiscount, то есть shop
    return this.prices.map(p => p - p * this.discount / 100);
  }
};

console.log(shop.withDiscount()); // → [90, 225, 36]
Правило на каждый день

Метод объекта пишем короткой записью method() { }. Колбэки внутри метода (map, filter, reduce) — стрелочными. Тогда this всегда будет тем, чем нужно.

Ловушка 2: метод «оторвали» от объекта

Если сохранить метод в отдельную переменную и вызвать её, перед точкой уже ничего нет. В строгом режиме ("use strict" — он включён в нашем запуске кода и во всех современных проектах) this становится undefined, и обращение this.name падает:

const user = {
  name: "Рустам",
  introduce() {
    console.log(`Я ${this.name}`);
  }
};

user.introduce();          // → Я Рустам
const f = user.introduce;  // взяли функцию без объекта
f();                       // TypeError: this — undefined, у него нет name

Как исправить: вызывать через объект — user.introduce(), или обернуть в стрелочную функцию: const f = () => user.introduce();. Так часто бывает, когда метод передают в другую функцию, например setTimeout(user.introduce, 1000) — там тоже потеряется this.

const user = {
  name: "Рустам",
  introduce() {
    console.log(`Я ${this.name}`);
  }
};

const f = () => user.introduce(); // обёртка: внутри вызов снова через точку
f(); // → Я Рустам

Для управления this есть ещё методы bind, call и apply — например, user.introduce.bind(user) навсегда «привязывает» объект. Мы разберём их позже, сейчас достаточно правила «объект перед точкой».

ИИ-подсказка

05 Деструктуризация

Деструктуризация — короткий способ «разложить» объект или массив по отдельным переменным. Вместо трёх строк const name = user.name; const age = user.age; ... — одна.

Аналогия из жизни

Вы пришли с базара с пакетом: дыня, нон, гранат. Можно каждый раз лезть в пакет — «пакет, дай дыню». А можно сразу разложить: дыню на стол, нон в хлебницу, гранат в вазу. Деструктуризация — это и есть «разложить содержимое по местам», чтобы дальше брать сразу.

Из объекта: по именам ключей

const user = { name: "Зарина", age: 21, city: "Пенджикент" };

// по-старому
const userCity = user.city;

// деструктуризация: берём ключи name и age в одноимённые переменные
const { name, age } = user;

console.log(name, age);  // → Зарина 21
console.log(userCity);   // → Пенджикент

Слева от = фигурные скобки означают не «создать объект», а «достать из объекта». Имена переменных должны совпадать с ключами, порядок не важен.

Переименование и значения по умолчанию

const user = { name: "Зарина", age: 21, city: "Пенджикент" };

// name: userName — «возьми ключ name, но назови переменную userName»
const { name: userName } = user;
console.log(userName); // → Зарина

// значение по умолчанию — если ключа нет (undefined)
const { country = "Таджикистан", city = "Душанбе" } = user;
console.log(country); // → Таджикистан (ключа не было)
console.log(city);    // → Пенджикент (ключ был — default не нужен)
Как запомнить двоеточие

В деструктуризации { откуда: куда }: слева от двоеточия — ключ объекта, справа — имя новой переменной. А = — значение по умолчанию.

Вложенная деструктуризация

const order = {
  id: 77,
  customer: { name: "Фарход", phone: "+992 90 111 22 33" },
  address: { city: "Душанбе", street: "проспект Рудаки, 45" }
};

const { id, customer: { name }, address: { street } } = order;
console.log(id, name, street); // → 77 Фарход проспект Рудаки, 45

// customer и address тут — только «путь», переменных с такими именами нет

Из массива: по позиции

Для массива используются квадратные скобки, и переменные берутся по порядку, а не по именам.

const route = ["Душанбе", "Варзоб", "Искандеркуль"];

const [start, stop, finish] = route;
console.log(start);  // → Душанбе
console.log(finish); // → Искандеркуль

// пропустить элемент — просто запятая
const [, , lake] = route;
console.log(lake);   // → Искандеркуль

// поменять две переменные местами
let first = "чой";
let second = "шакароб";
[first, second] = [second, first];
console.log(first, second); // → шакароб чой

В параметрах функции

Самое частое применение: функция принимает объект и сразу раскладывает его. Видно, какие поля ей нужны, и можно задать значения по умолчанию.

function showProduct({ title, price, currency = "сомони" }) {
  console.log(`${title}: ${price} ${currency}`);
}

showProduct({ title: "Гранат", price: 15 });   // → Гранат: 15 сомони
showProduct({ title: "Черешня", price: 3, currency: "$" }); // → Черешня: 3 $

// в колбэках массивов
const fruits = [{ title: "Дыня", price: 12 }, { title: "Виноград", price: 18 }];
console.log(fruits.map(({ title }) => title)); // → ["Дыня", "Виноград"]

// и в переборе пар объекта — теперь понятно, что тут происходит
for (const [fruit, kg] of Object.entries({ зардолу: 3, гранат: 2 })) {
  console.log(`${fruit} — ${kg} кг`);
}
// → зардолу — 3 кг
// → гранат — 2 кг
Почему это повсюду в React

Во frontend-фреймворке React, который вы будете изучать, компонент получает данные как объект — и почти всегда его сразу деструктурируют. А хук useState возвращает массив из двух элементов, который раскладывают по позициям. Пока просто узнайте знакомую форму:

function ProductCard({ title, price }) {          // деструктуризация объекта
  const [count, setCount] = useState(0);          // деструктуризация массива
  // ...
}
Частые ошибки

1) Опечатка в имени: const { nmae } = user — получите undefined, ошибки не будет.
2) Деструктуризация из undefined: const { name } = undefined → TypeError.
3) Переменная уже объявлена: const { name } = user, когда name уже есть выше → SyntaxError: ... has already been declared. Используйте переименование.
4) Значение по умолчанию срабатывает только для undefined, а не для null или 0.

06 Spread и rest: три точки ...

Три точки ... в JavaScript работают в двух ролях. Spread («распаковка») раскладывает массив или объект на отдельные элементы. Rest («остаток») наоборот собирает отдельные элементы в массив или объект. Запись одна, а смысл зависит от места.

Spread для массивов

const fruits = ["зардолу", "гранат"];
const more = ["дыня", "виноград"];

// объединить
const all = [...fruits, ...more];
console.log(all); // → ["зардолу", "гранат", "дыня", "виноград"]

// добавить элемент в начало или конец, не меняя исходный массив
const withCherry = ["черешня", ...fruits];
console.log(withCherry); // → ["черешня", "зардолу", "гранат"]

// разложить массив в аргументы функции
const prices = [12, 45, 7];
console.log(Math.max(...prices)); // → 45

Копия или ссылка?

Очень важная вещь. Знак = не копирует массив или объект — он даёт второе имя тому же самому. Настоящая копия — через spread.

Аналогия из жизни

const b = a — это второй ключ от той же квартиры: переставили диван — увидят оба хозяина. const b = [...a] — это новая квартира с такой же мебелью: в одной меняете что угодно, другая остаётся прежней.

const fruits = ["зардолу", "гранат"];

const same = fruits;      // НЕ копия — то же самое
same.push("дыня");
console.log(fruits);      // → ["зардолу", "гранат", "дыня"] (испортили!)

const copy = [...fruits]; // настоящая копия
copy.push("виноград");
console.log(fruits);      // → ["зардолу", "гранат", "дыня"] (не изменился)
console.log(copy);        // → ["зардолу", "гранат", "дыня", "виноград"]

Spread для объектов

С объектами — так же: копировать, объединять и «менять одно поле» в копии. Если ключ встречается дважды, побеждает последний.

const user = { name: "Далер", age: 20, city: "Куляб" };

// копия с изменённым полем
const older = { ...user, age: 21 };
console.log(user.age, older.age); // → 20 21

// объединить два объекта
const contacts = { phone: "+992 91 000 11 22", telegram: "@daler" };
const full = { ...user, ...contacts };
console.log(Object.keys(full)); // → ["name", "age", "city", "phone", "telegram"]

// порядок важен: последний побеждает
const wrong = { age: 21, ...user };
console.log(wrong.age); // → 20 (age из user перезаписал 21)

Почему frontend любит новые копии

Во frontend (и особенно в React) принято не менять старые данные, а создавать новые копии с изменениями. Это называется неизменяемость (immutability). Зачем? Программа сравнивает старые данные с новыми: если объект тот же самый (вы его просто поправили), она решает, что ничего не изменилось, и не обновляет экран. Новая копия — чёткий сигнал: «данные изменились, перерисуй».

const addToCart = (cart, item) => [...cart, item];
const updateQty = (item, qty) => ({ ...item, qty });

const cart = [{ title: "Нон", qty: 2 }];
const newCart = addToCart(cart, { title: "Чой", qty: 1 });

console.log(cart.length, newCart.length); // → 1 2
console.log(updateQty(cart[0], 5));       // → { title: "Нон", qty: 5 }
console.log(cart[0]);                     // → { title: "Нон", qty: 2 }
Ловушка: копия поверхностная

Spread копирует только первый уровень. Вложенные объекты и массивы не копируются — копия и оригинал продолжают делить их.

const student = { name: "Абдулло", address: { city: "Турсунзаде" } };

const copy = { ...student };
copy.name = "Абдулло К.";          // первый уровень — копия, оригинал цел
copy.address.city = "Душанбе";     // вложенный объект — общий!

console.log(student.name);         // → Абдулло
console.log(student.address.city); // → Душанбе (баг!)

// правильно: копируем и вложенный уровень
const student2 = { name: "Мадина", address: { city: "Худжанд" } };
const moved = { ...student2, address: { ...student2.address, city: "Душанбе" } };
console.log(student2.address.city, moved.address.city); // → Худжанд Душанбе

Полную (глубокую) копию можно сделать через structuredClone — разберём в теме 07.

Rest: собрать «всё остальное»

В параметрах функции ... собирает все переданные аргументы в массив. Так можно написать функцию, которая принимает сколько угодно чисел.

function sum(...nums) {
  console.log(nums); // это обычный массив
  return nums.reduce((total, n) => total + n, 0);
}

console.log(sum(10, 20, 5)); // → [10, 20, 5]
                             // → 35
console.log(sum());          // → []
                             // → 0

// rest после обычных параметров: первый — отдельно, остальные — в массив
function order(customer, ...dishes) {
  console.log(`${customer} заказал(а): ${dishes.length} блюда`);
}
order("Зарина", "курутоб", "самбуса", "чой"); // → Зарина заказал(а): 3 блюда

В деструктуризации rest собирает «остаток» объекта или массива. Очень удобно, чтобы убрать лишние поля — например, пароль перед отправкой данных на экран.

const account = { login: "madina", password: "12345", email: "m@mail.tj", city: "Худжанд" };

const { password, ...safeUser } = account;
console.log(safeUser); // → { login: "madina", email: "m@mail.tj", city: "Худжанд" }

const [winner, ...others] = ["Фарход", "Зарина", "Рустам"];
console.log(winner); // → Фарход
console.log(others); // → ["Зарина", "Рустам"]

Где стоитСправа от =, внутри [ ] или { }, в аргументах при вызовеВ параметрах функции, слева от = в деструктуризации
Что делаетМассив/объект → отдельные элементыОтдельные элементы → массив/объект

Частые ошибки

1) Думать, что = копирует массив или объект.
2) Rest не в конце: function f(...items, last) → SyntaxError.
3) Забыть, что копия поверхностная, и менять вложенный объект «копии».
4) { age: 21, ...user } вместо { ...user, age: 21 } — новое значение перезаписывается старым.

07 JSON: как данные путешествуют

Сервер и браузер — это разные программы, часто на разных компьютерах. Объект JavaScript нельзя «передать по проводу» как есть: по сети передаётся текст. Поэтому придумали JSON (JavaScript Object Notation) — текстовый формат для обмена данными. Он выглядит почти как объект JS, но это строка.

Аналогия из жизни

Вы переезжаете из Худжанда в Душанбе. Шкаф целиком в машину не влезет — вы его разбираете, упаковываете в коробки с инструкцией, а на новом месте собираете обратно. JSON.stringify — «разобрать и упаковать» объект в строку. JSON.parse — «собрать обратно» объект из строки.

Где вы встретите JSON:

  • Ответы сервера. Погода, список товаров, заказы — всё приходит строкой JSON, которую нужно превратить в объект.
  • localStorage — хранилище в браузере. Оно умеет хранить только строки, поэтому объекты кладут туда в виде JSON.
  • Файлы настроек проектов, например package.json.
{
  "name": "Мадина",
  "age": 19,
  "isStudent": true,
  "skills": ["HTML", "CSS"],
  "address": { "city": "Худжанд" },
  "phone": null
}

JSON.stringify: объект → строка

const order = { id: 501, dish: "Курутоб", price: 28, paid: true, extras: ["нон", "чой"] };

const json = JSON.stringify(order);
console.log(json); // → {"id":501,"dish":"Курутоб","price":28,"paid":true,"extras":["нон","чой"]}
console.log(typeof order, typeof json); // → object string
console.log(json.length); // → 73 (это просто строка из 73 символов)

Чтобы JSON было удобно читать человеку, передайте ещё два аргумента: JSON.stringify(obj, null, 2). Третий аргумент — сколько пробелов в отступе, второй пока всегда null.

const weather = { city: "Хорог", temp: 18, wind: 6 };
console.log(JSON.stringify(weather, null, 2));
// {
//   "city": "Хорог",
//   "temp": 18,
//   "wind": 6
// }

Функции и undefined в JSON не попадают — они просто пропадают:

const user = { name: "Нилуфар", age: undefined, greet() { return "Салом"; } };
console.log(JSON.stringify(user)); // → {"name":"Нилуфар"}

JSON.parse: строка → объект

const text = '{"city":"Душанбе","temp":31,"sunny":true}';

console.log(text.temp);   // → undefined (у строки нет свойства temp!)

const weather = JSON.parse(text);
console.log(typeof text, typeof weather); // → string object
console.log(weather.temp + 1); // → 32
console.log(weather.city);     // → Душанбе

Ошибки разбора и try/catch

Если строка — не правильный JSON (одинарные кавычки, лишняя запятая, обрезанный ответ), JSON.parse выбрасывает ошибку SyntaxError, и программа останавливается. Чтобы этого не было, используют конструкцию try...catch:

  1. try { ... } — «попробуй выполнить». Если всё хорошо, блок catch пропускается.
  2. catch (error) { ... } — «если внутри try что-то упало, приходи сюда». В error лежит объект ошибки, у него есть name и message.
  3. Программа продолжает работать со следующей строки после catch.
const bad = "{'city': 'Хорог'}"; // одинарные кавычки — это не JSON

try {
  const data = JSON.parse(bad);
  console.log(data.city);
} catch (error) {
  console.log("Не удалось прочитать данные");  // → Не удалось прочитать данные
  console.log(error.name);                      // → SyntaxError
}

console.log("Программа работает дальше");       // → Программа работает дальше

Сохранение в localStorage

localStorage хранит данные в браузере даже после перезагрузки страницы — например, корзину или тему оформления. Он принимает только строки, поэтому без JSON никак. Этот код запускайте у себя в проекте: во встроенном окошке запуска localStorage может быть недоступен.

const cart = [{ id: 1, title: "Нон", qty: 3 }, { id: 4, title: "Мёд", qty: 1 }];

// сохранить: объект → строка
localStorage.setItem("cart", JSON.stringify(cart));

// прочитать: строка → объект. Если ключа нет, getItem вернёт null
const saved = JSON.parse(localStorage.getItem("cart")) ?? [];
console.log(saved.length); // 2
Частая ошибка: забыли stringify

Если положить объект в localStorage без JSON.stringify, он превратится в бесполезную строку "[object Object]", и данные пропадут.

const cart = { id: 1, qty: 3 };
console.log(String(cart));         // → [object Object]  (вот что сохранится без JSON)
console.log(JSON.stringify(cart)); // → {"id":1,"qty":3}

Глубокая копия

Помните ловушку поверхностной копии из темы 06? Есть два способа сделать полную копию со всеми вложенными объектами:

const original = { name: "Шахром", address: { city: "Бохтар" }, skills: ["HTML"] };

const copy1 = JSON.parse(JSON.stringify(original)); // старый способ
const copy2 = structuredClone(original);            // современный способ

copy1.address.city = "Душанбе";
copy2.skills.push("CSS");

console.log(original.address.city); // → Бохтар (не изменился)
console.log(original.skills);       // → ["HTML"]

У JSON-способа есть минус: он теряет функции и undefined. structuredClone аккуратнее, но функции тоже не копирует (выдаст ошибку). Для обычных данных — объектов, массивов, строк и чисел — подходят оба.

Реальный пример: погода в Душанбе

Так примерно выглядит ответ сервиса погоды. Мы превращаем строку в объект, достаём нужное деструктуризацией и ищем самый жаркий день.

const response = `{
  "city": "Душанбе",
  "current": { "temp": 33, "wind": 3, "description": "солнечно" },

    { "day": "Вт", "max": 36, "min": 21 },
    { "day": "Ср", "max": 31, "min": 18 }

const nights = forecast.map(({ day, min }) => `${day}: ${min}°`);
console.log(nights); // → ["Пн: 19°", "Вт: 21°", "Ср: 18°"]

Итоги урока

  • Объект — одна вещь с названными свойствами: { name: "Фарход", age: 20 }. Массив — список однотипных вещей. Массив объектов — самая частая форма данных.
  • Чтение: obj.key или obj["key"] (ключ с пробелом или в переменной: obj[field]). Нет свойства → undefined.
  • Изменить/добавить: obj.key = value. Удалить: delete obj.key. Проверить: "key" in obj. Объект в const менять можно, переприсвоить нельзя.
  • Короткая запись: { name, age }. Стрелочная функция возвращает объект в скобках: () => ({ ... }).
  • Перебор: Object.keys / values / entries + for (const [key, value] of Object.entries(obj)). Число свойств: Object.keys(obj).length.
  • Вложенность: group.students[1].name. Необязательные данные: user.address?.city ?? "—".
  • Метод — функция в объекте: greet() { }, вызов со скобками obj.greet().
  • this — объект перед точкой при вызове. Методы с this — не стрелочные; колбэки внутри метода — стрелочные. Оторванный метод теряет this.
  • Деструктуризация: const { name: userName, city = "Душанбе" } = user, const [first, , third] = arr, function f({ title, price }).
  • Spread распаковывает: [...a, ...b], { ...user, age: 21 } — новая копия (поверхностная!). Rest собирает: function sum(...nums), const { password, ...safe } = user.
  • JSON — текст для обмена данными: JSON.stringify(obj, null, 2) и JSON.parse(str) внутри try...catch. localStorage хранит только строки. Глубокая копия — structuredClone(obj).
  • С ИИ: называйте методы и структуры, давайте пример данных и точный вывод, просите крайние случаи, проверяйте запуском. Не вставляйте код, который не можете объяснить.
