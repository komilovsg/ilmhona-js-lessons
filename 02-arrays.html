Массивы и их методы

Ассалому алейкум! Откройте любой сайт: список товаров в интернет-магазине, лента сообщений в чате, карточки ресторанов в доставке, расписание автобусов. Данные с сервера почти всегда приходят массивами, и работа фронтенд-разработчика — превратить такой массив в то, что человек видит на экране: отфильтровать, отсортировать, посчитать итог. 01 Что такое массив

До сих пор каждая переменная хранила одно значение: одно имя, одну цену, одну оценку. Но в жизни данные чаще идут списком: список покупок на Шохмансуре, расписание уроков на неделю, оценки всей группы за экзамен. Заводить переменные item1, item2, item3… неудобно: а если покупок будет сто?

Массив — это одна переменная, в которой хранится упорядоченный список значений. «Упорядоченный» значит, что у каждого значения есть своё место: первое, второе, третье и так далее.

Аналогия из жизни

Представьте поезд Душанбе–Худжанд. Поезд — это массив, вагоны — его элементы. Вагоны стоят строго по порядку, и у каждого есть номер. Только в JavaScript нумерация начинается не с 1, а с 0: самый первый вагон — нулевой.

Ещё одна картинка — ячейки камеры хранения на вокзале: ряд одинаковых ячеек, на каждой номер, в каждой что-то лежит. Знаете номер — сразу открываете нужную ячейку.

Массив
упорядоченный список значений в квадратных скобках: ["нон", "чой"].
Элемент
одно значение внутри массива, например "нон".
Индекс
номер места элемента. Считается с нуля: 0, 1, 2…
Длина
сколько элементов в массиве. Узнаём через .length.

Как создать массив

Пишем квадратные скобки, внутри — значения через запятую. Пустые скобки [] — пустой массив, в который потом можно что-то добавить.

const shopping = ["нон", "чой", "шакар", "зардолу"];
const scores = [78, 92, 65];
const empty = [];

console.log(shopping); // → ["нон", "чой", "шакар", "зардолу"]
console.log(scores);   // → [78, 92, 65]
console.log(empty);    // → []

Почему индексы начинаются с нуля

Индекс — это не «номер по порядку», а смещение: сколько шагов нужно сделать от начала массива, чтобы дойти до элемента. До первого элемента идти не нужно — ноль шагов, поэтому его индекс 0. До второго — один шаг, индекс 1. Так устроена память компьютера, и почти все языки программирования считают так же.

Отсюда простое правило: индекс последнего элемента = длина − 1. В массиве из 4 элементов последний индекс — 3.

Читаем элементы: индекс, length, at

const wagons = ["локомотив", "вагон-ресторан", "купе", "плацкарт"];

console.log(wagons.length);             // → 4
console.log(wagons[0]);                 // → локомотив
console.log(wagons[2]);                 // → купе
console.log(wagons[wagons.length - 1]); // → плацкарт
console.log(wagons.at(-1));             // → плацкарт
console.log(wagons.at(-2));             // → купе

wagons[wagons.length - 1] — классический способ взять последний элемент: длина 4, значит последний индекс 3. Современный способ короче: wagons.at(-1). Метод at понимает отрицательные числа: −1 — последний, −2 — предпоследний.

Меняем элемент по индексу

Обращаемся к ячейке по индексу и присваиваем новое значение — старое просто заменится.

const schedule = ["HTML", "CSS", "JavaScript"];
schedule[1] = "Figma";

console.log(schedule);     // → ["HTML", "Figma", "JavaScript"]
console.log(schedule[5]);  // → undefined
console.log(schedule[-1]); // → undefined

Если обратиться к индексу, которого нет, JavaScript не выдаст ошибку, а вернёт undefined — «здесь ничего нет». Обратите внимание: schedule[-1] тоже undefined. Отрицательные индексы в квадратных скобках не работают — для этого есть at(-1).

Разные типы в одном массиве

const student = ["Мадина", 19, true, null];
console.log(student);        // → ["Мадина", 19, true, null]
console.log(student.length); // → 4

Так писать можно, но на практике в одном массиве обычно хранят однотипные данные: только цены, только имена, только оценки. С таким массивом проще работать — все элементы можно обработать одинаково.

const-массив всё равно можно менять

Это удивляет почти всех. const запрещает переприсвоить переменную, то есть положить в неё другой массив. Но менять содержимое того же массива можно.

const cart = ["нон"];
cart[1] = "чой";
console.log(cart); // → ["нон", "чой"]

const cart = ["нон"];
cart = ["самбуса"]; // пытаемся положить в переменную другой массив
Аналогия из жизни

Вернёмся к камере хранения. Переменная хранит не сами вещи, а ключ от ячейки (программисты говорят «ссылку»). const означает: ключ поменять нельзя, он всегда от этой ячейки. Но открыть ячейку и переложить вещи внутри — пожалуйста.

Перебор массива циклом

Чаще всего с массивом нужно что-то сделать для каждого элемента. Вы уже знаете цикл for — он отлично подходит, когда нужен индекс.

const grades = [5, 4, 5, 3];

for (let i = 0; i < grades.length; i++) {
  console.log(`Оценка №${i + 1}: ${grades[i]}`);
}
// Выведет:
// Оценка №1: 5
// Оценка №2: 4
// Оценка №3: 5
// Оценка №4: 3

Если индекс не нужен, удобнее for...of: на каждом шаге в переменную попадает очередной элемент.

const fruits = ["зардолу", "гранат", "черешня"];

for (const fruit of fruits) {
  console.log(`Купить: ${fruit}`);
}
// Выведет:
// Купить: зардолу
// Купить: гранат
// Купить: черешня

Есть ли элемент в массиве: includes и indexOf

Два маленьких, но очень полезных метода. includes(значение) отвечает «да/нет», а indexOf(значение) возвращает индекс первого совпадения или -1, если ничего не нашлось.

const menu = ["оши палав", "самбуса", "курутоб"];

console.log(menu.includes("самбуса")); // → true
console.log(menu.includes("манту"));   // → false
console.log(menu.indexOf("курутоб"));  // → 2
console.log(menu.indexOf("манту"));    // → -1
Частые ошибки

1. Выход за границу. arr[arr.length] — это уже за последним элементом, получим undefined. Последний — arr[arr.length - 1].

2. Лишний шаг в цикле. Условие i <= arr.length делает на один шаг больше, и последний вывод будет undefined. Правильно: i < arr.length.

3. Скобки после length. length — это свойство, а не функция. arr.length() выдаст ошибку «is not a function». Пишем без скобок: arr.length.

Перед методами: мутирующие и немутирующие

Дальше в уроке будет много методов — встроенных функций, которые есть у каждого массива и вызываются через точку: arr.push(...). Все они делятся на две группы, и это деление надо держать в голове всегда.

Важно

Мутирующие методы меняют исходный массив («мутация» — изменение). После вызова старого массива в прежнем виде больше нет.

Немутирующие методы исходный массив не трогают: они возвращают новое значение, а оригинал остаётся как был. Во фронтенде (например, в React) это особенно важно: данные на экране обновляются правильно только тогда, когда мы не портим исходный массив, а создаём новый.

02 push и pop: добавить и убрать в конце

Самые частые операции со списком — положить что-то в конец и забрать последнее. Пользователь добавил товар в корзину — push. Нажал «Отменить последнее действие» — pop.

Аналогия из жизни

Стопка горячих лепёшек нон в пекарне. Пекарь кладёт новую лепёшку сверху — это push. Покупатель берёт тоже сверху — последнюю положенную. Это pop. Конец массива — это верх стопки.

push — добавить в конец

arr.push(элемент1, элемент2, …)Возвращает: новую длинуМеняет исходный массив
const stack = ["нон", "нон"];
const newLength = stack.push("нон с кунжутом");

console.log(newLength); // → 3
console.log(stack);     // → ["нон", "нон", "нон с кунжутом"]

stack.push("патыр", "фатир"); // можно добавить сразу несколько
console.log(stack.length);    // → 5

pop — забрать последний

arr.pop()Возвращает: удалённый элементМеняет исходный массив
const orders = ["самбуса", "курутоб", "шакароб"];
const last = orders.pop();

console.log(last);   // → шакароб
console.log(orders); // → ["самбуса", "курутоб"]

const empty = [];
console.log(empty.pop()); // → undefined

Из пустого массива pop() вернёт undefined — ошибки не будет, просто забирать нечего.

Частая ошибка

Думать, что push возвращает массив. Он возвращает число — новую длину. Поэтому так писать нельзя:

Так плохо

В cart окажется число, а не массив.

let cart = ["нон"];
cart = cart.push("чой");
console.log(cart); // 2 — массив потерян!
Так хорошо

Просто вызываем метод — массив изменится сам.

const cart = ["нон"];
cart.push("чой");
console.log(cart); // ["нон", "чой"]
Совет: shift и unshift — то же самое, но в начале

Если стопка — это push/pop, то очередь — это работа с началом. В очереди в банк или к маршрутке первым обслуживают того, кто пришёл первым: shift() убирает первый элемент и возвращает его. А unshift(элемент) ставит элемент в самое начало (например, пропускаем вперёд пожилого человека) и возвращает новую длину.

arr.shift()Возвращает: удалённый первыйМеняет исходный массив
arr.unshift(элемент)Возвращает: новую длинуМеняет исходный массив
const queue = ["Фарход", "Мадина", "Рустам"];

const first = queue.shift();
console.log(first); // → Фарход
console.log(queue); // → ["Мадина", "Рустам"]

const len = queue.unshift("Абдулло-ака");
console.log(len);   // → 3
console.log(queue); // → ["Абдулло-ака", "Мадина", "Рустам"]

После shift и unshift у всех оставшихся элементов меняются индексы: каждый сдвигается на одно место. Помните об этом, если сохранили индекс в переменную заранее.

03 splice: удалить, вставить, заменить в середине

push и pop работают только с концом. А что если нужно убрать остановку из середины маршрута или вставить новый урок между двумя другими? Для этого есть универсальный метод splice — «швейцарский нож» массивов.

Аналогия из жизни

Поезд стоит на станции. Рабочий может в любом месте состава отцепить несколько вагонов и на их место прицепить новые. Нужно сказать ему три вещи: с какого вагона начать, сколько отцепить и какие вагоны прицепить вместо них. Ровно эти три вещи принимает splice.

arr.splice(start, deleteCount, ...items)Возвращает: массив удалённыхМеняет исходный массив
start
индекс, с которого начинаем. Может быть отрицательным: −1 — последний элемент.
deleteCount
сколько элементов удалить, начиная со start. Если 0 — ничего не удаляем.
...items
необязательные элементы, которые вставятся на место start. Три точки означают «сколько угодно штук через запятую».

1. Удалить

const stops = ["Вокзал", "Зелёный базар", "Шохмансур", "Цирк", "Корвон"];
const removed = stops.splice(1, 2);

Отрицательный start

Ловушка: забыли deleteCount

Если указать только start, splice удалит всё от start до конца.

const cities = ["Душанбе", "Худжанд", "Бохтар", "Куляб"];

Частая ошибка

Ждать, что splice вернёт новый массив без удалённых элементов. Нет: он возвращает удалённые, а изменённым становится сам исходный массив. Если написать const result = arr.splice(0, 1), в result будет массив из одного удалённого элемента.

04 slice: скопировать часть массива

slice («ломтик, кусочек») берёт часть массива и возвращает её как новый массив. Исходный массив при этом не меняется совсем. Это один из самых безопасных методов.

Аналогия из жизни

Вам нужны три страницы из учебника. Вы не вырываете их, а делаете ксерокопию. У вас в руках новые листы, а учебник остался целым. slice — это ксерокопия, а splice из прошлой темы — это ножницы.

arr.slice(start, end)Возвращает: новый массивНе меняет исходный

Конец не включается

Самое важное правило: элемент с индексом end в результат не попадает. slice(1, 4) берёт индексы 1, 2 и 3 — «от 1 до 4, но 4 не трогаем».

const days = ["Пн", "Вт", "Ср", "Чт", "Пт", "Сб"];

console.log(days.slice(1, 4)); // → ["Вт", "Ср", "Чт"]
console.log(days.slice(3));    // → ["Чт", "Пт", "Сб"]
console.log(days.slice(-2));   // → ["Пт", "Сб"]
console.log(days.slice(0, -1)); // → ["Пн", "Вт", "Ср", "Чт", "Пт"]
console.log(days);             // → ["Пн", "Вт", "Ср", "Чт", "Пт", "Сб"]
  1. slice(3) — без end берём всё от индекса 3 до конца.
  2. slice(-2) — отрицательный индекс считается с конца: последние два элемента.
  3. slice(0, -1) — всё, кроме последнего: стоп-линия на последнем элементе.
  4. Последняя строка показывает, что days остался прежним.

Полная копия: slice() без аргументов

Иногда нужен полный дубликат массива, чтобы менять его, не трогая оригинал. Для этого — slice() без аргументов или запись [...arr] (три точки «раскладывают» элементы в новые скобки).

const original = ["нон", "чой"];
const copy1 = original.slice();
const copy2 = [...original];

copy1.push("самбуса");
copy2.push("курутоб");

console.log(original); // → ["нон", "чой"]
console.log(copy1);    // → ["нон", "чой", "самбуса"]
console.log(copy2);    // → ["нон", "чой", "курутоб"]
Частая ошибка: это не копия

const copy = original; не создаёт новый массив. Вы просто сделали второй ключ от той же ячейки камеры хранения. Меняете copy — меняется и original.

const original = ["Фарход", "Мадина"];
const notCopy = original; // это та же самая ссылка
notCopy.push("Рустам");

console.log(original); // → ["Фарход", "Мадина", "Рустам"]

splice или slice? Классическая путаница

Названия отличаются одной буквой, а поведение — полностью. Запомните: в splice есть «p» — как в слове «попортить» исходник.

05 Колбэк и map: преобразовать каждый элемент

Дальше идут методы, которые принимают функцию. Это ключевая идея всего урока, поэтому разберём её очень внимательно.

Что такое колбэк

Колбэк (от английского callback — «обратный вызов») — это функция, которую мы отдаём методу, а он сам вызывает её для каждого элемента. Мы не пишем цикл — цикл уже спрятан внутри метода. Мы только объясняем, что сделать с одним элементом.

Аналогия из жизни

Вы отдаёте ткачихе на фабрике в Худжанде мешок хлопка и инструкцию: «из каждого клубка сделай нитку». Вы не стоите рядом и не командуете каждым движением — она сама берёт клубки по одному и для каждого выполняет вашу инструкцию. Инструкция — это колбэк, ткачиха — это метод.

Чтобы колбэк не казался магией, напишем свой маленький «метод» на знакомом цикле. Именно так map устроен внутри:

function myMap(list, callback) {
  const result = [];
  for (const item of list) {
    result.push(callback(item)); // вызываем ВАШУ функцию для каждого элемента
  }
  return result;
}

const double = (n) => n * 2;
console.log(myMap([4, 7, 10], double)); // → [8, 14, 20]

Заметьте: мы передали double без скобок. Со скобками double() мы бы вызвали функцию сами и отдали её результат. А нам нужно отдать саму функцию, чтобы её вызывал метод.

map — встроенный способ

arr.map((element, index, array) => новоеЗначение)Возвращает: новый массив той же длиныНе меняет исходный

map («отобразить, сопоставить») проходит по каждому элементу, вызывает колбэк и складывает то, что колбэк вернул, в новый массив. Сколько элементов было — столько и останется.

const pricesKg = [18, 25, 12];
const pricesTwoKg = pricesKg.map((price) => price * 2);

console.log(pricesTwoKg); // → [36, 50, 24]
console.log(pricesKg);    // → [18, 25, 12]

Как это выполняется, шаг за шагом

ШагЭлемент priceКолбэк вычисляетРезультат кладётся в новый массив
11818 * 2[36]
22525 * 2[36, 50]
31212 * 2[36, 50, 24]

Параметры колбэка: element, index, array

Метод передаёт колбэку не только элемент. Вторым аргументом приходит индекс, третьим — весь массив. Обычно нужен только первый, иногда — первый и второй. Названия можно давать любые, важен порядок.

const guests = ["Нилуфар", "Далер", "Сабрина"];
const numbered = guests.map((name, index) => `${index + 1}. ${name}`);

console.log(numbered); // → ["1. Нилуфар", "2. Далер", "3. Сабрина"]

const cities = ["душанбе", "худжанд", "хорог"];
const titles = cities.map((city) => city[0].toUpperCase() + city.slice(1));

console.log(titles); // → ["Душанбе", "Худжанд", "Хорог"]

Во втором примере колбэк берёт первую букву (city[0]), делает её заглавной (toUpperCase()) и приклеивает остаток строки (slice(1) работает и у строк). Это обычная фронтенд-задача: привести данные к красивому виду перед показом.

Частая ошибка: забыли return в фигурных скобках

Стрелочная функция без фигурных скобок возвращает результат сама. А с фигурными скобками нужно писать return явно — иначе функция вернёт undefined, и весь новый массив будет из undefined.

const prices = [10, 20, 30];

const wrong = prices.map((p) => { p * 2 });
console.log(wrong); // → [undefined, undefined, undefined]

const right = prices.map((p) => { return p * 2; });
console.log(right); // → [20, 40, 60]

const short = prices.map((p) => p * 2);
console.log(short); // → [20, 40, 60]
Частая ошибка: map ради побочных действий

map нужен, когда вам нужен новый массив. Если вы просто хотите вывести каждый элемент в консоль и результат не используете, берите for...of (или метод forEach — он делает то же самое, но ничего не возвращает).

Так плохо

Создаётся ненужный массив из undefined.

names.map((name) => console.log(name));
Так хорошо

Цикл честно говорит: «просто пройдись по списку».

for (const name of names) {
  console.log(name);
}
ИИ-подсказка

Если колбэк кажется непонятным, попросите ИИ: «Распиши в таблице, что происходит на каждом шаге [3, 5, 8].map(n => n * 10): какой элемент приходит и что возвращается». Пошаговая таблица снимает почти все вопросы.

В реальных данных товар — это не просто цена, а набор сведений: название, цена, наличие. 07 find и findIndex: найти первый подходящий

Часто нужен не список, а один конкретный элемент: товар с нужным названием, студент с нужным именем, первый жаркий день. Для этого есть find.

Аналогия из жизни

08 some: есть ли хотя бы один?

Иногда не нужно ничего искать или отбирать — нужен просто ответ «да» или «нет». Есть ли в корзине товар без наличия? Есть ли среди оценок двойка? Есть ли непрочитанные сообщения? Для этого есть some («некоторые, хотя бы один»).

Аналогия из жизни

Учитель заходит в класс и спрашивает: «Хотя бы у одного есть зарядка для телефона?». Как только поднялась первая рука — ответ «да», остальных можно не спрашивать. Если не поднял никто — ответ «нет».

arr.some((element, index, array) => true или false)Возвращает: true / falseНе меняет исходный
const grades = [4, 5, 3, 5, 2];

console.log(grades.some((g) => g === 1)); // → false

some останавливается рано

Убедимся, что some действительно прекращает проверку на первом «да». Добавим в колбэк console.log:

  console.log(`Проверяю ${p}`);

// Проверяю 40
// Проверяю 250

До 30 и 600 очередь не дошла: ответ уже известен. На больших массивах это экономит время.

Пустой массив → false

const messages = [];
console.log(messages.some((m) => m === "новое")); // → false

Логично: в пустом массиве нет ни одного элемента, значит нет и «хотя бы одного подходящего».

Совет: some и includes

Если вы ищете конкретное значение, проще includes: grades.includes(2). А some нужен, когда есть условие: «есть ли оценка ниже трёх», «есть ли товар дороже 200».

Частая ошибка

Использовать filter(...).length > 0 там, где нужен просто ответ «да/нет». Работать будет, но filter пройдёт весь массив и создаст ненужный новый массив. some короче, понятнее и останавливается раньше.

09 every: все ли подходят?

every («каждый») — брат some. Он отвечает на вопрос: «все ли элементы подходят под условие?». Все ли товары в наличии? Все ли студенты сдали? Все ли поля формы правильные?

Аналогия из жизни

Водитель маршрутки перед поездкой на Искандеркуль проверяет: все ли пассажиры пристегнулись? Он идёт по салону, и как только видит первого непристёгнутого — ответ «нет», можно дальше не смотреть. Ответ «да» будет, только если пристёгнуты все до одного.

arr.every((element, index, array) => true или false)Возвращает: true / falseНе меняет исходный
const scores = [72, 85, 60, 91];

console.log(scores.every((s) => s >= 60)); // → true
console.log(scores.every((s) => s >= 70)); // → false

every останавливается на первом «нет», так же как some останавливается на первом «да». Во втором вызове проверка закончилась на 60.

Пустой массив → true. Почему?

const cart = [];
console.log(cart.every((qty) => qty > 0)); // → true

Это кажется странным, но логика такая: every ищет нарушителя — элемент, который не подходит. В пустом массиве нарушителей нет, значит «все подходят». Как у водителя маршрутки: если в салоне никого нет, то никто и не сидит непристёгнутым.

Ловушка

Из-за этого правила every на пустом массиве легко обманывает. Проверка «все товары в корзине в наличии» на пустой корзине даст true — и кнопка «Оформить заказ» станет активной. Если пустой массив для вас — особый случай, проверьте его отдельно: arr.length === 0.

Связь с логикой из прошлых уроков прямая. [a, b, c].some(check) — это как check(a) || check(b) || check(c). А [a, b, c].every(check) — как check(a) && check(b) && check(c).

console.log(ages.every(isAdult)); // → false
console.log(isAdult(19) && isAdult(22) && isAdult(17)); // → false

Обратите внимание: колбэк можно объявить заранее и передать по имени — ages.some(isAdult). Без скобок, как мы обсуждали в теме про колбэки.

10 reduce: свести массив к одному значению

reduce («свести, сократить») — самый мощный и самый непривычный метод урока. Он проходит по массиву и собирает из всех элементов одно значение: сумму, максимум, итоговую строку, подсчёт. Не торопитесь: разберём его медленно.

Аналогия из жизни

Касса в чайхоне. Компания заказала плов, самбусу, салат и чай. Кассир начинает с нуля на экране калькулятора. Берёт первое блюдо — прибавляет его цену, на экране новый промежуточный итог. Берёт следующее — прибавляет к тому, что уже на экране. И так до последнего блюда. То, что на экране в конце, — итог чека.

Число на экране кассира называется аккумулятор (от слова «накапливать»). Это как копилка: в неё всё время что-то добавляется, и в конце мы её открываем.

arr.reduce((acc, current) => новыйAcc, начальноеЗначение)Возвращает: одно итоговое значениеНе меняет исходный
acc
аккумулятор — промежуточный итог. На первом шаге равен начальному значению, дальше — тому, что колбэк вернул на прошлом шаге.

Считаем чек шаг за шагом

const bill = [120, 45, 30, 75];

const total = bill.reduce((acc, current) => acc + current, 0);
console.log(total); // → 270

Колбэк вызывается 4 раза — по разу на каждый элемент. Каждый раз он получает старый итог и текущую цену, а возвращает новый итог.

Обратите внимание на главное: то, что колбэк вернул, становится acc на следующем шаге. Если колбэк ничего не вернёт (забыли return в фигурных скобках), на следующем шаге acc будет undefined.

Тот же код, но с «подглядыванием» в каждый шаг:

const bill = [120, 45, 30, 75];

  console.log(`acc = ${acc}, current = ${current}, вернём ${acc + current}`);
  return acc + current;
}, 0);

// Выведет:
// acc = 0, current = 120, вернём 120
// acc = 120, current = 45, вернём 165
// acc = 165, current = 30, вернём 195
// acc = 195, current = 75, вернём 270
// Итого: 270 сомони

Всегда передавайте начальное значение

Начальное значение можно не писать — тогда acc на старте станет первым элементом массива, а обход начнётся со второго. Для суммы чисел это даже сработает. Но есть два случая, где это ломает программу.

Случай 1: пустой массив. Без начального значения reduce не знает, с чего начать, и выдаёт ошибку.

const emptyBill = [];
const total = emptyBill.reduce((acc, current) => acc + current);
console.log(total);

const emptyBill = [];
const total = emptyBill.reduce((acc, current) => acc + current, 0);
console.log(total); // → 0

Случай 2: элементы не того типа, что итог. Посчитаем общую длину имён. Без начального значения первым acc станет строка «Фарход», и дальше числа будут приклеиваться к строке.

const names = ["Фарход", "Мадина", "Рустам"];

const wrong = names.reduce((acc, name) => acc + name.length);
console.log(wrong); // → Фарход66

const right = names.reduce((acc, name) => acc + name.length, 0);
console.log(right); // → 18
Совет

Сделайте привычкой: всегда пишите начальное значение. Для суммы — 0, для строки — "", для подсчёта — {}. Это сразу показывает, какого типа будет результат.

Максимум

const temps = [36, 41, 38, 43, 39];
const max = temps.reduce((acc, t) => (t > acc ? t : acc), temps[0]);

console.log(max); // → 43

Здесь в acc хранится «самое большое на данный момент». На каждом шаге сравниваем: если текущий больше — он становится новым максимумом, иначе оставляем старый. Начинаем с первого элемента, а не с 0: вдруг все температуры отрицательные (зимой в Хороге бывает и −20).

Для простого максимума есть и короткий путь — Math.max(...temps). Но разобрать его через reduce полезно: так же решаются задачи, где готовой функции нет.

Подсчёт повторений (лёгкое знакомство с объектом)

Начальное значение может быть пустым объектом {}. На каждом шаге добавляем в него «счётчик» для текущего слова.

const orders = ["чой", "самбуса", "чой", "нон", "чой"];

const count = orders.reduce((acc, item) => {
  acc[item] = (acc[item] || 0) + 1;
  return acc;
}, {});
console.log(count); // → { чой: 3, самбуса: 1, нон: 1 }

Строка acc[item] = (acc[item] || 0) + 1 читается так: «возьми текущий счёт этого блюда, а если его ещё нет — возьми 0, прибавь 1 и запиши обратно». Квадратные скобки acc[item] — это способ обратиться к ключу, имя которого лежит в переменной. Подробнее — в уроке про объекты.

Склеиваем строку

const fruits = ["зардолу", "гранат", "дыня"];

const text = fruits.reduce((acc, fruit, i) => acc + (i === 0 ? "" : ", ") + fruit, "");
console.log(text); // → зардолу, гранат, дыня

console.log(fruits.join(", ")); // → зардолу, гранат, дыня

Для склейки есть готовый метод join(разделитель) — он возвращает строку из всех элементов. Используйте его, когда нужно просто склеить. А reduce пригодится, когда склейка сложнее: с условиями, с нумерацией, с подсчётом по ходу.

Частые ошибки

1. Забыли return в колбэке с фигурными скобками — на втором шаге acc станет undefined, а итог — NaN («не число»).

2. Перепутали порядок параметров. Первым всегда идёт аккумулятор, вторым — текущий элемент: (acc, current).

3. Не передали начальное значение — смотрите два случая выше.

11 sort: сортировка

Сортировка нужна везде: товары «сначала дешёвые», студенты по алфавиту, матчи по дате. Метод sort упорядочивает элементы массива. Но у него есть две особенности, на которых спотыкаются почти все. Разберём обе.

arr.sort((a, b) => число)Возвращает: тот же массив, уже отсортированныйМеняет исходный массив

Особенность 1: без колбэка sort сравнивает как строки

const prices = [5, 100, 25, 1];
prices.sort();

console.log(prices); // → [1, 100, 25, 5]

Почему 100 оказалось раньше 25? Без колбэка sort превращает каждый элемент в строку и сравнивает строки по символам, как слова в словаре: "1", "100", "25", "5". Строка "100" начинается с «1», поэтому стоит раньше "25", которая начинается с «2». Как в словаре «ананас» стоит раньше «банан», независимо от длины.

Колбэк-сравнитель: (a, b) => a - b

Чтобы сортировать числа правильно, передаём функцию сравнения (компаратор). sort сам много раз берёт пары элементов a и b и спрашивает колбэк: «кто из них должен стоять раньше?». Колбэк отвечает числом:

Колбэк вернулЧто это значит для sort
отрицательное число (например, −3)a ставим раньше b
положительное число (например, 7)b ставим раньше a
0порядок между ними не важен, оставляем как есть

Теперь смотрите, почему a - b даёт сортировку по возрастанию. Пусть a = 5, b = 25: 5 − 25 = −20, отрицательное — значит 5 раньше 25. Пусть a = 100, b = 25: 100 − 25 = 75, положительное — значит 25 раньше 100. Меньшие числа уходят вперёд. А b - a делает всё наоборот — по убыванию.

const prices = [5, 100, 25, 1];

prices.sort((a, b) => a - b);
console.log(prices); // → [1, 5, 25, 100]

prices.sort((a, b) => b - a);
console.log(prices); // → [100, 25, 5, 1]
Совет: как запомнить

a - b — «а потом б», по алфавиту, по возрастанию: от меньшего к большему. b - a — наоборот, от большего к меньшему.

Сортировка строк: localeCompare

Для строк вычитание не работает ("Абдулло" - "Далер" — это NaN). Можно вызвать sort() без колбэка, но для русских имён он ошибается: заглавные буквы у него идут раньше строчных, а буква «Ё» вообще улетает в начало.

const names = ["манижа", "Фарход", "Абдулло"];
console.log([...names].sort()); // → ["Абдулло", "Фарход", "манижа"]
console.log([...names].sort((a, b) => a.localeCompare(b))); // → ["Абдулло", "манижа", "Фарход"]

const team = ["Жасур", "Ёдгор", "Евгений"];
console.log([...team].sort()); // → ["Ёдгор", "Евгений", "Жасур"]
console.log([...team].sort((a, b) => a.localeCompare(b))); // → ["Евгений", "Ёдгор", "Жасур"]

a.localeCompare(b) — метод строки, который сравнивает её с другой строкой «по-человечески», с учётом правил языка. Он сам возвращает отрицательное число, положительное или 0 — ровно то, что нужно sort. Для сортировки «от Я до А» поменяйте местами: b.localeCompare(a).

Сортировка объектов

Колбэк получает два объекта, и мы сравниваем их нужное поле.

const products = [
  { name: "Курутоб", price: 35 },
  { name: "Самбуса", price: 6 },
  { name: "Оши палав", price: 30 },
];

products.sort((a, b) => a.price - b.price);
console.log(products[0].name);    // → Самбуса
console.log(products.at(-1).name); // → Курутоб

Особенность 2: sort меняет исходный массив

sort не создаёт новый массив — он переставляет элементы прямо в исходном. Если оригинальный порядок ещё нужен (например, порядок, в котором данные пришли с сервера), сначала сделайте копию.

const scores = [70, 95, 82];

const sorted1 = [...scores].sort((a, b) => b - a);
const sorted2 = scores.slice().sort((a, b) => b - a);
const sorted3 = scores.toSorted((a, b) => b - a);

console.log(sorted1); // → [95, 82, 70]
console.log(sorted2); // → [95, 82, 70]
console.log(sorted3); // → [95, 82, 70]
console.log(scores);  // → [70, 95, 82]

Третий способ — современный метод toSorted. Он делает то же, что sort, но возвращает новый массив и не трогает оригинал. Он появился в JavaScript недавно (2023 год) и работает во всех современных браузерах.

Частые ошибки

1. Сортировка чисел без колбэка: [5, 100, 25].sort() → [100, 25, 5]. Для чисел всегда пишите (a, b) => a - b.

2. Колбэк возвращает true/false вместо числа: (a, b) => a > b. Такой колбэк работает непредсказуемо. Нужно именно число: a - b.

3. Забыли, что sort мутирует, и «испортили» исходные данные. Сначала копия — потом сортировка.

12 Цепочки методов

Вы уже заметили: map, filter и slice возвращают новый массив. А у нового массива тоже есть все методы. Значит, можно сразу вызвать следующий метод через точку — получится цепочка. Так выглядит почти любой реальный код обработки данных на фронтенде.

Аналогия из жизни

Конвейер на заводе соков в Истаравшане. На первом участке отбраковывают гнилые абрикосы (filter), на втором их моют и режут (map), на третьем всё сливают в одну бочку сока (reduce). Каждый участок получает результат предыдущего. Читаем цепочку так же — сверху вниз, участок за участком.

Задача: в магазине на Корвоне взять товары дороже 100 сомони, сделать на них скидку 10% и посчитать сумму. Сначала по шагам, с промежуточными переменными:

const prices = [450, 60, 380, 15, 220];

const expensive = prices.filter((p) => p > 100);
console.log(expensive);  // → [450, 380, 220]

const discounted = expensive.map((p) => p * 0.9);
console.log(discounted); // → [405, 342, 198]

const total = discounted.reduce((acc, p) => acc + p, 0);
console.log(total);      // → 945

А теперь то же самое одной цепочкой. Каждый метод пишем с новой строки, начиная с точки, — так цепочку легко читать:

const prices = [450, 60, 380, 15, 220];

const total = prices
  .filter((p) => p > 100)       // [450, 380, 220]
  .map((p) => p * 0.9)          // [405, 342, 198]
  .reduce((acc, p) => acc + p, 0); // 945

console.log(`К оплате: ${total} сомони`); // → К оплате: 945 сомони
  1. prices — исходные данные, 5 цен.
  2. .filter(...) — остаются 3 дорогих товара. Возвращается новый массив.
  3. .map(...) — к новому массиву применяется скидка. Снова новый массив той же длины.
  4. .reduce(...) — массив сворачивается в одно число. Цепочка заканчивается: у числа уже нет методов массива.

Цепочка с объектами и сортировкой

const students = [
  { name: "Рустам", score: 54 },
  { name: "Мадина", score: 95 },
  { name: "Фарход", score: 88 },
  { name: "Нилуфар", score: 43 },
];

const honorBoard = students
  .filter((s) => s.score >= 60)
  .sort((a, b) => b.score - a.score)
  .map((s) => `${s.name} (${s.score})`)
  .join(", ");

console.log(honorBoard); // → Мадина (95), Фарход (88)

Здесь sort стоит после filter — и это безопасно: filter уже вернул новый массив, поэтому сортировка меняет его, а не исходный students.

Частые ошибки в цепочках

1. reduce в середине. После reduce обычно получается число или строка, и вызвать на нём .map нельзя — будет ошибка «is not a function».

2. sort в начале цепочки испортит исходный массив. Ставьте его после filter/map/slice или используйте toSorted.

3. Слишком длинная цепочка, которая не работает. Не гадайте — разбейте её на промежуточные переменные и выведите каждую через console.log, как в первом примере. Так вы сразу увидите, на каком участке конвейера проблема.

✓ Итоги: шпаргалка по массивам

  • [] — массив; индексы с 0; последний — arr[arr.length - 1] или arr.at(-1); несуществующий индекс → undefined.
  • const-массив можно менять внутри, но нельзя переприсвоить.
  • includes(x) → есть ли значение; indexOf(x) → индекс или -1.
  • push(x) / pop() — конец массива; unshift(x) / shift() — начало. Мутируют.
  • splice(start, deleteCount, ...items) — удалить/вставить/заменить в середине; возвращает удалённые. Мутирует.
  • slice(start, end) — копия части, end не включается; slice() и [...arr] — полная копия.
  • Колбэк — функция, которую метод сам вызывает для каждого элемента: (element, index, array).
  • map — преобразовать каждый, длина та же. Не забывайте return в фигурных скобках.
  • filter — оставить подходящие, результат может быть [].
  • find / findIndex — первый подходящий или undefined / -1. Проверяйте «не нашлось».
  • some — хотя бы один? (пустой → false); every — все? (пустой → true).
  • reduce((acc, cur) => ..., начало) — свести к одному значению. Начальное значение — всегда.
  • sort((a, b) => a - b) — числа по возрастанию; строки — a.localeCompare(b). Мутирует: копируйте или берите toSorted.
  • join(", ") — склеить массив в строку.
  • Цепочка: filter → map → reduce, читаем сверху вниз, как конвейер.
