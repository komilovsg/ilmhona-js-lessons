То охири дарс сайти шумо аз интернет маълумот гирифтан мегирад: обу ҳавои Душанбе, қурби сомонӣ ва рӯйхати филмҳоро нишон медиҳад, дар вақти боршавӣ ҳолати интизориро намоиш медиҳад ва агар чизе хато равад, ҳатман дар ин бора ҳушдор медиҳад.   • Нақшаи «клиент → дархост → сервер → ҷавоб»-ро шарҳ додан ва усулҳои асосии HTTP ва рамзҳои ҷавобро номбар кардан
  • JSON-ро хондан ва аз он майдони лозимиро гирифтан, инчунин JSON-и ҳақиқиро аз «қариб-JSON» фарқ кардан

  • Дар саҳифаи Next.js маълумоти API-и ҷамъиятиро бо экранҳои «боршавӣ», «хато», «муваффақият» нишон додан

  • Тағйирёбандаи муҳитро дар Vercel илова кардан ва шарҳ додан, ки чаро баъд аз ин деплойи нав лозим аст

01 Клиент ва сервер: саҳифа чӣ тавр ба браузер меояд

То ҳол маълумот дар лоиҳаҳои шумо бевосита дар код меистод: массиви мол, рӯйхати табибон, матни варақаҳо. Сайтҳои воқеӣ маълумотро аз компютерҳои дигар мегиранд: қурби асъор, обу ҳаво, фармоишҳо, паёмҳо. Ин компютерҳо доимо кор мекунанд ва ба дархостҳо ҷавоб медиҳанд. Онҳоро серверҳо ва касеро, ки мепурсад (браузери шумо ё барномаи шумо), клиент меноманд.

Сӯҳбат ҳамеша як хел сохта шудааст: клиент дархост (request) мефиристад, сервер ҷавоб (response) бармегардонад. Ҳеҷ яке аз онҳо наметавонад «содда занг занад»: сервер то он даме, ки аз ӯ напурсанд, хомӯш аст. Барои чунин сӯҳбат «забони» бо қоидаҳои умумӣ сохтаанд — протоколи HTTP (шакли ҳифзшудаи он — HTTPS, қуфлча дар сатри суроға).

Видео бо забони русӣ (тақрибан 16 дақиқа, соли 2025): манзараи умумии «клиент, сервер, API» бо суханони дигар. Метавонед ҳозир ё баъд аз амалиёт тамошо кунед.

Дархост аз чӣ иборат аст

  • Усул — чӣ кор кардан мехоҳед: гирифтан, сохтан, тағйир додан, нест кардан.
  • Суроға (URL) — ба куҷо: https://api.open-meteo.com/v1/forecast?latitude=38.56&longitude=68.77. Дар ин ҷо https:// — протокол, api.open-meteo.com — домени сервер, /v1/forecast — роҳ (кадом «бахш» лозим аст), ҳама чизи баъд аз ? — параметрҳо тавассути & (кадом шаҳр, кадом майдонҳо).
  • Сарлавҳаҳо (headers) — ёддоштҳои хидматӣ: маълумотро дар кадом формат мефиристед, шумо кистед. Калиди дастрасиро низ аксар вақт ба ин ҷо мегузоранд.
  • Бадан (body) — худи маълумот, агар шумо чизе мефиристед (масалан, аризаи форма). Дар дархости «деҳ» одатан бадан нест.

Дархостҳоро бо чашми худ мебинем: ҷадвали Network

Барои санҷиши API бисёриҳо барномаи алоҳида насб мекунанд. Ба мо он лозим нест: ҳама чиз дар браузер ҳаст. Ягон сайтро кушоед, F12-ро пахш кунед (дар Chrome) ва ҷадвали Network-ро интихоб кунед. Саҳифаро нав кунед (F5): рӯйхати ҳамаи дархостҳо пайдо мешавад. Барои он ки танҳо дархостҳои маълумотро монед, филтри Fetch/XHR-ро фаъол кунед. Ба сатр зер кунед: дар тарафи рост ҷадвали Headers усул ва рамзи ҷавобро, Preview ва Response — худи маълумотро нишон медиҳанд.

Монандӣ аз ҳаёт

Клиент ва сервер — харидор ва фурӯшанда дар бозор. Шумо ба растаи фурӯш наздик мешавед ва мегӯед: «Зардолу чанд пул?» (дархости GET). Фурӯшанда нархро мегӯяд (ҷавоби 200 ва маълумот). Агар шумо дар бораи молеро пурсед, ки дар бозор нест, ӯ дастонашро паҳн мекунад (404). Агар аз ӯ чизеро талаб кунед, ки ба шумо ҷоиз нест, ҷавоб медиҳад «намешавад» (403). Ва агар барқи фурӯшанда қатъ шуда, тарозу кор накунад, ин аллакай садамаи худи ӯст (500).

Хатогиҳои маъмули навомӯзон

1. Фикр кардан, ки саҳифа тамоми маълумотро якбора дорад: бисёр маълумот баъд аз боршавии саҳифа бо дархостҳои алоҳида меояд. 2. Хатои клиент (4xx)-ро бо хатои сервер (5xx) омехта кардан: дар 404 ғалатии суроғаро ҷустуҷӯ кунед, на «вайрон шудани интернет»-ро. 3. Ба Network нигоҳ накардан: нисфи муаммоҳои «чаро чизе нишон дода намешавад» дар як дақиқа ҳал мешаванд, агар ҷадвалро кушоед ва ҳолати сурхро бубинед. 4. Дар суроға холигоҳҳо ва ҳарфҳои кириллиро дастӣ гузоштан: дар параметрҳо онҳоро рамзгузорӣ мекунанд, браузер ва fetch аксар вақт инро худашон мекунанд, аммо суроғаро бо дасти худ вайрон накунед.

ВАЗИФАИ 1.1

Худро санҷед: HTTP

осон

Корбар дар сайт тугмаи «Расмӣ кардани фармоиш»-ро пахш кард ва фармоишро дар сервер сохтан лозим аст. Кадом усул беҳтар мувофиқ аст?

  1. GET, зеро ӯ аз ҳама содда аст
  2. DELETE, зеро фармоиш аз сабад «нопадид мешавад»
  3. POST, зеро мо барои сохтани сабти нав маълумот мефиристем
  4. Усул лозим нест, кушодани саҳифа кифоя аст

GET танҳо маълумот мегирад, сохтани сабти нав бошад тавассути POST анҷом дода мешавад: маълумот дар бадани дархост меравад. DELETE нест мекунад, намесозад.

Дархост ба API рамзи 404-ро баргардонд. Ин чӣ маъно дорад ва аз куҷо ҷустуҷӯи хаторо оғоз кардан лозим?

  1. Сервер афтод; бояд интизор шуд ва дархостро такрор кард
  2. Чунин суроға ё сабт нест; аввал суроға ва параметрҳоро барои ғалатӣ санҷидан лозим
  3. Калиди дастрасӣ лозим аст; бояд сабти ном кард
  4. Дархостҳо аз ҳад зиёданд; як дақиқа интизор шудан лозим

Рамзи 4xx мегӯяд, ки мушкил дар дархост аст. 404 — «ёфт нашуд»: ғалатӣ дар роҳ ё сабти чунин рақамдор нест. Афтодани сервер — ин 5xx аст, калид — 401/403, маҳдудият — 429.

Дар браузер дар куҷо дидан мумкин аст, ки саҳифа кадом дархостҳои маълумотро фиристодааст ва онҳо бо кадом рамз анҷом ёфтаанд?

  1. DevTools (F12), ҷадвали Network, филтри Fetch/XHR
  2. DevTools, ҷадвали Elements: дар он ҷо танҳо дархостҳо намоёнанд
  3. Дар коди сарчашмаи саҳифа, дар дохили теги <title>
  4. Ҳеҷ ҷо, браузер дархостҳоро аз корбар пинҳон мекунад

Network ҳар дархостро сабт мекунад: усул, суроға, рамз, вақт, сарлавҳаҳо ва худи ҷавобро. Ин ҳамон ивазкунандаи барномаҳои алоҳидаи санҷиши API аст.

Бештар хонед: MDN: шарҳи HTTP, рамзҳои ҳолати HTTP ва роҳнамои ҷадвали Network (охирин бо забони англисӣ).

02 JSON, API ва калиди дастрасӣ

JSON: забоне, ки серверҳо бо он маълумот медиҳанд

Ҷавоби сервер — матн аст. Барои он ки ҳам одам ва ҳам барнома онро якхела фаҳманд, матнро мувофиқи қоидаҳои JSON менависанд. Дар дарси 6 шумо танзимотро бо ҳамин шакл хонда будед, қоидаҳо ҳамонанд: қавсҳои фигурӣ { } бо ҷуфтҳои «калид: қимат», калидҳо дар нохунакҳои дукарата, рӯйхатҳо дар қавсҳои мураббаъ [ ], ҳеҷ шарҳ ва вергул баъд аз ҷуфти охирин нест.

{
  "latitude": 38.56,
  "current": {
    "time": "2026-10-27T15:30",
    "temperature_2m": 20.4,
    "weather_code": 2
  }
}

Барои гирифтани қимат аз рӯи калидҳо бо нуқта мегузарем: data.current.temperature_2m. Дар JavaScript ду функсия ба ин ҷо ва баракс табдил медиҳанд: JSON.parse(матн) матнро ба объект табдил медиҳад, JSON.stringify(объект) объектро ба матн, ки онро ба сервер фиристодан мумкин аст.

Машқ бе интернет: инак «ҷавоби сервер» дар шакли матн. Онро таҳлил кунед ва се сатр нишон диҳед, баъд объектро боз ба матн табдил диҳед.

«Қариб-JSON», ки барномаро вайрон мекунад

Ин навиштаҳо ба JSON монанданд, аммо JSON.parse бо онҳо бо хатои Unexpected token меафтад: калид бе нохунак {name: "Мадина"}; нохунакҳои яккарата {'name': 'Мадина'}; вергул баъд аз унсури охирин {"a": 1,}; шарҳ дар дохил. AI баъзан дар ҷавобҳо чунин «JSON» менависад, бинобар ин ҳангоми хатои таҳлил аввал ба худи матн нигоҳ кунед.

API: «меню»-и сервер

API (Application Programming Interface) — маҷмӯи суроғаҳо ва қоидаҳост, ки тибқи онҳо як барнома метавонад аз барномаи дигар чизе пурсад. Сервер мисли ошхонаи тарабхона аст: шумо ба ошхона намедароед ва маҳсулотро худатон намегиред, шумо менюро мебинед ва ба пешхизмат фармоиш медиҳед. Меню — ҳуҷҷатгузории API аст, пешхизмат — суроға ва усули дархост, таом дар табақ — JSON бо маълумот. Ошхона ҳал мекунад, ки шумо чиро ва дар кадом шакл гирифта метавонед.

Се намуди барои навомӯз қулай мавҷуданд:

  • Кушода, бе калид. Донистани суроға кифоя аст. Дар дарс чунинҳо лозим мешаванд: Open-Meteo (обу ҳаво), open.er-api.com (қурби асъор, сомонӣ ҳаст), TVMaze (сериалҳо ва шоуҳо), JSONPlaceholder (сабтҳои таълимӣ барои машқи POST).
  • Бо калиди дастрасӣ. Бояд дар сайти хидмат сабти ном кард ва калид (API key) гирифт: сатри дароз. Сервер аз рӯи он мефаҳмад, ки кӣ мепурсад, ва дархостҳои шуморо аз рӯи тариф ҳисоб мекунад.
  • Пулакӣ. Ҳамон калид, аммо барои дархостҳо пул гирифта мешавад. Ҳоло танҳо бо ройгон кор мекунем.
Калиди дастрасӣ — ин рамзи «ҳисоб»-и шумо дар хидмат аст

Агар калид фош шавад, дархостҳои бегонагон аз ҳисоби шумо мераванд ё маҳдудияти ройгони шуморо тамом мекунанд, ва хидмат метавонад аккаунтатонро масдуд кунад. Бинобар ин калидро набояд: ба коде гузошт, ки ба GitHub меравад; ба чат фиристод; дар скриншот нишон дод. Чӣ тавр дуруст нигоҳ доштани онро дар бахши 5 муфассал мебинем. Маълумоти корбарони API-ҳои кушодаро низ бе зарурат ба хидматҳои бегона нагузоред.

Чаро баъзан браузер намегузорад: CORS

Браузер корбарро муҳофизат мекунад. Агар саҳифаи шумо дар mysite.vercel.app аз домени дигар маълумот пурсад, браузер аввал ба ҷавоб менигарад: оё дар он ҷо иҷозати сервер барои сайти шумо ҳаст (сарлавҳаи Access-Control-Allow-Origin). Иҷозат нест? Дархост меравад, аммо браузер ҷавобро ба коди шумо намедиҳад ва дар консол хатои сурх бо калимаи CORS менависад. Ҳамаи API-ҳои ин дарс дархостҳоро аз ҳар сайт иҷозат медиҳанд, бинобар ин дар шумо ҳама чиз кор мекунад. Агар боре API-ро бе чунин иҷозат вохӯред, дархостро бояд на аз браузер, балки аз сервери худатон кард (дар Next.js ин функсияи серверии оддӣ аст, дар бахши 4 мебинем).

03 fetch ва async/await: «ҷавоби серверро интизор шав»

Ҷавоби сервер фавран намеояд: дархост аз симҳо ё ҳаво мегузарад, сервер фикр мекунад. Ин аз даҳҳо миллисония то якчанд сония давом мекунад. Агар саҳифа дар ин вақт «ях мекард», аз сайт истифода бурдан номумкин мешуд. Бинобар ин JavaScript дигар хел кор мекунад: дархост мефиристад, ба ивази он «талон» (дар барномасозӣ онро Promise, «ваъда» меноманд) мегирад ва то ҷавоб додани сервер оромона бо корҳои дигар машғул мешавад.

Аммо мо бояд дар лаҳзаи лозим бигӯем: «ҷавобро интизор шав ва танҳо баъд пеш рав». Инро калимаи await мекунад. Қоидаҳо кӯтоҳанд:

  • fetch(суроға) дархост мефиристад ва «талон»-и Promise бармегардонад.
  • await пеш аз он функсияро то расидани ҷавоб ба таваққуф мегузорад. Натиҷа: объекти response (тамоми ҷавоб: рамз, сарлавҳаҳо, бадан).
  • Бадани ҷавоб низ фавран хонда намешавад, бинобар ин await response.json() — таваққуфи дуюм аст: матни JSON-ро ба объекти тайёр табдил медиҳем.
  • await-ро танҳо дар дохили функсияе навиштан мумкин аст, ки бо калимаи async эълон шудааст. Дар мисолҳои худи ҳамин саҳифа await дар сатҳи боло низ иҷозат аст, гӯё ҳама чиз дар дохили функсияи async бошад.

«Иҷро кардан»-ро пахш кунед. Диққат диҳед, ки сатрҳо бо кадом тартиб нишон дода мешаванд: ҳангоми гузаштани дархост барнома намеистад, ва console.log-и дуюм фавран иҷро мешавад.

console.log("1. Отправили запрос");

const url = "https://api.open-meteo.com/v1/forecast?latitude=38.56&longitude=68.77¤t=temperature_2m";
const ticket = fetch(url);                       // запрос ушёл, в руках «талончик»
console.log("2. Это Promise:", ticket instanceof Promise);

const response = await ticket;                   // ждём ответ сервера
console.log("3. Ответ пришёл, код:", response.status);

Санҷиши ҷавоб ва хатогиҳо: қолаби панҷсатра

Домҳои асосии fetch, ки қариб ҳама ба он дучор мешаванд: ҷавоб бо рамзи 404 ё 500 барои ӯ хато нест. Дархост ба сервер расид ва баргашт, бинобар ин Promise «бомуваффақият» анҷом меёбад, ва response.ok оддӣ false мешавад. Хато (истисно) fetch танҳо он вақт ҳисоб мекунад, ки ҷавоб тамоман нест: интернет нест, суроғаи сервер вуҷуд надорад. Бинобар ин ҳамеша санҷишро нависед:

async function loadData(url) {
  const response = await fetch(url);                              // 1. ждём ответ
  if (!response.ok) throw new Error("HTTP " + response.status);   // 2. 404, 500: это тоже ошибка
  return await response.json();                                   // 3. ждём и разбираем JSON
}

try {
  const data = await loadData(url);
  console.log("Получили", data);
} catch (error) {                                                 // 4. сюда попадаем при любой ошибке
  console.log("Не получилось:", error.message);
}
Дуруст
  • const response = await fetch(url);
  • const data = await response.json();
  • if (!response.ok) throw new Error(…)
Нодуруст
  • const data = fetch(url).json(); — «талон» усули json надорад
  • const data = response.json(); бе await — ба ҷои маълумот дар тағйирёбанда боз «талон» мемонад
  • Дар try/catch печонидан ва фикр кардан, ки 404 ба catch меафтад: намеафтад

Амалиёти 1: аввалин дархост ба обу ҳаво ва қурбҳо

Дар ҳамин ҷо, дар редактор: обу ҳавои воқеии Душанбе ва қурби асъорро дархост кунед. Қиматҳои зинда (ҳарорат, қурб) ҳар рӯз гуногунанд, бинобар ин санҷиш ба онҳо не, балки ба шакли ҷавоб менигарад: кадом калидҳо дорад ва рақаманд ё не. Касбиён низ чунин мекунанд, вақте ки санҷиш мекунанд, ки API «зинда» аст ва мисли одат ҷавоб медиҳад.

Монандӣ аз ҳаёт

Шумо дар чойхона палав фармоиш додед. Пешхизмат дар паҳлуятон намеистад, то ошпаз мепазад: ӯ ба сӯи мизҳои дигар меравад, ва шумо шумора мегиред. Шумора — ин Promise аст. await — лаҳзаест, ки мегӯед: «Бе палав ман пеш намеравам» ва оромона дар сари миз мунтазир мешавед. Вақте ки палав тайёр аст, табақ мегиред: ин response аст. Агар ошпаз хабар диҳад, ки биринҷ тамом шудааст, ин 404 аст: палав надоданд, ҳарчанд пешхизмат баргашт (response.ok === false). Ва агар худи чойхона баста бошад ва ҷавоб тамоман набошад, ин хатои ҳақиқии шабака аст, ва шумо ба catch меафтед.

Хатогиҳои маъмули навомӯзон

1. await-ро фаромӯш кардан ва ба ҷои маълумот дар тағйирёбанда Promise { <pending> } гирифтан. 2. await-ро дар функсияи оддӣ навиштан: хатои «await is only valid in async function», пеш аз функсия калимаи async-ро илова кардан лозим. 3. response.ok-ро нагузарондан ва баъд дар undefined афтодан, зеро ба ҷои маълумот JSON бо тасвири хато омад. 4. response.json()-ро ду бор даъват кардан: бадан як бор хонда мешавад. 5. Маълумоти зиндаро ба консол баровардан ва муқоиса кардан «дар ман 21.4, дар мисол 20.4»: қиматҳо тағйир меёбанд, ба сохтор нигоҳ кунед. 6. Объектро бе JSON.stringify ба body фиристодан: сервер сатри [object Object]-ро мегирад.

  3. Зеро await-ро танҳо баъд аз try навиштан лозим
  4. Танҳо барои fetch мумкин нест, барои дигар функсияҳо мумкин аст

Варианти 1: компоненти серверӣ (аз ҳама содда)

Саҳифа худаш async мешавад ва маълумотро интизор мешавад. Корбар саҳифаи тайёрро мегирад, на useState ва на useEffect лозим нест.

export default async function DashboardPage() {
  const response = await fetch(
    "https://api.open-meteo.com/v1/forecast?latitude=38.56&longitude=68.77&current=temperature_2m",
    { cache: "no-store" }, // ҳар дафъа маълумоти нав
  );

  if (!response.ok) {
    return <p>Не удалось загрузить погоду (код {response.status}). Попробуйте позже.</p>;
  }

  const weather = await response.json();

  return (
    <main>
      <h1>Погода в Душанбе</h1>
      <p>Сейчас: {weather.current.temperature_2m} °C</p>
    </main>
  );
}

Ду тафсили муҳим аз ҳуҷҷатгузории Next.js. Якум: бе нишон додани cache ҳангоми сохтани лоиҳа (npm run build) саҳифа бе маълумоти динамикӣ ҷавобро як бор «ба ёд мегирад», ва дар сайт обу ҳаво яхкарда мемонад. Барои маълумоти зинда { cache: "no-store" } нависед. Дуюм: то даме ки сервер ҷавобро интизор аст, саҳифа нишон дода намешавад. Барои он ки корбар «Боршавӣ…»-ро бинад, дар паҳлуи саҳифа файли loading.tsx-ро мегузоранд, ки Next.js онро дар вақти интизорӣ нишон медиҳад.

Варианти 3: Route Handler, «функсияи серверии худӣ»

Ин файл бо номи route.ts дар папка дар зери app/api/… аст. Ӯ суроғаи сайти шуморо месозад, ки дар он на саҳифа, балки маълумот ҷавоб медиҳад. Дар дохил калиди махфиро аз тағйирёбандаи муҳит бехатар хондан, ба API-и бегона рафтан ва ба браузер танҳо он чизи лозимиро додан мумкин аст. Номи функсияҳо бо усулҳои HTTP мувофиқ аст: GET, POST, PUT, PATCH, DELETE.

export async function GET() {
  const key = process.env.WEATHER_KEY; // дар сервер хонда мешавад, ба браузер намеафтад

  const response = await fetch(
    "https://api.example.com/weather?city=Dushanbe",
    { headers: { Authorization: "Bearer " + key }, cache: "no-store" },
  );

  if (!response.ok) {
    return Response.json({ error: "Сервис погоды недоступен" }, { status: 502 });
  }

  const data = await response.json();
  return Response.json({ temperature: data.temp }); // танҳо лозимиро медиҳем
}

Суроғаи api.example.com дар ин ҷо шартӣ аст: суроға ва усули додани калидро аз ҳуҷҷатгузории API-и худ гузоред (калидро дар параметри суроға, дар сарлавҳаи Authorization ё дар сарлавҳаи худӣ мегузоранд: чӣ гуна — дар ҳуҷҷатгузории хидмат навишта шудааст). Он гоҳ браузер ба /api/weather-и худи сайти шумо меравад, ва калид дар коди ӯ нест. Ин нақшаро шумо дар модулҳои 4 ва 5 боз бисёр истифода мебаред: барои пойгоҳи маълумот ва чати AI.

Монандӣ аз ҳаёт

Компоненти серверӣ ва route handler — ин ошпаз дар ошхона аст, ки калиди анборро дорад. Компоненти клиентӣ — толор, ки меҳмонон дар он нишастаанд. Меҳмон (браузер) таомро талаб мекунад, ва калиди анбор (калиди API) назди ошпаз мемонад: онро ба толор овардан мумкин нест, зеро ҳар меҳмон метавонад онро бигирад. Бинобар ин ба «анбор рафтан» (ба API-и пӯшида) бояд ошпаз равад, ва ба толор танҳо табақи тайёр (маълумот) бароварда мешавад.

Хатогиҳои маъмули навомӯзон

1. fetch-ро бо калид дар компоненти клиентӣ кардан: калид дар коди саҳифа пайдо мешавад. 2. "use client" ва async-ро ба як компонент гузоштан: компоненти клиентӣ async шуда наметавонад, хукҳои useState ва useEffect дар серверӣ кор намекунанд. Яктоашро интихоб кунед. 3. cache: "no-store"-ро нанависед ва дар ҳайрат монед, ки баъд аз деплой обу ҳаво «ях кардааст». 4. «Боршавӣ» ва «Хато»-ро фаромӯш кардан: он гоҳ ҳангоми интернети суст корбар экрани холиро мебинад. 5. Дархостро дар дохили useEffect бе рӯйхати холии вобастагиҳо [] кардан: дархостҳо дар даври беохир мераванд, ва Network садҳо сатрро пай дар пай нишон медиҳад.

ВАЗИФАИ 4.2

Худро санҷед: дархостро дар куҷо кардан

миёна

Дар саҳифа бояд қурби асъор аз API бо калиди махфӣ нишон дода шавад. Дар куҷо кардани дархост бехатартар аст?

  1. Дар компоненти клиентӣ тавассути useEffect, ва калидро дар паҳлӯ дар константа гузоштан
  2. Дар компоненти серверӣ ё дар Route Handler, ва калидро аз process.env дар сервер хондан
  3. Дар файли public/key.txt, то ки браузер онро хонда тавонад
  4. Дар layout.tsx дар дохили теги <head>

Коди компоненти клиентӣ якҷоя бо калид ба браузер меравад. Коди серверӣ дар сервери шумо иҷро мешавад, ва калид ба браузер намеафтад: корбар танҳо маълумоти тайёрро мегирад.

Кадом файл суроғаи /api/weather-ро месозад, ки бо маълумоти JSON ҷавоб медиҳад?

  1. app/api/weather/page.tsx бо функсияи GET
  2. app/weather.json
  3. app/api/weather/layout.tsx
  4. app/api/weather/route.ts бо функсияи содиршавандаи GET

Файли page.tsx саҳифаро тавсиф мекунад, route.ts — коркарди дархостҳо (Route Handler). Функсияҳо мисли усулҳои HTTP ном доранд: GET, POST ва дигарон.

Дар саҳифаи app/dashboard/page.tsx (компоненти серверӣ) ҳарорати нав ҳангоми ҳар кушодан лозим аст, на маълумоти ҳангоми сохтан ба ёд мондашуда. Чиро илова кардан лозим?

  1. "use client" дар сатри якуми файл
  2. Ҳеҷ чиз: Next.js ҳамеша маълумотро ҳангоми ҳар кушодани саҳифа нав мекунад
  3. Параметри { cache: "no-store" } ҳамчун аргументи дуюми fetch
  4. fetch-ро ба JSON.parse иваз кардан

Агар чизи дигаре нагӯед, саҳифаи бе маълумоти динамикӣ метавонад як бор ҳангоми сохтан омода шавад, ва қиматҳо яхкарда мемонанд. cache: "no-store" бевосита талаб мекунад, ки маълумот ҳангоми ҳар дархост аз сервер гирифта шавад.

Бештар хонед: Next.js: гирифтани маълумот, Route Handlers ва маълумотномаи fetch (бо забони англисӣ).

05 Тағйирёбандаҳои муҳит: калидҳоро дар куҷо пинҳон кардан

Калиди дастрасӣ ба код лозим аст, аммо ба касе нишон додан мумкин нест. Ҳалли ҳамаи барномасозон як аст: калидро берун аз код, дар тағйирёбандаи муҳит (environment variable) нигоҳ доштан. Дар код танҳо ном мемонад: process.env.WEATHER_KEY, қимат бошад дар лаҳзаи оғози барнома гузошта мешавад. Дар компютери шумо он аз файл гирифта мешавад, дар хостинг (Vercel) — аз танзимоти лоиҳа. Код як аст, махфиятҳо барои ҳар муҳит худиашон.

Файли .env.local

Дар решаи лоиҳа (дар паҳлуи package.json) файлеро бо номи .env.local созед. Нуқта дар аввали ном ҳатмист. Ҳар сатр — як тағйирёбанда дар формати НОМ=қимат, бе холигоҳ дар атрофи аломати баробарӣ ва одатан бе нохунак:

WEATHER_KEY=abc123-not-a-real-key
NEXT_PUBLIC_SITE_NAME=Дашборд Душанбе

Next.js худаш чунин файлҳоро ҳангоми оғоз мехонад ва қиматҳоро ба process.env мегузорад. Агар файлро тағйир додед, вале қимат қабул нашуд, npm run dev-ро қатъ кунед (Ctrl+C) ва аз нав оғоз кунед.

Қоидаи асосӣ: NEXT_PUBLIC_

  • Тағйирёбандаи оддӣ (WEATHER_KEY) танҳо дар коди серверӣ дастрас аст: дар компонентҳои серверӣ ва route handlers. Дар компоненти клиентӣ process.env.WEATHER_KEY undefined медиҳад.
  • Бо пешванди NEXT_PUBLIC_ қимат ҳангоми сохтани лоиҳа бевосита ба JavaScript, ки ба браузер меравад, «дӯхта мешавад». Онро ҳар касе, ки коди саҳифаро кушояд, мебинад. Бинобар ин пешвандро танҳо ба он чизе мегузоранд, ки махфӣ нест: номи сайт, идентификатори ҷамъиятӣ, суроға.
  • Қимати бо NEXT_PUBLIC_ дар марҳилаи сохтан (next build) собит мешавад: агар баъд онро тағйир диҳед, сохтани нав лозим аст.
Дуруст
  • WEATHER_KEY=… ва хондан дар коди серверӣ
  • NEXT_PUBLIC_SITE_NAME=… барои номи сайт
Хатарнок
  • NEXT_PUBLIC_WEATHER_KEY=…: махфият ба браузер ва ба коди саҳифа меафтад
  • Калид бевосита дар код: const key = "abc123…"

.gitignore: файле, ки Git намебинад

Дар дарси 4 шумо бо .gitignore шинос шудед: ин рӯйхати файлҳо ва папкаҳост, ки Git ба репозиторий илова намекунад. Лоиҳаи бо фармони create-next-app сохташуда аллакай дар он сатри .env*-ро дорад: он ҳамаи файлҳоеро, ки номашон бо .env оғоз мешавад, аз ҷумла .env.local-ро мепӯшонад. Бинобар ин git add . ва git push онро намефиристанд. Аммо умед бастан намешавад, бояд санҷид, махсусан агар лоиҳа аз ҷониби шумо сохта нашуда бошад (масалан, агенти AI сохта бошад ё аз қолаб нусхабардорӣ шуда бошад).

Месанҷем, ки калид ба GitHub нарасидааст

Се санҷиш пай дар пай. Онҳо як дақиқа мегиранд, ва онҳоро пеш аз ҳар git push-и аввалини лоиҳаи нав иҷро кардан лозим.

  1. Оё файл нодида гирифта мешавад. Дар терминал дар папкаи лоиҳа: 
    git check-ignore -v .env.local
    Фармон сатрро бо қоида чоп мекунад, масалан .gitignore:34:.env* .env.local. Агар натиҷа холӣ бошад, файл нодида гирифта намешавад: ба .gitignore сатри .env*-ро илова кунед ва такрор кунед.
  2. Оё файл дар репозиторий ва дар таърих нест. 
    git ls-files | grep env
git log --all --oneline -- .env.local
    Ҳарду фармон бояд чизеро чоп накунанд. Якум дар байни файлҳои пайгирӣшаванда меҷӯяд, дуюм — дар байни ҳамаи коммитҳои гузашта, зеро файли нестшуда дар таърих мемонад. Дар Windows ба ҷои grep env findstr env-ро истифода баред.
  3. Бо чашм бинед. Репозиторийро дар GitHub дар ҳолати инкогнито кушоед (чунин он чизеро мебинед, ки ҳар кас мебинад): дар байни файлҳо дар реша .env.local набояд бошад, ва дар код сатр бо калид набояд бошад. Роҳи зуд: дар саҳифаи репозиторий ҷустуҷӯи кодро кушоед ва аввали калидатонро ворид кунед.
Агар калид аллакай ба GitHub афтода бошад

Нест кардани файл бо коммити нав кифоя нест: коммити кӯҳна бо калид дар таърих мемонад, ва нусхаҳоро ботҳои автоматӣ (онҳо GitHub-ро шабу рӯз скан мекунанд) шояд аллакай гирифта бошанд. Тартиби амал: 1. Фавран ба сайти хидмат дароед ва калидро бозгиред (revoke, delete, regenerate), калиди нав бароред. Калиди кӯҳна аз ҳамон лаҳза бефоида аст. 2. Калиди навро дар .env.local ва дар Vercel сабт кунед. 3. Файлро аз Git бароред: git rm --cached .env.local, мутмаин шавед, ки .env* дар .gitignore ҳаст, commit ва push кунед. 4. Ба ёрдамчии AI гӯед, ки чӣ шуд, вале худи калидро ба чат нагузоред.

Тағйирёбандаҳои муҳит дар Vercel

Сайти шумо дар Vercel файли .env.local-ро намебинад: ӯ дар компютери шумо мондааст. Пас, ҳар тағйирёбандаро ба лоиҳа дар Vercel дастӣ илова кардан лозим аст. Қадамҳо аз рӯи ҳуҷҷатгузории расмӣ:

  1. Лоиҳаро дар Vercel кушоед (аз панели идоракунӣ, dashboard) ва ба танзимоти он гузаред. Дар менюи паҳлуӣ Environment Variables-ро интихоб кунед.
  2. Дар майдони Name номро нависед (масалан, WEATHER_KEY), дар майдони Value — қиматро. Ном айнан мисли дар .env.local, бо назардошти ҳарфҳои калон ва хурд.
  3. Муҳитҳоеро қайд кунед, ки тағйирёбанда ба онҳо тааллуқ дорад: Production (сайти асосӣ), Preview (нусхаҳои санҷишӣ аз шохаҳои дигар), Development (кори маҳаллӣ). Барои калид одатан аввалин ду кифоя аст.
  4. Save-ро пахш кунед. Вобаста ба танзимот шояд навъи тағйирёбандаро пешниҳод кунанд: Secret (қимат баъд аз нигоҳ доштан нишон дода намешавад) барои калидҳо қулайтар аст.
  5. Деплойи нав кунед. Тибқи ҳуҷҷатгузории Vercel тағйирёбии тағйирёбандаҳо ба нусхаҳои тайёри сайт татбиқ намешавад, танҳо ба нусхаҳои нав. Ҷадвали Deployments-ро кушоед, дар деплойи охирин Redeploy-ро интихоб кунед ё танҳо git push-и нав кунед.
Монандӣ аз ҳаёт

Тағйирёбандаи муҳит — ин сейфи бо рамз аст, ки дар ҳар «ҳуҷра» меистад: дар хонаи шумо, дар сервери Vercel. Рамзи сейфро дар дар намениванд (дар коди оммавӣ) ва дар назди дарвоза намегузоранд (дар GitHub). Рамзро шумо ба ҳар «ҷой» шахсан медиҳед. Рамзи сейфи хонагиро иваз кардед — дар ҷои кор ӯ худаш иваз намешавад: дар он ҷо низ иваз кардан ва корро аз нав оғоз кардан (Redeploy) лозим.

Хатогиҳои маъмули навомӯзон

1. Файлро env.local ё .env.local.txt номидан (бе нуқта, бо пасванди изофӣ): Next.js онро намебинад. Номро дар проводник санҷед. 2. Файлро на ба реша, балки ба app/ гузоштан. 3. Холигоҳ ё нохунакҳои изофӣ гузоштан: KEY = "abc". 4. Пеш аз махфият NEXT_PUBLIC_ гузоштан «то ки кор кунад»: кор мекунад, аммо калид оммавӣ мешавад. Ба ҷои ин дархостро ба компоненти серверӣ ё route handler бароред. 5. .env ё .env.local-ро «як лаҳза» commit кардан. 6. Тағйирёбандаро дар Vercel илова кардан ва Redeploy накардан: дар сайт ҳанӯз қимати кӯҳна ё undefined аст. 7. .env.local-ро дар скриншот, дар занги видеоӣ ё дар чат бо AI нишон додан.

Онҳо аз сервери Next.js мераванд, ва ба браузер саҳифаи тайёр меояд. Филтрро ба Doc гузаронед: шумо як дархости саҳифаи dashboard-ро мебинед. Ин фарқи асосии байни fetch-и серверӣ ва клиентӣ аст.

09 Вазифаи хонагӣ: саҳифаи-dashboard бо маълумоти зинда (ВХ-10)

Саҳифаи-dashboard созед, ки маълумоти зиндаро камаш аз ду API-и ҷамъиятии гуногун нишон медиҳад. Натиҷа бо ду ҳавола супорида мешавад: ба репозиторийи GitHub ва ба сайти нашршуда дар Vercel.

Талабот

  • Ду ва зиёда API: масалан, обу ҳаво ва қурби асъор ё ҳар кадоме аз рӯйхати квест. Камаш 3 корт ё блок бо маълумот. Мавзӯъро озод интихоб кунед (шаҳр, варзиш, кино, мӯд, бозиҳо).
  • Дархости серверӣ: камаш як корт маълумотро дар компоненти серверӣ тавассути async/await бо cache: "no-store" мегирад (агар маълумот бояд нав бошад).
  • Дархости клиентӣ: камаш як блок дархостро аз браузер бо амали корбар (ҷустуҷӯ, интихоби шаҳр, тугмаи «Навсозӣ») мекунад ва ҳолатҳои loading, error (бо тугмаи «Повторить») ва натиҷаи холиро нишон медиҳад.
  • Хатогиҳо: санҷиши response.ok ҳама ҷо; хато дар як корт тамоми саҳифаро вайрон намекунад; «экрани сафед» нест.
  • Маълумот воқеӣ: аз рӯи Network дархостҳои зинда намоёнанд. Қиматҳои дар код навишташуда (hardcode) ба ҷои маълумоти API нестанд.
  • Махфиятҳо: калидҳо дар код нестанд. Дар лоиҳа .env.local ҳаст (ҳадди ақал бо ҷойгузор), ӯ дар репозиторий нест (git check-ignore -v .env.local тасдиқ мекунад).   • Тартибот: консоли браузер бе хатогиҳои сурх, npm run build мегузарад, намуд дар 390 px муқаррарӣ, сарчашмаи маълумот дар поёни саҳифа бо ҳавола ба ҳуҷҷатгузории API нишон дода шудааст.
  • Бонус: route handler app/api/…/route.ts, ки компоненти клиентӣ тавассути он маълумот мегирад; навсозии худкор як бор дар дақиқа; нигоҳ доштани интихоби охирин дар localStorage; API бо калид (сабти ном дар сайти хидмат, калид танҳо дар .env.local ва дар Vercel).

Чӣ кор кардан лозим аст

  1. Мавзӯъ ва ду API-ро интихоб кунед. Суроғаҳоро дар браузер кушоед ва боварӣ ҳосил кунед, ки JSON меояд. Майдонҳои лозимиро нависед.
  2. Вазифаро ба AI аз рӯи формулаи промпт тавсиф кунед ва порчаи JSON-и воқеиро замима кунед. Аввал нақшаро талаб кунед: дархости серверӣ дар куҷо, клиентӣ дар куҷо, кадом ҳолатҳо.
  3. Қадам ба қадам созед: як корт бо маълумоти серверӣ, commit; корти дуюм, commit; блоки клиентӣ бо ҳолатҳо, commit. Баъд аз ҳар қадам санҷиш дар ҷадвали Network.

  5. Махфиятҳоро санҷед: се фармон аз бахши 5, ҷустуҷӯи калид дар diff пеш аз commit.
  6. Нашр кунед (push ба GitHub, Vercel мисли дарси 5), тағйирёбандаҳои лозимиро ба Environment Variables илова кунед, Redeploy кунед, сайтро дар телефон кушоед ва ду ҳаволаи зеринро супоред.
Хатогиҳои маъмул дар вазифаи хонагӣ

1. Маълумот дар код навишта шудааст, ва «API» танҳо дар хаёл пайваст аст: дар ҷадвали Network дархостҳо нестанд. 2. ✓ Хулосаи дарс

  • Клиент ва сервер: клиент дархост мефиристад, сервер ҷавоб бармегардонад. Дархост: усул + суроға (+ сарлавҳаҳо, бадан). Усулҳо: GET гирифтан, POST сохтан, PUT/PATCH тағйир додан, DELETE нест кардан. Рамзҳо: 2xx муваффақият, 4xx хатои клиент (400 дархост, 401/403 калид ва ҳуқуқҳо, 404 ёфт нашуд, 429 маҳдудият), 5xx хатои сервер.
  • JSON: калидҳо ва сатрҳо дар нохунакҳои дукарата, бе вергул дар охир. JSON.parse матн → объект, JSON.stringify объект → матн. Қиматро аз рӯи калидҳо мегирем: data.current.temperature_2m.
  • API ва калид: API — суроғаҳо ва қоидаҳо, ки тибқи онҳо барнома маълумот мепурсад. Калид — рамзи барнома барои хидмат: на дар код, на дар чат, на дар GitHub. CORS: браузер ҷавоби сервери бегонаро бе иҷозат намедиҳад, ҳал — дархост аз сервери шумо.
  • async/await: fetch Promise бармегардонад, await ҷавобро интизор мешавад. await танҳо дар дохили async. Қолаб: await fetch, if (!response.ok) throw, await response.json(), try/catch. 404 ва 500 худ ба catch намеафтанд.
  • Next.js: дархост дар компоненти серверӣ (async, cache: "no-store" барои маълумоти нав, loading.tsx дар вақти интизорӣ), дар клиентӣ (useEffect + status) ё дар route handler (app/api/…/route.ts бо GET). Дархостҳои махфӣ — танҳо аз сервер.
  • Ҳолатҳо: loading, error (бо «Повторить»), empty, success. Бо ҳолатҳои Offline ва Slow 4G дар ҷадвали Network месанҷем.
  • .env: махфиятҳо дар .env.local (решаи лоиҳа, НОМ=қимат), тавассути process.env.НОМ дар сервер хонда мешаванд. Пешванди NEXT_PUBLIC_ қиматро ба браузер медиҳад: махфиятҳо бе он. Баъд аз тағйири файл сервери dev-ро аз нав оғоз кунед.
  • На дар GitHub: git check-ignore -v .env.local, git ls-files | grep env, git log --all --oneline -- .env.local. Калид фош шуд: фавран бозгиред ва калиди нав бароред.
  • Vercel: Settings → Environment Variables → Name, Value, муҳитҳо, Save. Қимати навро танҳо деплойҳои нав мебинанд: Redeploy ё push.
  • Бо AI: суроға ва намунаи JSON диҳед, ҳамаи ҳолатҳо ва ҷойи дархостро ном баред, калид танҳо дар .env.local ва худи калидро ба ӯ нишон надиҳед, дар ҷадвали Network санҷед.
