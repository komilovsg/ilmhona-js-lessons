01 Шумо кистед ва ба шумо чӣ мумкин аст: ду саволи гуногун

Дар дарси 11 саҳифаи /admin барои ҳар касе, ки истинодро медонист, кушода буд. Барои ислоҳи ин сайт бояд ба ду саволи гуногун ҷавоб диҳад, ва онҳоро аксар вақт омезиш медиҳанд.

Аутентификатсия (authentication)
Санҷиши шахсият: «оё шумо дарвоқеъ Мадинаед?» Исбот: парол, рамз аз мактуб, воридшавӣ бо Google. Натиҷа: сайт медонад, ки дар назди он кист.
Авторизатсия (authorization)
Санҷиши ҳуқуқҳо: «ба Мадина чӣ мумкин аст?» Дархостҳои худро хондан — ҳа, бегонаро — не, /admin-ро кушодан — танҳо ба администратор. Натиҷа: сайт медонад, ки чӣ иҷозат аст.

Тартиб ҳамеша як аст: аввал аутентификатсия, баъд авторизатсия. Ҳалли он, ки ба Мадина чӣ мумкин аст, ғайриимкон аст, то нафаҳмед, ки ин худи ӯст.

Видео бо забони русӣ, камтар аз як дақиқа: ҳамин чиз бо суханони дигар.

Монандӣ аз ҳаёт

Даромадгоҳи маркази тиҷоратӣ дар Душанбе. Назди турникет посбон шиноснома ва иҷозатномаи шуморо муқоиса мекунад: ин аутентификатсия аст. Минбаъд иҷозатнома танҳо ошёнаи шуморо мекушояд, ба ошёнаи директор лифт намеравад: ин авторизатсия аст. Шиноснома бисёриҳо доранд, аммо ҳуқуқҳо барои ҳама гуногунанд.

Хатогиҳои маъмули навомӯзон

1. Фикр кардан, ки «ворид шуд» маънои «ҳама чиз мумкин»-ро дорад: Фирдавси ворид шуда набояд дархостҳои Мадинаро бинад. 2. Тугмаи «Админка»-ро дар меню пинҳон кардан ва ҳисоб кардан, ки саҳифа ҳифз шудааст: суроғаро ба ҳар ҳол бо даст навиштан мумкин аст. 3. Ҳуқуқҳоро танҳо дар интерфейс санҷидан (тугмаро пинҳон кардан), на дар сервер ва на дар пойгоҳ. Интерфейс намоён аст ва онро гирифтан мумкин аст, барои ҳамин санҷиши воқеӣ он ҷо ҷойгир аст, ки меҳмон ба он нарасад.

02 Усулҳои воридшавӣ: e-mail бо парол ва воридшавӣ бо Google

Supabase Auth — хизмати тайёри воридшавӣ, ки ба лоиҳаи Supabase-и шумо сохта шудааст. Шумо нигоҳдории паролҳоро худатон наменависед: хизмат e-mail ва паролро қабул мекунад, на паролро, балки хеши онро («изи ангушти» барнагарданда) нигоҳ медорад, ва на шумо ва на соҳиби лоиҳа паролро дида наметавонед. Корбарон дар ҷадвали хизматии auth.users нигоҳ дошта мешаванд, ки онро дар панел дар бахши Authentication → Users мебинед.

E-mail + паролВоридшавӣ бо Google
Чӣ тавр ворид мешавандe-mail ва пароли ихтироъкардаро ворид мекунандтугмаро пахш мекунанд, ҳисоби Google-ро интихоб мекунанд
Парол дар сайти шумоҳаст (танҳо хеш нигоҳ дошта мешавад)не, паролро танҳо Google медонад
Танзимба таври пешфарз фаъол аст, чанд дақиқалоиҳа дар Google Cloud Console лозим аст, тақрибан 30 дақиқа
Мушкилоти маъмулпарол фаромӯш шуд, мактубҳои тасдиқсуроғаи бозгашти нодуруст (redirect URI)

Дар код ин як функсия барои як амал аст (клиенти supabase-ро шумо дар амалиёт танзим мекунед):

// Бақайдгирӣ: ном ба маълумоти хизматии корбар меравад
const { data, error } = await supabase.auth.signUp({
  email,
  password,
  options: { data: { full_name: fullName } },
});

// Воридшавӣ
const { error } = await supabase.auth.signInWithPassword({ email, password });

// Баромад
await supabase.auth.signOut();

Ҳар функсия { data, error } бармегардонад, мисли дархостҳо аз дарси 11: агар error холӣ набошад, паёми фаҳмо нишон медиҳем («e-mail ё парол нодуруст аст»), на alert бо матни техникӣ.

Тасдиқи e-mail ва маҳдудияти мактубҳо (барои машғулият муҳим)

Ба таври пешфарз дар лоиҳаи нав танзими Confirm email фаъол аст: баъди бақайдгирӣ корбар мактуб бо истинод мегирад ва танҳо баъди пахш кардани он ворид шуда метавонад. Барои маҳсулоти воқеӣ ин дуруст аст: ҳамин тавр касе суроғаи бегонаро бақайд намегирад. Аммо дар машғулият он маҳдудияти сахт дорад.

Почтаи дарунсохти Supabase барои гурӯҳ пешбинӣ нашудааст

Тибқи ҳуҷҷатҳои Supabase (дар моҳи октябри соли 2026 санҷида шуд), фиристандаи дарунсохти мактубҳо ҳоло 2 мактуб дар як соат медиҳад, ва онҳоро танҳо ба суроғаҳои аъзои гурӯҳи (ташкилоти) лоиҳаи шумо мерасонад, ба дигарон хатои Email address not authorized меояд. Он барои озмоиш ва намоиш лозим аст, на барои кори гурӯҳи 15 нафара. Рақамҳоро Supabase бе огоҳӣ иваз мекунад: аҳамияти ҳозираро дар ҳуҷҷатҳо бинед.

Барои ҳамин дар дарс ду роҳ ҳаст:

  • Роҳи 1 (дар дарс иҷро мекунем): тасдиқро хомӯш кардан. Дар панел Authentication → Sign In / Providers → Email гузариши Confirm email-ро хомӯш кунед (номи бахш дар панел каме фарқ карда метавонад: танзимоти провайдери Email-ро ҷӯед). Он гоҳ баъди бақайдгирӣ корбар якбора ворид мешавад, мактуб лозим нест. Барои сайти таълимӣ бо маълумоти фарзӣ ин муқаррарӣ аст.
  • Роҳи 2 (барои маҳсулоти воқеӣ): SMTP-и худӣ. Дар танзимоти Authentication бахши SMTP ҳаст: шумо ҳар хизмати почтаро, ки дастрасии SMTP дорад (хост, порт, логин, парол ва суроғаи фиристанда), пайваст мекунед. Баъд мактубҳо ба ҳар суроға мераванд; маҳдудият аввал 30 мактуб дар як соат гузошта мешавад ва дар бахши Rate Limits баланд бардошта мешавад. Барои домени воқеӣ сабтҳои SPF, DKIM ва DMARC илова мекунанд, то мактубҳо ба спам наафтанд.

Дар ёд доред: ҳангоми хомӯш будани тасдиқ ҳар кас метавонад ба суроғаи бегона бақайдгирӣ шавад. Вақте сайт ба маҳсулоти воқеӣ бо корбарони зинда табдил ёбад, тасдиқро бояд баргардонед ва SMTP-и худиро пайваст кунед. Ҳуҷҷатҳои Supabase ошкоро тавсия медиҳанд, ки тасдиқро дар лоиҳаи корӣ «зери фишор» хомӯш накунед.

Боз ду танзим дар ҳамин саҳифа. Дарозии ҳадди ақали парол: на камтар аз 8 аломат гузоред. Ва URL Configuration: дар он суроғаи сайт (Site URL) ва суроғаҳои иҷозатдодашудаи бозгашт (Redirect URLs)-ро менависанд. Онҳо барои воридшавӣ бо Google ва барои истинодҳои мактубҳо лозиманд (бахши 7, қадами 1).

Монандӣ аз ҳаёт

Воридшавӣ бо Google — мисли иҷозатномаи маркази тиҷоратӣ аз рӯи шиноснома, ки онро каси дигар санҷидааст. Посбон пароли почтаи шуморо намедонад, ба Google эътимод дорад, ки шумо худи шумоед. Сайти шумо аз Google тасдиқи «ин Мадина аст, e-mail-и ӯ ин аст» мегирад, парол бошад назди Google мемонад.

Хатогиҳои маъмули навомӯзон

1. Паролҳоро худатон дар ҷадвали худ нигоҳ доштан (users.password): ин тавр кардан мумкин нест, Auth-ро истифода баред. 2. Паролро ба console.log навиштан ё ҳангоми ҷустуҷӯи хато ба AI фиристодан. 3. Confirm email-ро бе почтаи худӣ фаъол гузоштан ва дар бақайдгирии корбари дуюм мондан. 4. Бо паролҳои воқеӣ озмудан: паролҳои таълимӣ ихтироъ кунед, мисли Test-2026-pass ва онро дар ҷои дигар истифода набаред. 5. Ба корбар ҷудогона «парол нодуруст аст» ё «чунин e-mail нест» гуфтан: ҳамин тавр маслиҳат медиҳанд, ки кадом суроғаҳо бақайд шудаанд. Беҳтараш «e-mail ё парол нодуруст аст».

осон

Supabase Auth дар бораи пароли корбар чиро нигоҳ медорад?

  1. Худи паролро дар шакли кушода, то ки онро ёдрас кардан мумкин бошад
  2. Паролро дар репозиторияи Git-и сайти шумо
  3. Хеши барнагарданда: паролли аслиро барқарор кардан мумкин нест

Хеш — «изи ангушти» парол аст. Паролро аз рӯи он санҷидан мумкин аст, аммо худи паролро баргардондан не. Барои ҳамин «паролро ёдрас кардан» номумкин аст, танҳо «аз нав танзим кардан ва пароли нав гузоштан» ҳаст.

  1. Ҳама чиз кор мекунад, маҳдудият нест
  2. Мактубҳо ба маҳдудият (тақрибан 2 дар як соат) бармехӯранд ва танҳо ба аъзоёни гурӯҳи лоиҳа мерасанд, боқимонда тасдиқ шуда наметавонанд
  3. Supabase худаш почтаи пулакиро пайваст мекунад
  4. Мактубҳо мераванд, аммо ба спам

Фиристандаи дарунсохт танҳо барои озмоиш аст. Барои гурӯҳ дар лоиҳаи таълимӣ Confirm email-ро хомӯш мекунанд ё SMTP-и худиро пайваст мекунанд.

Ҳангоми гузаштани сайт ба кори воқеӣ бо корбарони зинда чӣ кардан лозим? Ду ҷавобро интихоб кунед.

  1. Confirm email-ро боз фаъол кардан
  2. Тасдиқро хомӯш гузоштан: ин қулайтар аст
  3. Дар почтаи дарунсохти Supabase мондан
  4. SMTP-и худиро пайваст кардан ва домени фиристандаро танзим кардан

Дар маҳсулот тасдиқ лозим аст, то касе суроғаҳои бегонаро бақайд нагирад, расонидани мактубҳоро бошад SMTP-и худӣ таъмин мекунад.

03 Сессияҳо ва токенҳо: сайт чӣ тавр «ба ёд меорад», ки шумо ворид шудаед

Аз дарси 10 медонед, ки ҳар дархост ба сервер мустақил аст: сервер худ аз худ дархости пешинро дар ёд надорад. Пас чӣ тавр ӯ дар саҳифаи /account мефаҳмад, ки ин шумоед? Тавассути сессия: баъди воридшавӣ шумо «чипта» мегиред, ва браузер онро ба ҳар дархост замима мекунад.

Сессия
Давраи ба «воридшуда» буданатон: аз воридшавӣ то баромад (ё то бозхонди чипта).
Access-токен (JWT)
«Чипта»-и кӯтоҳмуддат бо маълумоти шумо дар дарун: id-и корбар, e-mail, нақш дар пойгоҳ (authenticated), мӯҳлати амал. Supabase имзо кардааст, барои ҳамин онро қалбакӣ кардан мумкин нест. Дар Supabase ба таври пешфарз 1 соат амал мекунад.
Refresh-токен
«Чиптаи барои чипта»: вақте access-токен ба охир мерасад, аз рӯи refresh-токен ҷуфти нав дода мешавад. Ҳар refresh-токен ба нав танҳо як маротиба иваз мешавад, истифодаи такрорӣ бошад дуздӣ ҳисоб мешавад ва сессияро мебандад.
Cookie
Файли хурде, ки браузер нигоҳ медорад ва худаш бо ҳар дархост ба сайт мефиристад. Дар Next.js бо @supabase/ssr токенҳо маҳз дар cookie ҷойгиранд, барои ҳамин сервер онҳоро ҳангоми тасвири саҳифа мебинад.

Токенро хондан мумкин аст, аммо қалбакӣ кардан не

JWT аз се қисм иборат аст, ки бо нуқта ҷудо шудаанд: сарлавҳа, маълумот ва имзо. Маълумот рамзгузорӣ нашудааст, танҳо рамзбандӣ шудааст: ҳар кас онро хонда метавонад. Аммо имзо бо сирри Supabase сохта шудааст, ва агар ҳатто як аломати маълумотро иваз кунед, имзо мувофиқ намеояд ва сервер токенро рад мекунад. Барои ҳамин ҳеҷ гоҳ ба токен ё ба маълумоти оммавӣ чизи сирриро насозед, ва ҳеҷ гоҳ ба «маълумоте, ки браузер фиристод» бе санҷиши имзо бовар накунед. Худатон озмоиш кунед:

ВАЗИФАИ 3.1

миёна

Ду усули санҷиш: getClaims ва getSession

Дар коди серверӣ воридшударо бояд тавассути supabase.auth.getClaims() санҷид: он имзои токенро месанҷад ва маълумоти онро (claims) бармегардонад, дар миёни онҳо sub — id-и корбар. Усули getSession() танҳо cookie-ро бе санҷиши имзо мехонад, ва тибқи ҳуҷҷатҳои Supabase ба он дар коди серверӣ бовар кардан мумкин нест: cookie-ро ҳар кас фиристода метавонад.

Монандӣ аз ҳаёт

Маршрутка бо талони роҳкиро. Талони як шабонарӯзиро (access-токен) ба ронанда ҳангоми ҳар савор шудан нишон медиҳед. Талон ба охир расид — бо абонемент (refresh-токен) ба хазина меравед ва нав мегиред. Мӯҳри талонро қалбакӣ кардан мумкин нест, хондани навиштаҷот бошад ҳар касро мешавад. Абонементро гум кардед — хазинадор мебинад, ки онро ду маротиба истифода кардаанд ва манъ мекунад.

Хатогиҳои маъмули навомӯзон

1. Дар сервер ба ҷои getClaims() ба getSession() бовар кардан. 2. Токенҳоро ба чат, скриншот ё Git гузоштан: касе, ки access-токени шуморо дорад, то анҷоми мӯҳлат аз номи шумо амал мекунад. 3. Фаромӯш кардан, ки баромад (signOut()) ба таври пешфарз сессияро дар ҳамаи дастгоҳҳо мебандад (доираи global; барои ҳозира танҳо { scope: "local" }). 4. Ба localStorage «токенҳо»-и худро гузоштан ба ҷои воситаҳои тайёри Supabase: ҳамин тавр шумо бори дигар он чиро, ки аллакай сохта ва санҷида шудааст, ихтироъ мекунед.

ВАЗИФАИ 3.2

Худро санҷед: сессияҳо ва токенҳо

миёна

Токени JWT рамзгузорӣ нашудааст, ҳар кас маълумоти онро хонда метавонад. Чаро онро ба ҳар ҳол қалбакӣ кардан мумкин нест?

  1. Зеро онро танҳо соҳиб медонад
  2. Зеро он бо сирри Supabase имзо шудааст: ҳангоми ҳар тағйири маълумот имзо мувофиқ намеояд
  3. Зеро он дар сервер нигоҳ дошта мешавад
  4. Зеро браузер намегузорад онро тағйир диҳанд

Хондан ба ҳама мумкин аст, ноаён тағйир додан не: имзо дар сервер санҷида мешавад.

Refresh-токен чӣ кор мекунад?

  1. Вақте access-токен кӯҳна шуд (ба таври пешфарз як соат амал мекунад), ба ҷуфти нави токенҳо иваз мешавад
  2. Ҳангоми воридшавӣ паролро иваз мекунад
  3. Маълумоти профилро нигоҳ медорад
  4. cookie-ро рамзгузорӣ мекунад

Мӯҳлати кӯтоҳи access-токен ҳангоми ошкоршавӣ бехатартар аст, refresh-токен бошад имкон медиҳад, ки ҳар соат парол напурсанд.

Саҳифаи серверӣ бояд бифаҳмад, ки кӣ ворид шудааст. Чиро даъват кунем?

  1. getSession(): он тезтар аст
  2. cookie-ро бо даст хондан ва id-ро аз он гирифтан
  3. getClaims(): он имзои токенро месанҷад
  4. Ҳеҷ чиро: Next.js худаш корбарро медонад

Cookie аз браузер меояд ва қалбакӣ шуда метавонад. getClaims() имзоро месанҷад, барои ҳамин ба он бовар мекунанд.

04 Саҳифаҳои ҳифзшуда: се қабати қулф

Пӯшидани саҳифа бо «як санҷиш» боэътимод нест. Ҳифзро касбӣ бо се қабат месозанд: агар яке хато кард, боқимонда нигоҳ медоранд.

Қабати 1: proxy.ts (дар Next.js 16)

Файл дар решаи лоиҳа (дар паҳлӯи app), ки пеш аз тасвири саҳифа иҷро мешавад. Дар Next.js 16 он proxy.ts ном дорад, функсияи дарун — proxy. Дар нусхаҳои то 16 ин middleware.ts бо функсияи middleware буд: дастурҳои кӯҳна ва ҷавобҳои AI аксар вақт маҳз ҳамин тавр менависанд. Тибқи ҳуҷҷатҳои Supabase, агар дар лоиҳаи Next.js 16 файл бо номи кӯҳна бошад, он даъват намешавад ва сессияҳо навсозӣ намешаванд. Нуқтаи муҳими дигар: худи Next.js огоҳ мекунад, ки proxy барои санҷишҳои зуд ва «хушбинона» мувофиқ аст, аммо набояд ҳифзи ягона бошад.

Дар proxy ду кор мекунанд: токенҳоро дар cookie нав мекунанд (тавассути getClaims()) ва меҳмонони номатлубро ба /login мефиристанд.

Қабати 2: санҷиш дар худи саҳифа

Саҳифаи серверӣ худаш аз getClaims() мепурсад. Корбар нест — redirect("/login"). Нақши администратор лозим аст — онро аз ҷадвали profiles мехонем (бахши 5) ва саҳифаро нишон медиҳем ё notFound().

Қабати 3: RLS

RLS-ро аз дарси 11 медонед. Акнун дар он воситаи асосӣ пайдо мешавад: функсияи auth.uid(), ки дар дохили пойгоҳ id-и корбари воридшударо бармегардонад (онро аз токен мегирад, ки имзо шудааст ва қалбакӣ кардан мумкин нест). Қоидаи «ҳар кас танҳо сатрҳои худро мебинад» чунин навишта мешавад: using ((select auth.uid()) = user_id).

Монандӣ аз ҳаёт

Хазинаи бонк. Посбон дар даромадгоҳ роҳгузарони тасодуфиро рад мекунад (proxy). Оператор шиноснома ва корти муштариро месанҷад (саҳифа). Худи сейф танҳо бо калиди маҳз ҳамин муштарӣ кушода мешавад (RLS). Агар оператор хато кунад, сейф ба ҳар ҳол ба бегона кушода намешавад.

Хатогиҳои маъмули навомӯзон

1. Воридшавиро танҳо дар proxy санҷидан: matcher-ро нодуруст навиштан мумкин аст ва ягон саҳифа кушода мемонад. 2. RLS-ро умуман нанависед ва ба он такя кунед, ки «истинодро касе намедонад». 3. Коди дастури кӯҳнаро дар proxy бо номи middleware.ts гузоштан ва дар ҳайрат мондан, ки чаро «сессия мепарад». 4. Ба суроғаи параметри ?next= бе санҷиш равона кардан: ҳамлагар сайти бегонаро ҷойгузин мекунад. Танҳо роҳҳоеро, ки бо як / оғоз мешаванд, иҷозат диҳед.

ВАЗИФАИ 4.1

Худро санҷед: қабатҳои ҳифз

миёна

Файл барои боздоштани дархостҳо дар Next.js 16 чӣ ном дорад ва номи функсия дар он чист?

  1. middleware.ts, функсияи middleware
  2. guard.ts, функсияи guard
  3. proxy.ts, функсияи proxy
  4. auth.ts, функсияи auth

Дар Next.js 16 middleware ба proxy тағйири ном шудааст. Имкониятҳо як хелананд, дастурҳои кӯҳна бошад дар ном куҳна шудаанд.

Дар коди саҳифаи /account хато ҳаст: санҷиши воридшавиро фаромӯш кардаанд ва саҳифа дархостҳоро бе филтр мепурсад. Дар пойгоҳ қоидаи «select танҳо сатрҳои худӣ» ҳаст. Шахси бегона чиро мебинад?

  1. Танҳо сатрҳои худӣ (яъне ҳеҷ кадом): қоидаи RLS намегузорад бегонаҳоро хонад
  2. Ҳамаи дархостҳои ҳамаи корбаронро
  3. Хатои 404-ро
  4. Танҳо дархостҳои администраторро

Маънои қабати сеюм ҳамин аст: ҳифз дар пойгоҳ аз хатоҳо дар интерфейс ё коди саҳифа вобаста нест.

Кадоме аз номбаршудаҳо ҳифзи воқеӣ аст, на танҳо қулайӣ? Ду ҷавобро интихоб кунед.

  1. Пинҳон кардани истиноди «Админка» дар меню
  2. Санҷиши getClaims() ва нақш дар саҳифаи серверӣ
  3. Қоидаи RLS дар ҷадвал
  4. Суроғаи саҳифаро ба касе нагуфтан

Истиноди пинҳоншуда ва «суроғаи махфӣ» ҳеҷ чизро ҳифз намекунанд. Ҳифз бояд он ҷо бошад, ки меҳмон ба он нарасад: сервер ва пойгоҳ.

05 Нақшҳо: корбар ва администратор

Нақш — нишоне, ки аз рӯи он сайт ҳал мекунад, ки ба шумо чӣ мумкин аст. Мо ду нақш дорем: user (муштарии оддӣ) ва admin (соҳиби тарабхона, ҳамаи дархостҳоро мебинад). Нақшро бояд дар ҷое нигоҳ дошт, ва маҳз дар ин ҷо навомӯзон хатои хатарноктаринро содир мекунанд.

Қоидаи асосии бахш

Нақшро дар user_metadata нигоҳ доштан мумкин нест (маълумоте, ки корбар ҳангоми бақайдгирӣ тавассути options.data медиҳад): тибқи ҳуҷҷатҳои Supabase, корбар онро худаш тағйир дода метавонад. Як сатр дар консоли браузер кофӣ аст, ва ӯ «админ мешавад». Нақшро дар ҷадвале нигоҳ доред, ки корбар онро тағйир дода наметавонад, ё дар app_metadata, ки танҳо ба сервер барои навиштан дастрас аст.

Мо ҷадвали profiles-ро интихоб мекунем: он барои кабинети шахсӣ ҳам лозим аст. Як сатр барои як корбар: id бо auth.users.id мувофиқ меояд, илова бар ин ном, телефон ва нақш.

Профил чӣ тавр сохта мешавад ва админӣ чӣ тавр дода мешавад

  • Профилро триггер месозад. Триггер — амалест, ки пойгоҳ худаш ҳангоми ҳодиса иҷро мекунад. «Баъди сатри нав дар auth.users сатр дар profiles илова кун» (SQL дар амалиёт). Нақш ҳамеша user аст: онро аз бақайдгирӣ гирифтан мумкин нест.
  • Админро шумо дастӣ таъин мекунед дар SQL Editor: update profiles set role = 'admin' where …. SQL Editor аз номи соҳиби пойгоҳ кор мекунад, на аз номи корбари сайт.
  • Корбар чӣ карда метавонад. Танҳо профили худро хондан ва тағйир додан ва танҳо ном бо телефонро. Сутуни role барои ӯ дастнорас аст: ба ӯ ҳуқуқи тағйир додани он дода намешавад (grant update (full_name, phone)).
  • Пойгоҳ чӣ тавр админро мешиносад. Функсияи хурди is_admin() нақшро дар profiles мебинад, қоидаҳо барои дархостҳо ва профилҳо бошанд онро даъват мекунанд.
Монандӣ аз ҳаёт

Бейҷҳо дар конфронс. Номи худро дар бейҷ шумо худатон менависед, аммо рангро (бейҷи «ташкилкунанда» ё «меҳмон») бақайдгирӣ медиҳад. Агар ранги онро дар ҷой бо маркер тағйир додан мумкин бошад, ҳар кас ташкилкунанда мешавад. Барои ҳамин нақш он ҷо нигоҳ дошта мешавад, ки маркер ба он нарасад.

Хатогиҳои маъмули навомӯзон

1. Нақш дар user_metadata ё дар localStorage. 2. Қоидаи «корбар сатри худро нав мекунад» бе маҳдуд кардани сутунҳо: он гоҳ ӯ role-и худро ба admin иваз мекунад. 3. Админро танҳо дар менюи интерфейс санҷидан. 4. Худро дар сайти воқеӣ бо корбарони воқеӣ админ таъин кардан ва пароли боэътимодро иваз карданро фаромӯш кардан. 5. Ба AI калиди махфӣ додан, то «админка кор кунад»: нақшро қоидаҳо ҳал мекунанд, на калиде, ки RLS-ро давр мезанад.

ВАЗИФАИ 5.1

Худро санҷед: нақшро дар куҷо нигоҳ доранд

миёна

Нақши admin-ро дар куҷо бехатар нигоҳ доштан мумкин аст?

  1. Дар ҷадвали profiles, ки сутуни role-ро корбар тағйир дода наметавонад
  2. Дар user_metadata ҳангоми бақайдгирӣ
  3. Дар localStorage-и браузер
  4. Дар майдони пинҳонии шакли бақайдгирӣ

Ҳар чизе, ки корбар худаш тағйир дода метавонад (метамаълумоти корбар, браузер, шаклҳо), барои нигоҳдории ҳуқуқҳо мувофиқ нест.

Дар ҷадвали profiles қоидаи «корбар сатри худро нав мекунад» ҳаст, ва ҳуқуқи update ба ҳамаи сутунҳо дода шудааст. Фирдавс аз консоли браузер чӣ карда метавонад?

  1. Ҳеҷ чиз: RLS ҳамаро манъ мекунад
  2. Профили бегонаро тағйир диҳад
  3. Дар сатри худ role-ро ба admin иваз кунад, зеро ин сатри худи ӯст ва қоида сутунҳоро маҳдуд намекунад
  4. Ҷадвалро нест кунад

RLS ба саволи «кадом сатрҳо» ҷавоб медиҳад, на «кадом сутунҳо». Барои ҳамин барои role маҳдудиятро бо ҳуқуқҳо ба сутунҳо мегузоранд: grant update (full_name, phone).

Администратори аввалинро чӣ тавр таъин мекунанд?

  1. Корбар дар саҳифаи бақайдгирӣ «ман админам»-ро интихоб мекунад
  2. Соҳиби лоиҳа дар SQL Editor update profiles set role = 'admin' …-ро иҷро мекунад
  3. Ҳар корбаре, ки суроғаи /admin-ро медонад
  4. Автоматӣ аввалин бақайдгиршуда

Администраторро шахсе таъин мекунад, ки ба пойгоҳ дастрасӣ дорад (шумо), на шакл дар сайт.

Бештар хонед: Supabase: Row Level Security ва Managing user data (бо забони англисӣ).

06 Блоки AI: авторизатсия ҷои «ҳамин ҳам мешавад» нест

Рӯйхатро талаб кунед: ба ҳар нақш дар ҳар ҷадвал чӣ иҷозат аст. 5. Паролҳо, токенҳо ва калидҳоро ба чат нагузоред. 6. Ҷавоб мувофиқ наомад: матни хаторо фиристед ва аз нав оғоз накунед.

create function public.is_admin()
returns boolean
language sql
stable
security definer
set search_path = ''
as $$
  select exists (
    select 1 from public.profiles
    where id = (select auth.uid()) and role = 'admin'
  );
$$;
revoke execute on function public.is_admin() from public, anon;
grant execute on function public.is_admin() to authenticated;

import { createServerClient } from "@supabase/ssr";
import { NextResponse, type NextRequest } from "next/server";

export async function updateSession(request: NextRequest) {
  let supabaseResponse = NextResponse.next({ request });

  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY!,
    {
      cookies: {
        getAll() {
          return request.cookies.getAll();
        },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) =>
            request.cookies.set(name, value),
          );
          supabaseResponse = NextResponse.next({ request });
          cookiesToSet.forEach(({ name, value, options }) =>
            supabaseResponse.cookies.set(name, value, options),
          );
        },
      },
    },
  );

  // Миёни createServerClient ва getClaims() чизе ворид накунед:
  // вагарна корбарон тасодуфан аз сессия «бароварда» мешаванд.
  const { data } = await supabase.auth.getClaims();
  const user = data?.claims;

  const path = request.nextUrl.pathname;
  const isProtected = path.startsWith("/account") || path.startsWith("/admin");

  if (!user && isProtected) {
    const url = request.nextUrl.clone();
    url.pathname = "/login";
    url.searchParams.set("next", path);
    return NextResponse.redirect(url);
  }

  // Айнан ҳамин объектро баргардонед: дар он cookie-ҳои навшуда ҳастанд
  return supabaseResponse;
}

  • Корбари воридшуда ном ва телефонро таҳрир мекунад, қиматҳо баъди навсозии саҳифа захира мемонанд
  • Дар кабинет танҳо дархостҳои худӣ намоёнанд, /admin ба корбари оддӣ кушода намешавад
  • Як корбар тавассути SQL админ таъин шуд, ва /admin ҳамаи дархостҳоро ба ӯ нишон медиҳад
  • Баромад кор мекунад: баъди «Баромадан» кабинет боз пӯшида аст

  4. Confirm email-ро фаъол кардан лозим аст

08 Бонус: воридшавӣ бо Google (дастури қадам ба қадам)

Ин бахш ихтиёрӣ аст. Он тугмаи «Бо Google ворид шудан»-ро медиҳад: корбар набояд парол ихтироъ кунад, шумо бошед мактубҳо лозим надоред. Танзим як маротиба анҷом дода мешавад, тақрибан 30 дақиқа. Google суроғаи бозгашт (redirect URI)-и маҳз лоиҳаи Supabase-и шуморо талаб мекунад, барои ҳамин тартиб чунин аст: суроғаро дар Supabase дарёфт кунед, клиентро дар Google созед, маълумотро ба Supabase баргардонед.

Сирҳо ва ҳисоб

Client Secret аз Google — пароли барномаи шумост: он танҳо ба панели Supabase ва ба менеҷери паролҳо гузошта мешавад, на ба код, на ба Git ва на ба чат. Ҳисоби шахсии Google-ро истифода баред, барои лоиҳаи таълимӣ ҳисоби корӣ лозим нест. Номи бахшҳо дар Google Cloud Console иваз мешаванд: онҳоро аз рӯи маъно ҷӯед ва ба ҳуҷҷатҳои Supabase такя кунед.

  1. Суроғаи бозгашт аз Supabase. Дар панел: Authentication → Sign In / Providers → Google. Callback URL-ро нусха кунед (намуди https://ЛОИҲАИ-ШУМО.supabase.co/auth/v1/callback). Саҳифаро набандед.
  2. Лоиҳа дар Google Cloud. Google Cloud Console-ро кушоед (console.cloud.google.com), лоиҳаро бо ҳар ном (масалан mfs-course) созед ва онро интихоб кунед.
  3. Google Auth Platform. Дар консол бахши Google Auth Platform-ро кушоед ва танзими ибтидоиро гузаред: номи барнома, e-mail-и шумо барои тамос, Audience (барои ҳисобҳои оддии Google External интихоб мешавад). Дар бахши Data Access (Scopes) бояд openid, .../auth/userinfo.email ва .../auth/userinfo.profile бошанд: ин барои воридшавӣ кофӣ аст, ҳуқуқҳои зиёдатиро илова накунед (онҳо санҷиши дарозмуддат талаб мекунанд). Агар барнома дар ҳолати озмоишӣ (Testing) бошад, танҳо корбарони аз рӯйхати Test users ворид шуда метавонанд: суроғаҳои худро ба он илова кунед, ё барномаро нашр кунед.
  4. Клиенти OAuth. Дар Google Auth Platform бахши Clients → Create client-ро кушоед, навъи барнома Web application, ном ҳар кадом.
  5. Authorized JavaScript origins. Суроғаҳои сайтро бе роҳ илова кунед: http://localhost:3000 ва https://сайти-шумо.vercel.app.
  6. Authorized redirect URIs. Callback URL-ро аз қадами 1 гузоред (суроғаи Supabase, на сайти шумо!). Create-ро пахш кунед ва Client ID ва Client Secret-ро захира кунед.
  7. Ба Supabase баргардед. Дар Authentication → Sign In / Providers → Google провайдерро фаъол кунед, Client ID ва Client Secret-ро гузоред, захира кунед. Дар URL Configuration Site URL-ро санҷед ва ба Redirect URLs суроғаи http://localhost:3000/auth/callback-ро илова кунед (ва ҳамонро бо суроғаи Vercel).
  8. Тугма ва коркардкунанда. Аз AI хоҳиш кунед, ки дар /login тугмаи «Бо Google ворид шудан» ва масири app/auth/callback/route.ts-ро илова кунад, коди зеринро ҳамчун намуна истифода бурда.
  9. Санҷиш. Тугмаро пахш кунед, ҳисоби Google-ро интихоб кунед: шуморо бояд ба /account баргардонанд, дар Authentication → Users корбар бо провайдери Google пайдо шуд, дар profiles — сатри ӯ (триггер ҳамон тавр кор кард, ки ҳангоми бақайдгирӣ бо парол).
const supabase = createClient(); // lib/supabase/client.ts

await supabase.auth.signInWithOAuth({
  provider: "google",
  options: { redirectTo: `${window.location.origin}/auth/callback` },
});

import { NextResponse } from "next/server";
import { createClient } from "@/lib/supabase/server";

export async function GET(request: Request) {
  const { searchParams, origin } = new URL(request.url);
  const code = searchParams.get("code");
  const next = searchParams.get("next") ?? "/account";
  // танҳо роҳҳои худӣ: бо як «/» оғоз мешаванд
  const safeNext = next.startsWith("/") && !next.startsWith("//") ? next : "/account";

  if (code) {
    const supabase = await createClient();
    const { error } = await supabase.auth.exchangeCodeForSession(code);
    if (!error) return NextResponse.redirect(`${origin}${safeNext}`);
  }
  return NextResponse.redirect(`${origin}/login?error=oauth`);
}
Агар вайрон шуд

Error 400: redirect_uri_mismatch. Суроға дар Authorized redirect URIs бо Callback URL аз Supabase мувофиқат намекунад. Онро аз нав пурра нусха кунед, бе фосила ва бе слеши охирин.

Google менависад, ки дастрасӣ масдуд аст ё барнома санҷишро нагузаштааст. Барнома дар ҳолати Testing аст, суроғаи шумо бошад дар рӯйхати Test users нест.

Баъди интихоби ҳисоб шуморо ба /login?error=oauth бармегардонанд. Суроғаи /auth/callback ба Redirect URLs-и Supabase илова нашудааст ё коркардкунанда exchangeCodeForSession-ро даъват намекунад.

Воридшавӣ дар localhost кор мекунад, аммо дар Vercel не. Дар Google суроғаи Vercel дар Authorized JavaScript origins нест, ё дар Supabase дар Redirect URLs нест.

09 Хусусияти дарс: «Ҳамсояро шикаст»

Бозӣ барои ҷуфтҳо: аввал шумо ба таври қасдан дар сайти худ қоидаҳои «танбал»-ро бо рахнаҳо месозед, ҳамсоя кӯшиш мекунад онҳоро истифода барад, баъд шумо рахнаҳоро бо қоидаҳо аз рӯи id-и корбар мепӯшед, ва ҳамсоя бори дигар кӯшиш мекунад. Ҳамааш бо маълумоти таълимӣ. Вақт: тақрибан 60 дақиқа. Дар аудитория ё онлайн гузаронида мешавад.

Қоидаҳои бехатарии бозӣ

Мо танҳо сайти ҳамсояро, ки худаш иҷозат додааст, ва танҳо дар пойгоҳи таълимӣ бо маълумоти фарзӣ мешиканем. Инро дар сайтҳои воқеии бегона озмудан мумкин нест: ин вайрон кардани қонун ва қоидаҳои ҳар хизмат аст. Қоидаҳои «танбал» ва саҳифаи /hack танҳо барои вақти бозӣ лозиманд: баъд аз он ҳама нест карда мешавад.

Видео бо забони англисӣ, камтар аз як дақиқа (субтитрҳоро фаъол кунед): RLS чист. Пеш аз бозӣ бинед.

Омодагӣ (барои ҳар кас 10 дақиқа)

  1. Панели ҳамла. Аз AI хоҳиш кунед, ки саҳифаи /hack-ро созад (муваққатӣ, танҳо барои бозӣ): компоненти клиентӣ бо createClient аз lib/supabase/client.ts бо панҷ тугма ва равзанаи натиҷа (JSON). Тугмаҳо: A «ҳамаи профилҳоро хондан» (from("profiles").select("*")); B «ҳамаи дархостҳоро хондан» (from("bookings").select("*")); C «номи профили бегонаро иваз кардан» (майдони id, update({ full_name: "Взломано" }).eq("id", id).select()); D «маро админ кардан» (update({ role: "admin" }) барои id-и худ, бо .select()); E «id-и маро нишон бидеҳ» (аз getClaims()). Натиҷа ё хато дар зери тугмаҳо чоп мешавад.
  2. Қоидаҳои «танбал». Дар SQL Editor блоки зерро иҷро кунед: он қасдан чор рахна илова мекунад. Ин танҳо аз он ҷиҳат мумкин аст, ки пойгоҳи таълимӣ бо маълумоти фарзӣ доред.
  3. Деплой ва мубодила. Сайтро дар Vercel деплой кунед (ҳамин тавр ҳамсоя истиноди зинда мегирад). Суроғаҳои сайтро иваз кунед. Дар пойгоҳи шумо бояд маълумот барои ҳамсоя барои «дуздӣ» бошад: дар профил ном ва телефони ихтироъкардаро +992 900 00 00 01 ва чанд дархости озмоишӣ монед.

Даври 1: ҳамла (15 дақиқа)

  1. Сайти ҳамсояро кушоед, дар он бақайд шавед ҳамчун корбари нав (e-mail ихтироъшуда, масалан hacker1@example.com) ва /hack-ро кушоед.
  2. Тугмаҳоро навбат ба навбат пахш кунед ва дар «протоколи шикаст» сабт кунед: чӣ ҳосил шуд, кадом матн баргашт. A: оё профилҳои ҳамсоя бо телефонҳо ва нақшҳо намоёнанд? B: оё дархостҳои бегона намоёнанд? C: оё номи бегона иваз шуд (id-ро дар натиҷаи A ёбед)? D: оё худро админ кардан муяссар шуд, ва оё ҳоло /admin кушода мешавад?

Даври 2: ҳифз (15 дақиқа)

Протоколро аз ҳамсоя гирифта, рахнаҳоро пӯшед. Блоки зер қоидаҳои «танбал»-ро мебардорад ва ҳуқуқҳоро ба сутунҳо бармегардонад.

drop policy if exists "lazy read profiles" on profiles;
drop policy if exists "lazy read bookings" on bookings;
drop policy if exists "lazy update profiles" on profiles;

10 Вазифаи хонагӣ: қисми пӯшидаи сайт ва нақши администратор (ВХ-12)

Сайтро ба ҳолати «маҳсулот бо корбарони воқеӣ ва нақшҳо» расонед: қисми сайт танҳо ба воридшудагон дастрас аст, соҳиб бошад тавассути админка идора мекунад. Супориш: ду истинод (репозиторияи GitHub ва сайт дар Vercel).

Талабот

  • Бақайдгирӣ ва воридшавӣ бо e-mail ва парол: хатоҳои фаҳмо, санҷиши майдонҳо, баромад. Дар сайт тугмаи баромад ҳаст ва дар сарлавҳа намоён аст, ки корбар ворид шудааст ё не. Воридшавӣ бо Google ихтиёрӣ (бонус).
  • Қисми пӯшида: ҳадди аққал ду саҳифа танҳо барои воридшудагон (кабинети шахсӣ /account ва боз як саҳифаи худӣ: масалан «Дархостҳои ман» ё «Интихобшудаҳо»). Барои меҳмонон — равона кардан ба воридшавӣ, баъди воридшавӣ бозгашт ба саҳифаи лозимӣ (?next= бо санҷиш).
  • Кабинети шахсӣ: дидан ва таҳрири профил (ном, телефон), маълумоти худӣ аз пойгоҳ (дархостҳо), ҳамааш тавассути RLS аз рӯи user_id.
  • Нақшҳо: ҷадвали profiles бо role (user / admin), нақш дар user_metadata нест, корбари оддӣ нақши худро иваз карда наметавонад (ҳуқуқҳо ба сутунҳо), админ тавассути SQL таъин шудааст.
  • Админка /admin: танҳо барои нақши admin, ҳамаи дархостҳоро мехонад (ё ҳамаи сабтҳои соҳаи мавзӯии шумо), дар саҳифа санҷиши нақш ҳаст, барои дигарон notFound(), аз индексатсия пӯшида (noindex). Калиди secret дар он истифода намешавад.

  • Санҷиши «Ҳамсояро шикаст» гузаронида шуд: дар протокол (README ё ёддошт) номбар шудааст, ки кадом рахнаҳоро ёфтанд ва чӣ тавр пӯшиданд.
  • Сирҳо: калидҳо танҳо дар .env.local ва Vercel; .env.example бе қиматҳо; дар репозиторий паролҳо, токенҳо ва калидҳо нестанд; саҳифаи /hack нест.
  • Сифат: npm run build бе хато; дар Vercel бақайдгирӣ, воридшавӣ, кабинет ва админка кор мекунанд; шумо метавонед ҳар қоидаи RLS-ро фаҳмонед.

✓ Хулосаи дарс

  • «Ҳамсояро шикаст»: ҳифзро бо ҳамлаи аз дарун санҷед (тугмаҳои A–E), протокол нависед, рахнаҳоро пӯшед, саҳифаҳо ва қоидаҳои муваққатиро нест кунед.
