01 CRUD: чор амал бо ҳар як сабт

Қариб ҳар маҳсулот, аз CRM то мағозаи интернетӣ, бо маълумот чор амал мекунад: месозад (Create), нишон медиҳад (Read), тағйир медиҳад (Update) ва нест мекунад (Delete). Ихтисори CRUD-ро як бор ба ёд гиред: он экран, амали пойгоҳ ва қоидаи RLS-ро мепайвандад. Барои як бахши маҳсулот одатан чор экран лозим аст: рӯйхат, шакли сохтан, саҳифаи сабт бо шакли тағйирдиҳӣ ва тасдиқи нестсозӣ.

Куҷо чӣ иҷро мешавад

Саҳифа маълумотро дар сервер мехонад (он компоненти серверӣ аст, дарси 9). Шаклҳо маълумотро ба амалҳои серверӣ (Server Actions) мефиристанд: инҳо функсияҳое бо директиваи "use server" мебошанд, ки Next.js ҳангоми фиристодани шакл даъват мекунад. Амал се корро аз рӯи тартиб мекунад: корбари воридшударо месанҷад (getClaims(), дарси 12), маълумоти шаклро месанҷад ва дархости Supabase-ро иҷро мекунад; баъд ба саҳифа мегӯяд, ки нав шавад (revalidatePath) ё ба суроғаи лозимӣ равона мекунад. Тамоми кодро ИИ мегузорад, шумо бошед онро аз рӯи се қоидаи зер месанҷед.

Се қоидаи экрани CRUD

1. Маълумотро сервер месанҷад. Санҷиши браузерӣ (required, дарозии майдон) барои қулайӣ аст, ҳимояи воқеӣ бошад дар амали серверӣ ва дар пойгоҳ аст: дархостро бе шакли шумо ҳам фиристодан мумкин аст. 2. Ҳуқуқро RLS ҳал мекунад. «Тугмаро пинҳон мекунем» нест, балки дар пойгоҳ қоидаҳои update ва delete танҳо барои сатрҳои худӣ ва барои admin ҳастанд. 3. Ҳар экран чор ҳолат дорад: боркунӣ, холӣ, хатогӣ, муваффақият (баъд аз захира паёми кӯтоҳ ё гузариш ба рӯйхат).

Нуктаҳои амалӣ

  • Нестсозӣ тасдиқ мепурсад. «Боварӣ доред?» аз клики тасодуфӣ муҳофизат мекунад. Нестсозии нарм (сутуни deleted_at ба ҷои delete-и воқеӣ) лозим аст, агар сабтро баргардонидан даркор шавад; дар лоиҳаи таълимӣ delete-и оддӣ кифоят аст.
  • Идентификатори соҳибро сервер мегузорад. Сутуни user_id дар амали серверӣ аз getClaims() пур мешавад, на аз майдони пинҳонии шакл: майдонро иваз кардан мумкин аст.
  • Баъд аз тағйирот рӯйхатро нав кунед. Агар саҳифаи рӯйхат кӯҳна монад, пас revalidatePath барои суроғаи он даъват нашудааст.
  • Як компоненти шакл барои сохтан ва тағйир додан. Фарқ дар қиматҳои ибтидоӣ ва тугма аст: ҳамин тавр код камтар ва хатогиҳо камтаранд.
Монандӣ аз ҳаёт

Дафтари ҳисоб дар дукони хурди бозор. Фурӯшанда маҳсули навро менависад (Create), сабтҳоро мебинад (Read), нархро ислоҳ мекунад (Update) ва фурӯхташударо хат мезанад (Delete). Аммо соҳиби дукон ҳал мекунад, ки кӣ ба дафтар даст мезанад: ёрдамчӣ танҳо дар қисми худаш менависад, хат задан ва ҳамаро дидан танҳо кори соҳиб аст. Дафтар — ҷадвал, соҳиб — қоидаҳои RLS, шакли шумо бошад танҳо тиреза аст, ки фурӯшанда аз он даст дароз мекунад.

Хатогиҳои маъмули навомӯзон

1. Қоидаи select ва insert ҳаст, аммо update ва delete-ро фаромӯш кардаанд: тугмаи «Захира кардан» зер мешавад, хатогӣ нест, аммо сабт тағйир намеёбад (RLS сатрро хомӯшона филтр кард). 2. user_id-ро аз шакл мегиранд. 3. Санҷиш дар сервер нест: сатрҳои холӣ ва аз ҳад дароз ба пойгоҳ мерасанд. 4. Нестсозӣ бе тасдиқ ва бе revalidatePath: сабт нест шуд, аммо дар рӯйхат ҳанӯз намоён аст. 5. Ҳолати сабтро дар интерфейс иваз мекунанд, дар пойгоҳ бошад қоида ба ҳар воридшуда имкон медиҳад, ки ҳар сатрро иваз кунад (using (true)). 6. Хатогии ҷавоби Supabase-ро намесанҷанд: const { error } = … навиштаанд, аммо error-ро истифода намебаранд.

ВАЗИФАИ 1.1

Худро санҷед: CRUD ва ҳуқуқҳо

миёна

Корбар дар шакли тағйирдиҳии сабти худ «Захира кардан»-ро зер кард. Хатогӣ нест, аммо қимат пештара монд. Дар ҷадвал RLS фаъол аст, қоидаҳои select ва insert ҳастанд. Эҳтимолтарин сабаб чист?

  1. Браузер саҳифаро барои як ҳафта нигоҳ дошт
  2. Дар Supabase квотаи ройгон тамом шуд
  3. Барои ин ҷадвал қоидаи update нест: RLS хатогӣ намедиҳад, балки барои тағйир додан сатр намеёбад
  4. Номи ҷадвал бо ҳарфҳои калон навишта шудааст

RLS-и фаъол бе қоидаи мувофиқ сатрҳоро аз фармон хомӯшона пинҳон мекунад. Аз ИИ хоҳиш кунед, ки қоидаҳои ҷадвалро нишон диҳад ва update-ро барои сатрҳои худӣ ва барои admin илова кунад, бе хомӯш кардани RLS.

user_id-и сабти нав бояд аз куҷо гирифта шавад?

  1. Аз майдони пинҳонии шакл: ин қулайтар аст
  2. Аз маълумоти санҷидашудаи корбари воридшуда дар сервер (getClaims())
  3. Аз суроғаи саҳифа
  4. Аз анбори маҳаллии браузер

Майдони пинҳонӣ ва ҳар чизе, ки аз браузер меояд, иваз карда мешавад. Соҳиби сабтро сервер аз рӯи сессияи санҷидашуда мегузорад, қоидаи with check дар пойгоҳ бошад кафолат медиҳад.

Кадом фармонҳои пойгоҳ ба ҳарфҳои C, R, U, D мувофиқанд?

  1. insert, select, update, delete
  2. create, read, use, drop
  3. post, get, put, remove
  4. Ҳар чор ҳарфро select иҷро мекунад

Дар SQL ин insert, select, update, delete аст ва барои ҳар фармон қоидаи худи RLS лозим. Вариантҳо бо post/get/put ба дархостҳои HTTP тааллуқ доранд (дарси 10).

02 Рӯйхати сабтҳо: ҷустуҷӯ, филтрҳо, ҷудокунӣ, саҳифабандӣ

Вақте сабтҳо даҳтоанд, рӯйхатро оддӣ баровардан мумкин аст. Вақте ҳазор шуданд, корбарро чор асбоб лозим мешавад: ҷустуҷӯ аз рӯи матн, филтр («танҳо кушодаҳо»), ҷудокунӣ («аввал гаронҳо») ва саҳифабандӣ (дар ҳар саҳифа 10 сабт). Фикри асосӣ: ҳамаи ин ҳолат дар суроғаи саҳифа, дар query string нигоҳ дошта мешавад:

/items?q=tea&status=open&sort=price_desc&page=2

Чунин суроғаро ба дӯст фиристодан, ба хатбарак гузоштан, саҳифаро нав кардан ва бо тугмаи «ақиб» баргаштан мумкин аст, аммо ҳолат гум намешавад. Агар онро дар useState нигоҳ доред, ҳама чиз ҳангоми нав кардани саҳифа нест мешавад. Дар Next.js саҳифаи серверӣ параметрҳои суроғаро тайёр мегирад: хосияти searchParams (дар Next.js 16 ин промис аст, онро тавассути await мехонанд).

Дар дархост ба Supabase ин чӣ тавр менамояд

Филтрҳои лозимӣ як-як ба дархост илова мешаванд (кодро ИИ менависад, аммо шумо бояд онро бо чашм хонед):

const size = 10;
const from = (page - 1) * size;
const to = from + size - 1; // range includes both ends

let query = supabase
  .from("items")
  .select("id, title, status, price, created_at", { count: "exact" })
  .order(sort, { ascending: dir === "asc" })
  .range(from, to);

if (q) query = query.ilike("title", `%${q}%`);
if (status) query = query.eq("status", status);

const { data, count, error } = await query;
const pages = Math.max(1, Math.ceil((count ?? 0) / size));
  • ilike бе ба назар гирифтани ҳарфи калон ва хурд меҷӯяд, аломатҳои % дар канорҳо маънои «ҳар чиз пеш ва баъд»-ро доранд. Барои ҷустуҷӯҳои зуд-зуд дар ҷадвали калон баъдтар индекс илова мекунанд, ба лоиҳаи таълимӣ ин таъсир намекунад.
  • range(from, to) аз сифр ҳисоб мешавад ва ҳудудҳо дохил мешаванд: range(0, 9) даҳ сатри аввалро бармегардонад. Ҳамеша бо order, вагарна тартиби сатрҳо кафолат дода намешавад ва сабтҳо байни саҳифаҳо «ҷаҳида» метавонанд.
  • { count: "exact" } шумораи умумии сатрҳои мувофиқро бармегардонад: аз рӯи он саҳифаҳоро ҳисоб мекунед. Барои панели омор варианти { count: "exact", head: true } ҳаст: танҳо рақам бе худи сатрҳо бармегардад.
  • Ҷудокуниро аз рӯи рӯйхати сафед санҷед. Агар sort-ро аз суроға ҳамон тавр гиред, корбар ҳар чизро мегузорад: танҳо майдонҳои маълумро иҷозат диҳед (created_at, price, title).
  • Партов дар суроға набояд саҳифаро вайрон кунад. ?page=abc ва ?page=-5 ба саҳифаи аввал табдил меёбанд, page, ки аз шумораи саҳифаҳо зиёд аст, саҳифаи охир ё ҳолати холиро нишон медиҳад.

Чиро бояд донист, то қарорро шарҳ диҳед

  • Саҳифабандии серверӣ. Ба браузер як саҳифа (10 сатр) дода мешавад, на тамоми ҷадвал: вагарна сайт суст аст ва маълумоти зиёдатӣ ба корбар мерасад.
  • Иваз кардани филтр саҳифаро ба аввал бармегардонад. Вагарна пас аз интихоби филтр корбар дар саҳифаи сеюм мемонад, ки он дигар вуҷуд надорад.
  • Шакл бо усули GET. Ҷустуҷӯ ва филтрҳоро бо шакли оддии <form> бе JavaScript сохтан мумкин аст: браузер худаш майдонҳоро ба суроға илова мекунад. Барои саҳифабандӣ истинодҳои оддӣ кифоянд.

Вазифаи баръакс: аз қиматҳои шакл суроға созед. Қиматҳоро бояд рамзгузорӣ кард (encodeURIComponent): фосила, кириллика, аломатҳои & ва = вагарна суроғаро вайрон мекунанд. Қиматҳои пешфарзро ба суроға намегузоранд: /items-и тоза аз /items?q=&status=all&page=1 беҳтар аст.

03 Файлҳо ва тасвирҳо: Supabase Storage

Тасвирҳо, PDF ва дигар файлҳоро дар ҷадвали оддӣ нигоҳ доштан мумкин нест: онҳо вазнинанд. Барои онҳо дар Supabase Storage ҳаст: анбори файлӣ, ки файлҳо дар он дар бакетҳо (buckets, «сабадҳо») ва дар дохили бакет дар папкаҳо нигоҳ дошта мешаванд. Ба ҷадвал шумо танҳо роҳи файлро (матн) менависед, худи файл дар анбор мемонад.

Бакети оммавӣ ё пӯшида

Бакети оммавӣ
  • Файлро аз рӯи истинод ҳар кас бе воридшавӣ ва бе RLS хонда метавонад (getPublicUrl)
  • Боркунӣ, иваз ва нестсозӣ ба ҳар ҳол бо қоидаҳо санҷида мешаванд
  • Барои логотипҳо ва тасвирҳои сайт мувофиқ аст, ки онро ҳама мебинанд
Бакети пӯшида (пешфарз)
  • Ҳама чиз, аз ҷумла хондан, тавассути қоидаҳои RLS мегузарад
  • Файлро бо истиноди имзошудаи муваққатӣ нишон медиҳанд (createSignedUrl)
  • Барои ҳуҷҷатҳо, сурати корбарон ва ҳар чизе, ки бегонагон набояд бубинанд, мувофиқ аст

Дар ин спринт тасвирҳои сабтҳо ва замимаҳоро дар бакети пӯшида месозем: бехатартар аст ва пешфарз ҳамин аст, оммавӣ кардани он баъдтар мумкин аст, агар маълум шавад, ки файл барои ҳама лозим аст. Қоидаи дарс: бакетро бо сабти оммавӣ ҳеҷ гоҳ намесозем (иҷозати «ҳар кас метавонад бор кунад» анбори шуморо ба файлбанди ройгон барои спам ва файлҳои зараровар табдил медиҳад).

Бакетро чӣ тавр дуруст сохтан

  1. Дар панели Supabase бахши Storage-ро кушоед, New bucket-ро зер кунед ва ном нависед, масалан item-images (дар ҳуҷҷатҳои Supabase ин роҳи «Storage → New Bucket → Create Bucket» аст).
  2. Гузаргари «Public bucket»-ро хомӯш гузоред.
  3. Дар танзимоти иловагии бакет маҳдудиятҳо гузоред: андозаи ҳадди аксари файл (масалан, 2 МБ) ва навъҳои иҷозатдодашуда (image/jpeg, image/png, image/webp). Маҳдудиятҳои бакетро пойгоҳ дар тарафи худ месанҷад ва ба браузер бовар намекунад. Номи бандҳо дар панел каме фарқ карда метавонад: «file size limit» ва «allowed MIME types»-ро ҷустуҷӯ кунед.
  4. Бакет сохта шуд, аммо ҳоло ба он бор кардан мумкин нест: бе сиёсатҳо дар storage.objects боркунӣ барои ҳама пӯшида аст. Ин муқаррарӣ ва бехатар аст: баъд шумо дақиқан ҳамон ҳуқуқҳоро медиҳед, ки лозиманд.

Сиёсатҳо аз рӯи id-и корбар (RLS дар storage.objects)

Файлҳо бо сатрҳои ҷадвали storage.objects тавсиф мешаванд: дар сутуни name-и он роҳи пурра бо намуди папка/файл.jpg меистад, дар bucket_id номи бакет. Яъне қоидаҳои RLS мисли ҷадвалҳои оддӣ навишта мешаванд (дарси 11), функсияи storage.foldername(name) бошад массиви папкаҳои роҳро бармегардонад. Созиш: папкаи аввали роҳ — id-и корбар аст, яъне файли корбари воридшуда ҳамчун <user-id>/<номи-тасодуфӣ>.jpg меистад.

Сиёсатҳоро ба файли db/003_storage.sql захира кунед ва дар SQL Editor иҷро намоед, чунон ки дар дарси 11 карда будед. Номи бакетро бо номи худ иваз кунед:

/* корбар файлҳоро танҳо ба папкаи худ бор мекунад */
create policy "item-images: insert own folder"
on storage.objects for insert to authenticated
with check (
  bucket_id = 'item-images'
  and (storage.foldername(name))[1] = (select auth.uid())::text
);

/* файлҳои худро мехонад; admin ҳамаро мехонад (функсияи is_admin аз дарси 12) */
create policy "item-images: select own or admin"
on storage.objects for select to authenticated
using (
  bucket_id = 'item-images'
  and ((storage.foldername(name))[1] = (select auth.uid())::text
       or (select public.is_admin()))
);

/* файлҳои худро нест мекунад; admin ҳар кадомро нест мекунад */
create policy "item-images: delete own or admin"
on storage.objects for delete to authenticated
using (
  bucket_id = 'item-images'
  and ((storage.foldername(name))[1] = (select auth.uid())::text
       or (select public.is_admin()))
);
  • to authenticated: меҳмони бе воридшавӣ тамоман бор карда наметавонад. Қоидаҳо «барои anon» ба сабт намениависем.
  • Папкаи кист, кӣ ҳал мекунад. На шакл ва на браузер: санҷиш роҳро бо auth.uid() аз сессия муқоиса мекунад. Кӯшиши ба папкаи корбари дигар бор кардан хатогии вайронкунии RLS мегирад.
  • Танҳо фармонҳое, ки лозиманд. Қоидаи update дар ин ҷо нест: файлҳо аз нав навишта намешаванд, балки бо номи тасодуфии нав бор карда мешаванд ва кӯҳна нест мешавад. (Барои аз нав навиштан бо upsert боз select ва update лозим аст.)
  • Хондан ҳатто барои истиноди имзошуда лозим аст: истинодро танҳо касе сохта метавонад, ки ба ӯ select иҷозат дода шудааст.
  • Дар ҳуҷҷатҳои расмии Supabase ҳамин санҷиш тавассути auth.jwt()->>'sub' навишта шудааст: ин ҳамон id-и корбар бо роҳи дигар аст.

Боркунӣ ва нишон додани файл

Боркунӣ аз браузер бо клиенти Supabase (аз файли lib/supabase/client.ts-и дарси 12) зери сессияи корбар мегузарад, барои ҳамин қоидаҳои RLS ба ӯ татбиқ мешаванд. Id-и корбарро аз сервер ба компоненти шакл диҳед: саҳифаи серверӣ онро аллакай аз getClaims() медонад.

const path = `${userId}/${crypto.randomUUID()}.${ext}`;

  return;
}

  .createSignedUrl(item.image_path, 3600); // истинод 3600 сония кор мекунад

  • Номи тасодуфии файл (crypto.randomUUID()) аз мувофиқатҳо ва аломатҳои аҷиб дар ном муҳофизат мекунад. Боркунӣ ба роҳи мавҷуда бе upsert хатогии «Asset Already Exists» мегардонад.
  • Андоза ва навъро ду бор месанҷем: дар браузер (барои қулайӣ: хатогӣ фавран) ва дар танзимоти бакет (барои ҳимоя). Ба санҷиши браузерӣ бовар кардан мумкин нест.
  • Боркунии оддӣ барои файлҳо тахминан то 6 МБ пешбинӣ шудааст; барои калонтарҳо боркунии барқароршаванда ҳаст, дар лоиҳаи таълимӣ он лозим нест.

  • Ҳангоми нест кардани сабт файлро низ нест кунед (storage.from(…).remove([path])), вагарна дар анбор партов ҷамъ мешавад. Қоидаи delete лозим аст, он дар SQL-и боло ҳаст.

Видео бо забони англисӣ, субтитрҳоро фаъол кунед. Бубинед, ки экрани сиёсатҳои бакет чӣ хел менамояд ва қоидаҳо чӣ тавр ҳал мекунанд, ки кӣ бо файлҳо чӣ карда метавонад. Интерфейси панел бо мурури замон иваз мешавад, аммо фикр ҳамон аст.

Монандӣ аз ҳаёт

Ҳуҷраи нигоҳдорӣ дар вокзали Душанбе. Ҳар мусофир ҳуҷраи рақамдори худро дорад, дар чек рақами ҳуҷра навишта шудааст (роҳ дар ҷадвал). Танҳо ҳуҷраи худро кушодан мумкин аст: хадамоти амният месанҷад, ки рақами чек бо рақами билети шумо мувофиқ аст (сиёсат аз рӯи id). Бакети оммавӣ бо сабт барои ҳама ҳуҷраи нигоҳдорӣ бе посбон ва бе қуфл мебуд: ҳар кас ҳар чизро дар он мегузорад.

Хатогиҳои маъмули навомӯзон

1. Бакетро оммавӣ кардан, то ки «кор кунад» ва дар бораи сиёсатҳо фаромӯш кардан. 2. Сиёсати with check (true)-ро барои insert навиштан: ҳар воридшуда ба ҳар папка бор карда метавонад. 3. Нақши anon-ро ба сабт гузоштан: меҳмонон файл бор карда метавонанд. 4. Номи файли корбарро бе тоза кардан ба роҳ гузоштан: кириллика, фосилаҳо ва такрорҳо боркуниро вайрон мекунанд. 5. Маҳдудияти андоза ва навъро нагузоштан: ба бакет видеоҳои гигабайтӣ ва файлҳои иҷрошаванда мерасанд. 6. Истиноди имзошудаи тайёрро дар ҷадвал нигоҳ доштан: он кӯҳна мешавад, дар ҳоле ки роҳро нигоҳ доштан лозим аст. 7. Secret key-ро дар браузер истифода бурдан «барои гузаштан аз RLS»: он ба ҳама чиз дастрасии пурра медиҳад ва бояд танҳо дар сервер зиндагӣ кунад (дарси 11). 8. Хатогии ҷавоби upload-ро нагузаронидан.

  1. Оё тасвир барои браузер аз ҳад вазнин нест
  2. Оё номи сайт аз ҳад дароз нест
  3. Оё сиёсати insert ҳаст ва оё папкаи аввали роҳ бо id-и корбари воридшуда мувофиқ аст
  4. Оё мавзӯи торик фаъол нест

Ин паём маънои онро дорад, ки сиёсат дарҷро иҷозат надод: ё қоида нест, ё роҳ бо id-и шумо оғоз намешавад, ё шумо ворид нашудаед. Андоза ва навъи файл хатогиҳои дигар медиҳанд (лимити андоза ва навъи MIME-и иҷозатнашуда).

Баъд аз боркунии бомуваффақият ба ҷадвал чиро навиштан лозим?

  1. Худи файлро пурра ба майдони матнӣ
  2. Роҳи файлро дар бакет (масалан, u-42/9f3a.webp), истинодро бошад дар сервер ҳангоми нишон додан месозанд
  3. Истиноди имзошударо: он ба ҳамеша мерасад
  4. Ҳеҷ чиро, Supabase худаш файлро аз рӯи номи сабт меёбад

Роҳ тағйир намеёбад, истиноди имзошуда бошад вақти маҳдуд кор мекунад, барои ҳамин ҳар дафъа ҳангоми нишон додан аз нав сохта мешавад. Файлро ба ҷадвал намегузоранд: анбор барои ҳамин аст.

04 Огоҳиномаҳо ба e-mail

Маҳсулот бояд дар бораи муҳим хабар диҳад: «дархости нав омад», «фармоиш қабул шуд», «ҳолат иваз шуд». Мактубҳо танҳо аз сервер фиристода мешаванд: сайт хидмати почтаро бо API ва калиди махфӣ даъват мекунад (мисли Gemini дар дарси 13), браузер бошад ин калидро набояд бубинад. Дар курс хидмати Resend-ро истифода мебарем: он тарифи ройгон дорад (дар лаҳзаи навиштан: то 3000 мактуб дар як моҳ, на зиёда аз 100 дар як шабонарӯз), API-и оддӣ ва китобхонаи тайёр барои Node.js.

Маҳдудияти асосӣ: бе домени худӣ мактубҳо танҳо ба шумо мераванд

Мактубҳоро «аз номи худ» ба ҳар суроға танҳо баъд аз тасдиқи домен (вебсайти-шумо.com) тавассути сабтҳои DNS фиристодан мумкин аст. То даме ки домен нест, фиристандаи озмоишӣ onboarding@resend.dev истифода мешавад ва мактубҳо танҳо ба суроғае мерасанд, ки ҳисоби шумо дар Resend бо он сабт шудааст. Кӯшиши ба каси дигар фиристодан хатогии 403 бо матни «You can only send testing emails to your own email address … To send emails to other recipients, please verify a domain»-ро бармегардонад. Барои вазифаи хонагӣ ин кифоя аст: огоҳиномаро соҳиби маҳсулот (шумо) мегирад. Домени худро баъдтар пайваст кардан мумкин аст, он танҳо барои оғози воқеӣ лозим аст.

Чиро фикр кардан лозим

Дар лоиҳаи хатмӣ мактубро соҳиб мегирад, яъне шумо: «дар мағозаи интернетӣ фармоиш расмӣ шуд», «дар Booking брон сохта шуд», «дар CRM дархости нав пайдо шуд». Суроғаи гирандаро дар тағйирёбандаи муҳит NOTIFY_EMAIL нигоҳ доред, на дар код. Огоҳиномаҳои Telegram дар дарси 21 пайдо мешаванд, дар ин ҷо танҳо e-mail.

Пайвастшавӣ бо панҷ қадам

  1. Дар resend.com бо ҳамон суроғае сабти ном кунед, ки мехоҳед мактуб гиред.
  2. Дар панел бахши API Keys-ро кушоед ва калидро бо ҳуқуқи фиристодан (sending access) эҷод кунед. Калидро як бор нишон медиҳанд: фавран дар .env.local ҳамчун RESEND_API_KEY=… захира кунед. Ба ҳамон ҷо NOTIFY_EMAIL=суроғаи-шумо. Дар .env.example номҳоро бе қиматҳо нависед.
  3. Китобхонаро насб кунед: npm install resend (ин ягона китобхонаи нави дарс аст, барои ҳамин қоидаи «бе пурсиш ҳеҷ чиз насб накун»-и AGENTS.md-ро шумо дар ин ҷо бошуурона иҷозат медиҳед).
  4. Дар амали серверӣ баъд аз захираи муваффақонаи сабт мактубро фиристед.
  5. Ҳарду тағйирёбандаро ба танзимоти Vercel илова кунед (Settings → Environment Variables) ва деплойро аз нав оғоз кунед.
import { Resend } from "resend";

const resend = new Resend(process.env.RESEND_API_KEY);

export async function notifyOwner(subject: string, html: string) {
  const { error } = await resend.emails.send({
    from: "My Project <onboarding@resend.dev>",
    to: [process.env.NOTIFY_EMAIL!],
    subject,
    html,
  });
  if (error) console.error("e-mail not sent:", error.message);
}

  • Маълумоти бегонаро ба мактуб бе экран кардан наандозед. Матни шакл метавонад теггҳо дошта бошад: ё HTML-ро экран кунед, ё матни оддӣ фиристед.
  • Мактубҳо метавонанд ба «Спам» афтанд. Барои фиристандаи озмоишӣ ин ҳолати маъмул аст: пеш аз ҷустуҷӯи хатогӣ дар код папкаро санҷед.
  • Лимитҳо. Барои ҳар зеркунии клавиш мактуб нафиристед ва даврҳо нанависед: сад мактуб дар як шабонарӯз дар тарифи ройгон зуд тамом мешавад.
  • Дар Resend суроғаҳои озмоишӣ мисли delivered@resend.dev ҳастанд, аммо онҳо танҳо барои санҷиши API лозиманд, на барои огоҳиномаи воқеӣ, ки бояд ба почтаи шумо расад.
Монандӣ аз ҳаёт

Почтальон аз ноҳияи ҳамсоя. То даме ки шумо лавҳаи худро (домен) надоред, почта розӣ аст мактубҳоро танҳо ба суроғаи соҳиби ҳисоб барад: ҳамин тавр месанҷанд, ки шумо аз номи бегона спам намефиристед. Вақте лавҳаро сабт мекунед ва ҳуҷҷатҳоро нишон медиҳед (сабтҳои DNS), почтальон мактубҳоро ба ҳар кас мебарад.

Хатогиҳои маъмули навомӯзон

1. Калиди RESEND_API_KEY ба код, ба чат ё ба репозиторий афтод. 2. Тағйирёбанда бо NEXT_PUBLIC_ номгузорӣ шудааст: калид ба браузер меравад. 3. Тағйирёбандаҳоро ба .env.local илова карданд, ба Vercel фаромӯш карданд: дар сайт мактубҳо намераванд. 4. Мактубро ба муштарӣ фиристодан мехоҳанд ва 403 мегиранд: то тасдиқи домен мактубҳо танҳо ба суроғаи шумо мераванд. 5. Дар Resend бо як суроға сабти ном мекунанд, NOTIFY_EMAIL-ро бо суроғаи дигар менависанд. 6. error-и ҷавобро намесанҷанд ва намефаҳманд, чаро ором ҳеҷ чиз нарасид.

05 Админ-панел: омор ва идоракунии сабтҳо

Админ-панел — бахши пӯшида барои нақши admin (дарси 12) мебошад, ки дар он соҳиб мебинад, корҳо чӣ тавр мераванд ва сабтҳои ҳамаи корбаронро идора мекунад. Барои лоиҳаи таълимӣ дар он ду блок аст: омор (якчанд рақам ва диаграммаи оддӣ) ва ҷадвали сабтҳо бо ҳамон ҷустуҷӯ, филтрҳо ва саҳифабандие, ки шумо аллакай сохтаед, ва илова бар он амалҳо: ҳолатро иваз кардан, файлро дидан, нест кардан.

Омор: чиро ҳисоб кардан лозим

  • Ҳамагӣ сабтҳо ва аз рӯи ҳолатҳо: барои ҳар ҳолат як дархост бо { count: "exact", head: true } (дархостҳоро якҷоя тавассути Promise.all оғоз мекунанд).
  • Нав дар давра: ҳамон дархостҳо бо шарти .gte("created_at", санаиОғоз).
  • Шумораи корбарон ва аз рӯи нақшҳо: ҳисоб кардани сатрҳои ҷадвали profiles.
  • Диаграмма бе китобхонаҳо: навор бо паҳно дар фоизи шумораи умумӣ. Пайваст кардани китобхонаи графикҳо дар ин спринт лозим нест.
  • Барои ҳисобҳои мураккаб (аз рӯи рӯзҳо, аз рӯи категорияҳо) ИИ метавонад намоиши SQL (view) пешниҳод кунад. Барои он дар Postgres 15+ параметри security_invoker = true лозим аст, вагарна намоиш RLS-ро давр мезанад. Агар боварӣ надошта бошед, бо дархостҳои оддӣ ҳисоб кунед.

Се сатҳи ҳимояи админка

СатҳЧӣ мекунадБе он чӣ мешавад
Меню (lib/nav.ts)банди «Админка»-ро танҳо ба admin нишон медиҳадкорбари оддӣ банди зиёдатиро мебинад (нороҳат, аммо даҳшатнок нест)
Саҳифа ва амалҳои серверӣнақшро аз profiles дар сервер месанҷанд; ба бегона 404 мегӯянд ва амалро иҷро намекунандкорбари оддӣ /admin-ро аз рӯи суроға мекушояд ё амалро дастӣ даъват мекунад
Пойгоҳ (RLS ва is_admin())сатрҳо ва файлҳои бегонаро танҳо ба admin медиҳадтавассути API-и Supabase ҳар воридшуда маълумоти бегонаро мехонад ва иваз мекунад

Сатҳи асосӣ охирин аст: менюро ва саҳифаро гузаштан мумкин аст, пойгоҳ бошад ҳар сатрро месанҷад. Secret key-ро «барои админка» истифода набаред: он RLS-ро давр мезанад ва ҳимоя нест мешавад. Сиёсатҳо бо is_admin() кифоя аст, ки шумо барои дархостҳо (дарси 12) ва анбор (бахши 3) аллакай навиштаед.

Идоракунии сабтҳо

  • Ҷадвал ҳамон компоненти рӯйхат ва ҳамон мантиқи searchParams-ро истифода мебарад, ки рӯйхати корбарӣ (истифодаи дубора, на нусхаи код).
  • Иваз кардани ҳолат ва нест кардан бо амалҳои серверӣ иҷро мешаванд, ки дар сатри аввал санҷиши «ин admin аст?» меистад; нест кардан тасдиқ мепурсад.
  • Барои амалҳои администратор журнал фоидаовар аст: сутуни updated_at ё ҷадвали алоҳида. Барои лоиҳаи таълимӣ updated_at кифоя аст.
  • Корбар набояд майдонҳоеро иваз кунад, ки ба администратор тааллуқ доранд (масалан, status). Сиёсати update иваз кардани тамоми сатрро иҷозат медиҳад, барои ҳамин дар ин спринт ҳолатро танҳо тавассути амали серверии админ иваз мекунанд, шакли корбар бошад ин майдонро тамоман надорад. Ҳимояи пурраи сутунҳо — мавзӯи сӯҳбати алоҳида.
Монандӣ аз ҳаёт

Мудири чойхона шабона дафтарро мебинад: чанд чойник фурӯхта шуд (омор), кадом фармоишҳо иҷро нашудаанд (ҷадвал) ва яке аз онҳоро бекор карда метавонад. Ба толор рафтани ӯ шарт нест, аммо дари кабинет баста аст: на танҳо лавҳаи «Ба бегонагон вуруд мамнуъ» (меню), балки қуфл (саҳифа) ва сейф низ ҳаст, ки калидаш танҳо дасти мудир аст (пойгоҳ).

Хатогиҳои маъмули навомӯзон

1. Танҳо менюро ҳимоя карданд: /admin ба ҳама аз рӯи суроға мекушояд. 2. Калиди махфӣ дар админка «то ҳама чиз кор кунад». 3. Омори тахайюлӣ (рақамҳо ба код навишта шудаанд) ба ҷои ҳисоб аз пойгоҳ. 4. Амалҳои серверии админка нақшро намесанҷанд. 5. Нусхаи рӯйхати корбарӣ бо номҳои дигар ба ҷои истифодаи дубора. 6. Админ тасвирҳои бегонаро мебинад, аммо сиёсати select барои анбор барои админ нест. 7. Ҳисоби ҳамаи сабтҳо бе саҳифабандӣ: ҷадвали админ тамоми пойгоҳро якбора боргирӣ мекунад.

ВАЗИФАИ 5.1

Худро санҷед: e-mail ва админка

миёна

Шумо мактубро аз onboarding@resend.dev ба муштарӣ ба суроғаи дигар мефиристед ва хатогии 403 мегиред. Ин чӣ маъно дорад ва чӣ кор кардан лозим?

  1. Калид гум шудааст: калиди нав созед ва ба код гузоред
  2. Бе домени тасдиқшуда Resend танҳо ба суроғаи соҳиби ҳисоб мефиристад: барои вазифа огоҳиномаро ба худатон фиристед, доменро пеш аз оғози воқеӣ пайваст кунед
  3. Тарифи ройгон абадӣ тамом шуд
  4. Мактубҳоро аз браузер фиристодан лозим, на аз сервер

Ин қоидаи хидмат барои фиристандаи озмоишӣ аст. Хатогӣ на дар бораи калид ва на дар бораи код. Огоҳинома ба соҳиб вазифаи спринтро пурра ҳал мекунад.

Тағйирёбандаи RESEND_API_KEY бояд дар куҷо нигоҳ дошта шавад?

  1. Дар коди компонент, то гум нашавад
  2. Дар тағйирёбанда бо префикси NEXT_PUBLIC_
  3. Дар .env.local ва дар тағйирёбандаҳои муҳити Vercel, ном дар .env.example бе қимат
  4. Дар файли README.md

Махфиҳо танҳо дар муҳити сервер зиндагӣ мекунанд. Ҳар чизе, ки префикси NEXT_PUBLIC_ дорад, ба браузер меафтад ва репозиторийро ҳама мебинанд.

Админ-панелро чӣ тавр дуруст ҳимоя кардан лозим?

  1. Нақш дар сервер (саҳифаҳо ва амалҳо) санҷида мешавад, дар пойгоҳ сиёсатҳо бо is_admin() кор мекунанд; меню танҳо бандро пинҳон мекунад
  2. Банди «Админка» дар меню нишон дода намешавад, ин кифоя аст
  3. Дар админка secret key истифода мешавад, то дархостҳо ҳатман гузаранд
  4. Суроғаи /admin содда нашр намешавад

Менюи пинҳон ва суроғаи «махфӣ» ҳимоя намекунанд. Ҳимоя бояд дар ҷое бошад, ки қарор қабул мешавад: дар сервер ва дар пойгоҳ. Secret key RLS-ро давр мезанад ва ҳимояро бартараф мекунад.

06 Блоки ИИ: чӣ тавр маълумот, файлҳо ва админкаро хоҳиш кардан

Қоидаҳои кор бо ИИ дар спринти дуюм

1. Мисли дарси 17: як вазифа = як промпт = як commit, аввал нақша ва «ок»-и шумо, баъд тағйирот. Буриданро дар ин ҷо такрор накунед: шаблонро аз бахши 6-и дарси 17 гиред. 2. Ба агент ҳуҷҷатҳо медиҳед: @AGENTS.md, @docs/SPEC.md, @docs/SCHEMA.md. 3. SQL ва сиёсатҳоро (ҷадвалҳо, RLS, анбор) бо блоки алоҳида хоҳиш кунед, худатон хонед ва иҷро кунед; ИИ онҳоро иҷро намекунад. 4. Дар ҳар вазифа ҳудудҳоро ном баред: кадом файлҳоро даст задан мумкин ва чиро не (махфиҳо, RLS, китобхонаҳои нав). 5. Мувофиқ наомад: аз нав оғоз накунед, матни хатогиро (бе калидҳо) фиристед ва тавсиф кунед, ки чӣ дақиқан нодуруст аст.

Промпти бади спринти 2 чунин менамояд:

Сделай полный CRUD с поиском, загрузкой картинок и админкой со статистикой, чтобы всё работало

Он чор чизи калонро якбора талаб мекунад, ҷадвал, ҳуқуқҳо ва маҳдудиятҳоро ном намебарад. ИИ ҷадвалҳои худашро меандешад, бакетро «то кор кунад» оммавӣ мекунад ва китобхонаи графикҳоро илова менамояд. Промпти хуб яктост ва танг. Мисол барои вазифаи филтрҳо ва саҳифабандӣ (қиматҳоро дар қавсҳои чоркунҷа бо қиматҳои худ иваз кунед). Промптҳоро ба забони русӣ ҳамон тавр истифода баред: онҳо ба модел бо ин забон беҳтар кор мекунанд, ва шумо метавонед онҳоро нусха кунед:

Контекст: проект по правилам @AGENTS.md, ТЗ @docs/SPEC.md, схема @docs/SCHEMA.md. Уже сделано: каркас, вход, роли, форма создания и изменения записей [таблица items]. Страница списка: app/(app)/items/page.tsx. Цель: добавить на страницу списка поиск по полю title, фильтр по status, сортировку (новые, по названию, по цене) и пагинацию по 10 записей. Состояние хранится в адресе страницы (searchParams). Ограничения: 1) сначала короткий план по файлам и жди подтверждения «ок»; 2) запрос к базе делает серверный компонент: ilike, eq, order, range и count; 3) sort принимай только из белого списка [created_at, title, price]; некорректные page и sort заменяй значениями по умолчанию; 4) смена фильтра сбрасывает page на 1; 5) форма поиска и фильтров с методом GET, пагинация обычными ссылками; 6) новые библиотеки не ставь, RLS и схему базы не меняй; 7) пустое состояние «Ничего не найдено» и кнопка «Сбросить». Примеры: адрес /items?q=tea&status=open&sort=title&page=2 показывает вторую страницу найденных открытых записей.   2. Дар Vercel RESEND_API_KEY ва NOTIFY_EMAIL илова нашудаанд ё баъд аз илова кардан деплои нав набуд
  3. Номи бакетро иваз кардан лозим
  4. Дар браузер JavaScript хомӯш аст

.env.local ба Git намеафтад, барои ҳамин сервери Vercel калидҳоро намедонад. Тағйирёбандаҳоро дар Settings → Environment Variables илова кунед ва деплойро аз нав оғоз намоед.

Тасвир бор шуд, роҳ сабт шуд, аммо дар рӯйхат ба ҷои он чоркунҷаи холӣ ва дар журнал хатогӣ дар бораи «hostname is not configured under images». Сабаб чист?

  1. Файл вайрон шудааст
  2. Бакет аз ҳад калон аст
  3. Тасвир тавассути next/image нишон дода мешавад, суроғаи анбор бошад ба images.remotePatterns илова нашудааст: ё онро илова кунед, ё <img>-и оддиро истифода баред
  4. RLS-ро хомӯш кардан лозим

Next.js тасвирҳоро аз суроғаҳое, ки дар танзимот номбар нашудаанд, коркард намекунад. RLS-ро хомӯш кардан лозим нест: ин ба ҳуқуқҳо тааллуқ надорад.

Корбари оддӣ /admin-ро мекушояд ва ҷадвали ҳамаи сабтҳоро мебинад. Чиро санҷидан лозим?

  1. Санҷиши нақшро дар сервери саҳифа ва сиёсатҳои пойгоҳ: шояд дархостҳои лозимӣ бо secret key иҷро мешаванд, сиёсатҳо бошанд ба ҳама иҷозат медиҳанд (using (true))
  2. Ранги тугмаи «Админка»
  3. Андозаи ҳарфи ҷадвал
  4. Номи репозиторий дар GitHub

Ин осебпазирии дастрасӣ аст: нақш дар сервер санҷида намешавад ё пойгоҳ сатрҳои бегонаро медиҳад. Қатъ кунед, вазифаро баргардонед ё ислоҳ кунед, то даме ки қоида ислоҳ нашавад, сайтро нашр накунед.

Бештар хонед: Vercel: Environment Variables, Next.js: компоненти Image (бо забони англисӣ).

Муҳимиятро чӣ тавр баҳо додан

  • critical (3 хол): сенарияи асосиро вайрон мекунад ё маълумоти бегонаро ошкор менамояд: сабт ё файли бегона кушода мешавад, корбари оддӣ админкаро мебинад, дар коди саҳифа махфӣ намоён аст.

  • minor (1 хол): хатогии хурд: матни нодуруст, тугмаи нороҳат, ҳолати холӣ нест.
  • cosmetic (0,5 хол): намуди зоҳирӣ: ҷойивазкунӣ, ранг, мувофиқсозӣ.

Холҳо

  • Холҳо аз рӯи муҳимият барои ҳар хатогии аз ҷониби муаллиф тасдиқшуда (такрорҳо ҳисоб намешаванд).
  • +1 барои репорте, ки дар он ҳама майдонҳо пур шудаанд ва муаллиф хатогиро аз рӯи қадамҳо аз бори аввал такрор кардааст.
  • +2 ба муаллиф барои ҳар хатогии критикӣ ё муҳими ислоҳшуда аз репортҳо то охири дарс (commit бо рақами репорт дар паём).
  • −1 барои «репорт» бе қадамҳо ё бе далел («дар шумо ҳама чиз кор намекунад»).

  • Дар ном гуфта шудааст, ки дақиқан чӣ вайрон аст, бе калимаҳои «кор намекунад» ва «ғалат мекунад»
  • Суроғаи саҳифа ва нақше, ки зери он тест кардам, нишон дода шудаанд
  • Қадамҳо аз рӯи тартиб навишта шудаанд, муаллиф метавонад онҳоро бе савол такрор кунад

  • Ман санҷидам, ки хатогӣ такрор мешавад ва ин такрор нест
ВАЗИФАИ 8.2

Худро санҷед: баг-репортҳо

миёна

Кадом баг-репорт аз ҳама судмандтар аст?

  1. «Сайт ғалат мекунад, ислоҳ кунед»
  2. «Филтр тамоман кор намекунад, хеле бад»
  3. «/items: нақши user. Қадамҳо: 1) /items-ро кушоед; 2) ҳолати open-ро интихоб кунед; 3) «Пеш»-ро зер кунед. Интизор будам: саҳифаи дуюми сабтҳои кушода. Гирифтам: саҳифаи 2 ҳамаи сабтҳоро нишон медиҳад, филтр аз суроға нопадид шуд. Скриншот замима шудааст»
  4. «Тарҳ ба ман маъқул нест»

Репорти сеюм суроға, нақш, қадамҳо, интизорӣ, натиҷа ва далелро медиҳад: муаллиф хатогиро дар як дақиқа такрор мекунад. Боқӣ имкон намедиҳанд, ки чизеро такрор кунед.

Тестер ҳамчун корбари оддӣ ворид шуд ва аз рӯи истиноди рост сабти корбари дигарро кушод. Ин кадом муҳимият аст?

  1. critical: маълумоти бегона ошкор шудааст, инро аввалин бор бояд ислоҳ кард
  2. cosmetic: танҳо намуди зоҳирӣ
  3. minor: нороҳатии хурд
  4. Хатогӣ нест: истинод ахир вуҷуд дорад

Дастрасӣ ба маълумоти бегона — вайронкунии ҳуқуқ дар сатҳи RLS ё коди серверӣ аст. Чунин хатогиҳо ҳамеша critical мебошанд: онҳо бехатариро вайрон мекунанд, на қулайиро.

Ҳангоми санҷидани маҳсули ғайр чиро кардан мумкин нест?

  1. Қиматҳои холӣ ва хеле дарозро ворид кардан
  2. Сканерҳо ва дархостҳои оммавиро оғоз кардан, парол ҷустан ё калидҳои бегонаро ҷустуҷӯ кардан
  3. Сайтро аз телефон кушодан
  4. Файли хеле калонро бор кардан

Бозӣ маҳсулро тавассути интерфейс дар ҳисобҳои озмоишӣ месанҷад. Сканерҳо, ҷустуҷӯи парол ва бор зарар расонида метавонанд ва аз доираи созиш берун мебароянд.

Бештар хонед: GitHub: дар бораи issues (бо забони англисӣ).

09 Вазифаи хонагӣ: админкаи корӣ ва сенарияи асосӣ (ВХ-18)

Лоиҳаро то ҳолате расонед, ки вазифаи асосии он аз аввал то охир иҷро мешавад, админ-панел омори воқеиро нишон медиҳад ва сабтҳоро идора мекунад. Супоридан: ду истинод (репозиторийи GitHub ва сайт дар Vercel). Агар дар дарс натавонистед, вазифаҳои боқимондаро аз бахши 7 анҷом диҳед ва хатогиҳоро аз репортҳо ислоҳ кунед.

Талабот

  • Сенарияи асосӣ: корбар сенарияи асосиро аз docs/SPEC.md аз аввал то охир дар сайти зинда бе таҳрири дастӣ дар пойгоҳ мегузарад.
  • CRUD: сохтан, дидан, тағйир додан ва нест кардани сабти асосӣ, санҷиши маълумот дар сервер, user_id аз сессия, RLS дар ҳамаи фармонҳо (select, insert, update, delete).
  • Рӯйхат: ҷустуҷӯ, ақаллан як филтр, ҷудокунӣ ва саҳифабандӣ, ҳолат дар суроға, партов дар суроға саҳифаро вайрон намекунад.
  • Файлҳо: боркунии тасвир ё файл ба бакети пӯшида, маҳдудияти андоза ва навъ, сиёсатҳо дар storage.objects аз рӯи id-и корбар дар db/, дар ҷадвал роҳ, нишон додан бо истиноди имзошуда. Бакетҳои оммавӣ бо сабт нестанд.
  • E-mail: соҳиб дар бораи сабти нав мактуб мегирад (гиранда танҳо суроғаи шумо), калид танҳо дар .env.local ва Vercel, хатогии мактуб захираро вайрон намекунад.
  • Админ-панел: омори воқеӣ (на камтар аз чор рақам ва диаграммаи ҳолатҳо) ва ҷадвали сабтҳои ҳамаи корбарон бо ҷустуҷӯ, саҳифабандӣ, иваз кардани ҳолат ва нест кардан; дастрасӣ танҳо барои admin дар се сатҳ.
  • Баг-репортҳо: шумо лоиҳаи ғайриро санҷидед ва ақаллан ду репорт аз рӯи шаблон сохтед; на камтар аз ду хатогиро аз репортҳои гирифташуда ислоҳ кардед (дар commit ё дар README рақам нишон дода шудааст).
  • Тартиб: на камтар аз даҳ commit-и нав аз рӯи вазифаҳо, README.md нав шудааст (бахши «Дар спринти 2 чӣ карда шуд ва минбаъд чӣ»), тахтаи docs/SPRINT.md ҷорӣ аст.
  • Махфиҳо: дар репозиторий калидҳо ва паролҳо нестанд, .env.example бе қиматҳо, npm run build мегузарад.

Чӣ кор кардан лозим

  1. Вазифаҳои 1–11-ро аз бахши 7 барои лоиҳаи худ иҷро кунед.
  2. Сенарияи асосиро дар сайти зинда бо ду ҳисоб (оддӣ ва admin) гузаред ва харитаи дастрасии «нақш × экран»-ро боз як бор санҷед.
  3. Хатогиҳоро аз баг-репортҳои гирифташуда ислоҳ кунед, аз critical оғоз карда.
  4. Дар README.md бахши «Дар спринти 2 чӣ карда шуд ва минбаъд чӣ»-ро илова кунед (3–5 банд) ва 2–3 скриншоти сенарияи асосӣ ва админкаро замима намоед (бе маълумоти шахсӣ ва калидҳо).
  5. Истинодҳоро дар зер гузоред ва рӯйхати санҷишро қайд кунед.
Хатогиҳои маъмул дар вазифаи хонагӣ

1. Бакет оммавӣ аст ё сиёсати with check (true). 2. Омори админка тахайюлӣ аст. 3. Рӯйхат тамоми ҷадвалро боргирӣ мекунад, саҳифабандӣ массивро дар браузер мебурад. 4. Калиди почта дар репозиторий ё дар NEXT_PUBLIC_ аст. 5. Дар Vercel тағйирёбандаҳо нестанд: мактубҳо намераванд. 6. /admin ба корбари оддӣ кушода мешавад. 7. Кӯшиши ба муштарӣ мактуб фиристодан ва хатогии 403: дар вазифа мактуб ба соҳиб кифоя аст. 8. Калиди махфӣ дар админка истифода мешавад. 9. Як commit-и азим. 10. Репортҳо бе қадамҳо ва далел.

Чӣ тавр месанҷанд

Санҷанда сайтро мекушояд, сабти ном мекунад, сенарияи асосиро мегузарад, ҷустуҷӯ ва саҳифабандиро бо суроғаҳои «партов» мекӯшад, тасвир бор мекунад (ва файли хеле калонро), /admin ва сабти бегонаро аз номи корбари оддӣ кушодан мекӯшад, сипас репозиторийро меомӯзад: таърихи commit-ҳо, папкаи db/ (сиёсатҳои ҷадвалҳо ва анбор), README.md, набудани махфиҳо, баг-репортҳои шумо. Холҳо: барои сенарияи асосии корӣ, барои ҷустуҷӯ ва саҳифабандӣ, барои кори бехатар бо файлҳо, барои админкаи ҳалол, барои сифати репортҳо ва қобилияти шарҳ додани қарори худ.

Истинод ба сайти нашршударо гузоред (суроғаи намуди https://…vercel.app).

Бештар хонед: Supabase Storage: шарҳи умумӣ, Resend: ҳуҷҷатгузорӣ (бо забони англисӣ).

✓ Варақаи кӯмакии дарс

  • CRUD: чор экран (рӯйхат, сохтан, сабт бо тағйирдиҳӣ, нестсозӣ бо тасдиқ); фармонҳои insert/select/update/delete ва барои ҳар кадом қоидаи RLS; амали серверӣ: корбар, санҷиши маълумот, дархост, санҷиши error, revalidatePath. user_id-ро сервер мегузорад.
  • Рӯйхатҳо: ҳолат дар суроға (q, status, sort, page); дархост дар сервер бо ilike, eq, order, range, count; range(from, to) ҳар ду ҳудудро дохил мекунад; ҷудокунӣ аз рӯи рӯйхати сафед; иваз кардани филтр саҳифаро бозмегардонад.
  • Storage: бакет пешфарз пӯшида аст, лимити андоза ва навъҳо дар танзимоти бакет; роҳи {user_id}/{номи тасодуфӣ}.{ext}; сиёсатҳо дар storage.objects тавассути storage.foldername(name) ва auth.uid(); дар ҷадвал роҳ; нишон додан тавассути createSignedUrl. Бакетро бо сабти оммавӣ намесозанд.
  • E-mail: танҳо аз сервер; Resend, RESEND_API_KEY ва NOTIFY_EMAIL дар .env.local ва Vercel; бе домени тасдиқшуда мактубҳо танҳо ба суроғаи ҳисоб мераванд (вагарна 403), барои ВХ ин кифоя аст; хатогии мактуб захираро вайрон намекунад.
  • Админка: омор аз рӯи дархостҳои воқеӣ (count: "exact", head: true), ҷадвали сабтҳо бо ҳамон филтрҳо; ҳимоя дар се сатҳ: меню, сервер, пойгоҳ (is_admin()); secret key-ро истифода набаред.
  • Маҳсули ғайриро вайрон кун: тест тавассути интерфейс дар ҳисобҳои озмоишӣ; як баг — як репорт (ном, муҳимият, дар куҷо, қадамҳо, интизор будам, гирифтам, муҳит, далел); critical = ошкор шудани маълумот ё вайрон шудани сенарияи асосӣ.
  • Тартиб: як вазифа = як промпт = як commit; пеш аз commit npm run build, санҷиш дар браузер, хондани diff бе махфиҳо.

  • Метавонам шарҳ диҳам, ки барои CRUD кадом экранҳо, фармонҳои пойгоҳ ва қоидаҳои RLS лозиманд

  • Метавонам шарҳ диҳам, ки чаро бе домени худӣ мактубҳо танҳо ба суроғаи ман мераванд ва фиристодан аз серверро пайваст кунам
  • Метавонам админ-панел бо омор созам ва онро дар се сатҳ ҳимоя кунам
