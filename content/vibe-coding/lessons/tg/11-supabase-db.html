Supabase: пойгоҳи додаи худӣ дар як дарс

То охири дарс маълумоти сайти шумо дар пойгоҳи додаи воқеӣ нигоҳ дошта мешавад: шакли брон дархостҳоро ба ҷадвали Supabase (Postgres) захира мекунад ва ҷадвали оддии админ онҳоро ба соҳиби сайт нишон медиҳад. Шумо нақшаи пойгоҳро то як сатри код дар коғаз мекашед, ҳифзи RLS-ро фаъол мекунед ва дақиқ медонед, ки кадом калидро ба браузер нишон додан мумкин аст ва кадомро ба ҳеҷ кас.

  • Фаҳмонед, ки пойгоҳи дода, ҷадвал, сатр, майдон, калиди аввалӣ ва калиди беруна чист ва нақшаи ду ҷадвали алоқаманд кашед
  • Лоиҳаи Supabase ва ҷадвалро дар Table Editor эҷод кунед, SQL-ро дар SQL Editor иҷро кунед
  • Дархостҳои select, insert, update, delete-ро бихонед ва бигӯед, ки онҳо бо ҷадвал чӣ мекунанд
  • RLS-ро фаъол кунед ва қоида (policy) нависед, ки ба шакл танҳо илова кардани дархостҳоро иҷозат медиҳад
  • Калидҳои publishable (anon) ва secret (service_role)-ро фарқ кунед ва онҳоро танҳо дар .env.local ва дар тағйирёбандаҳои Vercel нигоҳ доред
  • Маълумоти шаклро ба пойгоҳ захира кунед ва дар ҷадвали админ дар сервер нишон диҳед; Supabase ва Firebase-ро муқоиса кунед
Ин дарсро чӣ тавр гузаштан лозим

Лозим мешавад: Cursor, лоиҳаи Next.js ва шакл аз дарсҳои 7–9, дархостҳо ва .env.local аз дарси 10, ҳисоби GitHub (бо он ба Supabase даромадан қулай аст). Вақт: 3–4 соат. Дарсро дар нимаи экран кушоед, Cursor ва панели Supabase-ро дар нимаи дигар. Назарияро (бахшҳои 1–5) қисм-қисм хонед: SQL-ро дар браузери дарс иҷро кардан мумкин нест, барои ҳамин дархостҳоро дар ҷадвалҳои намуна таҳлил мекунед ва бо монандӣ бо массивҳои JavaScript машқ мекунед. Амалиётро (бахши 7) дар як нишаст иҷро кунед: охир шумо шакле доред, ки ба пойгоҳи воқеӣ менависад.

01 Пойгоҳи дода: ҷадвалҳо, майдонҳо ва алоқаҳо

То ҳол маълумоти сайти шумо дар код (массиви хидматҳо) ё дар браузери меҳмон нигоҳ дошта мешуд. Варақро пӯшед, ва он чи ворид шуда буд, нопадид мешавад, соҳиби тарабхона бошад, чизеро намебинад. Барои он ки дархостҳо захира шаванд ва баъд аз ҳар дастгоҳ хонда шаванд, пойгоҳи дода (ПД) лозим аст: барномае дар сервер, ки маълумотро боэътимод нигоҳ медорад ва метавонад зуд ҷустуҷӯ кунад, илова кунад, тағйир диҳад ва нест кунад.

Аксар вақт пойгоҳ ҳамчун маҷмӯи ҷадвалҳо сохта мешавад, ки ба варақҳои Excel монанданд. Чунин пойгоҳҳоро реляционӣ меноманд (аз relation: алоқа), чунки ҷадвалҳоро байни ҳам алоқаманд кардан мумкин аст.

Ҷадвал
Маҷмӯи сабтҳои ҳамҷинс: «дархостҳо», «мизҳо», «корбарон». Номи ҷадвал одатан бо шакли ҷамъ ва бо ҳарфҳои лотинӣ навишта мешавад: bookings.
Сутун (майдон)
Як намуди маълумот ва навъи он: name — матн, guests — адади бутун, booking_at — сана ва вақт.
Сатр (сабт)
Як дархости пурра: ном, телефон, шумораи меҳмонон ва ғайра.
Калиди аввалӣ (id)
Рақаме, ки сатрро яктоӣ муайян мекунад. Ду сатр бо як id намешавад. Номҳо ва телефонҳо такрор мешаванд, барои ҳамин сатрро «аз рӯи ном» ҷустан боэътимод нест.
Калиди беруна
Сутуне, ки дар он id-и сатр аз ҷадвали дигар нигоҳ дошта мешавад. Дархост бо ҳамин «медонад», ки ба кадом миз вобаста аст: bookings.table_id ба restaurant_tables.id ишора мекунад.
Алоқаи «як ба бисёр»
Як миз дар бисёр дархостҳо вомехӯрад, аммо дархост як миз дорад. Маъмултарин алоқа.

Алоқаҳо барои чӣ? Бе онҳо ба ҳар дархост навиштан лозим меомад: «Мизи назди тиреза, 4 ҷой». Агар хоҳед мизро ном иваз кунед, садҳо сатрро тағйир додан лозим мешавад. Бо алоқа ном дар як ҷой нигоҳ дошта мешавад, дархостҳо бошанд танҳо ба рақам ишора мекунанд.

Видео бо забони русӣ, тақрибан 6 дақиқа: ПД чист ва барои чӣ лозим аст. Соли 2021 сабт шудааст, аммо асосҳои пойгоҳи дода тағйир намеёбанд. Дар бораи Supabase дар он чизе нест, он барои тасвири умумӣ лозим аст.

Нақшаро то код мекашем

Одати асосии ин дарс: аввал нақша дар варақ ё тахта, баъд код. Қаламро гиред ва ба се савол ҷавоб диҳед: «Сайт кадом чизҳоро нигоҳ медорад?» (ин ҷадвалҳо), «Дар бораи ҳар кадоме чӣ донистан лозим?» (сутунҳо), «Кӣ ба кӣ ишора мекунад?» (тирҳо). Панҷ дақиқа кашидан соатҳо аз навнависиро сарфа мекунад, AI бошад аз рӯи нақшаи фаҳмо ҷадвалҳоро қариб бе хато месозад.

Монандӣ аз ҳаёт

Дафтари маъмури чойхона. Дар як саҳифа рӯйхати мизҳо: рақам, ном, шумораи ҷойҳо. Дар саҳифаи дигар китоби дархостҳо: номи меҳмон, телефон, вақт ва рақами миз. Рақами миз дар китоби дархостҳо калиди берунаст. Номи «Мизи назди тиреза» як бор навишта шудааст, дар дархостҳо бошад танҳо рақам.

Хатогиҳои маъмули навомӯзон

1. Ҳамаро дар як ҷадвал нигоҳ доштан ва номи мизро ба ҳар сатр нусха кардан: хатои имлоӣ дар як нусха, ва маълумот аз ҳам мехезад. 2. Ном ҳамчун калид истифода бурдан: ду Фирдавс, ва пойгоҳ онҳоро омехта мекунад. 3. Якчанд қиматро дар як сутун гузоштан («миз 3, миз 4»). 4. Санаро ҳамчун матни «фардо шом» нигоҳ доштан: рӯи он ҷудо кардан ва ҷустуҷӯ кардан мумкин нест, барои ин навъи «сана ва вақт» ҳаст. 5. Код навиштан бе кашидани нақша ва баъд ҷадвалҳоро ба интерфейси тайёр иваз кардан.

  2. Номҳоро дар пойгоҳ нигоҳ доштан мумкин нест
  3. Пойгоҳ бо матн кор карда наметавонад
  4. Ин тарз воридкунӣ дар шакл зудтар аст

Калиди аввалӣ барои он аст, ки як сатрро яктоӣ ном баред: дақиқ ҳамонро иваз кунед ё нест кунед, на ҳамаи ҳамном-ҳоро.

  2. Ном дар браузери меҳмон нигоҳ дошта мешавад
  3. Ном дар ҷадвали мизҳост, дархостҳо бошад тавассути table_id ба миз ишора мекунанд
  4. Ном дар .env.local аст

Маънои алоқаҳо ҳамин аст: маълумот як бор нигоҳ дошта мешавад, ҷадвалҳои дигар бо калид ба он ишора мекунанд.

02 Supabase: Postgres-и воқеӣ бе сервери худӣ

Postgres (PostgreSQL) — яке аз маъмултарин ва боэътимодтарин пойгоҳҳои додаи реляционӣ дар ҷаҳон. Танзими сервер, навсозиҳо ва нусхаҳои эҳтиётиро навомӯз лозим нест: Supabase Postgres-ро барои шумо дар абр мегузаронад ва болои он чизҳои қулай илова мекунад: панели веб, интерфейси барномавии (API) тайёр барои ҳар ҷадвал, воридшавӣ (дарси 12) ва анбори файлҳо. Яъне шумо дар код менависед supabase.from("bookings").insert(…), Supabase бошад инро ба дархости пойгоҳ табдил медиҳад.

Ду қисми панел: Table Editor ва SQL Editor

Дар панели лоиҳа аз чап Table Editor ҳаст: ин «Excel»-и пойгоҳи шумост. Ҷадвалҳо бо тугма сохта мешаванд, сатрҳо дарҳол намоён, ҳуҷайраҳоро бо мушак таҳрир кардан мумкин. Ва SQL Editor ҳаст: майдоне, ки матни дархостҳоро ба забони SQL гузошта, Run-ро пахш мекунанд. Барои ҷадвалҳои таълимӣ дуюм қулайтар аст: дархостро нигоҳ доштан, ба чат нусха кардан ва дар лоиҳаи дигар такрор кардан мумкин аст.

Нархномаи ройгон ва «як лоиҳа барои тамоми курс»

Нархномаи ройгон барои тамоми курс кифоя аст. Тибқи саҳифаи нархномаҳои Supabase (дар моҳи октябри соли 2026 санҷида шудааст) дар он: то 2 лоиҳаи фаъол, пойгоҳ то 500 МБ, то 5 ГБ трафик дар як моҳ, то 50 000 корбари фаъол дар як моҳ. Барои шумо муҳим: лоиҳаҳои ройгон баъд аз як ҳафта бе фаъолият ба таваққуф гузошта мешаванд. Таваққуф маълумотро нест намекунад: дар панел барқарорсозиро пахш мекунед, ва лоиҳа бедор мешавад, аммо баъд аз таваққуф сайт муддате кор намекунад. Нусхаҳои эҳтиётии худкор дар нархномаи ройгон нест.

  • Як лоиҳа барои тамоми курс созед. Барои вазифаҳои хонагии 11–15 дар он ҷадвалҳои гуногун бо номҳои фаҳмо созед (bookings, restaurant_tables, баъдтар chat_messages ва дигарон), на лоиҳаҳои нав: лоиҳаи дуюм лимити «2 фаъол»-ро пур мекунад.
  • Лимитҳо ва шартҳо тағйир меёбанд: рақамҳои аслиро дар саҳифаи нархномаҳо бинед. Агар лоиҳа ба таваққуф рафт, панелро кушоед ва онро барқарор кунед.
  • Рамзи пойгоҳ, ки ҳангоми сохтани лоиҳа таъин мекунед, дар менеҷери рамзҳо нигоҳ доред. Он ба Git ва чатҳо намеафтад.
Монандӣ аз ҳаёт

Анбор дар бозор. Пойгоҳи худӣ дар сервери худӣ — гӯё анборро худатон месозед: деворҳо, посбон, қуфлҳо. Supabase — гӯё бахши тайёрро иҷора мегиред: калидро медиҳанд, посбонро ба ҷои шумо киро мекунанд, аммо чӣ нигоҳ доштан ва ба кӣ дарро кушодан — шумо ҳал мекунед. Бахшро пӯшидан фаромӯш кунед (RLS), ва молро мебароранд.

Хатогиҳои маъмули навомӯзон

1. Барои ҳар вазифа лоиҳаи нав сохтан ва ба лимити ду лоиҳаи фаъол расидан. 2. Рамзи пойгоҳро гум кардан: барои кори сайт лозим нест, аммо барои пайвастшавии мустақим лозим аст, дар менеҷери рамзҳо нигоҳ доред. 3. Ҳайрон шудан, ки сайт баъд аз як ҳафта «вайрон шуд»: лоиҳа дар таваққуф аст, дар панел барқарор кунед. 4. Маълумоти шиносномаи бегонагон ва маълумоти пардохтиро дар пойгоҳи ройгон нигоҳ доштан: дар лоиҳаҳои таълимӣ танҳо маълумоти фарзӣ ё ҳадди ақал. 5. Ҳангоми сохтани лоиҳа минтақаи дур интихоб кардан: дархостҳо суст мешаванд, наздиктаринро аз пешниҳодшуда интихоб кунед.

03 Ҳадди ақали SQL: чор амал бо ҷадвал (CRUD)

SQL — забоне, ки бо пойгоҳи реляционӣ гап мезананд. Онро пурра омӯхтан лозим нест: ҳар барнома ба чор амал мерасад, ки онҳоро CRUD меноманд: Create (эҷод кардан), Read (хондан), Update (тағйир додан), Delete (нест кардан). AI дархостҳоро ба ҷои шумо менависад, аммо шумо бояд онҳоро хонед ва бифаҳмед, ки онҳо чӣ мекунанд, алалхусус бо маълумоти мизоҷон.

АмалSQLДар коди сайт (supabase-js)
Createinsert into.from("bookings").insert({…})
Readselect.from("bookings").select("*")
Updateupdate … set … where.update({…}).eq("id", 2)
Deletedelete from … where.delete().eq("id", 2)

Ҷадвал месозем

create table bookings (
  id bigint generated always as identity primary key,
  created_at timestamptz not null default now(),
  name text not null,
  phone text not null,
  guests int not null,
  status text not null default 'new'
);

Қариб мисли забони одамӣ мехонад: «ҷадвали bookings-ро созед; id — адади бузурги бутун, ки пойгоҳ худаш рақам мегузорад ва ин калиди аввалӣ аст; created_at — сана ва вақт, бо нобаёнӣ «ҳозир»; name, phone — матн, ҳатмӣ (not null); status бо нобаёнӣ 'new'».

Мехонем, илова мекунем, тағйир медиҳем, нест мекунем

-- Create: добавить строку
insert into bookings (name, phone, guests)
values ('Мадина', '+992900000001', 2);

-- Read: прочитать
select * from bookings;                                -- все строки, все столбцы
select name, guests from bookings                      -- только два столбца
where status = 'new' and guests >= 4                   -- фильтр
order by created_at desc                               -- сначала новые
limit 10;                                              -- не больше 10 строк

-- Update: изменить (where обязателен!)
update bookings set status = 'confirmed' where id = 2;

-- Delete: удалить (where обязателен!)
delete from bookings where id = 2;

Қиматҳои матниро дар SQL дар нохунакҳои ягона менависанд. Калимаи where барои «кадом сатрҳо» ҷавобгар аст. Ситора * маънои «ҳамаи сутунҳо»-ро дорад. Барои дар хотир доштани тартиб, дархостро мисли ҷумла бихонед: интихоб кардан (select) чиро, аз (from) кадом ҷадвал, ки (where) шарт иҷро мешавад, мураттаб кардан (order by), маҳдуд кардан (limit).

update ва delete-и хатарнок бе where

delete from bookings; бе where ҳамаи сатрҳои ҷадвалро нест мекунад, update bookings set status = 'cancelled'; бошад ҳамаи дархостҳоро бекор мекунад. Нусхаҳои эҳтиётӣ дар нархномаи ройгон нест. Пеш аз update ва delete аввал ҳамон дархостро бо select иҷро кунед ва бубинед, кадом сатрҳо ба шарт мувофиқанд. Аз AI хоҳиш кунед, ки чунин дархостҳоро бо where нависад ва нишон диҳад, чанд сатр тағйир ёфт.

04 Бехатарӣ: RLS ва ду намуди калид

Қоидаи асосии дарс

Суроғаи лоиҳа ва калиди publishable дар рамзи саҳифа ҳастанд, ҳар меҳмон метавонад онҳоро бубинад. Агар барои ҷадвал RLS фаъол нашуда бошад ва қоидаҳо навишта нашуда бошанд, бо чунин калид маълумотро аз консоли браузер мустақиман хондан, иваз кардан ё нест кардан мумкин аст. RLS-и хомӯшкардашуда ё фаромӯшшуда — маъмултарин сӯрохӣ дар лоиҳаҳоест, ки «бо вайб» ҷамъ шудаанд. Онро ҳамеша, дар ҳар ҷадвал, аз дақиқаи аввал фаъол кардан лозим аст.

RLS бо суханони оддӣ чист

RLS (Row Level Security, ҳифз дар сатҳи сатрҳо) — санҷиши дар Postgres сохташуда: пеш аз ҳар дархост пойгоҳ мепурсад «ин меҳмон метавонад?» ва ба рӯйхати қоидаҳои шумо (policy) менигарад. Қоидаи мувофиқ нест — дархост рад карда мешавад.

  • RLS-ро фаъол кардед ва як қоида ҳам нанавиштед: тавассути API бо калиди publishable ҷадвал пурра баста аст (тибқи ҳуҷҷатҳои Supabase). Ин оғози бехатар аст.
  • Ҳар қоида ба як амал (select, insert, update, delete) ва ба як нақш дахл дорад. Меҳмони бе воридшавӣ — нақши anon, корбари даромада (дарси 12) — authenticated.
  • Шарти using ҷавоб медиҳад «кадом сатрҳои мавҷударо дидан ё тағйир додан мумкин», шарти with check — «кадом сатрҳои навро сабт кардан мумкин».
alter table bookings enable row level security;

grant insert on table bookings to anon;

create policy "anon can create bookings"
on bookings for insert
to anon
with check (
  status = 'new'
  and guests between 1 and 20
  and char_length(name) between 2 and 80
);

Дар ин ҷо чӣ рӯй медиҳад. Сатри якум RLS-ро фаъол мекунад. grant insert ба нақши anon худи имкони ба ҷадвал барои илова муроҷиат карданро медиҳад (бе он шумо хатои 42501-ро мегиред, ва ин қабати алоҳидаи ҳифз пеш аз қоидаҳост). Қоида ба шакл иҷозат медиҳад, ки танҳо сатри бо статуси new, шумораи оқилонаи меҳмонон ва дарозии муқаррарии ном илова кунад. Меҳмони бе воридшавӣ дархостҳоро хонда наметавонад: қоидаи select нест. Рӯйхати дархостҳоро танҳо коди сервери шумо мебинад (бахши 7).

Монандӣ аз ҳаёт

Тарабхона. Калиди publishable — калиди дари даромад барои меҳмонон: меҳмон дохил шуда фармоиш дода метавонад (insert), аммо ба қуттии пул ва ба баҳисобгирӣ роҳ намедиҳанд. Қоидаҳои RLS — посбонест, ки ҳал мекунад меҳмон ба куҷо рафта метавонад. Калиди secret — калиди асосии ҳамаи дарҳо, аз ҷумла қуттии пул ва сейф: он танҳо дар дасти соҳиб аст, на дар девори толор овезон.

Хатогиҳои маъмули навомӯзон

1. Ҷадвалро дар SQL Editor сохтан ва RLS-ро фаъол накардан: ҷадвалҳое, ки бо дархост сохта шудаанд, худатон бояд ҳифз кунед (ҷадвалҳои бо тугма дар панел сохташуда RLS-ро бо нобаёнӣ мегиранд, аммо санҷед). 2. Барои select дар ҷадвали дархостҳо қоидаи using (true) навиштан: ин тавр телефонҳои меҳмононро ҳар меҳмон мебинад. 3. RLS-ро «то кор кунад» хомӯш кардан: вақте дархост намегузарад, бояд қоида илова кард, на қуфлро бардошт. 4. Калиди secret-ро ба NEXT_PUBLIC_…, ба компоненти мизоҷӣ ё ба репозиторияи ҷамъиятӣ гузоштан. 5. Калидро ба чат фиристодан ё дар скриншот нишон додан. Агар калид ошкор шуд, дарҳол онро дар панел нест кунед ва нав созед: то калид зинда аст, ҳар касе, ки онро нусха кардааст, метавонад аз он истифода барад.

миёна

Шумо ҷадвал сохтед ва RLS-ро фаъол накардед. Бо донистани суроғаи лоиҳа ва калиди publishable аз рамзи сайт, бо он чӣ кардан мумкин?

Калиди publishable-ро дар рамзи саҳифа ёфтан мумкин аст, барои ҳамин ҳифзро махфии калид не, балки RLS ва қоидаҳо таъмин мекунанд. Бе онҳо ҷадвал барои ҳар касе, ки ин калидро дорад, кушода аст. Пойгоҳҳои лоиҳаҳои вайбкод маҳз ҳамин тавр ошкор мешаванд.

  2. Хатои ҷамъкунии Next.js
  3. Ҳеҷ чиз: маълумот то сохтани қоидаҳо дастнорас аст (дар ҷавоб рӯйхати холӣ ё хатои дастрасӣ)
  4. Танҳо сатри якумро

  4. Дархостҳоро дар сервер бо калиди secret хондан

Хондани кушода телефонҳоро ба ҳама медиҳад, RLS-и хомӯшшуда бошад ҷадвалро пурра мекушояд. Бехатар: қоидаи танг барои илова ва хондан дар сервер.

07 Амалиёт: дархостҳо ба пойгоҳ захира мешаванд

Сайти тарабхонаро мегирем (ҳама версияи шумо: шакли брон аз дарсҳои 8–9 ё нав) ва ба он пойгоҳро мепайвандем. Тартиб: нақша → лоиҳа → ҷадвалҳо ва RLS → калидҳо → шакл → ҷадвали админ → санҷиш → деплой.

Қадам ба қадам

  1. Нақша дар коғаз. Дар варақ ё тахта ду ҷадвал ва тирро кашед, мисли нақша аз бахши 1: restaurant_tables ва bookings, дар ҳар сутун навъаш. Барои худатон акс гиред. Бо се савол санҷед: дар ҳар ҷадвал id ҳаст? Сутуне бо якчанд қимат нест? Тир ба куҷо меравад?
  2. Лоиҳаи Supabase созед. Ба supabase.com равед (воридшавӣ тавассути GitHub қулай аст), лоиҳа созед: ном (масалан mfs-course), рамзи пойгоҳ (ба менеҷери рамзҳо), минтақаи ба шумо наздиктарин. Интизор шавед, ки лоиҳа бархезад. Ин ягона лоиҳа барои тамоми курс аст.
  3. Ҷадвалҳо ва RLS. SQL Editor-ро кушоед ва SQL-ро аз блоки поён гузоред, Run-ро пахш кунед. Натиҷа: «Success». Баъд дар Table Editor боварӣ ҳосил кунед, ки ҳар ду ҷадвал ҳастанд ва бо RLS enabled қайд шудаанд.
  4. Калидҳо дар .env.local. Дар панел Settings → API Keys (ё тирезаи Connect)-ро кушоед: суроғаи лоиҳа, publishable key ва secret key-ро нусха кунед. Дар решаи лоиҳа .env.local-ро созед ё бо се тағйирёбандаи бахши 4 пурра кунед. Санҷед, ки .env.local дар .gitignore ҳаст (git check-ignore -v .env.local, дарси 10). npm run dev-ро аз нав оғоз кунед.
  5. Шакл ва клиент. Пакетро насб кунед: npm install @supabase/supabase-js. Ба AI промпти хубро аз бахши 6 фиристед (дар реҷаи «Нақша», дарси 6) ва тағйиротро қадам ба қадам татбиқ кунед. Шаклро кушоед, дархостро бо маълумоти фарзӣ фиристед: «дархост қабул шуд» пайдо шуд?
  6. Пойгоҳро санҷед. Дар Table Editor bookings-ро кушоед: сатри нав ҳаст? status чӣ аст, created_at пур шудааст?
  7. Ҷадвали админ. /admin-ро кушоед: ҳамаи дархостҳо намоёнанд, навҳо дар боло. Аз AI хоҳиш кунед фаҳмонад, ки чаро саҳифа серверӣ аст ва чаро дар ин ҷо калиди secret лозим аст.
  8. Санҷиши ҳифз. Муваққатан ба дохили async-коркарди шакл console.log(await supabase.from("bookings").select())-ро илова кунед, шаклро фиристед ва консоли браузерро кушоед (дарси 10): бояд рӯйхати холӣ ё хатои дастрасӣ (permission denied, рамзи 42501) бошад. Агар дархостҳои бегонаро бинед, ҳифз сӯрохӣ дорад: ба бахши 4 баргардед. console.log-и муваққатиро нест кунед.
  9. Деплой. Кодро commit кунед ва ба GitHub фиристед. Дар Vercel се тағйирёбандаро дар Settings → Environment Variables илова кунед, Redeploy кунед (дарси 10). Дархости санҷиширо дар сайти …vercel.app фиристед ва онро дар Table Editor ёбед.
  10. Шарҳ. Бо суханони худатон бигӯед (ё аз AI пурсед ва такрор кунед): кадом ду калид ҳаст, кадомаш ба куҷо мумкин аст, қоидаи шумо чӣ мекунад, чаро /admin дар сервер мехонад.

create table bookings (

08 Фишкаи дарс: «Нақша дар тахта» ва шикори сӯрохӣ

Аввал нақша, баъд код — одатест, ки онро дар бозӣ беҳтар машқ кардан мумкин аст. Блок барои омӯзгор ҳисоб шудааст ва дар аудитория ё онлайн гузаронида мешавад (тахтаи умумӣ, масалан Miro, ё танҳо коғаз ва акс). Вақт: тақрибан 50 дақиқа.

Қоидаҳо

1. Омӯзгор ҳолати ҳаётиро ном мебарад: сартарошхона бо сабт, мактаби рақс, такси, анбор, китобхона. Як ҳолат барои тамоми гурӯҳ ё ҳар ҷуфт ҳолати худ. 2. Иштирокчиён дар ҷуфтҳо кор мекунанд. 10 дақиқа: нақшаи пойгоҳро кашед (ҷадвалҳо, сутунҳо бо навъҳо, тирҳои алоқа), компютер хомӯш. 3. 5 дақиқа: ҷуфтҳо нақшаҳоро иваз мекунанд ва нақшаи бегонаро бо рӯйхати санҷиши поён месанҷанд. 4. 15 дақиқа: муаллиф аз AI хоҳиш мекунад, ки нақшаро ба SQL табдил диҳад (нақшаро бо матн нақл мекунад, мисли промпти бахши 6) ва натиҷаро бо расм муқоиса мекунад. 5. Ҳар using (true), ки AI дар ҷадвал бо маълумоти шахсӣ додааст — сабаби «аҳ-ҳа»-и умумӣ: кӣ ёфт, як хол мегирад.

Рӯйхати санҷиши нақшаи бегона

  • Дар ҳар ҷадвал калиди аввалии id ҳаст.
  • Сутунҳое нестанд, ки дар онҳо якбора якчанд қимат бошад.
  • Алоқаҳо бо тирҳо нишон дода шудаанд ва маълум аст, кадом ҷадвал «як» аст, кадомаш «бисёр».
  • Навъ оқилона интихоб шудааст: санаҳо — на матн, пул — адад, статус — матни кӯтоҳ аз рӯйхат.
  • Барои ҳар ҷадвал навишта шудааст, ки кӣ хонда метавонад ва кӣ илова карда метавонад (қоидаҳои ояндаи RLS).
  • Дар мисолҳо маълумоти шахсии воқеӣ нест.

09 Вазифаи хонагӣ: сайти тарабхона бо брони миз (ВХ-11)

Сайти тарабхонаро (фарзӣ ё ҳар муассисаи дигар бо сабт) ба ҳолате расонед, ки дархостҳои брони миз ба пойгоҳи Supabase захира шаванд. Супоридан: ду истинод (репозиторияи GitHub ва сайт дар Vercel).

Талабот

  • Нақша: то код дар коғаз кашида шудааст, дар README.md-и репозитория нусхаи матнии он ҳаст (ҷадвалҳо, сутунҳо, алоқаҳо). Ҳадди аққал ду ҷадвали алоқаманд (масалан restaurant_tables ва bookings бо table_id).
  • Як лоиҳаи Supabase барои тамоми курс; ҷадвалҳо бо номи фаҳмо, то баъдтар дар он дигарон низ зиндагӣ кунанд.
  • RLS дар ҳамаи ҷадвалҳо фаъол аст. Меҳмони бе воридшавӣ танҳо дархост илова карда метавонад (бо санҷиши маълумот дар қоида ё маҳдудиятҳо) ва маълумоти ҷамъиятиро (рӯйхати мизҳо) хонда метавонад. Дархостҳоро бо калиди publishable хонда намешавад.
  • Шакли брон: санҷиши майдонҳо дар саҳифа (дарси 8), ҳолатҳои фаҳмои «фиристода мешавад», «дархост қабул шуд», «хато», маълумот ба bookings меафтад. Миз аз рӯйхати аз пойгоҳ боршуда интихоб мешавад.
  • Ҷадвали админ /admin: саҳифаи серверӣ, дархостҳоро бо калиди secret мехонад, навҳо дар боло; аз индексатсия пӯшида (noindex). Ҳоло дар он танҳо маълумоти фарзӣ.
  • Калидҳо: суроға ва publishable key бо NEXT_PUBLIC_, secret танҳо бе он; ҳама дар .env.local ва дар тағйирёбандаҳои Vercel; дар репозитория .env.example бе қиматҳо ҳаст, худи калидҳо ва .env.local на дар код ва на дар таърихи Git нестанд.
  • Сифат: npm run build бе хато; дар сайти Vercel шакл кор мекунад; шумо ҳар сатри SQL ва ҳар қоидаро фаҳмонда метавонед.

Чӣ кор кардан лозим

  1. Аввал нақша дар коғаз, баъд SQL, баъд код (бахши 6 ва амалиёт).
  2. RLS-ро дар ҳамаи ҷадвалҳо фаъол кунед, қоидаҳо нависед ва ҳифзро бо санҷиши консолии қадами 8-и амалиёт санҷед.
  3. Тағйирёбандаҳоро дар Vercel танзим кунед ва Redeploy кунед.
  4. Дар истиноди Vercel дархости санҷиширо бо маълумоти фарзӣ фиристед ва боварӣ ҳосил кунед, ки сатр дар Table Editor ва дар /admin пайдо шуд.
  5. Истинодҳоро дар поён гузоред ва рӯйхати санҷишро қайд кунед.
Хатогиҳои маъмул дар вазифаи хонагӣ

1. RLS хомӯш аст ё танҳо дар як ҷадвал фаъол аст. 2. Қоидаи using (true) дар дархостҳо. 3. Калиди secret дар компоненти мизоҷӣ ё дар NEXT_PUBLIC_…. 4. Калидҳо ё .env.local дар репозиторияи ҷамъиятӣ. 5. Шакл дар компютер кор мекунад, дар Vercel не: тағйирёбандаҳо илова нашудаанд ё Redeploy анҷом нашудааст. 6. Нақша баъд аз код кашида шудааст ва ба он мувофиқ карда шудааст. 7. Дар пойгоҳ телефонҳои воқеии дӯстон. 8. Санҷиши майдонҳо нест: дар ҷадвал дархостҳои холӣ меафтанд.

Чӣ тавр месанҷанд

Санҷанда сайтро мекушояд, дархост мефиристад, /admin-ро мебинад, баъд репозиторияро месанҷад: оё калидҳо дар код ва дар таърих нестанд, .env.example чӣ гуна тартиб дода шудааст, нақша дар README ва SQL чӣ гуна менамоянд. Холҳо барои нақша, барои ҳифз (RLS ва калидҳо), барои шакли кории шумо ва барои он, ки қарори худро фаҳмонда метавонед.

✓ Хулосаи дарс

  • Пойгоҳи дода: ҷадвалҳо аз сатрҳо ва сутунҳо; ҳар ҷадвал калиди аввалии id дорад; калиди беруна id-ро аз ҷадвали дигар нигоҳ медорад (алоқаи «як ба бисёр»).
  • Тартиби кор: нақша дар коғаз → SQL → RLS → код. AI нақшаро ҳамчун матн мегирад.
  • Supabase: Postgres-и абрӣ + панел (Table Editor, SQL Editor) + API. Ройгон: то 2 лоиҳаи фаъол, 500 МБ, таваққуф баъд аз як ҳафта бе фаъолият, бе нусхаҳои эҳтиётии худкор. Як лоиҳа барои тамоми курс.
  • SQL ва CRUD: insert (эҷод), select … where … order by … limit (хондан), update … set … where (тағйир), delete … where (нест кардан). Бе where ҳамаи сатрҳо тағйир меёбанд.
  • RLS: дар ҳар ҷадвал фаъол кунед: alter table … enable row level security. Бе қоидаҳо тавассути API бо калиди publishable ҷадвал баста аст. Қоида: амал + нақш + using / with check. Барои anon боз grant лозим аст. Барои маълумоти шахсӣ using (true) нанависед.
  • Калидҳо: publishable (sb_publishable_…, пештар anon) — дар браузер мумкин, ҳуқуқҳоро RLS маҳдуд мекунад; secret (sb_secret_…, пештар service_role) — аз RLS мегузарад, танҳо дар сервер. Ҳар дуи онҳо дар .env.local ва Vercel, secret бе NEXT_PUBLIC_. Ошкор шуд — нест кунед ва нав созед.
  • Админка: саҳифаи серверӣ, калиди secret, dynamic = "force-dynamic". Бе воридшавӣ он барои ҳама кушода аст (воридшавӣ — дарси 12), барои ҳамин маълумот танҳо фарзӣ.
  • Firebase: пойгоҳи ҳуҷҷатии NoSQL Firestore, коллексияҳо ва ҳуҷҷатҳо, Security Rules; Supabase — Postgres, ҷадвалҳо ва SQL.
  • AI: SQL-ро алоҳида хоҳиш кунед, where, RLS дар ҳамаи ҷадвалҳо, набудани using (true) ва рамзҳои махфиро дар коди мизоҷӣ санҷед; хатоҳоро бо матни пурра бе калидҳо фиристед.
ВАЗИФАИ 10.1

Ман мавзӯъро воқеан фаҳмидам

осон

Танҳо он чиро қайд кунед, ки бе ишора карда метавонед.

  • Метавонам нақшаи ду ҷадвали алоқамандро кашам ва калиди аввалӣ ва берунаро фаҳмонам
  • Метавонам лоиҳаи Supabase, ҷадвал созам ва SQL-ро дар SQL Editor иҷро кунам
  • Метавонам select, insert, update, delete-ро бихонам ва фаҳмонам, бе where чӣ мешавад
  • Метавонам RLS-ро фаъол кунам, қоидаи илова нависам ва санҷам, ки дархостҳоро аз браузер хонда намешавад
  • Метавонам фарқи калидҳои publishable ва secret-ро фаҳмонам ва бигӯям, ҳар якро дар куҷо нигоҳ доштан лозим
  • Метавонам маълумоти шаклро ба пойгоҳ захира кунам ва дар ҷадвали админ дар сервер нишон диҳам
  • Метавонам дар ду ҷумла Supabase ва Firebase-ро муқоиса кунам
