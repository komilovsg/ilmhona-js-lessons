Интерактив: state, рӯйдодҳо, формаҳо

То охири дарс сайти шумо аз «акс» ба барнома мубаддал мешавад: менюи бургер, равзанаи модалӣ, гузаронандаи варақаҳо, мавзӯи торик ва формаи ариза, ки майдонҳоро месанҷад ва хатоҳоро нишон медиҳад, кор мекунанд. Шумо мефаҳмед, ки React чӣ тавр маълумотро «дар хотир нигоҳ медорад» (state), саҳифа ба зеркунӣ ва вуруди матн чӣ тавр вокуниш нишон медиҳад ва ба саволи маъмули баъди дарси 7 ҷавоб медиҳед: сатри "use client" дар аввали файл чист ва чаро бе он useState ва onClick дар Next.js кор намекунанд.

  • Фарқи state-ро аз тағйирёбандаи оддӣ шарҳ додан ва ҳисобкунакро тавассути useState навиштан
  • Handler-ҳои рӯйдодҳоро (onClick, onChange, onSubmit) пайваст кардан ва «додани функсия»-ро аз «даъвати функсия» фарқ кардан
  • Элементҳоро бо рендери шартӣ нишон додан ва пинҳон кардан: меню, равзанаи модалӣ, варақаҳо, паёмҳои хато
  • Формаро бо санҷиши майдонҳо ва экранҳои «боршавӣ, хато, муваффақият» ҷамъ кардан
  • Рӯйхатҳоро дар state бе мутатсия навсозӣ кардан: илова, ҳазф ва филтр кардан, ва дар ин асос сабади мағозаро сохтан
  • Шарҳ додан, ки директиваи "use client" барои чӣ лозим аст, ва онро ба файли дурусти лоиҳаи Next.js гузоштан

01 State: React чӣ тавр маълумотро байни такрорсозиҳо «дар хотир нигоҳ медорад»

Компонентҳои дарси 7 ҳамеша як чизро нишон медоданд. Аммо дар сайти воқеӣ ҳама чиз тағйир меёбад: ҳисобкунаки сабад меафзояд, меню кушода мешавад, дар майдон матн пайдо мешавад. Маълумоте, ки бо мурури замон тағйир меёбад ва ба он чи дар экран дида мешавад таъсир мерасонад, дар React state (ҳолат) номида мешавад. Онро функсияи махсуси хук — useState нигоҳ медорад.

Чаро наметавон тағйирёбандаи оддии let count = 0-ро гирифта афзун кард? Ду сабаб аз ҳуҷҷатҳои React мавҷуд аст. Якум: ҳангоми ҳар як такрорсозӣ функсияи-компонент аз нав даъват мешавад ва тағйирёбандаи оддӣ боз сифр мешавад. Дуюм: тағйири тағйирёбандаи оддӣ ба React хабар намедиҳад, ки экранро навсозӣ кардан лозим аст. Барои ҳамин «сандуқе» лозим аст, ки аз такрорсозиҳо мегузарад ва React-ро бедор карда метавонад.

const [count, setCount] = useState(0);
//     қимат     функсия    қимати
//               барои иваз ибтидоӣ

useState(0) ҷуфтро бармегардонад: қимати ҷорӣ ва функсияи «сеттер», ки онро иваз мекунад. Навишт бо қавсҳои [ ] — деструктуризатсияи массиви аз дарси 7 шинос аст. Номҳо ихтиёрианд, аммо одатан [чӣ, setЧӣ] менависанд. Вақте ки setCount(5)-ро даъват мекунед, React қимати навро ба хотир мегирад, компонентро боз даъват мекунад ва useState ин дафъа 5-ро бармегардонад.

Видеои кӯтоҳ бо забони русӣ (тақрибан 3 дақиқа): ғояи state дар мисоли ҳисобкунак. Он соли 2021 сабт шудааст, аммо худи useState аз он вақт тағйир наёфтааст.

Се қоидае, ки бояд аз ёд донист

  • State-ро танҳо бо сеттер иваз мекунанд. Навишти count = count + 1 ё count++ экранро навсозӣ намекунад. Лозим аст setCount(count + 1).
  • Хукҳоро танҳо дар сатҳи боло компонент даъват мекунанд: на дар дохили if, сикл ва функсияҳои дарунӣ. Хукҳоро аз пешванди use мешиносанд.
  • Ҳар нусхаи компонент state-и худро дорад. Ду тугмаи «Маъқул» дар саҳифа ҳисобро мустақилона меронанд: тавсиф як аст, аммо «сандуқҳо» гуногунанд.

Худатон кӯшиш кунед. Тугмаи поён ҳоло чизеро ҳисоб намекунад. State-и likes-ро эълон кунед, онро дар матни тугма нишон диҳед ва бо зеркунӣ афзун кунед. Блоки «САНҶИШ» худаш тугмаҳоро мезанад ва чӣ ҳосил шуданро чоп мекунад: тугмаи якумро се бор, дуюмро як бор.

Монандӣ аз ҳаёт

State — мисли ҳисоб дар дафтари фурӯшанда дар бозор. Тағйирёбандаи оддӣ — суханонест, ки фурӯшанда дар хотир нигоҳ медорад: бегоҳ фаромӯш шудаанд. Дафтар (state) тамоми рӯзро мегузаронад ва ҳар дафъа, ки фурӯшанда сатри навро менависад (сеттер), натиҷаро дар ҳисобкунак аз нав ҳисоб мекунад (такрорсозӣ). Ду фурӯшанда ду дафтари гуногун доранд: тугмаи якум ҳисоби худро дорад, дуюм — ҳисоби худро.

Хатогиҳои маъмули навомӯзон

1. State-ро бевосита тағйир додан: likes = likes + 1 ё likes++. Экран навсозӣ намешавад. 2. Импортро фаромӯш кардан: useState is not defined, сатри import { useState } from "react" лозим аст. 3. Хукро дар дохили if ё сикл даъват кардан. 4. Интизор шудан, ки қимат дар сатри баъд аз сеттер фавран иваз мешавад: қимати нав дар такрорсозии навбатӣ пайдо мешавад, ва дар даъвати ҷории функсия likes собиқ мемонад. 5. Дар state чизеро нигоҳ доштан, ки онро аз state-и дигар ҳисоб кардан мумкин аст (масалан, алоҳида «нарх» ва «нарх бо тахфиф»): онро дар лаҳзаи лозим ҳисоб кунед.

ВАЗИФАИ 1.2

Худро санҷед: state

осон

Барномасоз дар компонент let count = 0; навишта, дар onClick count = count + 1-ро иҷро мекунад. Чаро рақам дар экран меафзояд?

  1. Зеро тугмаҳо дар React ба зеркунӣ вокуниш нишон дода наметавонанд
  2. Зеро let-ро тағйир додан мумкин нест
  3. Зеро React аз тағйири тағйирёбандаи оддӣ бохабар намешавад ва компонентро аз нав намекашад, ва ҳангоми такрорсозӣ тағйирёбанда боз ба сифр баробар мешуд
  4. Зеро рақамро дар тирнишон навиштан лозим аст

Тағйирёбандаи оддӣ такрорсозиро оғоз намекунад ва аз он намегузарад. Барои маълумоте, ки ба экран таъсир мерасонад, useState лозим аст: сеттер ҳам ба React дар бораи тағйир хабар медиҳад, ҳам қиматро байни даъватҳои компонент нигоҳ медорад.

Дар саҳифа ду компоненти якхелаи <LikeButton /> ҳаст. Корбар ба якумӣ се бор зад. Дуюмӣ чиро нишон медиҳад?

  1. Низ 3-ро, зеро компонент як аст
  2. Ҳисоби худашро, яъне 0: ҳар нусхаи компонент state-и худро дорад
  3. Хатогӣ: ду компоненти якхела дар саҳифа манъ аст
  4. Миёнаи арифметикии ҳамаи тугмаҳо

Коди компонент муштарак аст, аммо state-и ҳар нусха алоҳида аст. Агар ҳисоб муштарак мебуд, онро ба волид «бардоштан» лозим мешуд: ҳангоми сохтани сабад дар ин бора мефаҳмед.

Кадом навишт ҳисобкунакро дуруст меафзояд?

  1. setCount(count + 1)
  2. count = count + 1
  3. count++
  4. useState(count + 1) дар дохили handler-и зеркунӣ

State-ро танҳо тавассути сеттер тағйир додан лозим аст. useState-ро дар дохили handler даъват кардан мумкин нест: хук танҳо дар сатҳи боло компонент кор мекунад.

Бештар хонед: React: state ҳамчун хотираи компонент ва маълумотнома оид ба useState (бо забони англисӣ).

02 Рӯйдодҳо ва рендери шартӣ: меню, равзанаи модалӣ, варақаҳо

Қариб ҳар як интерактив дар сайт омезиши ду усул аст. Рӯйдод («корбар зад») state-ро тағйир медиҳад, ва рендери шартӣ («агар state чунин бошад, инро нишон деҳ») state-ро ба тасвир табдил медиҳад. Менюи бургер, равзанаи модалӣ ва варақаҳо — се варианти як намуна.

Handler-ҳои рӯйдодҳо

Рӯйдодҳо дар JSX ҳамчун атрибутҳо бо camelCase навишта мешаванд: onClick, onChange (вуруд дар майдон), onSubmit (фиристодани форма). Қимат — функсия аст, ки React ҳангоми рух додани рӯйдод онро даъват мекунад. Номи функсияҳои худро одатан бо handle оғоз мекунанд: handleClick.

Дуруст: функсияро медиҳем
  • onClick={handleClick}
  • onClick={() => setOpen(true)}
Нодуруст: фавран даъват мекунем
  • onClick={handleClick()} — ҳангоми кашидани саҳифа иҷро мешавад, на ҳангоми зеркунӣ
  • onClick={setOpen(true)} — ҳамин тавр, ва боз такрорсозии бепоён ҳосил мешавад

Фарқ дар қавсҳои мудаввар аст: handleClick — «ана дастур, ҳангоми лозим иҷро кун», ва handleClick() — «ҳозир иҷро кун». Агар мантиқи кӯтоҳ лозим бошад, функсияи тирдорро бевосита дар атрибут нависед: () => setOpen(!open).

Боз ду усул, ки ба кор меоянд: e.preventDefault() амали пешфарзи браузерро бекор мекунад (форма одатан ҳангоми фиристодан саҳифаро аз нав бор мекунад), ва e.stopPropagation() намегузорад, ки рӯйдод ба волидон «боло равад» (зеркунӣ ба равзана набояд равзанаро тавассути зеркунӣ ба замина пӯшад).

Амалиёти 2: равзанаи модалӣ

ВАЗИФАИ 2.4

Худро санҷед: рӯйдодҳо ва рендери шартӣ

миёна

Саҳифа ҳангоми кушодан фавран паёми «Too many re-renders»-ро нишон медиҳад. Дар код: <button onClick={setOpen(true)}>. Сабаб дар чист?

  1. Лозим аст onClick-ро ба onclick иваз кард
  2. Сеттер ҳангоми кашидан даъват мешавад ба ҷои додани функсия; дуруст — onClick={() => setOpen(true)}
  3. Лозим аст ба тугма key илова кард
  4. Лозим аст setOpen(true);-ро бо нуқтавергул навишт

Қавсҳо баъд аз setOpen функсияро фавран даъват мекунанд. Сеттер state-ро иваз мекунад, React аз нав мекашад, сеттерро боз даъват мекунад ва ҳамин тавр даврӣ меравад. Ба атрибут функсия додан лозим аст, на натиҷаи он.

Дар сабад 0 маҳсулот аст. Навишти {count && <Badge />}, ки дар он count = 0, чиро нишон медиҳад?

  1. Ҳеҷ чизро
  2. Нишонро бо сифр
  3. Хатогиро
  4. Дар экран рақами 0 пайдо мешавад, зеро сифр барои React қимати «холӣ» ҳисоб намешавад

React false, null ва undefined-ро намебарорад, аммо рақами 0-ро мебарорад. Барои ҳамин муқоисаро ошкоро нависед: count > 0 && ….

Варақаҳои «Нархҳо», «Табибон», «Тамос» лозиманд, фаъол ҳамеша дақиқан як аст. Дар state чиро нигоҳ доштан беҳтар аст?

  1. Се қимати алоҳидаи true/false, барои ҳар варақа як
  2. Тамоми матни ҳамаи варақаҳоро
  3. Шиноса (ё рақам)-и варақаи фаъолро дар як state
  4. Ҳеҷ чизро: варақаҳоро бо тағйирёбандаи оддӣ гузаронидан мумкин аст

Як state-и «кадом варақа фаъол аст» наметавонад дар ҳолати зиддиятнок монад. Се парчами алоҳидаро осон аз ҳамоҳангӣ баровардан мумкин аст: ду варақа якбора фаъол мешаванд.

Бештар хонед: React: коркарди рӯйдодҳо ва рендери шартӣ (бо забони англисӣ).

03 Рӯйхатҳо дар state, формаҳо бо санҷиш, боршавӣ ва хатоҳо

Рӯйхатҳо дар state: тағйир надодан, балки массиви нав сохтан

Сабади мағоза, рӯйхати корҳо, мустаҳкамшудаҳо — ин массив дар state аст. Қоидаи асосии React: массивро дар state «дар ҷояш» тағйир додан мумкин нест (усулҳои push, splice, навишти arr[0] = …). Бояд массиви нав сохта, онро ба сеттер дод. Се намуна барои ҳама ҳолатҳо:

АмалЧӣ тавр навиштанҒоя
Илова карданsetCart([...cart, product])Се нуқта унсурҳои кӯҳнаро ба массиви нав «мерезанд», унсури нав дар охир мемонад
Ҳазф карданsetCart(cart.filter((p) => p.id !== id))filter танҳо онҳоеро мемонад, ки барояшон шарт дуруст аст
Яктоашро иваз карданsetItems(items.map((p) => p.id === id ? { ...p, done: true } : p))map ҳамон унсурро ё нусхаи навсозишударо бармегардонад

Филтр аз рӯи категория ҳазф аз state нест, балки ҳисоб аст: рӯйхати маҳсулот пурра мемонад, ва дар экран аз рӯи категорияи интихобшуда products.filter(…) бароварда мешавад. Каталоги мағозаи вазифаи хонагӣ ҳам ҳамин тавр кор мекунад: дар state ду қимат ҳаст (категорияи интихобшуда ва сабад), ва рӯйхат барои экран дар лаҳзаи лозим ҳисоб карда мешавад.

04 Директиваи "use client": чаро state ҳама ҷо кор намекунад

Дар дарси 7 шумо сатри "use client"-ро дар файли форма дида, ваъдаи шарҳи баъдтар гирифтед. Вақти он расид. Гап дар он аст, ки дар Next.js (App Router) компонентҳо ду намуд доранд.

Одатан саҳифаҳо ва макетҳо (page.tsx, layout.tsx) ва ҳар чӣ дар онҳо пайваст аст — компонентҳои серверӣ мебошанд. Ин зуд ва бехатар аст, аммо чунин компонент дар браузер «ҳаёт» надорад: ба зеркунӣ вокуниш нишон додан барояш касе нест, зеро саҳифаи HTML-и тайёр бе ин код омадааст. Барои он ки тугма кор кунад, JavaScript-и он бояд ба браузер расонида шавад. Директива ҳамин корро мекунад.

Видео бо забони англисӣ, субтитрҳоро фаъол кунед (тақрибан 10 дақиқа, 5 дақиқаи аввалро тамошо кунед): директиваро ба куҷо гузоштан лозим аст. Соли 2023 сабт шудааст, аммо қоидаи «директива дар файли интерактивӣ» тағйир наёфтааст.

Директиваро ба куҷо гузоштан лозим аст

  • Дар сатри аввали файл, пеш аз ҳамаи import-ҳо. Онро дар дохили компонент ё функсия гузоштан мумкин нест.
  • Танҳо дар файлҳое, ки бояд аз компонентҳои серверӣ пайваст шаванд ва дар онҳо state, рӯйдодҳо ё API-ҳои браузер ҳастанд. Агар файли BookingForm.tsx аллакай клиентӣ бошад, ҳамаи компонентҳое, ки он пайваст мекунад, низ дар браузер мешаванд: директиваро ба ҳар кадом гузоштан лозим нест.
  • То ҳадди имкон чуқуртар ва хурдтар. Тамоми саҳифаро барои як меню клиентӣ нишон надиҳед: менюро ба компоненти хурди BurgerMenu.tsx бо директива баред, ва саҳифа серверӣ мемонад. Он гоҳ ба браузер JavaScript-и камтар меравад.

Компоненти сервериро тавассути children ба клиентӣ андохтан мумкин аст

Агар равзанаи модалӣ бояд маълумоти дар сервер ҷамъшударо нишон диҳад, онро ҳамчун children дар дохил мегузоранд: дар саҳифа <Modal><Cart /></Modal>. Равзана (компоненти клиентӣ) state-и «кушода»-ро нигоҳ медорад, ва мазмунро боз сервер тайёр мекунад. Барои курс кофист дар хотир дошт, ки ин имконпазир аст, ва агар мазмуни равзана калон бошад, аз AI хоҳиш кард, ки ҳамин тавр кунад.

Агар директиваро фаромӯш кунед, чӣ мебинед

Агар дар файли бе "use client" шумо useState-ро пайваст карда ё onClick гузошта бошед, Next.js ҷамъкуниро қатъ мекунад ё экрани сурхро бо матни тақрибан чунин нишон медиҳад: «You're importing a component that needs useState. This React Hook only works in a Client Component. To fix, mark the file (or its parent) with the "use client" directive.» Ибораи дақиқ аз версия вобаста аст, аммо маъно як аст. Чора — директиваро дар сатри аввали файли лозимӣ гузоштан. Ду хатои хешовандӣ: «Event handlers cannot be passed to Client Component props» (компоненти серверӣ функсияи handler-ро ба клиентӣ додааст: handler-ро дар дохили компоненти клиентӣ сохтан лозим аст) ва window is not defined (код ҳангоми кашидани серверӣ ба объектҳои браузер муроҷиат мекунад: чунин код бояд дар компоненти клиентӣ бошад ва баъд аз пайдо шудани саҳифа дар браузер иҷро шавад).

Монандӣ аз ҳаёт

Компонентҳои серверӣ — мисли палове, ки дар ошхонаи чойхона пухта шудааст: онро ба дастурхон тайёр меоранд, ва меҳмон чизе намепазад. Клиентиҳо — мисли самовар дар сари дастурхон: онро худи меҳмон идора мекунад (об мерезад, кранро мепечонад), барои ҳамин онро ҷисман ба толор овардан лозим аст. Директиваи "use client" — лавҳаи «ин дастгоҳро ба дастурхон бибар». Чӣ қадар дастгоҳҳои камтар дар сари дастурхон бошанд, толор сабуктар аст: барои ҳамин ба толор танҳо самоварро мебаранд, на тамоми ошхонаро.

Хатогиҳои маъмули навомӯзон

1. Директиваро на дар сатри аввал (баъд аз import ё дар дохили функсия) гузоштан: он кор намекунад. 2. Тамоми саҳифаи app/page.tsx-ро «то ҳеҷ чиз вайрон нашавад» клиентӣ нишон додан: сайт бартариҳои кашидани сервериро аз даст медиҳад. 3. Калиди махфӣ ё муроҷиат ба базаро дар компоненти клиентӣ гузоштан: код ба браузер меравад, ва калидро ҳар кас мебинад. Махфиёт танҳо дар коди серверӣ зиндагӣ мекунанд. 4. Директиваро ба ҳар файл пайдарпай илова кардан. 5. Фикр кардан, ки «клиентӣ» маънои «танҳо дар браузер иҷро мешавад»-ро дорад: кашидани аввал боз ҳам дар сервер мегузарад. 6. Аз компоненти серверӣ ба клиентӣ функсияҳо додан: тавассути props танҳо маълумоти оддӣ медиҳанд (матн, рақамҳо, массивҳо, объектҳо).

ВАЗИФАИ 4.1

Худро санҷед: компонентҳои серверӣ ва клиентӣ

миёна

Дар файли components/Counter.tsx useState ва onClick ҳаст, аммо директива нест. Саҳифа ҷамъ намешавад. Чӣ кор кардан лозим аст?

  1. "use client"-ро ҳамчун сатри аввали файли Counter.tsx илова кардан
  2. "use client"-ро дар дохили функсияи Counter илова кардан
  3. useState-ро нест карда, тағйирёбандаи оддиро истифода бурдан
  4. Файлро ба counter.client.tsx тағйир додани ном

Файл бо ҳолат ва рӯйдодҳо бояд клиентӣ бошад, ва директива дар сатри аввали файл гузошта мешавад. Дар дохили функсия он амал намекунад, ва тағйири ном чизеро иваз намекунад.

Саҳифаи мағоза аз сарлавҳа, каталог ва як тугмаи «В корзину» иборат аст, ки ба он state лозим аст. Чӣ тавр дурусттар амал кардан лозим аст?

  1. Тамоми саҳифаро бо "use client" нишон додан
  2. Ҳар як файли лоиҳаро бо "use client" нишон додан
  3. Тугмаро ба компоненти алоҳидаи хурд бо "use client" баровардан, ва саҳифаро серверӣ мондан
  4. Аз тугма даст кашидан

Директиваро ба «баргҳои» хурди интерактивии дарахт мегузоранд: ба браузер танҳо JavaScript-и лозимӣ меравад, ва боқимондаи саҳифа сабук ва тез мемонад.

Дар бораи компонентҳо дар Next.js App Router бо пешфарз чӣ дуруст аст?

  1. Ҳамаи компонентҳо клиентианд, ва онҳоро серверӣ директиваи "use server" мекунад
  2. Саҳифаҳо ва компонентҳо серверианд, то даме ки файл бо "use client" нишон дода нашудааст (ё аз чунин файл пайваст нашудааст)
  3. Компонентҳои серверӣ useState-ро истифода бурда метавонанд
  4. Компонентҳои серверӣ танҳо дар браузер кор мекунанд

Компонентҳои серверӣ реҷаи пешфарз мебошанд. Директиваи "use client" реҷаи клиентиро барои файл ва ҳар чӣ он пайваст мекунад, фаъол мекунад. Компонентҳои серверӣ state ва handler надоранд.

Барномасоз калиди махфии API-ро дар компоненти клиентӣ гузоштааст. Чаро ин хатарнок аст?

  1. Зеро калид суст кор мекунад
  2. Зеро компонентҳои клиентиро дар Git нигоҳ доштан мумкин нест
  3. Зеро калид баъд аз нав бор кардани саҳифа нест мешавад
  4. Зеро коди компоненти клиентӣ ба браузер фиристода мешавад, ва калидро ҳар як меҳмони сайт дида метавонад

Ҳар чизе, ки дар компоненти клиентӣ аст, ба корбар мерасад. Махфиёт танҳо дар коди серверӣ ва тағйирёбандаҳои муҳит нигоҳ дошта мешаванд, мисли дарсҳо оид ба бехатарӣ.

07 Хусусияти дарс: «Як соат — як MVP»

MVP (minimum viable product) — нусхаи ҳадди ақали маҳсулот, ки аллакай истифода бурдан мумкин аст. Дар ин мусобиқа иштирокчиён дар 60 дақиқа хидмати хурди интерактивиро аз сифр месозанд ва истиноди зиндаро нишон медиҳанд. Блок барои омӯзгор тарҳрезӣ шудааст ва барои шоми мустақилона низ мувофиқ аст: таймер дар проектор лозим аст.

Қоидаҳо

1. Ҳар кас аз рӯйхати поён ғоя мегирад (бо қуръа ё аз ду то интихоб мекунад). 2. Таймери 60 дақиқа якбора ба кор медарояд. 3. Дар MVP ҳадди ақал се усули интерактивии дарс бояд бошад: масалан, state, рендери шартӣ ва рӯйхат тавассути map, форма ё филтр. 4. Кодро бо даст наменависед: вазифаро ба AI тавсиф мекунед ва натиҷаро месанҷед. 5. Маълумот метавонад ҳамчун массив дар код бошад, сервер ва база лозим нестанд. 6. Натиҷа — суроғаи ….vercel.app бо хидмати корӣ. 7. Агар дар 60 дақиқа нашр накардед — холҳо барои нашр дода намешаванд, барои ҳамин 10 дақиқаро барои commit, push ва санҷиши Vercel пешакӣ гузоред.

Ғояҳо барои MVP (интихоб кунед ё қуръа кашед)

  • Рӯйхати корҳо: илова, ҳамчун анҷомшуда қайд кардан, ҳазф, филтри «ҳама / анҷомшуда / не».
  • Ҳисобкунаки чойпулӣ ва тақсими ҳисоб барои чойхона: маблағ, фоиз, шумораи меҳмонон, натиҷа барои як нафар.
  • Викторинаи хурд дар бораи Душанбе: савол, вариантҳо, ҳисоби холҳо, экрани натиҷа ва тугмаи «Заново».
  • Менюи кафе бо фармоиш: категорияҳо, илова кардани хӯрок, ҷамъ бо сомонӣ.
  • Пайгирии одатҳо: рӯйхати одатҳо, қайди «имрӯз иҷро шуд», ҳисобкунаки силсила.
  • Конвертери асъор (сомонӣ, рубл, доллар) аз рӯи нархҳое, ки дар массив навишта шудаанд.

миёна

Суроғаи мағозаи нашршударо бо намуди https://clothing-shop-….vercel.app ворид кунед. Онро дар телефон кушоед ва роҳи «филтр, ба сабад, ҳазф, фармоиш»-ро гузаред.

Бештар хонед: React: бо компонентҳо фикр кардан ва state-и умумӣ барои якчанд компонент (бо забони англисӣ).

✓ Хулосаи дарс

  • State: const [x, setX] = useState(ибтидоӣ);. Танҳо бо сеттер иваз мекунем. Тағйирёбандаи оддӣ экранро навсозӣ намекунад ва аз такрорсозӣ намегузарад. Ҳар нусхаи компонент state-и худро дорад. Хукҳо танҳо дар сатҳи боло даъват мешаванд.
  • Рӯйдодҳо: onClick, onChange, onSubmit. Функсия медиҳем: onClick={() => setOpen(true)}, на даъвати setOpen(true). e.preventDefault() — амали пешфарзро бекор кардан, e.stopPropagation() — боло рафтани рӯйдодро қатъ кардан.
  • Рендери шартӣ: {open && <Menu />} — нишон додан ё ҳеҷ чиз; {open ? "✕" : "☰"} — яке аз дуро интихоб кардан; рақамро дар тарафи чапи && намегузорем (count > 0 && …).
  • Рӯйхатҳо дар state: илова [...arr, item], ҳазф arr.filter(…), иваз arr.map(…). На push ва на splice. Филтри каталог — ҳисоб барои экран, на ҳазф аз маълумот.
  • Формаҳо: майдони идорашаванда value + onChange (парчам — checked). Санҷиш дар onSubmit баъд аз e.preventDefault(), хатоҳо — объект дар state, намоиш — рендери шартӣ.
  • Боршавӣ ва хато: status = idle, loading, error, success. Барои ҳар статус экрани худ, ҳангоми боршавӣ тугма ғайрифаъол аст, ҳангоми хато «Повторить» ҳаст.
  • "use client": дар Next.js компонентҳо бо пешфарз серверианд. Директива дар сатри аввали файл реҷаи клиентиро фаъол мекунад: барои state, рӯйдодҳо, эффектҳо ва API-ҳои браузер лозим аст. Онро ба компонентҳои хурди интерактивӣ мегузорем, на ба тамоми саҳифа. Махфиёт дар коди клиентӣ нигоҳ дошта намешаванд.
  • Хатогиҳои маъмул: «Too many re-renders» (даъват ба ҷои функсия), «only works in a Client Component» (директива нест), «Hydration failed» (хондани маълумоти браузер ҳангоми нишондиҳии аввал), мутатсияи массив, форма бе preventDefault.
  • Бо AI: як блок дар як вақт, state-ро ном бурдан, ҳамаи ҳолатҳои формаро номбар кардан, директиваро танҳо дар компонентҳои хурд талаб кардан, бо даст ва дар консол санҷидан.
ВАЗИФАИ 9.1

Ман мавзӯъро воқеан фаҳмидам

осон

Танҳо онро қайд кунед, ки бе маслиҳат карда метавонед.

  • Метавонам фарқи state-ро аз тағйирёбандаи оддӣ шарҳ диҳам ва ҳисобкунакро тавассути useState нависам
  • Метавонам handler-и рӯйдодро пайваст кунам ва фарқи onClick={f}-ро аз onClick={f()} шарҳ диҳам
  • Метавонам элементро бо рендери шартӣ нишон диҳам ва пинҳон кунам ва менюи бургер, равзанаи модалӣ ва варақаҳоро созам
  • Метавонам унсурро дар массиви state бе мутатсия илова ва ҳазф кунам ва рӯйхатро аз рӯи категория филтр кунам
  • Метавонам формаро бо майдонҳои идорашаванда, санҷиш ва паёмҳои хато ҷамъ кунам
  • Метавонам ҳолатҳои боршавӣ, хато ва муваффақиятро нишон диҳам
  • Метавонам шарҳ диҳам, ки директиваи "use client" барои чӣ лозим аст, онро ба куҷо гузоштан лозим аст ва агар фаромӯш шавад чӣ мешавад
  • Метавонам сабаби хатогиҳои «Too many re-renders» ва «only works in a Client Component»-ро ёбам ва онҳоро ба AI фиристам
