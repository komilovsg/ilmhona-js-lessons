01 Структура страницы: теги, из которых всё собрано

Страница — это дерево из вложенных блоков. Самый внешний — <html>; внутри него две части: <head> («голова» со служебной информацией: заголовок вкладки, кодировка, стили) и <body> («тело»: всё, что видно на экране). Внутри <body> лежат шапка, основная часть и подвал, а внутри них — заголовки, абзацы, кнопки и картинки. Тег, который вложен в другой, называют дочерним, а внешний — родителем.

Шесть тегов, которые встречаются в каждом коде от ИИ

ТегЧто этоПример
<div>Универсальная «коробка»: ничего не рисует, только группирует содержимое, чтобы потом оформить его как единое целое<div class="card">…</div>
<section>Смысловой раздел страницы («Меню», «Контакты»). Для браузера это та же коробка, но с понятным названием: так код читается легче<section id="menu">…</section>
<button>Кнопка. Сама по себе только выглядит как кнопка; что она делает, задают отдельно<button>Заказать</button>
<input>Поле ввода: текст, почта, пароль, флажок. Одиночный тег — закрывающего нет. Вид поля задаёт атрибут type<input type="email" placeholder="Ваша почта">
<img>Картинка. Одиночный тег. src — адрес файла, alt — описание словами (его видно, если картинка не загрузилась, и читают программы для незрячих)<img src="logo.png" alt="Логотип чойхоны">

Как устроен один тег

<a href="https://example.com" class="link">Открыть сайт</a>

Разберём эту строку: <a …> — открывающий тег, </a> — закрывающий, href="…" и class="…" — атрибуты (пара «название = значение в кавычках»), а текст между тегами — то, что увидит человек.

Атрибуты — это «настройки» тега: href, src, alt, class, id, type, placeholder. Они пишутся внутри открывающего тега, значение — в кавычках. Большинство тегов парные (есть открывающий и закрывающий); одиночные — <img>, <input>, <br>.

Аналогия из жизни

Страница — как ряд на бозоре. <section> — отдельная лавка («Фрукты», «Специи»), <div> — ящик на прилавке, внутри ящика лежат товары: <h3> — табличка с названием, <p> — ценник, <img> — фото, <a> — стрелка «пройдите вон в ту лавку», <button> — колокольчик «позвать продавца». Ящик без товара ничего не стоит, а лавка без ящиков — просто пустое место.

Проверь себя: теги

лёгкая

Какой тег делает ссылку, по которой можно перейти на другую страницу?

  1. <a href="…">
  2. <img src="…">
  3. <div class="…">
  4. <input type="…">

Зачем у картинки атрибут alt?

  1. Чтобы задать размер картинки
  2. Чтобы описать картинку словами: текст виден, если она не загрузилась, и его читают программы для незрячих

  4. Чтобы картинка загружалась быстрее

Адрес файла — это src, а alt — текстовое описание. Хорошая привычка: ИИ часто его пропускает, поэтому проверяйте.

Какие из этих тегов одиночные, то есть у них нет закрывающего? (выберите все верные варианты)

  1. <button>
  2. <img>
  3. <input>
  4. <a>

Картинка и поле ввода ничего не «оборачивают», поэтому закрывающего тега у них нет. Кнопка и ссылка — парные: между тегами лежит текст.

02 Класс и стиль: как страница получает оформление

HTML говорит, что на странице есть. CSS говорит, как это выглядит. Связывает их класс — ярлык, который вы вешаете на тег: <button class="btn">. В CSS на этот ярлык пишут правило.

.btn {                     /* селектор: «все элементы с class="btn"» */
  background: #0e7a55;     /* свойство: значение; — точка с запятой обязательна */
  color: #fff;
  padding: 10px 18px;
}
Как записан селекторКого выбирает
h1все теги <h1> (имя тега)
.btnвсе элементы с class="btn" (точка = класс)
#menuодин элемент с id="menu" (решётка = id; он на странице один)
.dish pабзацы <p> внутри элементов с классом dish

У тега может быть несколько классов через пробел: class="btn big". Они складываются. А ещё стиль можно записать прямо в тег: <p style="color: red">. Так делают для быстрой проверки, но классы удобнее: правило в одном месте управляет всеми элементами.

Четыре свойства, которые вы будете менять чаще всего

  • Цвет: color — цвет текста, background — фон. Значения: #0e7a55, rgb(14, 122, 85), white.
  • Текст: font-size (размер), font-weight (жирность), text-align (выравнивание).
  • Отступы: padding — внутри блока, margin — снаружи блока.
  • Рамка и углы: border, border-radius.
Аналогия из жизни

Коробка с пловом на доставке. Плов внутри — content. Салфетки между пловом и стенкой коробки — padding. Стенка коробки — border. Расстояние между коробками на полке, чтобы они не слиплись, — margin. Хотите, чтобы плов «дышал» — добавьте padding; хотите отодвинуть коробку от соседней — margin.

ЗАДАЧА 2.2

Проверь себя: CSS

лёгкая

Что означает правило .btn { color: white; }?

  1. Все теги <btn> станут белыми
  2. Все элементы с class="btn" получат белый цвет текста
  3. Только один элемент с id="btn" получит белый цвет
  4. Фон страницы станет белым

Точка перед именем означает «класс». color — цвет текста, а не фона (фон — background).

Чем padding отличается от margin?

  1. padding — отступ внутри блока (между содержимым и рамкой), margin — отступ снаружи (от соседних блоков)
  2. padding — отступ снаружи, margin — внутри
  3. Это одно и то же
  4. padding меняет цвет, margin — размер шрифта

Порядок слоёв снаружи внутрь: margin → border → padding → content.

В CSS написано colour: red;. Что сделает браузер?

  1. Покажет красное сообщение об ошибке
  2. Сломает всю страницу
  3. Молча пропустит эту строку, цвет не изменится
  4. Исправит опечатку сам

Браузер не ругается на неизвестные свойства, он их игнорирует. Поэтому опечатки в CSS так трудно заметить: страница просто «не слушается». В DevTools такая строка помечается предупреждением, об этом — в разделе 5.

03 Flexbox и Grid на пальцах: как блоки встают на места

По умолчанию блоки идут друг под другом, как строки в тетради. Чтобы поставить их в ряд, сделать колонки или галерею, используют два инструмента. Оба включаются одним свойством у родителя, а потом дочерние блоки сами раскладываются по правилам.

Flexbox: одна линия

Включается у родителя: display: flex. Дети выстраиваются в ряд. Три свойства покрывают почти всё, что вам встретится:

СвойствоЧто делаетЗначения
gapпромежуток между детьми16px
justify-contentкак распределить блоки вдоль линииflex-start, center, space-between, space-around
align-itemsкак выровнять блоки поперёк линии (по высоте)stretch, flex-start, center, flex-end
flex-directionнаправление: ряд или колонкаrow (по умолчанию), column

Видео на русском (6,5 минут): все свойства Flexbox на живых примерах. Запомнить их все не нужно, достаточно понять идею «одна ось, блоки по очереди».

Grid: сетка

Когда нужны и строки, и колонки (каталог, галерея, тарифы), берут Grid: display: grid. Главное свойство — grid-template-columns, описание колонок. Запись repeat(3, 1fr) читается как «три колонки равной ширины» (fr — «доля свободного места»). Строки добавляются сами, по мере того как заканчиваются клетки. Чтобы элемент занял две колонки: grid-column: span 2.

04 Как читать код, который выдал ИИ

Файл на 200 строк выглядит страшно, пока не знаешь, куда смотреть. У вас теперь есть карта: любой HTML-файл от ИИ состоит из одних и тех же частей.

Пять приёмов чтения

  1. Читайте отступами. Вложенность видна по сдвигу вправо: всё, что сдвинуто глубже, лежит внутри предыдущего тега. Если отступы «поехали», запустите форматирование: в VS Code это Shift+Alt+F (Windows) или Shift+Option+F (macOS).
  2. Сворачивайте блоки. Рядом с номерами строк в VS Code есть стрелки: нажмите, и тег свернётся. Сверните всё лишнее и оставьте скелет.
  3. Ищите по тексту. Видите на странице слово «Заказать» — нажмите Ctrl+F (Cmd+F), введите его и попадёте на кнопку в коде.
  4. От класса — к правилу. Нашли class="btn" — снова Ctrl+F, введите .btn, и вот правило с цветом и отступами. Если у тега несколько классов, ищите каждый.
  5. Спрашивайте ИИ про конкретное. Не «объясни всё», а «что делает строка 42» или «зачем здесь gap».
Аналогия из жизни

Незнакомый город вы изучаете не по каждому переулку: смотрите на карту, находите площадь, главную улицу и свой район. Код читается так же: сначала скелет (теги header, main, section), потом нужный район, потом конкретный дом (строка).

Правило страховки

Перед любой правкой сохраните копию файла: index.html → index-v1.html (в VS Code: правая кнопка по файлу в панели слева → «Copy», затем «Paste» и переименуйте). Если что-то сломается, вернётесь к рабочей версии за секунду. С уроком 4 эту роль возьмёт Git.

Типичные ошибки новичков

1. Пытаться понять все 200 строк подряд. Читайте «по запросу»: вам нужно то место, которое вы хотите изменить. 2. Править то, что не понял, без копии файла. 3. Искать оформление в HTML: цвета и отступы лежат в CSS (<style>), в HTML только классы. 4. Удалять «непонятные» строки в <head>: в том числе <meta charset="UTF-8">, без неё русский текст превратится в «кракозябры».

05 DevTools за 10 минут: рентген для страницы

DevTools («инструменты разработчика») встроены в Chrome и Edge, ставить ничего не надо. Они показывают, из чего сделана любая страница, дают временно поменять её и ловят ошибки. Это ваш главный помощник: когда ИИ сделал «не то», DevTools показывают, что именно получилось.

Как открыть

  • Правой кнопкой мыши по нужному месту страницы → пункт «Inspect» (в русском интерфейсе — «Просмотреть код» в Chrome, в Edge название может отличаться). Откроется панель с уже выбранным элементом.
  • Клавиши: F12 или Ctrl+Shift+I (Windows), Cmd+Option+I (Mac).
  • Сразу Console: Ctrl+Shift+J (Windows), Cmd+Option+J (Mac).
  • Режим «выбрать элемент мышью»: Ctrl+Shift+C (Windows), Cmd+Shift+C (Mac).

1. Elements: посмотреть и временно поменять

  1. Выберите элемент. Нажмите значок «стрелка в квадрате» (1) или Ctrl+Shift+C и наведите курсор на страницу: блоки подсвечиваются. Щёлкните по нужному, и в дереве тегов (5) он выделится.
  2. Посмотрите стили. В области Styles (6) видны все CSS-правила, которые действуют на элемент, и файл со строкой, откуда они взялись. Строка с опечаткой в названии свойства помечена значком предупреждения.
  3. Поменяйте. Щёлкните по значению (например, цвету) и введите другое, нажмите Enter. Страница изменится сразу. Галочка слева от строки временно выключает правило: удобно проверять «а что будет без него».
  4. Скопируйте найденное. Понравившееся значение перенесите в свой файл в VS Code и сохраните.
Главное про DevTools

Правки в DevTools временные: они меняют только копию страницы в вашем браузере. Обновите страницу — всё вернётся как было, а ваш файл в VS Code вообще не изменится. Если нашли хорошее значение, перенесите его в код руками.

2. Режим устройства: страница глазами телефона

Нажмите значок «телефон и планшет» (2) или Ctrl+Shift+M (Cmd+Shift+M на Mac). Страница сожмётся до размера экрана телефона. Сверху можно выбрать готовую модель или тянуть границу, меняя ширину. Так вы проверяете то, о чём говорили в уроке 2: не вылезает ли текст за край, не слиплись ли блоки, помещаются ли кнопки. Это приближение: настоящий телефон всё равно полезно открыть.

3. Console: красные ошибки

Вкладка Console (4) — это «журнал» страницы. Если в коде есть ошибка в JavaScript (в уроках 7–8 он появится в проектах), браузер напишет её здесь красным. Ошибка читается просто: что случилось, в каком файле и в какой строке. Именно этот текст нужно копировать ИИ вместе с кодом.

Uncaught ReferenceError: nosuchthing is not defined
    at <anonymous>:1:1

Переведём: «ссылка на несуществующее имя nosuchthing». Попробуйте сами: откройте Console, введите nosuchthing() и нажмите Enter. Красная строка — это нормально, так выглядит большинство ошибок. Опечатки в HTML и CSS в Console не попадают: их ищут во вкладке Elements, глядя на дерево и на строки в Styles. Жёлтые строки — предупреждения, они не критичны.

Видео на русском (около 21 минуты): обзор DevTools. Смотрите части про Elements, Styles и Console, остальное можно пропустить. Названия кнопок в новых версиях Chrome могут немного отличаться — ориентируйтесь на смысл.

Аналогия из жизни

DevTools — как рентген и «примерочная» сразу. Рентген показывает, из каких костей (тегов) сделана страница. Примерочная позволяет примерить другой цвет и отступ, не покупая ткань, то есть не трогая файл. Не подошло — вышли, и всё вернулось на место.

Типичные ошибки новичков

1. Править в DevTools и забывать перенести правку в файл. 2. Думать, что красных строк в Console «не должно быть никогда»: учебная страница без JavaScript вообще не пишет в Console, а ошибка бывает у любой живой страницы. Важно уметь её прочитать. 3. Искать ошибки CSS в Console. 4. Проверять адаптив только в режиме устройства: он приближённый.

✓ Шпаргалка урока

  • Страница — дерево тегов: html → head и body → header, main, footer → блоки и элементы.
  • Теги: div и section — коробки, button — кнопка, input — поле (type), img — картинка (src + alt), a — ссылка (href). img и input без закрывающего тега.
  • Класс — ярлык на теге; в CSS ему соответствует правило с точкой: .btn { … }. #id — единственный на странице.
  • Коробка: margin (снаружи) → border → padding (внутри) → content.
  • Частые свойства: color, background, font-size, padding, margin, border-radius.
  • Flexbox — одна линия: display: flex, gap, justify-content, align-items. Grid — сетка: display: grid, grid-template-columns: repeat(3, 1fr), gap.
  • Читать код ИИ: смотреть отступы, сворачивать блоки, искать по тексту (Ctrl+F), от класса идти к правилу, перед правками делать копию файла.
  • DevTools: F12 или Cmd+Option+I; Elements — посмотреть и временно поменять стиль; режим устройства — телефон; Console — красные ошибки. Правки временные: переносите их в файл.
  • Типичные баги: незакрытый тег, опечатка в классе или свойстве, пропущенная точка или ;, одинаковый цвет текста и фона, картинка без alt, мелкий шрифт, неправильный порядок блоков.
  • Промпт для правок: симптом → ожидание → «минимальная правка, остальное не трогай» → список изменений («было → стало → почему») и полный файл.
