01 Зачем нужен React и что такое компонент

Откройте файл app/page.tsx вашего лендинга из урока 5. Скорее всего, это одна длинная простыня на 200–400 строк: шапка, hero, три карточки услуг, три врача, отзывы и форма. Теперь представьте типичные просьбы клиента: «поменяйте цвет кнопок», «добавьте четвёртую услугу», «сделайте такой же сайт для моего брата-кофевара». В длинном файле одна и та же карточка скопирована по несколько раз, и правка превращается в поиск по тексту: легко пропустить копию и получить сайт, где три кнопки голубые, а четвёртая осталась зелёной. ИИ в таком файле тоже путается чаще.

React решает это так: интерфейс собирается из компонентов — небольших независимых «кирпичей», каждый из которых отвечает за свой кусок экрана. Карточку услуги вы описываете один раз и потом используете сколько нужно, подставляя разные данные. React создан в Meta (Facebook) и сегодня остаётся самой популярной библиотекой для интерфейсов, поэтому и ИИ пишет на нём лучше всего. А Next.js, с которым вы работали на уроке 5, — это фреймворк на основе React: он добавляет страницы, маршруты и публикацию, а сами кирпичи интерфейса в нём — React-компоненты.

Ролик на английском, включите субтитры (около 2 минут): идея React и компонентов в сжатом виде. Подробности про состояние и хуки из ролика пока пропустите: к ним мы вернёмся в уроке 8.

Аналогия из жизни

Компонент — это форма для печенья на кухне. Форма одна, а печенья можно сделать сколько угодно, и у каждого своя начинка. Захотели добавить в форме звёздочку на крышку — поправили форму один раз, и все следующие печенья уже со звёздочкой. Без формы вы лепите каждое печенье руками и каждое получается чуть-чуть по-разному.

Файлы .tsx: ответ, обещанный в уроке 5

В названии page.tsx две части. JSX — способ записывать разметку прямо внутри кода (разберём в разделе 3). TS — TypeScript: к JavaScript добавлены «подписи» к данным, чтобы редактор и сборка ловили ошибки заранее. Вам сейчас нужно только узнавать их в коде. Вот типичная строка, которую напишет ИИ:

export default function Card({ title, price }: { title: string; price: number }) {
  // ...
}

Часть после двоеточия — описание типов: «в эту карточку приходит название (текст) и цена (число)». Читайте её как подпись на коробке: что внутри должно лежать. Если вы передадите цену словом, сборка остановится и напишет ошибку типов — её, как в уроке 5, целиком копируют и отправляют ИИ. В упражнениях на этой странице типов нет: мы пишем «чистый» React на JavaScript, а в проекте Cursor ИИ добавит подписи сам.

Типичные ошибки новичков

1. Путать React и Next.js: React строит кирпичи, Next.js делает из них сайт со страницами и публикацией. 2. Думать, что нужно выучить весь JavaScript, прежде чем начать: для чтения кода достаточно небольшого набора из раздела 2. 3. Считать, что «компонент» — это целая страница. Компонентом может быть и целая секция, и маленькая кнопка. 4. Копировать одну и ту же карточку три раза вместо одного компонента: так и получается длинная простыня, от которой мы уходим.

02 JavaScript-минимум: чтобы читать код компонентов

Компоненты React — это обычный JavaScript плюс разметка. Писать его будет ИИ, а вот читать вам придётся самим: проверять, что он сделал, находить, где лежит цена, и просить правки точными словами. Для этого не нужен весь язык: хватит шести понятий. Каждое — короткий пример, который можно запустить кнопкой «Запустить» прямо здесь, и задача. После этого раздела массивы и объекты в коде перестанут выглядеть как шифр.

Как работают примеры

В блоках с кнопкой «Запустить» код выполняется в браузере, а результат появляется в консоли под ним. console.log(…) — это «напечатай значение в консоль». Меняйте числа и слова и запускайте снова: сломать ничего нельзя.

1. Переменная: const

Переменная — подписанная коробка, в которую кладут значение, чтобы потом вернуться к нему по имени. Слово const (от constant, «постоянная») создаёт такую коробку; значение после знака = кладётся в неё один раз и дальше не переприсваивается. В коде ИИ вы увидите ещё let — коробку, которую можно переприсвоить, но в этом уроке достаточно const.

const city = "Душанбе";
const price = 200;

console.log(city);
console.log(price);

2. Строка и число

Строка — текст в кавычках: "Чистка зубов". Число — без кавычек: 200. Разница важна: числа можно складывать и вычитать, а строки — склеивать. Для склейки удобнее шаблонная строка в обратных кавычках: внутрь неё через ${…} подставляют переменные и даже вычисления. Именно так в React-коде собирают подписи вроде «Чистка зубов: 150 сомони».

const title = "Пломба";
const price = 350;
const discount = 50;

console.log(price - discount);              // число: 300
console.log("Услуга: " + title);            // склейка: Услуга: Пломба
console.log(`${title} стоит ${price - discount} сомони`);   // шаблонная строка
console.log("350" + 50);                    // строка + число = строка: 35050

3. Массив: список значений

Массив — упорядоченный список в квадратных скобках: [120, 200, 350]. У каждого элемента есть номер (индекс), и считать нужно с нуля: первый элемент — prices[0]. Длина списка — prices.length. Когда на лендинге несколько услуг, врачей или отзывов, в коде они лежат именно в массиве.

4. Объект: карточка из пар «ключ: значение»

Объект — набор подписанных значений в фигурных скобках: { name: "Зарина", experience: 7 }. Значение берут по ключу через точку: doctor.name. Если вы уже видели JSON, это очень похоже, только ключи обычно без кавычек. Чаще всего в React встречаются массивы объектов: список, где каждый элемент — карточка с несколькими полями.

const doctor = { name: "Зарина", role: "терапевт", experience: 7 };
const prices = [120, 200, 350];

console.log(doctor.name);          // Зарина
console.log(prices[0]);            // 120 — счёт с нуля
console.log(prices.length);        // 3

// деструктуризация: достаём сразу несколько полей из объекта
const { name, role } = doctor;
console.log(`${name} — ${role}`);

Строка const { name, role } = doctor; называется деструктуризацией: «возьми у объекта поля name и role и сделай из них переменные». Запомните её: именно так компоненты принимают данные в разделе 4.

5. Функция и стрелочная функция

Функция — именованный набор действий: принимает значения на вход (параметры), что-то делает и отдаёт результат через return. Важно не путать: console.log только печатает значение, а return возвращает его тому, кто функцию вызвал. Стрелочная функция — короткая запись того же самого со стрелкой =>. Если после стрелки идёт одно выражение, return можно не писать.

function formatPrice(value) {
  return value + " сомони";
}

const formatPrice2 = (value) => value + " сомони";    // то же самое короче

console.log(formatPrice(120));
console.log(formatPrice2(200));

Каждый React-компонент — тоже функция: на вход получает данные, а возвращает разметку. Поэтому понимание функций — главный кирпич раздела.

6. import и export: как файлы находят друг друга

Проект состоит из многих файлов, и файлам нужно получать друг у друга кусочки кода. export — «выставить наружу» то, что файл готов отдать, import — «взять» это в другом файле. Без них компонент, лежащий в components/Hero.tsx, невозможно показать на странице.

// главный экспорт файла: имя в импорте можно выбрать любое
import Hero from "@/components/Hero";

// именованный экспорт: имя в скобках должно совпасть с именем в export
import { services } from "@/data/services";

// встроенные кирпичи React / Next.js — из библиотек, а не из ваших файлов
import Link from "next/link";

Путь вида "@/components/Hero" означает «от корня проекта»: проект, созданный на уроке 5 командой create-next-app, настроен на такой псевдоним по умолчанию (@/*). Путь без точек и слэшей в начале, например "next/link", ведёт в установленную библиотеку.

Аналогия из жизни

Представьте большой склад на бозоре. В каждой лавке на витрине написано, что она отдаёт в общий оборот: «export: сомса, лепёшка». Повар на кухне делает заявку: «import: беру сомсу из лавки номер три». Если лавка не выставила товар или повар написал название с ошибкой, заказ не пройдёт: JavaScript так же строго сверяет слова.

Типичные ошибки новичков

1. Путать = (положить значение в коробку) и === (сравнить два значения). 2. Забыть, что счёт в массиве идёт с нуля, и ждать первый элемент по индексу 1. 3. Писать "200" в кавычках, когда нужно число: тогда "200" + 50 даст "20050", а не 250. 4. В импорте поставить фигурные скобки у default-экспорта или не поставить у именованного. 5. Написать функцию, но не вызвать её: без скобок formatPrice(120) ничего не произойдёт. 6. Использовать console.log там, где нужен return: результат тогда напечатан, но не передан дальше.

03 JSX и компонент: функция, которая возвращает разметку

Компонент в React — это обычная функция, имя которой начинается с заглавной буквы и которая возвращает разметку. Эта разметка записывается в виде JSX: она похожа на HTML, но живёт прямо внутри JavaScript. Готовый компонент вызывают как свой собственный HTML-тег: <Hero />.

Нажмите «Запустить» ниже: здесь два компонента, а третья функция App собирает их вместе. Поменяйте город или год в Hero и запустите ещё раз.

function Header() {
  return (
    <header className="header">
      <b>Улыбка</b>
      <span>Душанбе</span>
    </header>
  );
}

function Hero() {
  const city = "Душанбе";
  const since = 2019;
  return (
    <section className="hero">
      <h1>Стоматология в городе {city}</h1>
      <p>Лет на рынке: {2026 - since}</p>
    </section>
  );
}

export default function App() {
  return (
    <>
      <Header />
      <Hero />
    </>
  );
}

3. Атрибуты пишутся иначе: class становится className, составные имена — через camelCaseclass="btn"className="btn"
4. Значения из JavaScript вставляются в фигурных скобках {…}<p>city</p> (выведет слово «city»)<p>{city}</p>

Внутри {…} можно писать любое выражение: переменную, расчёт {2026 - since}, вызов функции. А вот имя компонента с маленькой буквы — тоже ошибка: React решит, что <hero /> — это обычный HTML-тег, и ничего не покажет. Заглавная буква — это способ сказать «это мой компонент».

Где компонент должен жить

Объявляйте каждый компонент на «верхнем уровне» файла, а не внутри другого компонента: React предупреждает, что вложенное объявление работает медленно и приводит к странным багам. Если ИИ написал функцию-компонент внутри другой функции-компонента, попросите вынести её наружу.

Аналогия из жизни

Компонент — как кирпич из одной и той же формы на кирпичном заводе под Душанбе: у каждого одинаковый размер, поэтому из них можно строить любую стену. 04 Props: как одна карточка показывает разные данные

Пока ваши компоненты показывают всегда один и тот же текст. Чтобы одна карточка могла быть и «Чисткой зубов за 200», и «Пломбой за 350», ей нужно передавать данные. Эти данные называются props (от properties, «свойства»). Передают их так же, как атрибуты у HTML-тега, а внутри компонента они приходят как входные параметры функции, — вы уже умеете их читать из раздела 2.

Как это выглядит в коде

function Card({ title, price }) {
  return (
    <div className="card">
      <h3>{title}</h3>
      <p>{price} сомони</p>
    </div>
  );
}

<Card title="Чистка зубов" price={200} />
  • Строку передают в кавычках: title="Пломба". Число, массив, объект, функцию — в фигурных скобках: price={200}. Если написать price="200", вместо числа придёт строка.
  • { title, price } в скобках функции — та самая деструктуризация из раздела 2: «возьми из входящего объекта эти два поля».
  • Значение по умолчанию задают знаком равно: { title, price = 0 }. Оно сработает, если prop не передали.
  • Props только читают. Менять их внутри компонента нельзя: данные принадлежат родителю. (Как менять данные, узнаем в уроке 8.)
  • Особый prop children — всё, что вы положили между открывающим и закрывающим тегом компонента: <Card>любой текст или разметка</Card>. Так делают обёртки — например, рамку для любых блоков.

Аналогия из жизни

Props — как бланк заказа в чойхоне. Бланк одинаковый: «блюдо», «количество», «столик». Официант заполняет его по-разному для каждого гостя, а повар читает один и тот же формат и готовит нужное. Повар не вычёркивает и не переписывает чужой заказ: он его только читает, и поэтому в кухне нет путаницы. Так и props: родитель заполняет, компонент читает.

Типичные ошибки новичков

1. Опечатка в имени prop: передали titel, а читаете title, получаете пустое место, потому что значение undefined. 2. Копируете карточку три раза вместо того, чтобы вызвать один компонент с разными props.

05 Данные в массиве и map: карточки сами появляются из списка

Даже с props три вызова <ServiceCard … /> выглядят повторением. А если услуг десять, а завтра будет двенадцать? Ещё удобнее вынести данные в массив объектов и пусть React сам нарисует по карточке на каждый элемент. Данные отдельно, вёрстка отдельно: чтобы добавить услугу, вы добавляете одну строку в массив, а страница обновляется сама. Именно такой формат ИИ выберет по умолчанию, и именно его просит домашнее задание.

Нужный инструмент — метод массива map. Он берёт каждый элемент списка, превращает его с помощью вашей стрелочной функции во что-то новое и собирает результаты в новый массив той же длины. Сначала попробуем на обычных строках.

const services = [
  { title: "Чистка", price: 200 },
  { title: "Пломба", price: 350 },
];

const titles = services.map((service) => service.title);
console.log(titles);                 // ["Чистка", "Пломба"]

const lines = services.map((service) => `${service.title} — ${service.price} сомони`);
console.log(lines.join("\n"));       // join склеивает элементы в одну строку

В React map возвращает не строки, а JSX: на каждый элемент данных — один компонент. Результат вставляют в фигурные скобки прямо в разметке. К каждому элементу списка нужно добавить prop key: уникальную «метку», по которой React узнаёт, какая карточка какая, когда список меняется.

  { id: 1, title: "Чистка зубов", price: 200 },
  { id: 2, title: "Пломба", price: 350 },
];

export default function Services() {
  return (
    <div className="grid">
      {services.map((service) => (
        <ServiceCard key={service.id} title={service.title} price={service.price} />
      ))}
    </div>
  );
}
  • Круглые скобки после стрелки => ( — чтобы вернуть многострочную разметку. Если вместо них стоят фигурные скобки => {, слово return нужно написать самому.
  • key ставят на внешний элемент внутри map, то есть на сам <ServiceCard />. Внутрь компонента он не передаётся, это служебная метка для React.
  • Ключ должен быть уникальным среди соседей и стабильным: идентификатор из данных (id) подходит; Math.random() — нет. Номер элемента (index) годится только для списка, который никогда не переставляют и не удаляют из него.
  • Без key React выводит в консоль браузера предупреждение «Each child in a list should have a unique "key" prop». Страница при этом может работать, но предупреждение нельзя оставлять: оно говорит о настоящей проблеме с порядком элементов.

  3. Уникальный service.id из данных
  4. Ключ не нужен вообще

Ключ должен быть уникальным среди соседей и стабильным между отрисовками. Идентификатор из данных подходит; случайное число каждый раз новое, одинаковое слово не различает карточки, а без key React предупредит об ошибке.

Цены услуг понадобились в двух разных компонентах. Где их лучше хранить?

  1. Скопировать цены в оба компонента
  2. В одном массиве в отдельном файле (например, data/services.ts) и импортировать оттуда
  3. В файле package.json
  4. В папке node_modules

Один источник данных: изменили цену в массиве, и она поменялась везде, где её показывают. Копии цен рано или поздно разойдутся.

Страница падает с сообщением «Element type is invalid: expected a string … but got: undefined. You likely forgot to export your component». Что проверить первым делом?

  1. Купить новый домен
  2. Удалить папку .next и надеяться
  3. Переустановить Cursor
  4. Есть ли в файле компонента export default и совпадает ли способ импорта (без скобок для default, со скобками для именованного)

Сообщение прямо подсказывает причину: компонент не экспортирован или импорт не соответствует экспорту. Это самая частая ошибка после разбиения кода по файлам.

1. Сначала сохраните работающую версию (commit), потому что ИИ будет менять много файлов сразу. 2. Просите сохранить внешний вид: «рефакторинг» означает менять устройство кода, а не картинку. 3. разбей код на компоненты

09 Фишка урока: «Компонентный конструктор»

Настоящая сила компонентов видна, когда из одних и тех же кирпичей собираются совсем разные сайты. В «Компонентном конструкторе» участники за один вечер делают три разных лендинга (например, стоматология, кофейня и курсы английского) и при этом не копируют ни одного компонента: отличаются только данные и несколько props. Блок рассчитан на преподавателя и подходит для самостоятельного вечера.

Правила

1. Исходные кирпичи — ваши Header, Hero, Services, Pricing, Footer и Card из практики. 2. Нужно три лендинга на трёх адресах одного проекта: главная / и две новые страницы. Страницу в Next.js создаёт папка с файлом page.tsx: например, app/cafe/page.tsx откроется по адресу /cafe. Как это работает, разберём в уроке 9: пока просто попросите ИИ создать их. 3. У каждого лендинга свои данные (массивы) и тексты, а компоненты общие. Меняться могут только props: заголовок, цвет акцента, список услуг. 4. Копировать компонент и переименовывать его нельзя. Если кирпичу чего-то не хватает, добавьте ему prop. 5. Код руками не пишете: вы описываете задачу ИИ и проверяете результат. 6. Результат — одна живая ссылка на Vercel с тремя адресами.

Подсказка про цвет

Чтобы кирпич менял акцентный цвет, передайте ему prop с полным названием класса Tailwind: accent="bg-amber-600". Нельзя собирать класс из частей вроде bg-${color}-600: Tailwind ищет в коде только целые имена классов и не создаст стиль для «склеенного» названия.

Ограничения: не копируй и не переименовывай компоненты; если компоненту не хватает настройки, добавь ему необязательный prop (например accent с полным названием Tailwind-класса вроде "bg-amber-600" и заголовок). Внешний вид главной страницы не меняй. Только Tailwind, без новых библиотек. Проверка: запусти npm run build; в конце перечисли, какие файлы созданы и какие props добавлены.

  • React: интерфейс собирается из компонентов-«кирпичей»; Next.js — фреймворк на основе React. .tsx = JSX + типы TypeScript; ошибки типов копируем целиком и отправляем ИИ.
  • JS-минимум: const x = 5; — переменная; "текст" и 5 — строка и число; `${a} и ${b}` — шаблонная строка; [1, 2] — массив (счёт с нуля, .length); { key: value } — объект, поле через точку; const { a, b } = obj; — деструктуризация.
  • Функции: function f(x) { return … } и const f = (x) => …; return возвращает значение, console.log только печатает.
  • import / export: export default → import Name from "…" (без скобок); export const x → import { x } from "…"; @/ — от корня проекта.
  • JSX: один корень (или <>…</>), все теги закрыты, className вместо class, значения из JS — в {…}.
  • Компонент: функция с заглавной буквы, возвращает JSX; вызывается как тег <Card />; объявляется на верхнем уровне файла.
  • Props: параметры компонента: function Card({ title, price }); строки в кавычках, остальное в {…}; только читаем; особый prop children.
  • Списки: данные в массиве объектов + {items.map((item) => <Card key={item.id} … />)}; key — уникальный и стабильный (id).
  • Структура: app/page.tsx только собирает; components/ — кирпичи (один файл — один компонент, имя с заглавной); data/ — массивы данных.
  • Типичные ошибки: нет export default («Element type is invalid»), неверный регистр в пути, нет key, объект вместо поля («Objects are not valid as a React child»).
  • С ИИ: commit перед рефакторингом, называть файлы и props, «внешний вид не менять», проверка npm run build, просить объяснить непонятное.
