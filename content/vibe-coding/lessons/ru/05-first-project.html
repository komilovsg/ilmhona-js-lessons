Первый настоящий проект: Next.js + Tailwind + деплой

К концу урока у вас будет первый проект на настоящем фреймворке, опубликованный в интернете: лендинг стоматологии с живой ссылкой вида https://…vercel.app, которую можно отправить маме, другу или первому клиенту. Вы поймёте, что такое хостинг, домен и URL, из каких файлов состоит проект и как прочитать лог сборки, если публикация не удалась.

  • Объяснять разницу между хостингом, доменом и URL и показывать, из чего состоит адрес сайта
  • Создать проект командой npx create-next-app, запустить его на localhost и назвать главные файлы проекта
  • Объяснить, что такое Tailwind CSS и почему ИИ пишет его так охотно, и прочитать строку классов вроде bg-sky-600 px-8 py-3
  • Собрать через ИИ лендинг из пяти секций (hero, услуги, врачи, отзывы, форма заявки) с адаптивной вёрсткой
  • Опубликовать проект на Vercel из репозитория GitHub и обновлять сайт обычным git push
  • Найти причину в логе сборки Vercel, если деплой упал, и отправить её ИИ для исправления

Нужны: компьютер с установленными на 4-м уроке Cursor, Node.js, Git и аккаунтом GitHub, интернет и около 2,5 часов. Откройте урок в одной половине экрана, а Cursor — в другой. 01 Что такое хостинг, домен и URL

До сих пор ваши страницы жили только на вашем компьютере: файл index.html или адрес localhost, который не открывается ни у кого, кроме вас. Чтобы страницу увидели другие, её нужно положить на компьютер, который всегда включён и подключён к интернету. Такие компьютеры называют серверами, а услугу «разместить свои файлы на чужом сервере» — хостингом.

Хостинг
Место на сервере, где хранится ваш сайт и откуда его отдают всем желающим. Как арендованный прилавок на бозоре: товар ваш, а место и охрана чужие.
Домен
Читаемое имя сайта, например vercel.app или example.tj. Компьютеры ищут друг друга по числовым адресам (IP), а имя нужно людям. Специальная «телефонная книга» интернета (DNS) переводит имя в адрес сервера.
URL
Полный адрес конкретной страницы: протокол, домен и путь. Домен — часть URL, а не синоним.

Из чего состоит URL

Короткий ролик на русском (2,5 минуты): те же понятия на другом примере. Видео записано давно, но идея не устарела.

Аналогия из жизни

Представьте лавку на бозоре в Душанбе. Хостинг — ваш прилавок: место, где лежит товар и куда приходят покупатели. Домен — вывеска и название, по которому вас находят: «Улыбка, ряд 5». URL — полный маршрут «ряд 5, прилавок 12, левая полка»: он ведёт не просто на бозор, а к конкретному товару. А localhost — это товар, разложенный у вас дома на кухне: удобно проверять, но покупатели его не увидят.

Типичные ошибки новичков

1. Пытаться отправить другу ссылку http://localhost:3000: она работает только на вашем компьютере. 2. Думать, что без покупки домена сайта «нет». Адрес …vercel.app доступен всем в мире. 3. Путать «хостинг» и «домен»: можно купить домен и не иметь хостинга, и наоборот. 4. Публиковать вместе с сайтом личные данные: сайт в интернете видят все.

лёгкая

Друг просит ссылку на ваш лендинг, а он открыт у вас по адресу http://localhost:3000. Почему друг его не увидит?

  1. Потому что в адресе нет буквы «s» после http
  2. Потому что localhost — это ваш собственный компьютер, а не сервер в интернете

  4. dental-landing

02 create-next-app: проект из одной команды

Next.js — популярный фреймворк на основе React: набор готовых правил и инструментов, из которых собирают современные сайты и приложения. На 1-м уроке вы создавали один файл index.html. Для настоящего проекта файлов десятки (страницы, стили, настройки, библиотеки), поэтому начинают не с пустой папки, а с заготовки. Её создаёт официальная команда:

npx create-next-app@latest dental-landing

npx скачивает и запускает программу создания проекта (она ставится из интернета, поэтому нужен интернет), create-next-app — сама программа, @latest — «самая свежая версия», dental-landing — имя папки с новым проектом. Если терминал спросит, можно ли установить пакет create-next-app, ответьте y.

Что спросит мастер установки

Вопросы зависят от версии, поэтому не заучивайте их. По документации Next.js на сегодня первый вопрос — название проекта, второй — использовать ли рекомендуемые настройки. Вам нужен первый вариант («Yes, use recommended defaults»): стрелками выберите его и нажмите Enter.

What is your project named? dental-landing
Would you like to use the recommended Next.js defaults?
  ❯ Yes, use recommended defaults
    No, reuse previous settings
    No, customize settings

Рекомендуемые настройки включают всё, что нужно курсу: TypeScript, ESLint (проверка стиля кода), Tailwind CSS, App Router (современная система страниц), папку проекта без src, а также файл AGENTS.md с подсказками для ИИ-помощников. После ответа программа создаст папку и установит библиотеки: это занимает от одной до нескольких минут.

Быстрый способ без вопросов

Та же заготовка одной командой: npx create-next-app@latest dental-landing --yes. Флаг --yes пропускает вопросы и берёт сохранённые или стандартные настройки. Выбирайте этот способ, когда настройки уже знакомы.

Dev-сервер и package.json

В папке проекта лежит package.json: в нём перечислены библиотеки и «кнопки» — короткие команды для работы. Главные три:

Файлы .tsx — что это?

Страница лежит в page.tsx. Расширение .tsx означает TypeScript + JSX: это язык React (компоненты, из которых строится интерфейс), к которому добавлена проверка типов. Подробно React, JSX и компоненты вы разберёте в уроке 7, а TypeScript встретится позже. Сейчас достаточно двух правил: 1) код в таких файлах пишет ИИ, вы его запускаете и проверяете глазами; 2) если в терминале или логе сборки появляется «ошибка типов» (type error), скопируйте её целиком и отправьте ИИ — так это и разбираем.

Аналогия из жизни

Создать проект через create-next-app — как арендовать готовое кафе вместо стройки: стены, кухня, проводка и вывеска уже есть. Вам остаётся привезти своё меню (page.tsx) и покрасить стены (Tailwind). Строить фундамент заново каждому не нужно.

Типичные ошибки новичков

1. Создать проект внутри другого Git-репозитория (например, внутри папки прошлого урока): Git-репозиторий заготовки тогда не создаётся, и позже будет путаница. Создавайте проект в обычной папке, например на рабочем столе. 2. Закрыть терминал и удивляться, что localhost:3000 перестал открываться: dev-сервер остановился. 3. Открывать в Cursor папку выше проекта: открывайте именно dental-landing. 4. Лезть в node_modules и править там что-то.

03 Tailwind CSS: стили прямо в разметке

На 3-м уроке вы читали CSS: правила в отдельном файле, где есть селектор и набор свойств. Tailwind CSS устроен иначе: готовые короткие классы-«кирпичики» вы пишете прямо на элементе. Один класс отвечает за одну мелочь: px-8 — отступ по бокам, bg-sky-600 — голубой фон, font-semibold — полужирный шрифт.

Почему Tailwind любит ИИ

  • Всё в одном месте. Чтобы изменить кнопку, ИИ правит одну строку и не ищет правило в другом файле, не ломая соседние элементы.
  • Предсказуемый словарь. Классы стандартные, и по ним написано очень много кода в открытом доступе: модель знает их наизусть.
  • Меньше ошибок. Нет конфликтов имён и «каскада» из прошлого урока, где одно правило неожиданно перебивает другое.
  • Адаптив одним приёмом. Приставка sm: или md: означает «начиная с такой ширины экрана»: grid sm:grid-cols-3 — одна колонка на телефоне и три на экране побольше.
КлассЧто означает
p-4, px-8, py-3, mt-6Отступы: со всех сторон, по бокам, сверху и снизу, только сверху. Число — размер (4 ≈ 16 px)
text-lg, text-4xl, font-boldРазмер и жирность шрифта
bg-sky-600, text-whiteЦвет фона и текста: название цвета и оттенок (50 — светлый, 900 — тёмный)
rounded-2xl, shadow-smСкругление углов и тень
flex, grid, gap-4Расположение элементов в строку или сетку и расстояние между ними
hover:bg-sky-700Изменение при наведении курсора
sm:grid-cols-3На экранах от «small» и шире — три колонки

Новый проект уже настроен: Tailwind подключён в файле app/globals.css одной строкой @import "tailwindcss";. Ничего ставить и настраивать не нужно, просто пишите классы.

Ролик на русском (2 минуты): идея Tailwind в самом сжатом виде. Подключать Tailwind по видео не нужно: в вашем проекте он уже подключён.

Аналогия из жизни

Обычный CSS — как заказ индивидуального костюма: портному объясняют каждую мерку отдельным письмом. Tailwind — как конструктор из готовых деталей на рынке тканей: «рукав короткий, воротник стойка, цвет синий». Деталей мало, названия у всех одинаковые, и любой помощник сразу понимает, что вы хотите.

Типичные ошибки новичков

1. Пугаться длинной строки классов: читайте её слева направо по одному слову, как предложение. 2. Вписывать в классы выдуманные слова вроде big-blue-button: такого класса нет, и стиль не применится. Просите ИИ использовать только стандартные классы Tailwind. 3. Следовать видео про Tailwind старых версий и заново «подключать» его: в вашем проекте всё уже готово. 4. Смешивать оба подхода хаотично: договоритесь с ИИ, что стили только на Tailwind.

ЗАДАЧА 3.1

Проверь себя: Tailwind

лёгкая

Что делает строка className="grid gap-4 sm:grid-cols-3" на блоке с карточками?

  1. Скрывает карточки на телефоне
  2. Раскладывает карточки сеткой с промежутками: на узком экране в одну колонку, на экранах от sm и шире в три
  3. Делает три копии каждой карточки
  4. Подключает три внешние библиотеки

grid включает сетку, gap-4 задаёт промежутки, а sm:grid-cols-3 переключает сетку на три колонки, начиная с ширины sm. Без приставки класс действует всегда.

Какой из вариантов — настоящие классы Tailwind?

  1. big-blue-button
  2. make-it-pretty
  3. bg-sky-600 px-8 py-3
  4. color: blue;

Классы Tailwind собираются из стандартного словаря: bg-… — фон, px-… — горизонтальные отступы, py-… — вертикальные. Остальные варианты — выдуманные слова или обычный CSS.

04 Деплой: из GitHub на Vercel

Деплой (deploy) — выкладка проекта на сервер, чтобы его видели все. Vercel — хостинг, созданный командой Next.js; для учебных проектов хватает бесплатного тарифа Hobby (он предназначен для личных и некоммерческих проектов; условия смотрите на сайте сервиса). Схема простая: код лежит на GitHub, Vercel следит за репозиторием и при каждом изменении сам собирает и публикует сайт.

Как подключить репозиторий (по документации Vercel)

  1. Зарегистрируйтесь на vercel.com/signup через кнопку входа с GitHub: так аккаунты сразу связаны. Выберите бесплатный личный (Hobby) вариант.
  2. Нажмите «Add New…» → «Project» (или кнопку нового проекта на главной панели). Появится список ваших репозиториев GitHub. Если репозитория нет в списке, разрешите Vercel доступ к нему в настройках GitHub (кнопка настройки доступа на этом же экране).
  3. Рядом с репозиторием нажмите «Import». Откроется страница настройки: Vercel сам определяет фреймворк (Framework Preset: Next.js), корневую папку оставьте ./. Переменные окружения и настройки сборки не трогайте: они понадобятся позже.
  4. Нажмите «Deploy». Идёт сборка, после неё появляется поздравление и миниатюра сайта. Кнопка «Visit» открывает ваш сайт, а адрес вида название.vercel.app можно отправлять кому угодно.
  5. Дальше — только git push. Каждый push в главную ветку (main) обновляет сайт, а push в другие ветки создаёт отдельный пробный адрес (preview). Публиковать вручную больше не нужно.

Видео на английском, включите субтитры: те же шаги на живом примере (4,5 минуты). Если интерфейс отличается от схемы выше, ориентируйтесь на названия кнопок «Import» и «Deploy».

Как читать лог сборки, если деплой упал

Бывает, что у вас на компьютере всё работает, а на Vercel рядом с проектом красный статус Error. Это нормально: сервер собирает проект строже, чем dev-сервер. Причина всегда написана в логе сборки (build log) — подробной записи того, что сервер делал по шагам.

  1. Откройте проект на Vercel → вкладка «Deployments» и нажмите на деплой с красным статусом.
  2. В блоке «Deployment Details» раскройте «Building» — там лог сборки.
  3. Листайте до красных строк со словом «Error». Не пугайтесь последней строки вроде «Command "npm run build" exited with 1»: она лишь говорит «сборка не удалась». Настоящая причина обычно на несколько строк выше: имя файла, номер строки и текст ошибки.
  4. Скопируйте этот кусок целиком (с именем файла) и отправьте ИИ в Cursor: «Деплой на Vercel упал, вот ошибка из лога. Объясни причину и исправь, остальное не меняй».
  5. Проверьте исправление у себя: запустите npm run build в терминале. Если локально сборка проходит, делайте commit и push — Vercel соберёт заново.

Аналогия из жизни

Лог сборки — как чек-список у приёмщика на складе: он по шагам отмечает, что принял, и на каком пункте остановился, потому что «не хватает коробки номер 7». Последняя запись «приёмка не завершена» ничего не объясняет, а вот строка «нет коробки 7» подсказывает, что искать.

Типичные ошибки новичков

1. Не выполнить git push после правок и недоумевать, почему сайт не обновился. 2. Отправлять ИИ только последнюю строку лога «exited with 1»: нужен весь красный блок. 3. Выкладывать проект с секретами внутри кода: ключи доступа в репозиторий не кладут. Правильное хранение секретов — в уроке 10, а пока в этом проекте их просто нет. 4. Создать репозиторий с личными данными в открытом доступе: проверяйте, что в проекте нет телефонов и паспортных данных. 5. Публиковать «сломанную» версию без npm run build.

ЗАДАЧА 4.1

Проверь себя: деплой

лёгкая

Вы изменили page.tsx в Cursor, сохранили файл, но по ссылке …vercel.app старая версия. Что скорее всего пропущено?

  1. Нужно заново регистрироваться на Vercel
  2. Нужно купить домен
  3. Не сделаны commit и push: Vercel обновляет сайт, когда в GitHub приходит новый код
  4. Нужно перезапустить компьютер

Vercel следит за репозиторием на GitHub. Пока изменения лежат только в файле на вашем компьютере, сайт о них не знает. После commit и push сборка запускается сама.

ЗАДАЧА 4.2

Проверь себя: лог сборки

средняя

В логе упавшего деплоя последняя строка — Error: Command "npm run build" exited with 1, а выше красным: app/page.tsx(39,57): error TS2339: Property 'toUpperCase' does not exist on type 'number'. Что нужно отправить ИИ?

  1. Только последнюю строку
  2. Красный блок целиком: файл, номер строки и текст ошибки
  3. Ничего: нужно просто нажать Redeploy ещё раз
  4. Скриншот домашней страницы Vercel

Последняя строка лишь сообщает, что сборка не удалась. Причина — выше: в файле app/page.tsx на строке 39 у числа вызван метод строки. Повторный запуск без правки приведёт к той же ошибке.

Как проверить исправление до нового push, чтобы не ждать Vercel?

  1. Выполнить в терминале npm run build: там выдаётся та же ошибка типов, если она осталась
  2. Открыть localhost:3000 и посмотреть, красиво ли
  3. Удалить папку .next и надеяться
  4. Никак, только через push

Команда npm run build делает ту же проверку, что и сервер Vercel. Если она проходит локально, шансов на удачный деплой гораздо больше. Dev-сервер бывает мягче: он может показать страницу, которую сборка отклонит.

05 ИИ-блок: как попросить лендинг, а не «сделай сайт»

Правила работы с ИИ в проекте

1. Просите сначала одну секцию, потом следующую: небольшие шаги легче проверять. 2. Всегда называйте стек: Next.js, Tailwind, один файл app/page.tsx. 3. Каждую правку проверяйте глазами в браузере и на узком окне. 4. Ошибки из терминала и лога сборки отправляйте целиком. 5. Не просите ИИ добавлять ключи доступа и платные сервисы. 6. Правим в том же чате, а не начинаем сначала.

В Cursor ИИ видит весь проект и сам правит файлы, поэтому промпт строится по знакомой формуле: контекст → цель → ограничения → примеры → проверка.

сделай сайт для стоматологии
Контекст: учебный проект Next.js с Tailwind CSS (создан командой create-next-app, App Router, TypeScript). Нужен одностраничный лендинг вымышленной стоматологии «Улыбка» в Душанбе. Цель: заменить содержимое app/page.tsx на лендинг из 5 секций: 1) hero с заголовком, подзаголовком и кнопкой «Записаться на приём»; 2) «Услуги» — 3 карточки с названием и ценой в сомони; 3) «Врачи» — 3 карточки с именем и специализацией (вместо фото — круг с первой буквой); 4) «Отзывы» — 2 отзыва; 5) «Запись на приём» — форма с полями «Имя» и «Телефон» и кнопкой «Отправить заявку». Ограничения: только Tailwind-классы, без отдельных CSS-файлов и внешних библиотек; без картинок из интернета (эмодзи и цветные блоки допустимы); весь текст на русском; данные вымышленные; адаптивная вёрстка: на телефоне колонки друг под другом, на экранах от sm — три колонки; спокойная палитра с одним акцентным цветом (голубой), крупные заголовки. Форма пока ничего не отправляет: кнопка не должна перезагружать страницу. Никаких ключей, API и баз данных. Проверка: после правок запусти npm run build и исправь ошибки, если они есть. В конце коротко перечисли, какие секции добавлены.

Чем сильный промпт лучше: стек и файл названы, секции перечислены, адаптив описан словами, а проверка сборки сразу ловит ошибки типов. ИИ не придумывает лишнего и не подключает ненужные библиотеки.

Правки: короткие, по одной

Сделай секцию «Услуги» заметнее: добавь иконку-эмодзи к каждой карточке, тень при наведении и скругление побольше. Остальные секции не меняй.
Проверь адаптивность: на ширине 390 px ничего не должно вылезать за экран. Исправь, если что-то выходит за края, и скажи, что именно изменил.
Объясни простыми словами, как для новичка: что делает функция Home в app/page.tsx, как работает список services.map и какую одну строку менять, чтобы поменять цвет кнопок. Код не переписывай.
Если ИИ в Cursor что-то сломал

Вы работали с Git, поэтому у вас есть «кнопка отмены»: до начала крупной правки делайте commit, а если результат не нравится, вернитесь к сохранённой версии командой git restore . (она отменяет все несохранённые изменения в файлах, будьте осторожны) или попросите ИИ откатить правку. Подробно откаты разберём в уроке 6.

Проверь себя: промпт для проекта

Какое ограничение лучше всего убережёт проект от лишней сложности?

  1. «Сделай красиво и по-современному»
  2. «Только Tailwind-классы в app/page.tsx, без новых библиотек и картинок из интернета»

06 Практика: лендинг стоматологии от нуля до ссылки

Время делать. Вы создадите проект командой, соберёте лендинг вместе с ИИ, отправите код на GitHub и опубликуете сайт на Vercel. Вот что должно получиться (ваш вариант будет другим: свои цвета, названия и цены):

Шаг 0. Подготовка

ЗАДАЧА 6.1

Чек-лист: всё готово к работе

лёгкая

Отметьте выполненное. Если команда не работает, вернитесь к уроку 4.

  • В терминале команда node -v показывает версию 20.9 или выше (требование Next.js на сегодня)
  • В терминале команда git --version показывает версию Git

  • Есть аккаунт на GitHub, и вы помните логин

Шаг за шагом

  1. Откройте Cursor и терминал. Файл → Open Folder: откройте пустую папку для проектов или рабочий стол. Затем в меню выберите «Terminal → New Terminal» (в Cursor работает и сочетание Ctrl+` — обратный апостроф под Esc). Убедитесь, что терминал стоит в нужной папке, и при необходимости перейдите в неё командой cd.
  2. Создайте проект. Выполните команду и выберите рекомендуемые настройки (первый вариант), как в разделе 2: 
    npx create-next-app@latest dental-landing
    Дождитесь надписи «Success! Created dental-landing». Появится папка dental-landing.
  3. Откройте папку проекта в Cursor. Файл → Open Folder → dental-landing. Слева в панели файлов вы увидите app, public, package.json. Если Cursor спросит, доверяете ли вы авторам файлов, это ваш проект: ответьте «Да, доверяю».
  4. Запустите dev-сервер в терминале Cursor (откройте новый терминал, он должен стоять в папке проекта): 
    npm run dev
    Откройте http://localhost:3000 — вы должны увидеть стартовую страницу Next.js. Терминал не закрывайте.
  5. Откройте чат ИИ в Cursor (панель чата справа, сочетание Ctrl+L или Cmd+L; если клавиши другие, найдите значок чата в верхней части окна) и выберите режим Agent, при котором ИИ сам правит файлы проекта. Режимы и правила проекта разберём подробно в уроке 6.
  6. Отправьте промпт для лендинга из раздела 5 (кнопка «Копировать» в углу блока). Замените название и данные на свои, если хотите. ИИ создаст секции и, скорее всего, сам запустит проверку сборки; если он просит разрешения запускать команды, прочитайте команду и разрешите только знакомые (npm run build).
  7. Посмотрите результат в браузере: вкладка localhost:3000 обновится сама. Проверьте все пять секций. Нажмите F12 → значок «устройства» (Device Mode, урок 3) и убедитесь, что при ширине 390 px карточки встают друг под другом.
  8. Сделайте минимум три правки короткими промптами из раздела 5: усилить услуги, проверить адаптив, поменять акцентный цвет. После каждой правки смотрите на страницу. Если ИИ сломал страницу, скопируйте ошибку из терминала и отправьте ему.
  9. Попросите объяснение: «Объясни, из чего состоит app/page.tsx: что такое массив services и как он превращается в карточки». Это ваш шаг «от результата к пониманию».
Если сломалось на этом этапе

Команда npx не найдена или node не найден. Node.js не установлен или терминал открыт до установки. Закройте и откройте терминал заново, проверьте node -v; если версия ниже 20.9, поставьте актуальную LTS-версию с сайта nodejs.org.

Порт 3000 занят: «Port 3000 is in use». Другая программа или прошлый dev-сервер уже занимает порт. Закройте старый терминал (Ctrl+C) или согласитесь на предложенный Next.js другой порт, например 3001, и откройте адрес из терминала.

Красная ошибка «Module not found» или «Parsing ecmascript source code failed» в браузере. ИИ допустил ошибку в коде. Скопируйте весь текст ошибки из терминала и отправьте ИИ: «Исправь эту ошибку, остальное не меняй».

Ошибка типов (Type error) в терминале. Это ошибка проверки TypeScript. Копируйте всю ошибку с путём файла и номером строки и отправляйте ИИ: исправит он, а разобраться в типах вы сможете в следующих уроках.

Страница белая, в браузере только заголовок вкладки. Проверьте терминал: чаще всего там красная ошибка после последней правки. Если ИИ слишком сильно всё поменял, вернитесь к последней рабочей версии (git restore ., если делали commit) или попросите откатить.

rejected … fetch first. В репозитории на GitHub что-то уже лежит (например, README). Проще создать новый пустой репозиторий и подключить его; либо попросите ИИ помочь аккуратно объединить историю, объяснив, что именно вывел терминал.

Сайт открылся, но выглядит иначе, чем локально. Чаще всего не отправлена последняя версия. Сделайте git status: если там есть неотправленные изменения, выполните commit и push.

Картинка с вашего компьютера не показывается на сайте. Она должна лежать в папке public и быть закоммичена. Проверьте путь и регистр букв в имени.

07 Фишка урока: «Клон-день»

Лучший способ научиться — повторить то, что уже сделано хорошо. В «Клон-день» каждый выбирает сайт-референс (образец) и за один вечер пытается воспроизвести его внешний вид на своём проекте Next.js + Tailwind. Это не копия чужого кода, а тренировка: увидеть макет, описать его словами и добиться сходства с помощью ИИ. Блок рассчитан на преподавателя и подходит и для самостоятельного вечера.

Правила

1. Референс — любая одна страница (лендинг кафе, мастерской, школы, приложения) из тех, что вам нравятся. Берите простые одностраничные сайты, не сложные сервисы. 2. Повторяете композицию, цвета, типографику и сетку, а не логотипы, фирменные названия, тексты и фотографии: пишете свои вымышленные названия и берёте эмодзи или цветные блоки. 3. Новый проект с новым репозиторием и публикацией на Vercel (или новая ветка в текущем проекте). 4. Весь вечер вы только описываете и проверяете: код руками не пишете. 5. Результат — живая ссылка ….vercel.app и скриншот референса рядом с вашей версией.

Расписание вечера (около 2 часов)

ВремяЧто делают
0:00–0:10Выбирают референс, делают скриншот, выписывают 5 секций и 3 цвета
0:10–0:25Описывают ИИ макет словами по формуле промпта (контекст, цель, ограничения)
0:25–1:20Сборка и правки: сначала общая структура, затем цвета и шрифты, затем отступы, затем адаптив
1:20–1:40Commit, push, деплой на Vercel, проверка на телефоне
1:40–2:10«Галерея»: каждый показывает референс и свою версию, группа голосует

Шаблон промпта для клона

Читать подробнее: Vercel: деплои (на английском).

✓ Шпаргалка урока

  • Хостинг — сервер, где лежат файлы сайта. Домен — читаемое имя сайта. URL — полный адрес страницы: протокол + домен + путь. localhost видит только ваш компьютер.
  • Создание проекта: npx create-next-app@latest имя, выбрать рекомендуемые настройки; быстро: --yes. Нужен Node.js 20.9+.
  • Файлы: app/page.tsx — главная страница, app/layout.tsx — общая рамка, app/globals.css — общие стили с Tailwind, public — картинки, package.json — библиотеки и команды, node_modules — не трогаем.
  • Команды: npm run dev — разработка на localhost:3000, npm run build — проверка боевой сборки, Ctrl+C — остановка.
  • .tsx — TypeScript + JSX (React): подробно в уроке 7; ошибки типов копируем целиком и отправляем ИИ.
  • Tailwind: готовые классы прямо на элементе (px-8 bg-sky-600 rounded-full); sm: и hover: — адаптив и состояния. ИИ знает его словарь и правит одну строку без побочных эффектов.
  • Деплой: код на GitHub → импорт репозитория в Vercel → Deploy → ссылка ….vercel.app; дальше каждый git push обновляет сайт сам.
  • Если деплой упал: проект на Vercel → Deployments → деплой → Building → красные строки «Error» → скопировать блок целиком → отправить ИИ → проверить npm run build → commit и push.
  • Безопасность: секреты и ключи не кладём в код и репозиторий, личные данные не публикуем; правильное хранение ключей — в уроке 10.
