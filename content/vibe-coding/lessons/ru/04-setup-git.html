Нужны: компьютер (Windows или Mac) с правом устанавливать программы, интернет и около 2,5 часов. Раздел 1 выполните дома до урока: установка Node.js и Git занимает 20–30 минут, и на уроке это время нужно для практики. Откройте урок в одной половине экрана, а Cursor и терминал — в другой.

Это самый «технический» урок курса: часть слов будет незнакомой, и это нормально. Главное — повторять шаги и сверять результат с рисунками. Если что-то не получается, не ищите виноватого в себе: скопируйте текст ошибки и покажите его ИИ или преподавателю (раздел 7).

01 Перед уроком: установка Node.js и Git дома

Вам нужно поставить две программы: Node.js (вместе с ней придёт npm) и Git. Зачем они нужны, узнаете из теории; сейчас важно только установить их и проверить. Скачивайте программы только с официальных сайтов из этого списка: «взломанные» версии и установщики с чужих сайтов могут содержать вирусы.

Куда вводить команды проверки

Windows: нажмите кнопку «Пуск», наберите PowerShell и откройте «Windows PowerShell» (подойдёт и «Терминал»). macOS: нажмите Cmd+Пробел, наберите Terminal и нажмите Enter. Откроется окно с мигающим курсором: это терминал, подробнее о нём в разделе 4.

Windows

  1. Node.js. Откройте nodejs.org/en/download, выберите версию LTS (Long Term Support, «долгая поддержка» — самая стабильная) и скачайте установщик для Windows. Запустите его и нажимайте «Next», оставляя настройки по умолчанию. Если установщик предлагает поставить «necessary tools» (дополнительные инструменты) — ставить галочку не нужно, для курса хватит стандартной установки.
  2. Git. Откройте git-scm.com/install/windows, скачайте установщик Git-…-64-bit.exe (для компьютеров с процессором ARM — версию arm64) и запустите. Во всех окнах мастера нажимайте «Next»: настройки по умолчанию подходят для курса. Альтернатива для тех, кто любит терминал: winget install --id Git.Git -e --source winget.
  3. Перезапустите PowerShell: закройте окно и откройте новое. Это важно: старое окно не знает о только что установленных программах.
  4. Проверьте версии тремя командами из блока ниже. Если каждая напечатала номер версии — всё готово.

macOS

  1. Node.js. Откройте nodejs.org/en/download, выберите версию LTS, скачайте установщик для macOS (файл .pkg), откройте его и пройдите все шаги, оставляя настройки по умолчанию.
  2. Git. В терминале введите git --version. Если Git уже есть, появится номер версии. Если нет, macOS покажет окно с предложением установить «command line developer tools» (инструменты командной строки): нажмите «Установить» («Install») и дождитесь окончания — это может занять 5–15 минут. Вместе с ними придёт Git. Если вы пользуетесь Homebrew, можно выполнить brew install git.
  3. Закройте терминал и откройте заново, чтобы он увидел новые программы.
  4. Проверьте версии тремя командами из блока ниже.
node -v
npm -v
git --version

Ответ должен выглядеть примерно так (номера у вас будут свои, главное — что они есть):

v24.22.1
11.19.1
git version 2.50.1

Видео для Windows (на русском, около 1 минуты): установка Node.js. Берите версию LTS, даже если в ролике показан другой номер.

Видео для macOS (на русском, около 3 минут): то же самое для Mac. Ролик записан раньше, номера версий на нём устарели — это нормально.

Если команда не находится

Тексты вида node : The term 'node' is not recognized… (Windows) или zsh: command not found: node (macOS) почти всегда значат одно: терминал был открыт до установки. Закройте все окна терминала и откройте новое. Не помогло — перезагрузите компьютер. Другие ошибки (PowerShell и «Command Line Tools») разберём в разделе 8.

02 Редактор, терминал, Node.js, npm, Git, GitHub: зачем каждый

Профессиональная рабочая среда — это набор из шести простых «винтиков». Каждый делает одну вещь, и вместе они дают то, что вы будете использовать до конца курса. Сначала общая картина, потом подробности.

ИнструментЧто этоЗачем в курсе
Редактор кодаПрограмма, где вы открываете папку проекта, правите файлы и общаетесь с ИИ-помощником. Основной в курсе — Cursor, запасной — VS CodeЗдесь вы будете работать каждый урок
ТерминалОкно, в которое команды вводят текстом. Он встроен в редакторЗапуск проекта, установка пакетов, Git: всё это делается командами
Node.jsПрограмма, которая умеет запускать JavaScript не в браузере, а прямо на компьютереНужна для локального сервера, а позже для Next.js, Tailwind и других инструментов
npm«Магазин готовых деталей» для проектов: ставит чужие пакеты одной командой. Приходит вместе с Node.jsУстановка Next.js, Tailwind и других библиотек в следующих уроках

Аналогия из жизни

Представьте мастерскую в Душанбе. Редактор кода — верстак, на котором вы работаете. Терминал — телефон, по которому вы чётко говорите, что сделать («запусти», «сохрани», «отправь»). Node.js — электричество, без которого станки не включатся. npm — оптовый рынок запчастей. Git — тетрадь, куда мастер записывает каждую доработку с датой. GitHub — копия тетради, которую вы храните у надёжного родственника на случай, если дома что-то случится.

Типичные ошибки новичков

1. Путать Git и GitHub: Git — программа на вашем компьютере, GitHub — сайт, куда отправляют копию. Git работает и без GitHub. 2. Путать Node.js с JavaScript в браузере: Node.js — отдельная программа, браузеру она не нужна. 3. Путать VS Code с Visual Studio — это разные программы. 4. Думать, что терминал «ломает» компьютер: безобидные команды из урока ничего не удалят.

ЗАДАЧА 2.1

Проверь себя: инструменты

лёгкая

Что из этого делает Git?

  1. Показывает страницу в браузере
  2. Хранит сайт в интернете, чтобы его мог открыть любой человек
  3. Записывает историю изменений проекта на вашем компьютере, чтобы можно было вернуться к прошлой версии
  4. Подсказывает ИИ, какой код писать

Git — «тетрадь версий» проекта. Хранение копии в интернете делает GitHub, а страницу показывает браузер.

В чём разница между Git и GitHub?

  1. Это два названия одной и той же программы
  2. Git — программа для записи версий на вашем компьютере, GitHub — сайт, где хранится копия проекта в интернете
  3. Git платный, а GitHub бесплатный
  4. Git нужен только для сайтов, а GitHub — только для приложений

Git работает локально и без интернета. GitHub — один из сайтов, куда можно отправить («push») копию проекта.

Вместе с какой программой на компьютер приходит npm?

  1. С Node.js
  2. С Git
  3. С браузером Chrome
  4. С редактором кода

npm устанавливается вместе с Node.js: поэтому после установки Node.js работают обе команды, node -v и npm -v.

03 Cursor или VS Code: что выбрать и что делать с лимитами

Cursor — редактор кода, построенный на основе VS Code (вы уже установили VS Code в первом уроке). Внешне и по горячим клавишам они похожи: слева панель файлов, сверху вкладки, внизу терминал. Главное отличие — в Cursor ИИ-агент встроен в сам редактор: он видит все файлы проекта, умеет создавать и менять их, а вы проверяете результат.

VS Code
  • Бесплатный, стандарт отрасли
  • ИИ можно подключить расширениями
  • Уже установлен после урока 1
  • Все кнопки Git и терминала — как в Cursor
Cursor
  • На основе VS Code: интерфейс знаком
  • ИИ-агент встроен и видит весь проект
  • Есть бесплатный тариф с ограничениями
  • Основной редактор для курса
Аналогия из жизни

VS Code — хорошая чойхона: чистый зал, быстрая кухня, всё делаете сами. Cursor — та же чойхона, но с официантом, который понимает заказ «сделай как в прошлый раз» и сам идёт на кухню. Только не забывайте проверять, что принесли: ответственность за блюдо остаётся на вас.

Бесплатный тариф Cursor и его лимиты

На странице cursor.com/pricing указано: тариф Free стоит 0 долларов в месяц и включает ограниченное число запросов к агенту и в чат. Платные тарифы начинаются с Plus (8 долларов в месяц на момент написания урока). Точных цифр на странице нет, а условия и список моделей Cursor меняет часто — поэтому не планируйте работу «до последнего запроса». Когда лимит заканчивается, редактор показывает уведомление, а лимит обновляется со временем (смотрите раздел Usage в вашем аккаунте).

Как экономить запросы

1. Один запрос — одна понятная задача, а не «сделай весь сайт». 2. Правьте точечно («поменяй цвет кнопки в шапке»), а не просите переписать файл. 3. Не отправляйте один и тот же запрос повторно, если не прочитали ответ. 4. Для вопросов «что значит эта ошибка» подойдёт обычный чат с ИИ из урока 1.

Скачивать Cursor не с официального сайта cursor.com. 4. Паниковать, когда закончился лимит: переключитесь на запасной вариант и продолжайте, Git и терминал везде одинаковы.

Проверь себя: редакторы и лимиты

лёгкая

В Cursor закончился лимит запросов на бесплатном тарифе. Что разумнее всего сделать?

  1. Сразу купить самый дорогой тариф
  2. Продолжить работу в VS Code с чатом или бесплатным помощником, а в Cursor вернуться, когда лимит обновится
  3. Бросить курс: без Cursor работать нельзя
  4. Найти «взломанную» версию Cursor

Cursor — «форк» (ответвление) VS Code со встроенным ИИ. Ошибки возможны у любого ИИ, поэтому результат всегда проверяет человек.

04 Терминал и 10 базовых команд

Терминал (его ещё называют «командная строка» или «консоль») — это окно, в котором компьютером управляют текстом: вы печатаете команду, нажимаете Enter, терминал отвечает. Всё то же самое можно сделать мышкой в Проводнике или Finder, но терминал быстрее, а многие инструменты (Node.js, npm, Git) работают именно через него. В Cursor и VS Code терминал встроен: откройте его через меню «Terminal → New Terminal» или сочетанием Ctrl+` (на macOS — Control+`; значок ` находится на клавише с буквой Ё).

Аналогия из жизни

Проводник и Finder — это ходить по бозору и показывать пальцем на нужный товар. Терминал — позвонить знакомому продавцу и назвать точную просьбу: «пожалуйста, две лепёшки». Быстрее и точнее, но нужно знать слова. Десять слов ниже — весь «разговорник» на сегодня.

Где вы сейчас: папка, в которой работает терминал

Терминал всегда «стоит» в какой-то папке: команды выполняются там. Узнать, в какой именно, помогает команда pwd. Если вы открыли терминал в Cursor после «Open Folder», он стоит в папке проекта.

10 команд, которые работают и в Windows PowerShell, и в macOS

№КомандаЧто делает
1pwdПоказывает, в какой папке вы находитесь (print working directory)
2lsПоказывает, что лежит в текущей папке (list)
3mkdir имяСоздаёт новую папку (make directory)
4cd имяЗаходит в папку (change directory)
5echo "текст" > файл.txtСоздаёт файл и записывает в него текст
6cat файл.txtПоказывает содержимое файла
7cp что кудаКопирует файл (copy)
8mv что кудаПереименовывает или перемещает файл (move)
9rm файл.txtУдаляет файл (remove), минуя Корзину
10cd ..Выходит из папки на уровень выше (две точки — «родительская папка»)

Бонус: команда clear очищает экран. Клавиша Tab дописывает имя файла или папки (начните печатать и нажмите Tab), а стрелка ↑ возвращает предыдущую команду. В Windows PowerShell эти команды работают как «псевдонимы» встроенных команд PowerShell, а в macOS — как настоящие команды оболочки.

pwd
ls
mkdir bingo-test
cd bingo-test
echo "hello" > hello.txt
cat hello.txt
cp hello.txt copy.txt
mv copy.txt renamed.txt
rm renamed.txt
cd ..
Типичные ошибки новичков

1. Пробелы в именах папок и файлов: cd my site не сработает, терминал решит, что это два разных слова. Называйте папки латиницей, без пробелов (my-site). 2. Забыть, в какой папке находитесь: сначала pwd, потом команда. 3. Команда rm удаляет навсегда, в Корзину ничего не попадает: проверяйте имя перед Enter и не вставляйте в терминал чужие команды, которых не понимаете. 4. Копировать команды вместе с символом $ в начале строки: этот знак — часть приглашения, а не команды.

ЗАДАЧА 4.1

Проверь себя: терминал

лёгкая

Вы не помните, в какой папке стоит терминал. Какая команда это покажет?

  1. ls
  2. pwd
  3. cat
  4. mv

pwd печатает путь к текущей папке. ls показывает содержимое папки, а не её имя.

Вы находитесь в папке my-site и хотите выйти на уровень выше. Что ввести?

  1. cd my-site
  2. cd и закрыть терминал
  3. rm ..
  4. cd ..

Две точки означают «родительская папка». rm удаляет, а не переходит.

Что будет после команды rm notes.txt?

  1. Файл переместится в Корзину, его можно вернуть
  2. Файл будет переименован
  3. Файл будет удалён сразу и навсегда, минуя Корзину
  4. Откроется окно с вопросом «Вы уверены?»

Терминал не задаёт лишних вопросов и не использует Корзину. Поэтому перед Enter всегда перечитывайте команду.

05 Node.js, npm, localhost и порт

Node.js — программа, которая запускает JavaScript прямо на компьютере. До сих пор ваши страницы открывались двойным щелчком, и в адресной строке был путь вида file:///…. Профессиональные проекты открывают иначе: специальная программа («сервер») запускается на вашем компьютере и «раздаёт» страницу браузеру по адресу localhost. Так страница работает ближе к настоящему сайту в интернете, и так же запускаются Next.js и другие проекты курса.

Что значит localhost

localhost — это «этот самый компьютер». Адрес http://localhost:3000 означает: «зайди на этот же компьютер, на дверь с номером 3000». Страницу по такому адресу видите только вы: другие люди открыть её не смогут, пока вы не опубликуете сайт (урок 5).

Аналогия из жизни

Многоэтажка в Душанбе. Адрес дома — это localhost: «этот дом, вы внутри». Номер порта — номер подъезда или квартиры: в одном доме живёт много семей, и каждая отвечает на своём звонке. На порту 3000 может жить ваша страница, на порту 3001 — другой проект. Если подъезд занят, нужно позвонить в другой.

Порт и типичное сообщение «порт занят»

Порт — число от 0 до 65535, «номер двери» для программ на компьютере. Один порт может занять только одна программа. Если вы запустили два проекта на порту 3000, второй сообщит: address already in use («адрес уже используется»). Решение — остановить первый проект (Ctrl+C) или запустить второй на другом порту.

Что такое npm и npx

npm
Менеджер пакетов: команда npm install название скачивает чужой готовый код в ваш проект. С Next.js и Tailwind вы встретитесь в следующих уроках.
npx
Запускает пакет без постоянной установки. Сегодня вы используете npx serve: он скачает маленький сервер serve и запустит его в нужной папке. При первом запуске терминал спросит Ok to proceed? (y): ответьте y и нажмите Enter.
cd my-site
npx serve

Через несколько секунд терминал напечатает сообщение, примерно такое:

 INFO  Accepting connections at http://localhost:3000

Откройте этот адрес в браузере. Номер порта у вас может быть другим: берите адрес из вашего терминала. В новых версиях serve ответ может быть оформлен в рамочке и содержать строки «Local» и «Network»: нужна строка Local.

Типичные ошибки новичков

1. Закрыть терминал или нажать Ctrl+C и удивляться, что localhost «не открывается»: сервер остановился. 2. Запускать npx serve не в той папке: сервер покажет список файлов вместо страницы, потому что в папке нет index.html. Проверьте pwd и ls. 3. Набирать в браузере порт, которого нет в терминале. 4. Думать, что localhost — это сайт в интернете: его видите только вы.

06 Git как кнопка «сохранить»: commit и push

Вы наверняка теряли файл после неудачной правки или называли документы финал, финал2, финал-точно-последний. Git решает эту проблему: он запоминает состояние всей папки проекта в нужные моменты, и к любому из этих «снимков» можно вернуться. Для работы с ИИ это особенно важно: если очередная правка сломала страницу, вы откатываетесь к последнему рабочему снимку вместо того, чтобы искать, что именно поменялось.

Репозиторий (repo)
Папка проекта, за которой следит Git. Внутри неё появляется скрытая папка .git с историей. Её нельзя удалять и править руками.
Commit
Один «снимок» проекта с короткой подписью: что вы сделали. Как сохранение в игре: можно вернуться.
Push
Отправить свои коммиты на GitHub. Пока вы не сделали push, копии в интернете нет.
Ветка (branch)
Линия истории. Сейчас достаточно одной ветки, она называется main.
Аналогия из жизни

Торговец на бозоре записывает каждый день в тетрадь: «12 октября — продано 20 кг изюма, получено 840 сомони». Каждая запись — это commit: коротко и с датой. Если запись потерялась или ошибся в числах, можно найти, когда это случилось. Push — когда торговец раз в день фотографирует страницы и отправляет брату. Если лавка сгорит, тетрадь сохранится у брата. GitHub — «брат», у которого хранится копия вашей тетради.

Настройка Git: имя и почта (один раз)

В каждом коммите Git подписывает автора. Чтобы он знал, кто вы, один раз введите две команды (подставьте своё имя латиницей и почту):

git config --global user.name "Madina Rakhimova"
git config --global user.email "madina@example.com"

Проверить: git config --global user.name напечатает сохранённое имя. Если не настроить, на первом коммите Git ответит Author identity unknown и попросит представиться. Почту лучше указать ту же, на которую вы зарегистрируете GitHub: так коммиты привяжутся к вашему профилю. Если не хотите показывать настоящую почту, в настройках GitHub («Settings → Emails») можно скрыть её и взять специальный адрес вида …@users.noreply.github.com: его и укажите в user.email.

Вход в GitHub из редактора: пароль не подходит

GitHub давно не принимает обычный пароль от аккаунта для работы Git: в документации прямо написано, что «password-based authentication for Git has been removed». Но вводить ничего не придётся. Когда вы первый раз отправляете проект на GitHub из Cursor или VS Code, редактор сам предлагает войти: откроется браузер со страницей GitHub, вы нажимаете «Authorize» («Разрешить»), и браузер возвращает вас в редактор. Если возврата не произошло, в строке состояния внизу есть пункт «Signing in to github.com…»: нажмите на него и вставьте код из браузера.

Что не стоит отправлять на GitHub

Репозиторий можно сделать публичным (виден всем) или закрытым. Для домашних заданий он должен быть публичным, поэтому никогда не кладите в него пароли, ключи API, файлы .env и документы с личными данными. Запомните правило: секреты хранят в файле .env, который в Git не попадает (урок про Supabase покажет, как это делается). Если секрет случайно попал в репозиторий, считайте его скомпрометированным и замените на новый.

Видео на русском (14 минут): как устроен Git, коммиты и отправка на GitHub. Если нет времени, достаточно первых 7 минут. В ролике основной упор на команды; на уроке вы будете делать то же самое кнопками Source Control.

Типичные ошибки новичков

1. Делать один гигантский коммит в конце недели: правило курса «каждый шаг = коммит». 2. Писать сообщения вроде «asdf» или «правки»: через неделю вы не поймёте, что это было. Пишите коротко и по делу (add my-site, fix header color). 3. Забыть про push: коммит есть на компьютере, а на GitHub пусто. 4. Вводить пароль от GitHub в терминале — он не подойдёт. 5. Создавать репозиторий внутри другого репозитория или внутри папки, которая синхронизируется с облаком (OneDrive, iCloud): держите проекты в простой папке на диске.

07 ИИ-блок: как попросить помощь с ошибкой установки

ИИ как переводчик ошибок

В этом уроке ошибки будут: у каждого свой компьютер и своя версия системы. ИИ отлично объясняет сообщения терминала, но только если вы дали ему точный текст ошибки и сказали, какая у вас система. Пересказ «что-то не работает» не поможет. Формула та же: контекст → цель → ограничения → пример (текст ошибки) → проверка.

ничего не запускается, помоги
Контекст: новичок, первый раз работаю в терминале. Система: [Windows 11 или macOS], терминал внутри редактора Cursor, папка проекта vibe-course. Выполняется шаг: [ЧТО ДЕЛАЛИ, например "запуск npx serve"]. Цель: понять, что означает ошибка, и починить её. Ограничения: объясняй простыми словами; давай ровно одну команду за шаг и жди ответа; не предлагай удалять папки, переустанавливать систему и запускать команды с правами администратора без объяснения, чем это опасно. Текст ошибки (скопирован из терминала целиком): [ВСТАВЬТЕ ТЕКСТ ОШИБКИ БЕЗ ПАРОЛЕЙ И КЛЮЧЕЙ]. Проверка: после каждого шага скажи, что должно появиться на экране, если всё получилось.

Если первый совет не помог, не открывайте новый чат: ответьте в том же диалоге «сделал, появилось вот это: …» и вставьте новый текст из терминала. Так ИИ видит всю историю попыток. Копируйте только текст ошибки: не отправляйте в чат пароли, ключи и содержимое файла .env.

Полезные запросы по ходу урока

Объясни простыми словами, что делает команда: [КОМАНДА]. Что она изменит на компьютере и можно ли отменить? Ничего не запускай и не предлагай заменять команду.
Предложи 5 коротких понятных сообщений для коммита по такому изменению: [ОПИШИТЕ ИЗМЕНЕНИЕ СВОИМИ СЛОВАМИ]. Английский язык, до 50 символов, глагол в начале (например "add header").
Прочитай этот вывод команды git status и объясни, что в нём означает каждая строка и что делать дальше: [ВСТАВЬТЕ ВЫВОД].
Правила безопасности

1. Не запускайте команды из чата, смысл которых не понимаете: попросите объяснить (первый запрос выше). 2. Особо опасны rm -rf, sudo и всё, что просит «отключить защиту» или скачать файл с неизвестного сайта. 3. Если ИИ советует отключить антивирус или обойти проверку подписи, остановитесь и спросите преподавателя.

08 Практика: окружение, localhost и первый push

Идём по порядку: подготовим папку, установим Cursor, заведём аккаунты, запустим проект из терминала и отправим его на GitHub. Каждый шаг короткий. Если застряли, посмотрите блок «Если сломалось» в конце раздела.

Шаг 0. Подготовьте папку проекта

  1. На рабочем столе создайте папку vibe-course (латиницей, через дефис). Это будет ваш репозиторий.
  2. Скопируйте в неё (не перемещайте!) папки my-site из урока 1, coffee из урока 2 и fitness из урока 3. Копируйте через Ctrl+C / Ctrl+V (в macOS — Cmd+C / Cmd+V). Какой-то из папок нет — не страшно, возьмите те, что есть.

Шаг 1. Установите Cursor и заведите аккаунты

  1. Cursor. Откройте cursor.com/download, нажмите кнопку скачивания для вашей системы. Windows: запустите скачанный установщик и пройдите его шаги. macOS: откройте скачанный файл и перетащите Cursor в папку «Программы» (Applications).
  2. Запустите Cursor из меню «Пуск» (Windows) или из «Программ» (macOS). Редактор попросит войти: создайте бесплатный аккаунт Cursor (можно через Google или почту) и подтвердите вход в браузере. Если предложит перенести настройки из VS Code, можете согласиться или пропустить: для курса это не важно.
  3. GitHub. Откройте github.com/signup, зарегистрируйтесь (можно через «Continue with Google»), придумайте имя пользователя латиницей: оно будет в ссылке на ваши работы, поэтому выберите нейтральное и аккуратное (например, madina-rakhimova). Подтвердите почту: без этого GitHub не даст создать репозиторий. Рекомендуем сразу включить двухфакторную защиту.
ЗАДАЧА 8.1

Чек-лист: редактор и аккаунты

лёгкая
  • Папка vibe-course создана, в неё скопированы работы из уроков 1–3
  • Cursor установлен, запускается, выполнен вход в аккаунт (или установлен запасной вариант: VS Code)
  • Аккаунт GitHub создан, почта подтверждена, имя пользователя запомнено или записано
  • Двухфакторная защита GitHub включена (рекомендуется)

Шаг 2. Откройте папку и терминал

  1. В Cursor выберите «File → Open Folder…» и укажите папку vibe-course. На вопрос «Trust the authors?» («Доверяете авторам?») ответьте «Yes, I trust the authors»: это ваша папка.
  2. Откройте терминал: «Terminal → New Terminal» или Ctrl+` (на macOS — Control+`). Внизу появится панель терминала, и она уже стоит в папке проекта. Проверьте командой pwd.
  3. Проверьте инструменты командами node -v, npm -v, git --version. Если вышла ошибка — смотрите «Если сломалось» ниже.

Шаг 3. Представьтесь Git

  1. В терминале введите две команды из раздела 6, подставив своё имя латиницей и почту, на которую зарегистрирован GitHub (или адрес …@users.noreply.github.com из настроек GitHub).
  2. Проверьте: git config --global user.name и git config --global user.email должны напечатать то, что вы ввели.

Шаг 4. Запустите проект на localhost

  1. Войдите в папку: cd my-site. Проверьте, что ls показывает index.html.
  2. Запустите сервер: npx serve. Если терминал спросит Ok to proceed? (y), введите y и нажмите Enter.
  3. Дождитесь строки с адресом http://localhost:… и откройте его в браузере (в терминале Cursor можно нажать на адрес с зажатым Ctrl или Cmd). Вы увидите свою страницу.
  4. Сделайте скриншот для домашнего задания: окно браузера с адресом localhost:… в адресной строке и рядом терминал с запущенным сервером.
  5. Остановите сервер: нажмите Ctrl+C в терминале, затем выйдите из папки командой cd ...

Шаг 5. Первый коммит кнопкой Source Control

  1. Создайте в корне vibe-course файл README.md (значок «New File» в панели файлов) и напишите в нём две строки: заголовок # vibe-course и список работ (my-site, coffee, fitness). Сохраните файл (Ctrl+S / Cmd+S).
  2. Слева на боковой панели нажмите значок Source Control (три кружка, соединённые линиями) или сочетание Ctrl+Shift+G (на macOS — Control+Shift+G). Если папка ещё не под Git, появится кнопка Initialize Repository: нажмите её. То же самое делает команда git init.
  3. В списке «Changes» будут все ваши файлы с буквой U (untracked — «новый, Git его ещё не видел»). В поле «Message» напишите сообщение: add my-site, coffee, fitness и нажмите Commit. Если редактор спросит, добавить ли все изменения в коммит («stage all changes»), согласитесь.
  4. После коммита кнопка превратится в Publish Branch. Нажмите её: редактор предложит создать репозиторий на GitHub. Выберите public (публичный) и подтвердите. Первый раз откроется браузер: войдите в GitHub и нажмите «Authorize» («Разрешить»), затем вернитесь в редактор. Пароль нигде вводить не нужно.
  5. Когда редактор покажет уведомление об успехе, откройте репозиторий на сайте: github.com/ваш-логин/vibe-course. Вы должны увидеть свои папки и файл README.

Шаг 6. Второй коммит: привычка «каждый шаг = коммит»

  1. Откройте README.md и допишите строку со своим именем и одним предложением о том, чему научились сегодня. Сохраните.
  2. В Source Control появится файл с буквой M (modified, «изменён»). Напишите сообщение update readme и нажмите Commit.
  3. Нажмите Sync Changes: коммит отправится на GitHub. Обновите страницу репозитория в браузере: в списке коммитов должно быть минимум два.
С этого урока: каждый шаг = коммит

После каждого значимого шага (страница заработала, добавили блок, починили ошибку) делайте коммит с понятным сообщением, а в конце работы — push. Если следующая правка ИИ сломает проект, вы просто вернётесь к прошлому коммиту. Домашние задания теперь сдаются ссылкой на GitHub.

Если сломалось

PowerShell: «выполнение сценариев отключено» (Windows)

При запуске npx или npm в Windows PowerShell может появиться красный текст вида: npx : File C:\Program Files\nodejs\npx.ps1 cannot be loaded because running scripts is disabled on this system (в русской Windows: «…так как выполнение сценариев отключено в этой системе»). Это защита PowerShell: пока политика выполнения («execution policy») запрещает скрипты, npx.ps1 не запустится. Разрешите запуск локальных скриптов только для вашего пользователя:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

На вопрос о смене политики ответьте Y (или «Д»), затем закройте терминал и откройте заново. Политика RemoteSigned разрешает ваши локальные скрипты, но требует подписи для скриптов, скачанных из интернета. Если команда пишет, что параметр задан групповой политикой (рабочий или школьный компьютер), в выпадающем списке рядом с «+» в панели терминала выберите профиль Command Prompt: там эта защита не действует.

macOS: запрос на установку Command Line Tools

Если Git не установлен, первая команда git вызывает окно с текстом примерно «The “git” command requires the command line developer tools. Would you like to install the tools now?». Нажмите «Install» («Установить»), примите условия и дождитесь окончания (5–15 минут). Вторая команда терминала, запущенная во время установки, снова вызовет окно: просто подождите. Когда окно закроется, повторите команду. Если окно не появилось, запустите в терминале xcode-select --install. Потом закройте терминал и откройте заново.

Другие частые ошибки

node : The term 'node' is not recognized / zsh: command not found: node. Терминал открыт до установки Node.js: закройте все окна терминала (и перезапустите Cursor), откройте заново. На Windows при необходимости перезагрузите компьютер.

fatal: not a git repository (or any of the parent directories): .git. Папка не инициализирована или вы не в той папке: проверьте pwd, откройте в редакторе именно vibe-course и нажмите Initialize Repository в Source Control.

Author identity unknown / Please tell me who you are. Git не знает автора. Выполните две команды git config --global user.name и user.email из раздела 6.

Error: listen EADDRINUSE: address already in use :::3000 или сообщение «Port 3000 is already in use». Порт занят другой программой, возможно, вашим же старым запуском. Нажмите Ctrl+C в окне, где он работает, или выберите другой порт: npx serve -l 3001.

Браузер пишет «Не удаётся получить доступ к сайту» / «localhost refused to connect». Сервер не запущен (вы остановили его Ctrl+C) или в адресе другой порт. Запустите npx serve снова и откройте адрес из терминала.

remote: Support for password authentication was removed или Authentication failed при push. Пароль от GitHub для Git не подходит. Не вводите его: нажмите Publish Branch или Sync Changes ещё раз и пройдите вход через браузер. Если вход не завершается, в строке состояния нажмите «Signing in to github.com…» и вставьте код из браузера.

Не получается войти в Cursor или он недоступен. Попробуйте снова через несколько минут; если не помогло, продолжайте урок в VS Code: терминал, Git и GitHub работают в нём точно так же (раздел 3).

В списке изменений сотни файлов. Скорее всего, вы открыли слишком большую папку (например, весь рабочий стол). Закройте папку и откройте именно vibe-course. Если Git случайно инициализирован в лишней папке, попросите помощи у преподавателя: не удаляйте ничего наугад.

ЗАДАЧА 8.3

Если сломалось: найди причину

средняя

В Windows PowerShell команда npx serve вывела красный текст: «npx.ps1 cannot be loaded because running scripts is disabled on this system». Что делать?

  1. Переустановить Windows
  2. Выполнить Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, подтвердить и открыть терминал заново
  3. Удалить Node.js
  4. Скачать npx.ps1 с другого сайта

PowerShell по умолчанию запрещает запуск скриптов, а npx в нём — скрипт. Команда разрешает локальные скрипты для вашего пользователя без прав администратора.

При push терминал пишет «Support for password authentication was removed». Что верно?

  1. Нужно ввести пароль ещё раз, внимательнее
  2. Нужно сменить пароль на более длинный
  3. Пароль для Git на GitHub не подходит: войдите через браузер, используя кнопки Publish Branch или Sync Changes
  4. Нужно создать новый аккаунт

GitHub не принимает пароль от аккаунта для Git. Редактор открывает браузер и получает разрешение без пароля в терминале.

На macOS после git --version появилось окно «The “git” command requires the command line developer tools». Что нажать?

  1. «Install» («Установить») и дождаться окончания, затем повторить команду
  2. «Cancel» и больше не пользоваться Git
  3. Закрыть терминал и скачать Git с неизвестного сайта
  4. Перезагрузить Mac, не нажимая ничего

Это штатный способ получить Git на macOS: вместе с инструментами командной строки приходит и Git.

09 Фишка урока: «Терминал-бинго»

Закрепим 10 команд игрой. У каждого участника карточка из десяти клеток; задача — выполнить команду в своём терминале, увидеть результат и отметить клетку. Блок рассчитан на преподавателя и подходит и для аудитории, и для онлайн.

Правила

1. Работаем в терминале Cursor или VS Code в учебной папке bingo-test (её создаёт команда 3): основные проекты не трогаем. 2. Клетки закрываются по порядку 1–10, как в примере из раздела 4. 3. Команду нужно набрать самому (можно подсматривать в таблицу). Копирование из чата не считается. 4. После каждой команды сверьтесь с тем, что напечатал терминал: ошибок быть не должно. 5. Закрыли все десять клеток — поднимите руку или напишите «Бинго!» в чат группы.

Как проводить (для преподавателя)

ВремяЧто делают
0:00–1:00Показать карточку на экране, объяснить правила, напомнить про осторожность с rm
1:00–9:00Участники закрывают клетки; преподаватель ходит по рядам или смотрит демонстрацию экрана у тех, кто просит помощи
9:00–12:00«Бинго!»: первые трое получают бонусный балл; проверка — просьба показать терминал с историей команд
12:00–15:00Разбор: какая команда вызвала больше всего ошибок, какая оказалась самой полезной

Усложнения

  • Без подсказок: таблицу команд скрывают, пользоваться можно только стрелкой ↑ и клавишей Tab.
  • Бинго-линия: первый, кто закрыл любые пять клеток подряд (1–5 или 6–10), получает «полбинго».
  • Командный режим: пары. Один диктует команду по картинке, второй набирает; затем меняются.
  • Бонус: выполнить node -v, npm -v, git --version и git status в папке vibe-course — это «звёздные» клетки.
Для преподавателя

Если у кого-то не работает PowerShell или не стоит Git, не останавливайте игру: пусть этот участник играет в паре с соседом. После игры спросите, какие ошибки встретились, и разберите две-три на экране: это самая ценная часть. Перед игрой убедитесь, что рядом нет важных файлов: команда rm удаляет без Корзины.

10 Домашнее задание: скриншот localhost и ссылка на репозиторий

ДЗ-4 подтверждает, что у вас работает вся цепочка: проект запускается на localhost, а работы лежат в публичном репозитории GitHub с историей коммитов. Начиная с этого урока домашние задания сдаются ссылкой на GitHub.

Что нужно сделать

  1. Скриншот окружения. Запустите npx serve в любой из своих работ (my-site, coffee или fitness) и сделайте один скриншот: браузер с адресом localhost:… и терминал с запущенным сервером. Отправьте скриншот в чат группы.
  2. Репозиторий. Убедитесь, что vibe-course опубликован на GitHub как public и в нём видны my-site, coffee, fitness (все, что у вас есть) и README.md.
  3. История. В репозитории не меньше двух коммитов с понятными сообщениями (например, add my-site, coffee, fitness и update readme).
  4. Проверка ссылки. Откройте ссылку в окне инкогнито: страница должна открыться без входа. Если просит войти, репозиторий закрытый (private): откройте его «Settings» на GitHub и смените видимость на Public.
  5. Сдайте ссылку в поле ниже: адрес вида https://github.com/ваш-логин/vibe-course.
Типичные ошибки в домашнем задании

1. Ссылка на закрытый репозиторий: проверяющий не сможет её открыть. 2. Скриншот без адреса localhost в адресной строке или с адресом file:///…: это не localhost. 3. Репозиторий пустой: сделан commit, но не push. 4. Ссылка не на репозиторий, а на профиль или на один файл. 5. В репозитории лежат пароли, ключи или личные документы. 6. Все файлы в одном коммите «update» — тренируйте привычку «каждый шаг = коммит».

Как проверяющий оценит

  • Ссылка открывается без входа и ведёт именно на репозиторий.
  • Видны папки работ 1–3 и README.md со своим именем.
  • В истории не меньше двух коммитов, автор подписан именем (не «unknown»).
  • На скриншоте виден адрес localhost с портом и запущенный сервер.
  • Нет секретов и файлов .env.
