01 App Router: папка — это адрес

В уроке 7 вы просили ИИ создать app/cafe/page.tsx и получили адрес /cafe. Сегодня разбираем, почему это работает. В Next.js действует файловый роутинг: адрес страницы определяется структурой папок. Не нужно писать список маршрутов в коде и что-то регистрировать: создали папку и файл — страница появилась.

Сегмент
Одна часть адреса между слэшами. В /services/web два сегмента: services и web. Каждому сегменту соответствует папка.
page.tsx
Файл, который делает адрес открываемым. Внутри — компонент с export default. Без этого файла папка — просто папка, адрес не появится.
layout.tsx
Общая «рамка» для страниц: шапка, подвал, фон. Разберём в разделе 2.
Динамический сегмент
Папка в квадратных скобках, например [slug]: один файл обслуживает много адресов (/cases/bank, /cases/cafe).

Как выглядит страница и динамический адрес

export default function ServicesPage() {
  return (
    <main>
      <h1>Услуги</h1>
    </main>
  );
}

export default async function CasePage({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  return <h1>Кейс: {slug}</h1>;
}

Страница — это обычный компонент из урока 7, только с именем файла page.tsx. У динамической страницы адрес /cases/bank передаёт slug = "bank". В Next.js 16 params приходит как «обещание» (Promise), поэтому перед использованием его нужно «дождаться» словом await — ИИ делает это сам, просто не удаляйте await.

Аналогия из жизни

Корпус на бозоре. Каждая дверь в ряду — папка, а табличка «Открыто» на двери — файл page.tsx. Дверь без таблички есть, но покупателя не пустят: получите 404. Квадратные скобки — это как лавка «Всё на заказ»: одна лавка принимает любые названия товаров и выдаёт нужный.

Типичные ошибки новичков

1. Назвать файл Services.tsx или index.tsx вместо page.tsx: страницы не будет. 2. Положить папку не внутрь app, а рядом: Next.js её не увидит. 3. Написать pages/about.tsx по старым руководствам: так работал прежний Pages Router, в нашем проекте он не нужен. 4. Забыть export default в page.tsx.

  1. app/about.tsx

  3. app/pages/about.tsx

  4. Папку, в которой хранятся только картинки

02 Общий layout: шапка и подвал один раз

Если шапку копировать в каждую из пяти страниц, при первой же правке меню придётся менять пять файлов. Для этого есть layout: компонент-«рамка», внутрь которой Next.js подставляет нужную страницу. Вы уже видели файл app/layout.tsx в новом проекте — это корневой layout. Он обязателен и обязан содержать теги <html> и <body>.

import "./globals.css";
import Header from "@/components/Header";
import Footer from "@/components/Footer";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="ru">
      <body>
        <Header />
        <main>{children}</main>
        <Footer />
      </body>
    </html>
  );
}

Главное слово здесь — children (prop из урока 7). Это «то, что положили внутрь»: при адресе /services там окажется app/services/page.tsx, при /cases — app/cases/page.tsx. Шапка и подвал остаются теми же.

Layout не перезагружается и бывает вложенным

При переходе между страницами Next.js заменяет только содержимое children, а layout остаётся на месте: он не перерисовывается заново и не теряет состояние (например, открытое меню или текст в поле поиска в шапке). Layout можно вкладывать: файл app/cases/layout.tsx обернёт только страницы раздела /cases, а корневой — все сразу.

Ролик на английском, 4,5 минуты, включите субтитры: как работает layout.tsx и вложенность. Версия Next.js в ролике 15, но для layout правила те же, что в 16.

Аналогия из жизни

Маршрутка. Кузов, водитель и табличка с маршрутом — layout: они едут весь путь. Меняются только пассажиры на сиденьях — это children. На каждой остановке (странице) салон не перекрашивают, а лишь пересаживают людей.

Типичные ошибки новичков

1. Копировать шапку в каждую страницу вместо одного layout.tsx. 2. Забыть {children} в layout: страницы просто не появятся. 3. Добавить второй <html> или <body> во вложенный layout — они нужны только в корневом. 4. Поставить lang="en" на русскоязычном сайте: поисковики и читалки экрана решат, что язык другой.

03 Навигация: Link вместо обычной ссылки

Между страницами сайта переходят компонентом Link из next/link. Он выглядит как обычная ссылка <a> и даже превращается в неё в HTML, но умеет два трюка: переход без перезагрузки всей страницы (меняется только children, layout остаётся) и предзагрузку страницы, пока ссылка видна на экране. Предзагрузка работает только в боевой сборке (npm run build и деплой), в режиме npm run dev вы её не увидите.

import Link from "next/link";

export default function Cta() {
  return (
    <>
      {/* внутренний адрес сайта: Link */}
      <Link href="/contacts">Связаться с нами</Link>

      {/* внешний сайт: обычная ссылка */}
      <a href="https://t.me/saru_studio" target="_blank" rel="noopener">Telegram</a>
    </>
  );
}

Меню с подсветкой текущей страницы

Чтобы посетитель понимал, где он, пункт меню текущей страницы выделяют. Узнать адрес помогает хук usePathname из next/navigation. Это хук, а хуки (как useState в уроке 8) работают только в клиентских компонентах, поэтому файл меню начинается с "use client". Сами страницы и layout при этом остаются серверными: Metadata API из раздела 5 работает именно там.

"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";

const items = [
  { href: "/", label: "Главная" },
  { href: "/services", label: "Услуги" },
  { href: "/cases", label: "Кейсы" },
  { href: "/about", label: "О компании" },
  { href: "/contacts", label: "Контакты" },
];

function isActive(pathname: string, href: string) {
  if (href === "/") return pathname === "/";
  return pathname === href || pathname.startsWith(href + "/");
}

export default function Nav() {
  const pathname = usePathname();
  return (
    <nav className="flex gap-4">
      {items.map((item) => (
        <Link
          key={item.href}
          href={item.href}
          aria-current={isActive(pathname, item.href) ? "page" : undefined}
          className={isActive(pathname, item.href) ? "font-bold text-brand-600" : "text-slate-600"}
        >
          {item.label}
        </Link>
      ))}
    </nav>
  );
}

Всё в этом файле вам знакомо: массив и map (урок 7), условие в классе (урок 8). Новое — только usePathname и функция isActive. Зачем в ней два условия? Адрес / — начало любого адреса, поэтому для главной сравниваем строго. А раздел /services должен оставаться «активным» и на вложенной странице /services/web, но не на /servicesX: поэтому проверяем href + "/".

Потренируйтесь на «чистой» логике. В Next.js адрес даёт usePathname, а здесь он приходит как prop, и вместо Link стоит обычная ссылка (компонент Link в браузере урока недоступен).

Чем <Link href="/services"> лучше обычной ссылки для перехода внутри сайта?

  2. Ссылка автоматически становится красивее
  3. Работает без интернета

Link заменяет только children и подгружает следующую страницу заранее. Внешний вид задают классами, как у любой ссылки.

В файле меню вы используете usePathname(). Что обязательно должно стоять в начале файла?

  1. "use server"
  2. "use client"
  3. export const metadata

Хуки работают только в клиентских компонентах, поэтому нужна директива "use client" (урок 8). metadata, наоборот, экспортируют из серверных файлов.

Как правильно оформить ссылку на ваш Telegram-канал https://t.me/saru_studio?

  1. <Link href="t.me/saru_studio"> без https
  2. <Link href="/https://t.me/saru_studio">

  4. Положить файл app/t.me/page.tsx

04 Картинки: next/image

Обычная <img> скачивает файл «как есть»: фото с телефона на 4 МБ грузится и на ноутбуке, и на смартфоне с медленным интернетом. Компонент Image из next/image берёт это на себя: отдаёт подходящий размер и современный формат, откладывает загрузку картинок за пределами экрана и резервирует место, чтобы текст не «подпрыгивал», когда картинка загрузилась.

import Image from "next/image";

export default function Examples() {
  return (
    <>
      {/* 1. Размер известен: width и height обязательны */}
      <Image src="/images/team.webp" alt="Команда студии за работой" width={800} height={533} />

      {/* 2. Картинка заполняет блок: родителю нужен position: relative */}
      <div className="relative h-64 w-full">
        <Image src="/images/office.webp" alt="Офис студии" fill sizes="(max-width: 768px) 100vw, 50vw" className="object-cover" />
      </div>
    </>
  );
}
PropЧто делает
srcПуть к файлу: /images/team.webp значит файл public/images/team.webp (слово public в пути не пишут)
altОписание для читалок экрана и поисковиков; обязателен. Для чисто декоративной картинки — пустая строка alt=""
width, heightНастоящий размер файла в пикселях: нужен браузеру, чтобы зарезервировать место. Показываемый размер задают CSS-классами
fillВместо width и height: картинка заполняет родителя. У родителя должен быть position: relative (в Tailwind — класс relative) и размер; обрезку задаёт object-cover
sizesПодсказка, какую часть экрана займёт картинка: браузер скачает файл нужного размера, а не самый большой
preloadЗагрузить картинку заранее: только для самой первой картинки экрана. В старых примерах вместо него встретится priority: с Next.js 16 это название устарело
Откуда брать картинки

Свои фото или картинки с бесплатных стоков, где разрешено использование (проверьте лицензию). Кладите в public/images, формат .webp или .jpg, до 300 КБ на файл — большие пережмите. Для логотипов и значков подойдёт .svg: Next.js сам не оптимизирует его (SVG и так лёгкий). Картинки с чужого адреса (https://…) нужно сначала разрешить в next.config.ts в настройке images.remotePatterns, иначе будет ошибка: это защита от чужих злоупотреблений. Для учебного сайта проще положить файлы в public.

Аналогия из жизни

Фотограф на свадьбе приносит снимки сразу в трёх размерах: маленький для телефона, средний для планшета и большой для печати. Гость с телефона получает лёгкую версию и не ждёт. next/image — такой фотограф: он сам готовит нужный размер и формат под устройство.

Типичные ошибки новичков

1. Не указать alt или написать «картинка» / «image1». Пишите, что на фото, коротко и по делу. 2. Писать путь /public/images/team.webp: файлы из public доступны от корня сайта. 3. Использовать fill без relative у родителя: картинка улетает или растягивается на весь экран. 4. Указать width и height «от балды», в другой пропорции, чем файл: картинка исказится, пока CSS не задаст размер. 5. Разместить картинку с чужого сайта без remotePatterns: ошибка вида Invalid src prop … hostname "…" is not configured under images in your next.config.js. 6. Ставить preload на все картинки: выигрыш пропадает.

ЗАДАЧА 4.1

Проверь себя: next/image

средняя

Картинка лежит в public/images/team.webp, её размер 800×533 пикселей. Как правильно подключить?

  1. <Image src="/public/images/team.webp" alt="Команда" />
  2. <Image src="/images/team.webp" alt="Команда" width={800} height={533} />
  3. <Image src="images/team.webp" width={800} />
  4. <Image src="C:\\site\\team.webp" alt="Команда" />

Путь начинается от корня сайта без слова public; нужны alt и оба размера (если не используется fill).

Вы поставили <Image fill … /> внутрь <div>, и картинка расползлась по всей странице. Что проверить в первую очередь?

  1. У родителя нет position: relative (класс relative) и заданной высоты
  2. Забыт "use client"
  3. Файл слишком маленький
  4. Нужно заменить Image на Link

При fill картинка позиционируется относительно ближайшего позиционированного родителя, поэтому родителю нужны relative и размер.

В <Image src="https://images.example.com/photo.jpg" … /> терминал показал ошибку про hostname, который не настроен в next.config. Что делать?

  1. Удалить alt
  2. Поставить priority
  3. Добавить адрес в images.remotePatterns в next.config.ts или скачать файл в public (с учётом лицензии)
  4. Заменить Image на Link

Внешние адреса для оптимизации нужно разрешить явно. Для учебного проекта проще положить картинку в public.

05 Метатеги и базовое SEO

SEO — это приёмы, которые помогают поисковикам понять, о чём ваша страница, и показать её нужным людям. Начинается всё с двух строчек, которые видны в результатах поиска: title (синий заголовок) и description (серое описание под ним). В Next.js их задают через Metadata API: в файле layout.tsx или page.tsx экспортируется объект metadata, а Next.js сам создаёт теги в <head> страницы.

import type { Metadata } from "next";

export const metadata: Metadata = {
  title: {
    default: "Студия «Сарв» — сайты и приложения в Душанбе",
    template: "%s | Студия «Сарв»",
  },
  description: "Делаем сайты и приложения для бизнеса в Душанбе. Фиксированная цена в сомони.",
  openGraph: {
    title: "Студия «Сарв»",
    description: "Сайты и приложения для бизнеса в Душанбе.",
    type: "website",
    locale: "ru_RU",
  },
};

import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Услуги",
  description: "Сайты, приложения и поддержка: что входит и сколько стоит в сомони.",
};

export default function ServicesPage() {
  return <h1>Услуги</h1>;
}

Шаблон "%s | Студия «Сарв»" из корневого layout подставит название страницы вместо %s: в <title> будет «Услуги | Студия «Сарв»». Для главной берётся default. Поле openGraph задаёт заголовок и описание для карточки при отправке ссылки в Telegram и соцсети (картинку карточки можно положить в app/opengraph-image.png — Next.js подключит её сам).

Важное правило слияния

Если страница задаёт свой openGraph, он целиком заменяет общий из layout, а не дополняет его. Поэтому для страниц, где вам нужны особые данные для соцсетей, перепишите все нужные поля, а общую картинку вынесите в файл opengraph-image.

Ролик на английском, 8 минут, включите субтитры: статические метаданные, шаблон заголовка, generateMetadata. Для этого урока важны первые 5 минут.

Базовое SEO: чек-лист на каждую страницу

  • Свой title и description у каждой страницы: у «Услуг» и «Контактов» они не должны совпадать. Заголовок — коротко (около 50–60 символов), описание — 1–2 предложения (около 150 символов), по делу и без «лучшие в мире».
  • Один <h1> на странице: главная мысль страницы. Подзаголовки — <h2>.
  • Осмысленные адреса: /services, а не /page2. Они же помогают посетителю понять, где он.
  • alt у каждой содержательной картинки.
  • Язык: <html lang="ru"> в корневом layout.
  • Мобильная версия: сайт должен хорошо выглядеть на телефоне (урок 3 и Tailwind).
  • Файлы robots.ts и sitemap.ts в папке app: Next.js превратит их в /robots.txt и /sitemap.xml — карту сайта для поисковиков. Для первого сайта хватит просьбы к ИИ их сгенерировать.
Честно про SEO

Метатеги не гарантируют позиций: на них влияет содержание, скорость, ссылки на сайт и многое другое. Метатеги — основа, без которой остальное не работает. И ещё: не размещайте на сайте скрытый текст или «простыню» ключевых слов — поисковики наказывают за это.

Аналогия из жизни

Вывеска и меню у входа в чойхону. Вывеска (title) говорит прохожему, что внутри; строка под ней (description) — чем здесь кормят. Если на всех пяти дверях одинаковая вывеска «Магазин», никто не поймёт, куда идти. А хорошая вывеска не гарантирует очередь, но без неё очереди точно не будет.

Типичные ошибки новичков

1. Положить export const metadata в файл с "use client": сборка остановится с сообщением, что экспорт metadata из клиентского компонента запрещён. Метаданные живут в серверных page.tsx и layout.tsx. 2. Оставить в layout.tsx заготовку «Create Next App»: она покажется в Telegram и поиске. 3. Написать title: "Услуги | Студия «Сарв»" на странице при готовом шаблоне: получится «Услуги | Студия «Сарв» | Студия «Сарв»». 4. Сделать description одинаковым на всех страницах. 5. Указать относительный адрес картинки в openGraph.images и не задать metadataBase: сборка выдаст ошибку, нужен адрес сайта целиком.

ЗАДАЧА 5.1

Проверь себя: metadata и SEO

средняя

В корневом layout.tsx задан шаблон title: { template: "%s | Сарв", default: "Сарв" }, а в app/about/page.tsx — title: "О компании". Какой <title> у страницы /about?

  1. О компании
  2. О компании | Сарв
  3. %s | Сарв
  4. Сарв | О компании

Next.js подставляет название страницы вместо %s в шаблон из родительского layout.

Где можно экспортировать metadata?

  1. В серверных page.tsx и layout.tsx (без "use client")
  2. Только в файлах с "use client"
  3. В любом компоненте из папки components

Что относится к базовому SEO страницы? (выберите все верные варианты)

  3. Один <h1> и осмысленный alt у картинок
  4. <html lang="ru"> и понятные адреса вроде /services

Дублирующиеся описания не помогают поисковику отличить страницы. Остальное — основа, на которой строится всё остальное SEO.

06 Дизайн-система в Tailwind: цвета и правила в одном месте

Когда сайт из пяти страниц, а цвет кнопки «Связаться» записан в двадцати местах как bg-[#0e7a55], смена бренда превращается в поиск по всему проекту. Дизайн-система — это договорённость: цвета, шрифты, скругления и отступы заданы один раз, а страницы только используют их. Состоит она из двух слоёв.

Токены в Tailwind 4

Tailwind CSS 4 настраивается прямо в файле app/globals.css блоком @theme. Любая переменная из «пространства» --color-*, --font-*, --radius-* превращается в классы:

@import "tailwindcss";

@theme {
  --color-brand-50: #ecfdf5;
  --color-brand-600: #0e7a55;
  --color-brand-700: #0b6045;
  --color-ink: #0f172a;
  --radius-card: 16px;
}

Теперь доступны классы bg-brand-600, text-brand-700, bg-brand-50, text-ink и rounded-card. Чтобы сменить палитру, вы правите три строки в одном файле. В новом проекте в globals.css уже могут быть переменные и блок @theme inline для шрифтов: не удаляйте их, добавьте свой блок @theme рядом.

Правило из урока 7 остаётся в силе

Tailwind находит в коде только целые названия классов. Нельзя собирать bg-${color}-600: стиль не появится. Если цвет приходит как prop, передавайте полное название класса целиком, например accent="bg-brand-600".

Попробуйте идею на чистом CSS

Принцип «одно значение — много мест» одинаков и в Tailwind (@theme), и в обычном CSS (переменная var(--brand)). В Tailwind вы уже используете готовые классы, а здесь потренируйтесь в самой идее: три элемента должны брать цвет из одной переменной.

ЗАДАЧА 6.1

Один токен вместо трёх цветов

средняя

В CSS цвет #0e7a55 записан в трёх правилах вручную. Замените его в каждом на var(--brand) (переменная --brand уже объявлена вверху). Проверка сменит --brand на красный и посмотрит, перекрасились ли все три элемента. Блок «ПРОВЕРКА» не трогайте.

<header class="bar">
  <a class="link" href="#">Services</a>
  <span class="badge">New</span>
  <button class="btn">Contact us</button>
</header>

:root { --brand: #0e7a55; }

body { font-family: system-ui, sans-serif; margin: 0; padding: 24px; background: #f8fafc; }
.bar { display: flex; align-items: center; gap: 14px; }
.link { color: #0e7a55; font-weight: 700; }
.badge { background: #0e7a55; color: #fff; padding: 2px 10px; border-radius: 999px; font-size: 13px; }
.btn { background: #0e7a55; color: #fff; border: 0; padding: 10px 18px; border-radius: 10px; font-weight: 700; }

// ПРОВЕРКА — этот код не меняйте. Правьте только вкладку CSS.
const css = (s, p) => getComputedStyle(document.querySelector(s))[p];
const ok = (name, cond) => console.log((cond ? '✓ ' : '✗ ') + name);

document.documentElement.style.setProperty('--brand', '#dc2626');
const red = 'rgb(220, 38, 38)';
ok('link uses --brand', css('.link', 'color') === red);

ok('btn uses --brand', css('.btn', 'backgroundColor') === red);
Ожидаемый результат
✓ link uses --brand
✓ badge uses --brand
✓ btn uses --brand
Подсказка 1

В каждом из трёх правил замените значение #0e7a55 на var(--brand). В :root оставьте как есть: это единственное место, где цвет записан цифрами.

Подсказка 2

Должно получиться, например, .btn { background: var(--brand); … }. Следите за точкой с запятой после значения.

Аналогия из жизни

Школьная форма. Школа решает один раз: цвет — тёмно-синий, галстук — зелёный. Классы не спорят о цветах каждый день, а любой новый ученик сразу «в стиле». Захотели обновить форму — решаете в кабинете директора (@theme), а не обходите каждого ученика.

Типичные ошибки новичков

1. Заводить 12 оттенков «на всякий случай»: хватит бренда (2–3 тона), нейтрального серого и акцента. 2. Вписывать цвет прямо в компонент (bg-[#0e7a55]), потому что «так быстрее»: единый стиль ломается на второй странице. 3. Каждой странице писать свои кнопки с разными скруглениями: заведите один Button. 4. Забыть, что тёмная тема (урок 8) — это ещё один набор значений токенов, а не копия компонентов.

ЗАДАЧА 6.2

Проверь себя: дизайн-система

средняя

Вы хотите, чтобы в проекте работали классы bg-brand-600 и text-brand-600. Что нужно сделать в Tailwind 4?

  1. Создать файл brand.tsx с цветом
  2. Добавить в @theme в globals.css переменную --color-brand-600: …
  3. Написать className="bg-brand-600" без настройки: Tailwind угадает
  4. Установить пакет brand-colors

Переменные в @theme из пространства --color-* автоматически становятся классами цвета.

Главная причина вынести цвета и скругления в токены:

  1. Сменить стиль сайта можно правкой в одном месте, и у всех страниц он останется единым
  2. Сайт начнёт работать быстрее в десять раз
  3. Tailwind перестанет работать с цветами
  4. Не придётся использовать компоненты

Токены дают единый стиль и дешёвые правки. Скорость сайта от них напрямую не зависит, а компоненты нужны по-прежнему: токены — это значения, компоненты — готовые «кирпичи» из них.

Читать подробнее: Tailwind CSS: Theme variables (на английском).

07 ИИ-блок: как просить многостраничный сайт

Правила для многостраничного сайта

1. Сначала режим «План» (урок 6): карта сайта, дерево файлов, дизайн-токены, и только потом код. 2. Одно дело за раз: сначала токены и кирпичи, потом layout и меню, потом страницы по одной. 3. Правила проекта (AGENTS.md) держат ИИ в рамках: перечислите в них свои договорённости (см. шаг 2 практики). 4. После каждого шага: npm run build и проверка глазами в браузере. 5. Коммит перед каждой крупной задачей (урок 6), чтобы можно было откатиться.

Сделай сайт компании на next js с несколькими страницами
Контекст: проект Next.js 16 (App Router, TypeScript, Tailwind CSS 4, без папки src), создан через create-next-app. Нужен корпоративный сайт вымышленной студии «Сарв» из Душанбе: веб-разработка для бизнеса. Правила проекта лежат в AGENTS.md. Цель: многостраничный сайт из 5 страниц: Главная (/), Услуги (/services), Кейсы (/cases), О компании (/about), Контакты (/contacts). У всех страниц общая шапка с меню и подвал, всё в одном стиле. Ограничения: общий layout в app/layout.tsx (lang="ru"); меню в components/Nav.tsx с подсветкой текущей страницы через usePathname (только этот файл с "use client"); ссылки внутри сайта только через Link; картинки только через next/image из public/images, у каждой alt и размеры; на каждой странице свой title и description через metadata, шаблон заголовка в корневом layout; цвета, шрифты и скругления только через @theme в app/globals.css и классы bg-brand-600 и т. п.; общие кирпичи Container, Section, Button в components/ui; без новых библиотек; адаптивно для телефона. Примеры: тексты короткие и по делу на русском, цены в сомони, вымышленные контакты. Проверка: после изменений запусти npm run build, исправь ошибки и в конце перечисли созданные файлы и адреса.

Вместо одного огромного промпта удобнее делить работу на шаги (в практике они уже расписаны). Если ИИ «залез» не туда, не начинайте заново: откатите шаг через Checkpoint или Discard Changes (урок 6) и дайте точечную правку.

Правки: короткие, по одной

Подсветка в меню не работает на странице /services/web. Исправь isActive в components/Nav.tsx так, чтобы раздел оставался активным на вложенных адресах, но главная подсвечивалась только на «/». Остальное не меняй.
Найди в проекте все места, где цвет написан напрямую (hex или bg-[#…]) и замени на токены из @theme. Новые токены добавь в globals.css. Список изменённых файлов выведи в конце.
Проверь все страницы: у каждой должны быть уникальные title и description, один h1 и alt у каждой картинки. Покажи таблицу «страница → title → description» и исправь недочёты.
Объясни простыми словами, как для новичка: как Next.js понимает по папкам, какие адреса есть на сайте, что такое children в layout.tsx и почему Nav.tsx помечен "use client", а page.tsx нет. Код не переписывай.

08 Практика: корпоративный сайт из пяти страниц

Собираем сайт вымышленной студии «Сарв» (кипарис: символ стойкости). Свою студию, бренд и цвета выберите сами: сайт получится вашим. План такой: новый проект → правила → дизайн-система → layout и меню → пять страниц → картинки и метатеги → проверка → публикация.

Шаг 0. Подготовка

  • Cursor, Node.js, Git и аккаунты GitHub и Vercel из уроков 4–5 готовы.
  • Решите: название студии, чем занимается, 3 услуги с ценами в сомони, 3 кейса (вымышленных), 2–3 «людей из команды». Для картинок подготовьте 3–4 файла (свои фото, сгенерированные или со стоков с разрешённой лицензией), каждый до 300 КБ.
  • Контакты на сайте — только вымышленные или те, что готовы показать публично.

Шаг за шагом

  1. Создайте проект. В терминале из папки, где хранятся ваши проекты: npx create-next-app@latest saru-site, ответы по умолчанию (рекомендуемые настройки, как в уроке 5: TypeScript, ESLint, Tailwind, App Router, без src). Откройте папку в Cursor, запустите npm run dev и убедитесь, что страница открывается на localhost:3000. Сделайте первый коммит.

Картинки — только next/image из public/images, всегда alt, width и height. Цвета и шрифты — только токены из @theme. "use client" — только в Nav и форме. У каждой страницы свой title и description». Ошибка про usePathname и Client Component. В файле меню нет "use client" первой строкой. Добавьте или попросите ИИ.

Картинка «улетела» или растянулась на весь экран. У Image с fill родитель без relative и высоты. Задайте классы вроде relative h-64.

Меню подсвечено на всех страницах. Для главной сравнивается startsWith("/"). Верните точное сравнение для / (см. задачу 3.1).

Vercel собрал не то, что на компьютере. Забыли git push или не закоммитили файлы (особенно public/images). Файл в имени с заглавной буквой на Windows и macOS работает, а на Vercel (Linux) может сломаться: сверьте регистр в импортах.

средняя

Меню ведёт на /services, но показывает 404. В проекте есть файл app/services/Services.tsx. Причина?

09 Фишка урока: взаимное код-ревью

Профессиональные команды не выпускают код, который не посмотрел второй человек. Это называется код-ревью. Сегодня вы попробуете себя в двух ролях: автор и ревьюер. Работаете парами, проверяете чужой сайт по чек-листу и пишете полезные комментарии. Блок рассчитан на преподавателя и может проводиться в аудитории или онлайн.

Правила

1. Пары назначает преподаватель (или жребий). Каждый проверяет сайт соседа и получает ревью на свой. 2. У ревьюера две вкладки: живой сайт на Vercel и репозиторий на GitHub. 3. Идём строго по чек-листу ниже, ничего не правим в чужом коде: только комментарии. 4. Комментарий должен быть конкретным: где (файл или страница), что не так, почему это важно, как исправить. Без «плохо» и «мне не нравится». 5. Каждому замечанию — уровень: блокер (сайт ломается или не выполнено требование), важно (стоит исправить), улучшение (на желание). 6. Хотя бы одно замечание обязательно и хотя бы одна похвала за что-то удачное. 7. Автор отвечает на каждое замечание: «исправлено» или «не согласен, потому что…».

Пример хорошего комментария

Где: components/Nav.tsx, функция isActive. Что: для главной используется startsWith("/"), поэтому все пункты подсвечены одновременно. Почему: посетитель не понимает, на какой он странице; на скриншоте на странице /cases подсвечены все пять пунктов. Как исправить: для href === "/" сравнивать pathname === "/". Уровень: блокер.
Ревью и ИИ

Сначала ревью делаете сами, глазами и по чек-листу. Потом можно попросить ИИ о втором мнении: «Проверь этот файл по чек-листу …», но любое замечание ИИ подтвердите в коде: он может ошибаться и не видеть всего проекта. Передавайте ему только код, без ключей и приватных данных.

Как считаем очки (необязательно)

  • +2 за каждое подтверждённое автором замечание уровня «блокер» или «важно».
  • +1 за каждое улучшение, которое автор принял.
  • +1 за каждую конкретную похвалу.
  • +3 автору, если все блокеры исправлены до конца блока.
  • −2 за замечание без «где» и «как исправить».

10 Домашнее задание: корпоративный сайт из пяти страниц (ДЗ-9)

Доработайте сайт из практики или создайте новый корпоративный сайт на любую вымышленную или реальную тему (компания, клиника, школа). Сдача: две ссылки (репозиторий GitHub и сайт на Vercel).

  5. Вставьте две ссылки в блоки ниже и отметьте чек-лист требований.
