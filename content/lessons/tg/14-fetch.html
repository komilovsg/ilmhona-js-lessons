fetch ва HTTP

Қурби сомонӣ дар барномаи бонк, обу ҳавои Душанбе, рӯйхати мол дар дӯкони интернетӣ, ленти хабарҳо: ҳамаи инҳо на дар браузери шумо, балки дар компютерҳои бегона — серверҳо ҷойгиранд. Барои гирифтани маълумот аз он ҷо саҳифа дархости HTTP мефиристад ва ҷавобро интизор мешавад. Имрӯз шумо меомӯзед, ки инро бо JavaScript-и пок тавассути fetch иҷро кунед — ва печонандаи худии api.js-ро созед, ки онро дар ҳар лоиҳаи оянда истифода мебаред.

  • Шарҳ додан, ки дархости HTTP ва ҷавоб аз чӣ иборатанд: усул, URL, сарлавҳаҳо, бадан, статус
  • Фарқ кардани усулҳои GET, POST, PUT, PATCH, DELETE ва гурӯҳҳои рамзҳои статус 2xx / 3xx / 4xx / 5xx
  • Дархост кардан тавассути fetch ва хондани ҷавоб: response.json(), status, ok, headers
  • Фиристодани маълумот бо усули POST: сарлавҳаи Content-Type ва JSON.stringify
  • Фарқ кардани хатои шабакавӣ аз ҷавоби «404» ва коркарди ҳардуи онҳо тавассути response.ok ва try / catch
  • Сохтани печонандаи api.js ва санҷидани коде, ки ЗС навиштааст, дар ҷавобҳои хатоӣ
Бо ин саҳифа чӣ тавр кор кардан лозим

Коди дар заминаи торик бо тугмаи ▶ Иҷро кардан зинда аст. Дар ин дарс бисёр мисолҳо ба интернет мераванд (ба серверҳои таълимии jsonplaceholder ва dummyjson): як-ду сония интизор шавед, то ҷавоб ояд ва консол сатрҳоро пурра кунад. Агар интернет набошад, дархостҳо меафтанд — ва ин ҳам таҷрибаи судманд аст: дар поён мо чунин вазъиятҳоро коркард карданро меомӯзем. Як қисми вазифаҳо бе шабака кор мекунанд (дар онҳо мо худамон ҷавобҳои серверро «қалбакӣ» месозем) — онҳо фавран санҷида мешаванд. Ишораҳо зери қулфак 🔒 пинҳонанд.

01 HTTP: браузер бо сервер чӣ тавр гап мезанад

Муштарӣ (клиент) — ин браузери шумост (ё коди шумо дар он). Сервер — компютере, ки маълумот дар он ҷойгир аст. Онҳо мувофиқи қоидаҳои протоколи HTTP муошират мекунанд: клиент дархост (request) мефиристад, сервер ҷавоб (response) бармегардонад. Ҳамеша ба навбат: сервер худаш аввал навиштанро оғоз намекунад.

Қиёс аз ҳаёт

Шумо дар қаҳвахона назди Рӯдакӣ тавассути пешхизмат фармоиш медиҳед. Дархост: «Палав биёред (усул) (суроғаи хӯрок дар меню), бе сабзӣ (сарлавҳа бо хоҳишҳо)». Ҷавоб: пешхизмат бармегардад ва аввал статус мегӯяд — «Овардам» (200) ё «Чунин хӯрок нест» (404) ё «Ошпаз бемор шуд» (500), баъд баданаи ҷавобро — худи палавро — ба рӯи миз мегузорад.

Суроға аз чӣ иборат аст

Суроғаи захира URL номида мешавад. Он якчанд қисм дорад ва браузер онҳоро бо ёрии синфи дарунсохти URL таҷзия карда метавонад.

const url = new URL("https://jsonplaceholder.typicode.com/todos?userId=1&_limit=3");

console.log(url.protocol);               // https:
console.log(url.hostname);               // jsonplaceholder.typicode.com
console.log(url.pathname);               // /todos
console.log(url.searchParams.get("userId"));   // 1  (ҳамеша сатр!)

Дархост ва ҷавоб

Дархост аз чор қисм, ҷавоб аз се қисм иборат аст. Ин схемаро дар хотир доред: вай барои фаҳмидани ҳама гуна ҳуҷҷатгузории API лозим аст.

Дархост (клиент → сервер)

Усул (чӣ кор кардан) · URL (дар куҷо) · сарлавҳаҳо (маълумоти хидматӣ) · бадан (маълумот, агар мефиристем).

Ҷавоб (сервер → клиент)

Статус (рақам: чӣ тавр гузашт) · сарлавҳаҳо (масалан, навъи маълумот) · бадан (худи маълумот, аксаран JSON).

Усулҳо: феъли дархост

Усул ба сервер мегӯяд, ки мо чиро иҷро кардан мехоҳем. Барои кор бо маълумот панҷ усули асосӣ ҳаст. Суроғаи онҳо метавонад якхела бошад — фақат феъл фарқ мекунад.

Рамзҳои статус: рақаме, ки сервер аввал мегӯяд

Рақами аввали рамз — ин гурӯҳ аст. Агар гурӯҳҳоро дар хотир доред, 90%-и рамзҳоро бе маълумотнома мефаҳмед.

Сарлавҳаҳо: ёддоштҳои хидматӣ

Content-Type
Бадан кадом навъ аст. Барои JSON ин application/json аст. Ҳам дар дархост (чиро мефиристем), ҳам дар ҷавоб (чиро гирифтем) мешавад.
Accept
Дар дархост: «ман кадом формати ҷавобро мефаҳмам».
Authorization
Дар дархост: калид ё токен, ки тасдиқ мекунад шумо кистед. Бе он API-ҳои пӯшида бо 401 ҷавоб медиҳанд. Дар ин дарс он лозим нест — мо API-ҳои кушодаро мегирем.

JSON: забоне, ки API-ҳо бо он гап мезананд

Маълумот тавассути шабака ҳамчун матн мегузарад. Объектҳо ва массивҳоро ба матни формати JSON табдил медиҳанд ва баръакс: JSON.stringify(объект) → сатр, JSON.parse(сатр) → объект. Қоидаҳо аз JS сахттаранд: калидҳо ва сатрҳо танҳо дар нохунакҳои дукарата, бе шарҳҳо ва бе вергул дар охир.

const student = { name: "Мадина", age: 17, courses: ["JS", "CSS"] };

const text = JSON.stringify(student);
console.log(text);                  // ин сатр аст
console.log(typeof text);

const back = JSON.parse(text);
console.log(back.name, back.courses.length);
Хатои маъмул

JSON-ро «мисли дар JavaScript» навиштан: бе нохунак дар калидҳо ё бо нохунакҳои яккарата. Чунин матнро JSON.parse қабул намекунад ва SyntaxError мепартояд.

const text = "{ name: 'Мадина' }";    // ✖ калид бе нохунак, сатр дар нохунакҳои яккарата

const student = JSON.parse(text);
console.log(student.name);

02 fetch: дархости аввалин

fetch(url) — функсияи дарунсохти браузер барои дархостҳои HTTP. Ягон чизро пайваст кардан лозим нест. Вай промис бармегардонад (дарси 13), барои ҳамин бо он тавассути then ё, қулайтар, тавассути async / await кор мекунанд. Мекӯшем як вазифаро аз сервери таълимии jsonplaceholder гирем — вай махсус барои машқ кардан сохта шудааст:

async function main() {
  const response = await fetch("https://jsonplaceholder.typicode.com/todos/1");
  const todo = await response.json();

  console.log(todo.title);
  console.log("выполнена?", todo.completed);
}

main();

Сатрҳо кам аст, аммо дар ин ҷо ду await ҳаст ва ин тасодуф нест. Биёед фаҳмем, барои чӣ.

  1. fetch(url) дархостро мефиристад. Промис ҳамин ки оғози ҷавоб — статус ва сарлавҳаҳо — расад, иҷро мешавад.
  2. await ба мо объекти response-ро медиҳад — ин «лифофа» аст: дар он статус ва сарлавҳаҳо ҳастанд, бадан бошад ҳанӯз дар роҳи шабака буда метавонад.
  3. response.json() баданро то охир мехонад ва матни JSON-ро ба объект табдил медиҳад. Ин ҳам промис аст — барои ҳамин await-и дуюм.
Қиёс аз ҳаёт

Шумо аз нонвойхона расониданро фармоиш додед. Аввал курйер занг мезанад: «Фармоиш қабул шуд, меравам» — ин response бо статус аст. Баъд ӯ бо қуттӣ назди шумо мебарояд — ин response.json() аст. Занг ва қуттӣ дар вақтҳои гуногун меоянд, барои ҳамин ду бор интизор шудан лозим мешавад.

Дар response чӣ ҳаст

response.status
Рақам — рамзи статус: 200, 404, 500…
response.ok
true, агар статус аз 200 то 299 бошад. Судмандтарин санҷиш — ба он дар қисми 04 бармегардем.
response.headers
Сарлавҳаҳои ҷавоб. Бо усули get хонда мешаванд: response.headers.get("content-type").
response.json()
Баданро ҳамчун JSON хондан → объект ё массив мегирем.
response.text()
Баданро ҳамчун матни оддӣ хондан (қулай аст, агар на JSON омада бошад).
async function main() {
  const response = await fetch("https://jsonplaceholder.typicode.com/todos/1");

  console.log("статус:", response.status);
  console.log("ok:", response.ok);
  console.log("тип данных:", response.headers.get("content-type"));
}

main();

Ҳамин чиз тавассути then

Варианти бе async / await низ дар кодҳои бегона вомехӯрад — шумо бояд онро шиносед. Маъно ҳамон аст, фақат дохилшавӣ дигар аст:

fetch("https://jsonplaceholder.typicode.com/todos/1")
  .then((response) => response.json())
  .then((todo) => {
    console.log("Задача:", todo.title);
  });
Хатои маъмул

await-ро пеш аз fetch ё пеш аз response.json() фаромӯш кардан. Он гоҳ дар тағйирёбанда на маълумот, балки промис мемонад ва ҳама муроҷиат ба майдонҳо undefined медиҳанд.

async function main() {
  const response = await fetch("https://jsonplaceholder.typicode.com/todos/1");
  const todo = response.json();     // ✖ await-ро фаромӯш кардем — ин промис аст, на объект

  console.log(todo.title);          // undefined
}

main();

04 Хатоҳо: 404 — хатои fetch нест

Ин барои навомӯзон ғайричашмдоштарин ҷост. Дархост метавонад ду навъи комилан гуногуни ноком дошта бошад — ва fetch ба онҳо гуногун муносибат мекунад.

Қиёс аз ҳаёт

Шумо бо маршрутка ба Рӯдакӣ меравед. Хатои шабакавӣ — маршрутка дар роҳ вайрон шуд ва шумо умуман нарасидед (интернет нест, суроғаи сервер нодуруст, сервер хомӯш аст). Ҷавоб бо рамзи 404 ё 500 — шумо расидед, ба мағоза даромадед, фурӯшанда бошад мегӯяд «чунин мол нест» ё «имрӯз мо пӯшидаем». Шумо бо сервер алоқа кардед, вай ҷавоб дод — фақат на он чизе, ки шумо интизор будед.

Вазъиятfetch чӣ мекунадЧӣ тавр фаҳмидан
Шабака нест, сервер дастнорас аст, суроға нодурустПромис рад мешавад (хатои TypeError)catch кор мекунад
Сервер 404, 500 ва ғайра ҷавоб додПромис бомуваффақият иҷро мешавад!response.ok ё response.status-ро санҷед

Бинед: дархости вазифаи вуҷуднадошта хато напартофт. catch хомӯш аст, ok бошад ба false баробар аст.

async function main() {
  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/todos/99999");
    console.log("запрос дошёл до сервера");
    console.log("статус:", response.status, "ok:", response.ok);
  } catch (error) {
    console.log("сюда мы не попадём");
  }
}

Схемаи дуруст: ok-ро месанҷем ва хаторо худамон мепартоем

Барои он ки ҳарду ноком дар як ҷой коркард шаванд, «статуси бад»-ро ба хатои ҳақиқӣ табдил медиҳем:

async function loadTodo(id) {
  const response = await fetch("https://jsonplaceholder.typicode.com/todos/" + id);

  if (!response.ok) {
    throw new Error("HTTP " + response.status);   // 404 → хатои ҳақиқӣ
  }
  return response.json();
}

async function main() {

    } catch (error) {

  }

main();

Хатои шабакавӣ: сервер умуман нест

Вақте дархост ба сервер расида натавонист, fetch промисро рад мекунад ва catch хатои навъи TypeError мегирад. Барои тақлид кардани ин суроғаеро мегирем, ки яқинан вуҷуд надорад (минтақаи .invalid барои суроғаҳои «вуҷуднадошта» ҷудо карда шудааст):

    console.log("Сеть недоступна. Тип ошибки:", error.name);
  }
}

Матни худи хато дар браузерҳои гуногун фарқ мекунад (дар Chrome — Failed to fetch, дар Safari — Load failed), барои ҳамин ба error.message такя кардан мумкин нест. Боэътимодтар аст ба error.name нигаред ё оддӣ ба корбар матни фаҳмои худатонро нишон диҳед.

Сабаби дигари «Failed to fetch» — CORS

Браузер ба саҳифаҳо иҷозат намедиҳад ҷавобҳои серверҳои бегонаро хонанд, агар онҳо ошкоро иҷозат надода бошанд (сарлавҳаи Access-Control-Allow-Origin). API-ҳои таълимии оммавӣ ба ҳама иҷозат медиҳанд, барои ҳамин назди мо ҳама чиз кор мекунад. Аммо вақте сервери «пӯшида»-ро дархост кунед, дар консол паёми сурх дар бораи CORS пайдо мешавад, fetch бошад ҳамон хатои шабакавиро медиҳад. Ин хатои коди шумо нест: соҳиби сервер бояд дархостҳоро аз сайти шумо иҷозат диҳад. Муфассалтар дар дарсҳои оянда таҳлил мекунем.

Вақте бадан JSON нест

Нохушии сеюм: сервер ҷавоб дод, аммо дар бадан JSON нест (масалан, саҳифаи HTML «Хидмат муваққатан дастнорас аст»). Он гоҳ response.json() SyntaxError мепартояд. Дар ҷавоби қалбакӣ месанҷем:

  try {
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.log("Не удалось разобрать JSON. Тип ошибки:", error.name);
  }
}

main();
Хатои маъмул

Фавран response.json()-ро иҷро кардан ва ба беҳтарин умедвор будан. Барои ҷавоби 404 бо бадани холӣ ({}) код «кор мекунад» ва ба ҷои маълумот undefined медиҳад — сабаби воқеӣ (сабт ёфт нашуд) бошад ношинохта мемонад.

05 POST, PUT, DELETE: маълумот мефиристем

Барои сохтан ё тағйир додани сабт, аргументи дуюми fetch — объекти танзимот аст. Дар он се калиди асосӣ ҳаст: method, headers ва body.

Дар бораи сервери таълимии мо

jsonplaceholder — сервери «ҳамчун гӯӣ»: вай POST, PUT ва DELETE-ро қабул мекунад, мисли воқеӣ ҷавоб медиҳад, аммо ҳеҷ чизро нигоҳ намедорад. Пост сохтед — аммо дар дархости оянда он нест. Барои омӯзиш ин беҳтарин аст: ҳеҷ чизро вайрон кардан мумкин нест. Серверҳои воқеӣ, албатта, маълумотро ба ёд мегиранд.

async function main() {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ title: "Мой первый пост", body: "Салом, мир!", userId: 1 }),
  });

  const created = await response.json();

  console.log("статус:", response.status);   // 201 — Created
  console.log("id:", created.id);            // сервер рақам дод
  console.log("заголовок:", created.title);  // ва он чиро, ки фиристодем, баргардонд
}

main();
  1. method: "POST" — ба сервер хабар медиҳем, ки мехоҳем сабт созем.
  2. Content-Type: application/json — огоҳ мекунем: «дар бадан JSON ҳаст». Бе ин сервер баданро нафаҳмидан метавонад.
  3. JSON.stringify(...) — бадани дархост бояд сатр бошад, объектро бевосита фиристодан мумкин нест.
  4. Дар ҷавоб сервер 201 Created ва сабти сохташударо — бо id-и нав — бармегардонад.

Қадами 4. Таймаут: абадӣ интизор намешавем

Агар сервер овезон шавад, корбар то беохир ба «Боркунӣ…» менигарад. Барои ҳамин маҳдудияти вақтро илова мекунем. Барои ин fetch «тугмаи бекор кардан» дорад — AbortController: controller.abort()-ро даъват мекунем ва дархост бо хатои AbortError қатъ мешавад.

const BASE_URL = "https://jsonplaceholder.typicode.com";

async function request(path, { method = "GET", body, timeout = 8000 } = {}) {
  const options = { method, headers: {} };

  if (body !== undefined) {
    options.headers["Content-Type"] = "application/json";
    options.body = JSON.stringify(body);
  }

  const controller = new AbortController();
  options.signal = controller.signal;
  const timer = setTimeout(() => controller.abort(), timeout);   // баъд аз timeout мс — бекор кардан

  try {
    const response = await fetch(BASE_URL + path, options);

    if (!response.ok) {
      const error = new Error("HTTP " + response.status);
      error.status = response.status;
      throw error;
    }
    return await response.json();
  } catch (error) {
    if (error.name === "AbortError") {
      throw new Error("сервер не ответил за " + timeout + " мс");
    }
    throw error;
  } finally {
    clearTimeout(timer);               // таймер акнун лозим нест
  }
}

async function main() {
  try {
    await request("/todos/1", { timeout: 1 });     // 1 мс — хеле кам
  } catch (error) {
    console.log("Ошибка:", error.message);
  }
}

main();

07 Блоки ЗС: печонандаи fetch аз ЗС ва санҷиши он

Печонандаи fetch-ро ЗС тез ва зебо менависад. Аммо маҳз дар ин ҷо вай «роҳро кӯтоҳ кардан»-ро дӯст медорад: санҷиши response.ok-ро фаромӯш мекунад, ҷавоби бе JSON-ро дастгир намекунад ё фарқ намекунад, ки дар асл чӣ вайрон шуд. Барои ҳамин малакаи имрӯза — на «гирифтани код», балки санҷидани он дар ҷавобҳои бад: 404, 500, на-JSON ва шабакаи гумшуда.

Қоидаҳои курс, ки дар ин ҷо махсусан муҳиманд

1. Аввал 15 дақиқа худатон кӯшиш мекунед: қолабро аз қисми 04 ва қадамҳои печонандаро аз қисми 06 ба ёд оред. 2. Танҳо баъд ба сӯи ЗС мераванд. 3. Ба лоиҳа коде гузоред, ки онро сатр ба сатр шарҳ дода наметавонед — барои печонанда ин маънои онро дорад: шумо медонед, ки ҳар санҷиш барои чӣ аст. 4. На дар «роҳи хушбахтӣ» (200 OK), балки дар ҷавобҳои хатоӣ санҷед: ЗС қариб ҳамеша бо сенарияи хуб мефаромӯшад ва дар бадҳо хато мекунад.

Чӣ тавр пурсидан: бад ва хуб

Формулаи промпти курс: контекст → вазифа → маҳдудиятҳо → формати ҷавоб → санҷиш.

функсия барои fetch нависед
Ман JavaScript меомӯзам, сатҳ — навомӯз, промисҳо, async/await ва try/catch-ро медонам. Печонандаи fetch нависед: URL-и асосӣ, таймаут тавассути AbortController, санҷиши response.ok, хатоҳои фаҳмо. JS-и пок, бе китобхонаҳо, дар як файл, на зиёда аз 40 сатр, бо шарҳҳо ба забони тоҷикӣ барои ҳар блок. Формати ҷавоб: код, баъд рӯйхати «ҳар санҷиш чӣ мекунад» дар 5 банд. Дар охир бигӯед, кадом сенарияҳои хатоиро ман бояд дастӣ санҷам.

Баъд аз ҷавоби ЗС кодро аз рӯи чек-лист гузаронед. Агар ақаллан як банд «не» бошад — шумо хато ёфтед:

Чек-листи санҷиши печонанда

1) Дар ҷавоби 404 хато бо рамзи статус мепарад? 2) Дар ҷавоби 500 — ҳамин тавр? 3) Агар на JSON омад, хато фаҳмост, на «Unexpected token <»? 4) Ҳангоми хомӯш будани шабака (Wi-Fi-ро хомӯш кунед) корбар матни шуморо мебинад, на стеки даҳшатнокро? 5) Таймаут ҳаст ва таймер дар finally тоза мешавад? 6) Бадан ду бор хонда намешавад? 7) Шумо метавонед ҳар сатрро шарҳ диҳед?

Дар сервери воқеӣ санҷидан нобароҳат аст: jsonplaceholder-ро аз рӯи фармоиш «афтондан» мумкин нест. Барои ҳамин касбиён серверро бо пойгоҳи озмоишӣ иваз мекунанд — функсияе, ки ҷавобҳои пешакӣ омодашударо медиҳад. Дар вазифаи поён маҳз чунин пойгоҳ ҳаст ва шумо бояд «печонандаи аз ЗС»-ро санҷед ва ислоҳ кунед.

ВАЗИФАИ 7.1

Печонандаи аз ЗС-ро санҷ ва ислоҳ кун

душвор

ЗС функсияи aiRequest-ро дод. Пойгоҳро иҷро кунед — мебинед, ки дар ҷавобҳои бад вай нодуруст рафтор мекунад. Танҳо aiRequest-ро чунон бознависед, ки сенарияҳо аз рӯи ҷадвал рафтор кунанд: ok → маълумот, notfound → хатои HTTP 404, server → HTTP 500, html (статус 200, аммо бадан на JSON) → ответ не JSON, network (дархост нарасид) → сеть недоступна.

// --- пойгоҳи озмоишӣ, тағйир надиҳед ---
function fakeFetch(scenario) {
  switch (scenario) {
    case "ok":       return Promise.resolve(new Response(JSON.stringify({ name: "Мадина" })));
    case "notfound": return Promise.resolve(new Response("{}", { status: 404 }));
    case "server":   return Promise.resolve(new Response("Internal Server Error", { status: 500 }));
    case "html":     return Promise.resolve(new Response("<html>Привет</html>"));
    case "network":  return Promise.reject(new TypeError("Failed to fetch"));
  }
}

// --- коди ЗС: ислоҳ кунед ---
async function aiRequest(scenario) {
  const response = await fakeFetch(scenario);
  const data = await response.json();
  return data;
}

// --- санҷиш, тағйир надиҳед ---
async function main() {
  for (const scenario of ["ok", "notfound", "server", "html", "network"]) {
    try {
      const data = await aiRequest(scenario);
      console.log(scenario + ": данные получены: " + data.name);
    } catch (error) {
      console.log(scenario + ": Ошибка: " + error.message);
    }
  }
}

main();

Се ҷо ҳимоя металабанд: худи fakeFetch (шабака), санҷиши response.ok (404 ва 500) ва response.json() (на JSON). Ҳар якро дар try / catch ё if-и худаш.

Ишора 2

Печонед: let response; try { response = await fakeFetch(scenario); } catch { throw new Error("сеть недоступна"); }. Баъд if (!response.ok) throw new Error("HTTP " + response.status);. Баъд try { return await response.json(); } catch { throw new Error("ответ не JSON"); }.

Маълумотро аз ду API-и гуногун гирифтан ва дар саҳифа кашидан. Артефакт — файли api.js: печонандаи худии шумо болои fetch, ки ҳарду API тавассути он мераванд.

Чӣ кор кардан лозим

  1. ✓ Лавҳаи ёддошти дарс

  • HTTP: клиент дархост мефиристад (усул + URL + сарлавҳаҳо + бадан), сервер ҷавоб медиҳад (статус + сарлавҳаҳо + бадан). Маълумот аксаран дар формати JSON.
  • Усулҳо: GET — гирифтан, POST — сохтан, PUT — иваз кардан, PATCH — як қисмро тағйир додан, DELETE — нест кардан.
  • Статусҳо: 2xx муваффақият (200, 201), 3xx равонакунӣ, 4xx хатои клиент (404, 401, 403), 5xx хатои сервер (500).
  • fetch промис бо response (статус ва сарлавҳаҳо) бармегардонад. Баданро ҷудо ва як маротиба мехонем: await response.json() ё text().
  • 404 ва 500 — хатои fetch нестанд. response.ok-ро санҷед ва хаторо худатон бипартоед. Хатои шабакавӣ (шабака нест, сервери нодуруст) — промиси радшуда, TypeError.
  • Қолаб: try { const r = await fetch(url); if (!r.ok) throw new Error("HTTP " + r.status); const data = await r.json(); … } catch (e) { … } finally { … }
  • POST: fetch(url, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(data) }). Бадан — ҳамеша сатр.
  • URL ва параметрҳо: new URL(…) суроғаро таҷзия мекунад, new URLSearchParams(объект) сатри дархостро ҷамъ мекунад.
  • api.js: як функсияи request — суроғаи асосӣ, сарлавҳаҳо, JSON, санҷиши ok, таймаут тавассути AbortController; дар боло — get / post.
  • Бо ЗС: аввал худатон, баъд промпт аз рӯи формула. Печонандаи аз ЗС-ро дар ҷавобҳои бад месанҷем: 404, 500, на-JSON, шабака нест, таймаут.
