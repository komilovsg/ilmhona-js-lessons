Git ва GitHub + ислоҳи хатоҳои код

Ҳар лоиҳаи гурӯҳӣ дар Git зиндагӣ мекунад, ва ҳар код як рӯз вайрон мешавад. Имрӯз шумо ёд мегиред, ки таърихи корро нигоҳ доред, тағйиротро тавассути pull request пешниҳод кунед, низоъҳоро ҳал намоед ва хатоҳоро оромона ҷустуҷӯ кунед — ба ҷои суханони «дар назди ман кор намекунад».

  • Дар таърихи фаҳмо commit кардан ва паёмҳоро аз рӯи Conventional Commits навиштан
  • Бо шохаҳо кор кардан ва давраи «шоха → push → pull request → ревью → merge»-ро гузаштан
  • Низои ҷамъкуниро (merge conflict) ҳал кардан ва .gitignore-ро танзим намудан
  • Хатоҳоро гирифтан ва партофтан: try / catch / finally, throw, навъҳои хатоҳо
  • Стеки даъватҳоро хондан, breakpoint-ро дар DevTools гузоштан ва ҷадвали Network-ро дидан
  • Хаторо тавре тасвир кардан, ки ЗС (ва одам) кумак карда тавонад: мисоли ҳадди ақали такроршаванда
Бо ин саҳифа чӣ тавр кор кардан лозим

Блокҳои «Терминал» — фармонҳо барои компютери шумо ҳастанд, дар браузер онҳо иҷро намешаванд: онҳоро дар терминали VS Code ворид кунед. Коди JavaScript бо тугмаи ▶ Иҷро кардан — зинда аст: онро тағйир додан ва худи ҳамин ҷо санҷидан мумкин аст. Git-ро мо бо массивҳо ва объектҳои оддӣ моделсозӣ мекунем, барои ҳамин мантиқи add, commit, шохаҳо ва низоъҳоро бе насб ламс кардан мумкин аст. Ишораҳо ба вазифаҳо пинҳонанд: аввал худатон кӯшиш кунед.

01 Git: таърихи лоиҳа

Тасаввур кунед, ки шумо барои чойхона сайт месозед. Имрӯз ҳама чиз кор мекунад, пагоҳ шумо менюро «каме ислоҳ кардед», ва сайт вайрон шуд. Чӣ тавр бозгашт кард? Папкаро бо номҳои site-final, site-final-2, site-final-REAL нусха кардан? Навомӯзон ҳамин тавр мекунанд. Касбиҳо Git-ро истифода мебаранд — низоми назорати версияҳо. Он ҳар ҳолати нигоҳдошташудаи лоиҳаро сабт мекунад, нишон медиҳад, ки чӣ ва кӣ тағйир дод, ва имкон медиҳад ба ҳар лаҳза бозгашт кард.

Монандӣ: албоми оилавӣ

Шумо аз телефон аксҳои тӯйро интихоб карда, ба лифофа мемонед — ин git add аст. Баъд лифофаро ба албом мечаспонед ва менависед «Никоҳ, 12 июн» — ин git commit аст. Албом ҳамаи саҳифаҳоро бо тартиб нигоҳ медорад. Хоҳед — ҳар саҳифаро мекушоед ва мебинед, ки он вақт чӣ гуна буд.

Се минтақа ва чор ҷой

Файл дар Git дар компютери шумо аз се минтақа мегузарад. Ҷойи чорум — сервери GitHub аст, ки шумо нусхаро ба он мефиристед.

Репозиторийи аввал

Як бор дар компютер бояд худро муаррифӣ кунед — ин ном ба ҳар commit меафтад:

git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"

Акнун лоиҳа эҷод мекунем ва commit-и аввалро мегузаронем:

mkdir chaykhona-site
cd chaykhona-site
git init -b main
echo "# Чойхона" > README.md
git status
git add README.md
git commit -m "docs: add readme"
git log --oneline

Қадам ба қадам чӣ рух дод:

  1. git init папкаи пинҳонии .git-ро эҷод кард — тамоми таърих дар он зиндагӣ мекунад. Онро хориҷ кунед, ва лоиҳа дигар репозиторий нахоҳад буд.
  2. git status гуфт: файли README.md «untracked» аст — Git онро ҳанӯз пайгирӣ намекунад.
  3. git add файлро ба индекс («лифофа») гузошт.
  4. git commit -m "…" акси фаврӣ (snapshot)-ро бо имзо сабт кард.
  5. git log --oneline таърихро нишон дод: рамзи кӯтоҳи commit ва имзо.

Хатогиҳои маъмул

1. git add . бе нигоҳ кардан: ба commit файлҳои зиёдатӣ (паролҳо, node_modules) меафтанд. Аввал git status, баъд git add.

2. git commit бе -m муҳаррири матнии Vim-ро мекушояд. Агар часпидед: Esc-ро пахш кунед, :q! ворид кунед ва Enter. Ё ҳамеша -m-ро нависед.

3. Як commit-и азим «ҳама чиз барои як ҳафта». Commit — ин як андешаи ба итмом расида: «филтр илова кардам», «маҷмӯи ниҳоиро ислоҳ кардам».

Барои ҳис кардани сохти минтақаҳо, онҳоро бо код моделсозӣ мекунем. Ин вазифаи аввал дар саҳифа аст.

Амал: мустаҳкам мекунем

Мо Git-ро бо JavaScript-и оддӣ моделсозӣ мекунем — ҳамин тавр мебинед, ки дар дохил ҷодугарӣ нест.

ВАЗИФАИ 1.1

Се минтақаи Git дар код

осон

Мо се минтақаи Git-ро бо массивҳои оддӣ моделсозӣ мекунем. add (git add: файл аз work ба staged мегузарад) ва commit (git commit: ҳар чизи аз staged ба commit-и нав меравад, ва staged тоза мешавад)-ро анҷом диҳед. Таърих мисли git log чоп мешавад — commit-ҳои нав дар боло.

  staged: [],                                  // омодашуда: git add
  commits: [],                                 // таърих: git commit
};

function add(file) {
  // файлро аз work хориҷ кунед ва ба staged гузоред
}

function commit(message) {
  // файлҳоро аз staged ба commit-и нав { message, files } нигоҳ доред
  // ва staged-ро тоза кунед

add("index.html");
add("style.css");
commit("add page skeleton");
add("app.js");

Ишора 1

Дар add ду чиз лозим аст: файлро аз work хориҷ кардан (масалан, тавассути filter) ва push ба staged кардан.

Ишора 2

Дар commit нусхаи рӯйхатро нигоҳ доред: files: [...repo.staged]. Баъд repo.staged = []. Одати нусха бардоштан дар қисми 8 кор меояд — дар он ҷо мутатсия барномаҳоро вайрон мекунад.

ВАЗИФАИ 1.2

git status чӣ нишон медиҳад

осон

Функсияи statusLine файлро ҳамон тавр тасвир мекунад, ки git status. Аммо як ҳолатро намедонад: файл аллакай дар индекс аст (staged), ва пас аз git add он боз як бор тағйир ёфт (changedAfterAdd: true). Барои он сатри staged, but changed again: ном лозим аст. Шартро анҷом диҳед.

const files = [
  { name: "index.html", tracked: true, changed: false, staged: false },
  { name: "app.js", tracked: true, changed: true, staged: false },
  { name: "notes.txt", tracked: false, changed: true, staged: false },
  { name: "style.css", tracked: true, changed: true, staged: true, changedAfterAdd: false },
  { name: "README.md", tracked: true, changed: true, staged: true, changedAfterAdd: true },
];

function statusLine(f) {
  if (!f.tracked) return `untracked: ${f.name}`;
  if (f.staged) return `to be committed: ${f.name}`;
  if (f.changed) return `modified: ${f.name}`;
  return null; // файли тоза дар статус нишон дода намешавад
}

files.map(statusLine).filter(Boolean).forEach((line) => console.log(line));
Натиҷаи интизоршаванда
modified: app.js
untracked: notes.txt
to be committed: style.css
staged, but changed again: README.md
Ишора 1

Санҷиши навро бояд пеш аз санҷиши оддии f.staged гузоред: вагарна он кор мекунад, ва то шарти шумо навбат намерасад.

Ишора 2

if (f.staged && f.changedAfterAdd) return `staged, but changed again: ${f.name}`;

02 Шохаҳо: кор мекунем, асосиро вайрон намекунем

Дар репозиторий шохаи асосӣ ҳаст — одатан main (гоҳо онро master меноманд). Дар он версияи «ҳатман кор мекунанда» ҷойгир аст. Функсияи навро дар шохаи алоҳида месозанд: кӯшиш кардан, хато кардан ва commit кардан ба қадри дилхоҳ мумкин аст — шохаи асосӣ зарар намебинад. Вақте функсия тайёр ва санҷида шуд, шохаро бозпас медароранд.

Монандӣ: палави озмоишӣ

Дар дегҳои калон палав барои меҳмонон мепазад — ин main аст. Шумо мехоҳед дорупази нави бо биҳиро санҷед. Шумо ба дегҳои умумӣ даст намезанед, балки дегчаи хурд мегиред — ин шоха аст. Лазиз баромад — биҳиро ба дегҳои умумӣ илова кардем (merge). Нашуд — дегчаро партофтем, ва меҳмонон чизеро пай набурданд.

Шоха нусхаи папка нест. Ин танҳо «хатчӯби» ҳаракаткунанда ба яке аз commit-ҳост. Commit-и нав хатчӯбро пеш мебарад. Ба шарофати ин шохаҳо дар Git фавран эҷод мешаванд ва қариб чизе арзиш надоранд. Хатчӯби махсуси HEAD нишон медиҳад, ки шумо ҳоло дар кадом шоха ҳастед.

git branch                         # список веток, звёздочка у текущей
git switch -c feature/filters      # создать ветку и перейти на неё
# ...правим файлы, git add, git commit...
git log --oneline --graph --all    # история в виде дерева
git switch main                    # вернуться на main
git merge feature/filters          # влить ветку в main
git branch -d feature/filters      # удалить ветку, она больше не нужна

Шохаҳоро чӣ тавр номгузорӣ кардан

Дар фармонҳо шохаро аз рӯи қолаби навъ/тавсифи-кӯтоҳ меноманд: feature/order-filters, fix/wrong-total, docs/readme-tajik. Калимаҳои англисӣ, ҳарфҳои хурд, бе фосила, калимаҳо бо дефис. Аз рӯи ном фавран намоён аст, ки дар шоха чӣ ҳаст ва барои чӣ.

Хатогиҳои маъмул

Бевосита дар main кор кардан. Он гоҳ аз чӣ PR сохтан намешавад, ва ҳангоми мушкил бозгашт кардан ҷое нест. Одат: аввал git switch -c, баъд код.

Шохаро бо таҳрирҳои нигоҳнадошта иваз кардан. Git ё онҳоро мебарад, ё рад мекунад. Беҳтараш аввал commit кунед.

Шохаҳо — графи commit-ҳо ҳастанд, ва мо онро бо код гашта метавонем. Аз оддӣ оғоз мекунем: занҷири «падар → падар»-ро мегузарем, чунон ки git log мекунад.

03 GitHub: push, pull request, ревью

Git дар компютери шумо зиндагӣ мекунад. GitHub — сайтест, ки нусхаи репозиторий дар он нигоҳ дошта мешавад (онро origin — «репозиторийи дур» меноманд). Маҳз тавассути GitHub гурӯҳ коди худро мубодила мекунад, ва корфармо портфолиои шуморо мебинад.

git remote add origin https://github.com/ВАШ_ЛОГИН/chaykhona-site.git
git push -u origin main            # первая отправка, -u запоминает связь веток
git push                           # дальше достаточно просто push
git clone https://github.com/ВАШ_ЛОГИН/chaykhona-site.git   # скачать чужой репозиторий
git pull                           # забрать новые коммиты с GitHub
git fetch                          # только скачать информацию, ничего не менять

git pull — ин fetch (зеркашӣ) + merge (ба шохаи шумо даровардан) аст. Агар дар GitHub commit-ҳои нави ҳамкорон пайдо шуда бошанд, вале дар назди шумо нестанд, пеш аз push аввал pull мекунанд.

Pull request — ғояи асосии кори гурӯҳӣ

Pull request (PR) — ин хоҳиш аст: «тағйироти маро дар шоха бинед ва агар ҳама хуб бошад, онҳоро ба main дароред». PR фармони Git нест, балки имкони GitHub аст. Шумо шохаро push мекунед, дар сайт «Compare & pull request»-ро пахш мекунед, тавсиф менависед, ва ҳамкор тағйиротро сатр ба сатр мехонад, шарҳ мемонад, тасдиқ мекунад ё ислоҳ металабад.

Монандӣ: чек пеш аз пардохт дар бозор

Фурӯшанда маблағро дар коғазча навишт, аммо пеш аз пардохт шумо коғазчаро ба ҳамсоя нишон медиҳед: «Санҷ, дуруст ҷамъ кардаам?». Ҳамсоя хатои як сомониро ёфт — шумо ислоҳ кардед, ва танҳо баъд пул додед. PR — ҳамон «нигоҳи аз берун» пеш аз он аст, ки код ба шохаи асосӣ мерасад.

Давраи корӣ дар ҷуфт

Маҳз ҳамин тавр шумо имрӯз дар машғулот ва минбаъд — дар лоиҳаҳо ва дар кор кор мекунед:

  1. main-ро навсозӣ кунед: git switch main, git pull.
  2. Шоха эҷод кунед барои як вазифа: git switch -c feature/order-filters.
  3. Кор кунед ва commit кунед бо қадамҳои хурди бомаъно.
  4. Шохаро фиристед: git push -u origin feature/order-filters. GitHub истиноди эҷоди PR-ро чоп мекунад.
  5. Pull request-ро кушоед: сарлавҳа, чӣ анҷом шуд, барои чӣ, чӣ тавр санҷидан. Ҳамкорро ҳамчун ревьюер таъин кунед.
  6. Ревью: ҳамкор diff-ро мехонад, шарҳ менависад. Шумо ҷавоб медиҳед ва ислоҳ мекунед — commit-ҳои нав ба ҳамон шоха худашон ба PR мерасанд.
  7. Merge: пас аз тасдиқ (approve) ва санҷишҳои муваффақ PR-ро бо тугмаи Merge pull request дар GitHub ба main медароранд.
  8. Аз паси худ тоза кунед: git switch main, git pull, git branch -d feature/order-filters.
Ҳангоми ревью ба чӣ нигоҳ кардан лозим

Оё код кор мекунад (шохаро иҷро кунед)? Оё номҳо фаҳмоанд? Оё файлҳои зиёдатӣ ва console.log нестанд? Оё ҳолатҳои канорӣ тасвир шудаанд (рӯйхати холӣ, сифр, хатои шабака)? Шарҳро дар бораи код менависем, на дар бораи одам: «Дар ин ҷо ҳангоми рӯйхати холӣ хато мешавад» ба ҷои «Ту фаромӯш кардӣ».

04 Низоъҳои ҷамъкунӣ (merge conflict)

Git метавонад тағйиротро худкор ҷамъ кунад, агар шумо ва ҳамкор ҷойҳои гуногунро таҳрир карда бошед. Аммо агар шумо ҳарду як сатри ягонаро гуногун тағйир диҳед, Git намедонад, версияи кӣ дуруст аст, ва аз одам хоҳиш мекунад, ки ҳал кунад. Ин низоъ (conflict) аст. Он вайроншавӣ нест, балки қисми оддии кор: дар ҳар гурӯҳ низоъҳо ҳар ҳафта рух медиҳанд.

Фарз кунем, ки шумо бо ҳамкор файли rate.js-ро таҳрир кардед. Ҳамкор шохаи худро аллакай ба main даровард, ва шумо дар шохаи худ git pull origin main кардед:

git switch feature/rate
git pull origin main
# Auto-merging rate.js
# CONFLICT (content): Merge conflict in rate.js
# Automatic merge failed; fix conflicts and then commit the result.

Git истод ва дар файл маркерҳои низоъ-ро сабт кард:

// қурби мубодила
<<<<<<< HEAD
const convertUsd = (usd, rate = 10.9) => Math.round(usd * rate);
=======
const toSomoni = (usd) => usd * 11;
>>>>>>> origin/main
<<<<<<< HEAD
Оғози низоъ. Дар зер — версияи шумо (аз шохае, ки дар он истодаед).
=======
Ҷудокунанда. Дар зер — версияи аз шохаи дигар (дар ин ҷо origin/main).
>>>>>>> origin/main
Охири низоъ ва номи шохае, ки версияи дуюм аз он омадааст.

Низоъро чӣ тавр ҳал кардан

  1. Файлро кушоед бо калимаи CONFLICT. Дар VS Code болои блок тугмаҳо пайдо мешаванд: Accept Current (аз они ман), Accept Incoming (аз они бегона), Accept Both (ҳарду) ва Compare.
  2. Аз рӯи маъно ҳал кунед, ки чӣ бояд бимонад. Гоҳо бояд порчаҳоро аз ҳарду версия гирифт — ва коди ниҳоиро бо даст навишт. Бо муаллифи таҳрири дуюм мувофиқа кунед.
  3. Ҳамаи се сатри маркерҳоро хориҷ кунед. Дар файл танҳо коди муқаррарӣ бояд бимонад.
  4. Лоиҳаро иҷро кунед ва боварӣ ҳосил намоед, ки ҳама кор мекунад.
  5. Ҷамъкуниро анҷом диҳед: 
    git add rate.js
git commit -m "merge main into feature/rate"
git push
Агар ошуфтед

Фармони git merge --abort (ё git rebase --abort) ҷамъкуниро бекор мекунад ва ҳама чизро ба ҳолати пеш аз он бармегардонад. Низоъро дар шохаи худ пеш аз merge ҳал мекунанд: он гоҳ ба main натиҷаи тоза мерасад.

Хатои хатарнок

Файлеро commit кардан, ки дар он сатрҳои <<<<<<< мондаанд. Чунин код иҷро намешавад. Пеш аз git add дар лоиҳа <<<<<<<-ро ҷустуҷӯ кунед (Ctrl+Shift+F дар VS Code).

Маркерҳо — матни оддӣ ҳастанд, ва онҳоро бо код таҳлил кардан мумкин аст. Вазифаи аввалро шумо бо даст, мисли низои ҳақиқӣ ҳал мекунед. Дар дуюмӣ «ҳалли худкор»-ро менависед, чунон ки муҳаррирҳо мекунанд.

function matchRule(rule, path) {
  const parts = path.split("/");
  const name = parts[parts.length - 1];
  if (rule.endsWith("/")) {                          // «папка/»: ҳар феҳрист бо чунин ном
    return parts.slice(0, -1).includes(rule.slice(0, -1));
  }
  if (rule.startsWith("*.")) return name.endsWith(rule.slice(1)); // «*.log»: аз рӯи васеъкунӣ
  return name === rule;                              // номи дақиқи файл
}

function isIgnored(path, rules) {
  let ignored = false;
  for (const rule of rules) {                        // қоидаҳо аз боло ба поён хонда мешаванд
    if (rule.startsWith("!")) {                      // «!ном» файлро бозпас мегардонад
      if (matchRule(rule.slice(1), path)) ignored = false;
    } else if (matchRule(rule, path)) {
      ignored = true;
    }
  }
  return ignored;
}

06 Хатоҳо: try / catch / finally ва throw

Хатоҳо ба ҳама рух медиҳанд: корбар сатри холӣ ворид кард, сервер ҷавоб надод, аз localStorage партов омад. Агар коре накунем, барнома дар сатри аввалини дорои хато меистад. Вазифаи таҳиягар — пешакӣ дида баромадани ҷойҳоест, ки код метавонад биафтад, ва ҳамин тавр кардан, ки корбар паёми фаҳморо бубинад, на экрани сафедро.

try / catch / finally

Монандӣ: суғурта дар маршрутка

try — «кӯшиш мекунем аз ин роҳ равем». catch — нақшаи эҳтиётӣ, агар роҳ баста бошад: рӯ тоб додан ва аз гирди роҳ рафтан. finally — он чизе, ки ба ҳар ҳол мешавад: аз маршрутка баромадан ва ба ронанда пул додан.

function readAge(text) {
  try {
    const age = JSON.parse(text);          // метавонад хато партояд
    console.log("прочитали:", age);
    return age;
  } catch (error) {
    console.log("не получилось:", error.name);
    return 0;                              // нақшаи эҳтиётӣ
  } finally {
    console.log("— чтение закончено —");   // ҳамеша иҷро мешавад
  }
}

console.log(readAge("19"));
console.log(readAge("девятнадцать"));

Хато дар дохили try онро фавран қатъ мекунад, ва идора ба catch мегузарад. Сатрҳои боқимондаи try гузашта мешаванд. Ба catch объекти хато меояд (онро одатан error ё e меноманд).

throw: хатои худро мепартоем

Гоҳо хаторо худатон бояд эҷод кунед. Масалан, функсия аз корбар миқдори манфӣ гирифт. throw функсияи ҷориро қатъ мекунад ва хаторо ба боло — то наздиктарин catch «мепартояд». Объекти хато-ро партоед (new Error("матн")), на танҳо сатр: объект стек дорад.

function setQuantity(qty) {
  if (!Number.isInteger(qty)) throw new TypeError("Количество должно быть целым числом");
  if (qty < 1) throw new RangeError("Количество не может быть меньше 1");
  return qty;
}

for (const value of [3, 0, 2.5]) {
  try {
    console.log("ок:", setQuantity(value));
  } catch (e) {
    console.log(`${e.name}: ${e.message}`);
  }
}
Хатои маъмул: catch-и холӣ

catch (e) {}-и холӣ хаторо «фурӯ мебарад»: барнома хомӯш аст ва ғайриодатӣ рафтор мекунад, ва сабабро ёфтан намешавад. Ҳадди ақал — хаторо ба консол бароред ё ба корбар паём нишон диҳед. Ва танҳо он хатоҳоеро бигиред, ки коркард карда метавонед: боқиро тавассути throw e ба пеш гузаронед (вазифаи 6.5).

  throw new Error("что-то пошло не так");

console.log("до этой строки мы уже не дойдём");

Хатоҳоро дар коди ғайримуттаҳид бо ҳамон try / catch дар гирди await мегиранд (шумо инро дар дарси 13 дидед, ва дар дарсҳои минбаъда ҳамин тавр дархостҳои fetch-ро коркард мекунед). try-и алоҳида дар гирди setTimeout кор намекунад: колбэк баъдтар иҷро мешавад, вақте блок аллакай анҷом ёфтааст.

ВАЗИФАИ 6.1

Пешгӯӣ кунед: тартиб бо finally

осон

Аввал бе иҷро ҳал кунед, ки сатрҳо бо кадом тартиб пайдо мешаванд. Блоки finally «ҳамеша» иҷро мешавад — ҳатто агар дар try аллакай return буд. Пешгӯиро ба prediction нависед (сатрҳо бо тартиб, айнан чунон ки console.log нишон медод) ва иҷро кунед. Боқии кодро тағйир додан лозим нест.

const log = [];   // дар ин ҷо код «баромад»-ро ҷамъ мекунад

  try {
    log.push("1: try");
    return "результат";
  } catch (e) {
    log.push("catch");
  } finally {
    log.push("2: finally");
  }
  log.push("после");
}
log.push("3: " + test());

07 Стеки даъватҳо ва DevTools

Хатои сурхро чӣ тавр хондан

Вақте код меафтад, браузер сатри сурх ва стеки даъватҳо-ро чоп мекунад: рӯйхати функсияҳо аз ҷойи хато то оғози кор. Онро аз боло ба поён хонед: сатри якум — дар куҷо афтод, сатрҳои баъдӣ — кӣ ин функсияро даъват кард.

Донишҷӯ аз куратор мепурсад, куратор — аз муаллим, муаллим — аз методист, ва дар охир маълум мешавад, ки дар ҷадвал хато ҳаст. Стек — ин сабти он аст, ки кӣ аз кӣ пурсид. Барои ёфтани он, ки хато аз куҷост, занҷирро аз поён ба боло мегузарем, аммо ба даъвати болоӣ менигарем: маҳз он «натавонист».

Sources — ислоҳи қадам ба қадам ва breakpoint-ҳо

Ба ҷои даҳҳо console.log метавонед барномаро дар сатри даркорӣ қатъ кунед ва атрофро дида бароед. Ҷадвали Sources-ро кушоед, файлро интихоб кунед ва ба рақами сатр дар чап зер кунед: нишони кабуд — breakpoint пайдо мешавад. Акнун дар саҳифа амалеро иҷро кунед (масалан, тугмаро пахш кунед): иҷро пеш аз ин сатр қатъ мешавад.

  1. Атрофро бубинед. Дар тарафи рост дар панели Scope қиматҳои ҳамаи тағйирёбандаҳо дар ин лаҳза намоёнанд. Дар Watch ҳар ифодаро илова кардан мумкин аст, масалан items.length. Дар Call Stack — ҳамон стеки даъватҳо.
  2. Қадам ба қадам равед. F10 (Step over) — сатрро иҷро кардан ва ба навбатӣ гузаштан. F11 (Step into) — ба дохили функсияи даъватшаванда даромадан. Shift+F11 (Step out) — аз функсия баромадан. F8 — то breakpoint-и навбатӣ идома додан.
  3. Интизориро бо воқеият муқоиса кунед. Дар кадом сатр қимат на он тавр шуд, ки шумо меандешидед? Ин ҳамон ҷойи хатост.

Вариантҳои қулай: breakpoint-и шартӣ (зеркунии рост ба рақами сатр → Add conditional breakpoint, масалан i === 3) ва Pause on exceptions (тугмаи бо таваққуф): DevTools худаш дар лаҳзае, ки код хато меандозад, қатъ мешавад.

09 ЗС: commit-ҳо, тавсифи PR ва савол дар бораи хато

Блоки ЗС-и дарс

ЗС ду корро хуб мекунад: commit-ро аз рӯи diff-и тайёр таҳия мекунад ва фарзияҳоро дар бораи хато пешниҳод менамояд. Аммо масъулият бар дӯши шумост: diff-ро худатон хондед, ва фарзияҳоро бо иҷро месанҷед, на бо суханони ӯ бовар мекунед. Қоидаҳои курс: аввал 15 дақиқа худатон кӯшиш кунед; кодеро, ки сатр ба сатр шарҳ дода наметавонед, нагузоред.

1. Commit ва тавсифи PR аз рӯи diff

Баромади git diff --staged-ро нусха кунед ва аз ЗС хоҳиш намоед, ки паёмро таҳия кунад. Бе контекст ӯ «update files» менависад:

commit бисоз
Инак diff: [баромади git diff --staged-ро гузоред]. Паёми commit-ро бо услуби Conventional Commits нависед (навъ: мавзӯъ, то 50 аломат, англисӣ, шакли амр, бе нуқта) ва тавсифи кӯтоҳи PR: чӣ анҷом шуд ва барои чӣ. Формати ҷавоб: аввал як сатри commit, баъд PR аз се бахш «Чӣ анҷом шуд», «Барои чӣ», «Чӣ тавр санҷидан». Он чизеро, ки дар diff нест, наандеш.

Дар ҷавоб чиро санҷидан лозим:

  • Навъ ба ҳақиқат мувофиқ аст: feat ё fix, на «ба эҳтимол».
  • Дар матн он чизе нест, ки дар diff нест (ЗС «самаранокиро беҳтар кардам» илова карданро дӯст медорад, дар ҳоле ки шумо ба он даст назадаед).
  • Паём мушаххас аст: онро аз санҷишҳои вазифаҳои 5.3 ва 9.2 гузаронед.
  • Агар дар diff ду андешаи гуногун бошад, беҳтар аст ба ду commit тақсим кунед, на ин ки аз ЗС хоҳиш намоед «зебо муттаҳид кунад».

2. Хато: ба ҷои «кор намекунад» — мисоли ҳадди ақали такроршаванда

дар назди ман сабад кор намекунад, ислоҳ кун
Хато: интизорам [чӣ], мегирам [чӣ]. Коди ҳадди ақал: [код]. Хато дар консол: [матн]. 3 фарзияи сабабро аз рӯи эҳтимол деҳ.

Мисоли ҳадди ақали такроршаванда (minimal reproducible example, MRE) — кӯтоҳтарин коде, ки хато дар он ҳанӯз намоён аст. Чӣ тавр онро ба даст овардан:

  1. Ҷойи мушкилдорро ба файли алоҳида ё ба консол дар ҳамин саҳифа нусха кунед.
  2. Ҳар чизи зиёдатиро порча-порча хориҷ кунед: услубҳо, функсияҳои ҳамсоя, майдонҳои зиёдатӣ. Пас аз ҳар қадам санҷед, ки хато ҷой дорад.
  3. Маълумоти оддиро ҷойгузин кунед ба ҷои дархостҳо ба сервер: массиви 2–3 унсур.
  4. Сабт кунед натиҷаи интизоршаванда ва воқеӣ, ҳамчунин матни хаторо калима ба калима.

Бонус: то шумо кодро содда мекардед, аксар вақт худатон хаторо меёбед. Ин муқаррарӣ ва хеле қиматнок аст. Усул «мурғобича» (rubber duck) ном дорад: мушкилро бо овози баланд чунон возеҳ шарҳ додан, ки ҷавоб худаш пайдо шавад.

Бо фарзияҳо чӣ тавр кор накардан лозим

ЗС се фарзия дод. Онҳоро пай дар пай, аз эҳтимолтарин месанҷед, ва пас аз ҳар кадом — иҷро. Агар якбора се «ислоҳ»-ро гузоред, намефаҳмед, кадомаш кор кард, ва ёд намегиред, ки ин хаторо дафъаи оянда пай бурдан лозим аст. Ҳамчунин ЗС гоҳо методҳои вуҷуднадоштаро бо боварӣ маслиҳат медиҳад: номи ношиносро дар MDN санҷед.

Ба варақаи кӯмакии промптҳо ду сатри ин дарсро илова кунед — «Commit-ҳо ва pull request» ва «Хато ба ҷои „кор намекунад“». Ҳарду маҳоратро бо код машқ мекунем.

function calcTotal(items) {
  let sum = 0;
  for (let i = 1; i < items.length; i++) {
    sum += items[i].price;
  }
  return sum;
}

function priceWithDiscount(items) {
  const total = calcTotal(items);
  return total > 500 ? total * 0.9 : total;
}

function withDelivery(items) {
  items.push({ id: 0, name: "Доставка", price: 15 });
  return items;
}
