Формы и валидация

Регистрация, вход, заказ плова с доставкой, запись на курс — почти всё, что пользователь «даёт» сайту, он вводит через форму. А пользователи ошибаются: пропускают поля, пишут телефон без кода страны, ставят пробел в конец email. Сегодня вы научитесь читать данные из формы и вежливо объяснять человеку, что нужно исправить, — ещё до отправки.

  • Читать value и checked у разных полей: текст, число, радиокнопки, чекбоксы, список
  • Перехватывать отправку формы событием submit и собирать данные через FormData
  • Пользоваться встроенной валидацией браузера и понимать, чего ей не хватает
  • Писать простые регулярные выражения и применять их в проверках
  • Писать свои функции-валидаторы и выводить понятные тексты ошибок прямо под полями
  • Делать «живую» валидацию: проверять поле, пока человек вводит данные

01 Форма и её поля: value и checked

Форма в HTML — это тег <form>, внутри которого лежат поля ввода: <input>, <select>, <textarea> и кнопка отправки. Вёрстку вы уже знаете — сегодня нас интересует, как достать из этих полей данные с помощью JavaScript.

Аналогия из жизни

Анкета в банке или бланк заказа в чайхоне: у каждой строки есть название («Имя», «Телефон») и то, что вы вписали. В форме название — это атрибут name, а то, что вписано, — свойство value. Оператор берёт заполненный бланк и читает строку за строкой — ровно так же работает ваш скрипт.

Как найти поле

Каждое поле можно найти через querySelector, но у формы есть удобный путь — коллекция form.elements. В ней поля доступны по атрибуту name:

<form id="reg">
  <label>Имя <input name="fullName" value="Мадина"></label>
  <label>Возраст <input name="age" type="number" value="19"></label>
  <label>Город
    <select name="city">
      <option value="dushanbe">Душанбе</option>
      <option value="khujand">Худжанд</option>
    </select>
  </label>
  <label><input type="checkbox" name="agree"> Согласен с правилами</label>
  <button type="button" id="show">Показать значения</button>
</form>

label { display: grid; gap: 4px; font-size: 14px; }
input, select, button { padding: 6px 8px; font: inherit; }

const form = document.querySelector("#reg");

document.querySelector("#show").addEventListener("click", () => {
  console.log("fullName:", form.elements.fullName.value);
  console.log("age:", form.elements.age.value, typeof form.elements.age.value);
  console.log("city:", form.elements.city.value);
  console.log("agree:", form.elements.agree.checked);

Главная ловушка: value — всегда строка

Даже у type="number" значение приходит строкой. Это та самая история с приведением типов из урока 2:

document.body.innerHTML = `
  <input name="plov" type="number" value="40">
  <input name="tea" type="number" value="10">`;

const plov = document.querySelector("[name=plov]").value;
const tea = document.querySelector("[name=tea]").value;

console.log(plov + tea);                   // "4010" — склеились как строки!
console.log(Number(plov) + Number(tea));   // 50 — сначала превращаем в числа
console.log(document.querySelector("[name=plov]").valueAsNumber); // 40 — число сразу
Частые ошибки

1) Читать у чекбокса .value вместо .checked — вы всегда получите строку "on", даже если галочки нет. 2) Забыть .value и вывести сам элемент: console.log(form.elements.fullName) покажет тег, а не текст. 3) Сложить два числовых поля через + — получится склейка строк.

Атрибуты name, label и type

  • name — «имя поля». Через него мы находим поле в form.elements, и именно по нему данные попадают в FormData (раздел 3). Без name поле «невидимо» для формы.
  • <label> — подпись. Оберните в неё поле или свяжите через for и id: тогда клик по тексту ставит курсор в поле, а экранные читалки понимают, что за поле перед ними.
  • type — подсказывает браузеру, какую клавиатуру показать на телефоне (tel — цифровую, email — с «@») и какие проверки включить.

02 Отправка формы: событие submit

Когда человек нажимает кнопку «Отправить» или жмёт Enter в текстовом поле, форма генерирует событие submit. Если ничего не делать, браузер отправит данные на сервер и перезагрузит страницу — все введённые данные и вся ваша JS-логика пропадут. Поэтому первая строка любого обработчика отправки — event.preventDefault() (вы знаете это из урока 9).

document.body.innerHTML = `
  <form id="order">
    <input name="dish" value="Оши палав">
    <input name="qty" type="number" value="2">
    <button>Заказать</button>
  </form>`;

const form = document.querySelector("#order");

form.addEventListener("submit", (event) => {
  event.preventDefault();                       // не даём странице перезагрузиться
  const dish = form.elements.dish.value;        // читаем значения ВНУТРИ обработчика
  const qty = Number(form.elements.qty.value);
  console.log(`Заказ принят: ${dish} × ${qty}`);
});

form.dispatchEvent(new Event("submit", { cancelable: true }));   // имитируем нажатие кнопки «Заказать»

Слушаем submit, а не click

Плохо: click на кнопке

Если человек отправит форму клавишей Enter, кнопку никто не нажимал — ваш код не сработает.

button.addEventListener("click", () => {
  // Enter в поле сюда не попадёт
});
Хорошо: submit на форме

Срабатывает при любом способе отправки: мышь, Enter, кнопка на телефоне.

form.addEventListener("submit", (event) => {
  event.preventDefault();
  // ...
});

Полезные детали

event.target
В событии submit это сама форма. Значит, поля можно взять как event.target.elements.email — обработчик не зависит от переменной снаружи.
form.reset()
Возвращает все поля к начальным значениям (тем, что записаны в атрибутах value / checked, или пустым). Вызываем после успешной отправки.
form.dispatchEvent(new Event("submit", { cancelable: true }))
Вручную «стреляет» событием submit. Так мы имитируем нажатие «Отправить» в примерах и задачах: учебная песочница блокирует настоящую отправку форм, поэтому обычный form.requestSubmit() (он нажимает кнопку сам) здесь не сработает. На обычном сайте вы кликаете по кнопке или вызываете именно requestSubmit().
<button type="button">
Кнопка внутри формы по умолчанию отправляет её. Если кнопка нужна для другого (например, «показать пароль»), пишите type="button".
novalidate
Атрибут формы: отключает встроенную проверку браузера, чтобы работала ваша собственная (раздел 4).
Типичный баг: читаем значение слишком рано

Значение поля меняется, пока человек печатает. Поэтому читать его надо в момент события, внутри обработчика. Если прочитать один раз в начале скрипта, вы получите то, что было в поле при загрузке страницы (чаще всего — пустую строку).

document.body.innerHTML = `<form><input name="email"></form>`;
const form = document.querySelector("form");

const email = form.elements.email.value;   // ✖ прочитали сразу — там ещё пусто

form.addEventListener("submit", (event) => {
  event.preventDefault();
  console.log("email:", "[" + email + "]");
});

form.elements.email.value = "madina@mail.tj";  // «пользователь» вписал адрес
form.dispatchEvent(new Event("submit", { cancelable: true }));                          // → email: []
Аналогия из жизни

Официант в чайхоне записывает заказ не тогда, когда вы только сели за стол, а когда вы сказали «можно заказывать». Значения в форме читаем так же — в момент отправки, а не заранее.

03 FormData: собираем все поля разом

Если в форме 10 полей, читать их по одному через .value — скучно и легко что-то забыть. Для этого в браузере есть встроенный объект FormData: вы отдаёте ему форму, а он сам обходит все поля с атрибутом name и собирает их «имя → значение».

document.body.innerHTML = `
  <form>
    <input name="fullName" value="Мадина">
    <select name="city">
      <option value="dushanbe" selected>Душанбе</option>
      <option value="khujand">Худжанд</option>
    </select>
    <input type="checkbox" name="skills" value="css" checked>
    <input type="checkbox" name="skills" value="js" checked>
    <input type="checkbox" name="skills" value="git">
    <input type="checkbox" name="agree" checked>
    <input type="checkbox" name="news">
  </form>`;

const form = document.querySelector("form");
const data = new FormData(form);

console.log(data.get("fullName"));    // Мадина — одно значение по имени
console.log(data.getAll("skills"));   // ["css", "js"] — все значения одного имени
console.log(data.has("news"));        // false — чекбокс без галочки в FormData не попадает
console.log(data.get("agree"));       // "on" — у чекбокса без атрибута value значение "on"

for (const [key, value] of data) {    // FormData можно перебрать как пары «ключ, значение»
  console.log(key, "=", value);
}

Из FormData легко получить привычный объект — он пригодится, чтобы сохранить данные или показать их пользователю (упакованный в JSON, как на уроке 7):

document.body.innerHTML = `
  <form>
    <input name="fullName" value="Мадина">
    <input name="age" type="number" value="19">
  </form>`;

const data = new FormData(document.querySelector("form"));
const obj = Object.fromEntries(data);   // { fullName: "Мадина", age: "19" }

console.log(JSON.stringify(obj));
console.log(typeof obj.age);   // string — все значения по-прежнему строки!
Аналогия из жизни

Это как почтовый курьер, который забирает из офиса все заполненные бланки одним пакетом. Но в пакет он берёт только бланки с подписью (name) и только те, которые заполнены. Поле без name — безымянный бланк, его курьер не возьмёт.

Что не попадает в FormData
  • поля без атрибута name;
  • поля с атрибутом disabled (для «только чтения» используйте readonly);
  • чекбоксы и радиокнопки без галочки — их ключа в данных просто нет. Если нужно false, берите checked напрямую: form.elements.news.checked.

А ещё Object.fromEntries оставляет только последнее значение для повторяющихся имён (skills), поэтому для групп чекбоксов используйте data.getAll("skills").

Позже, когда мы дойдём до работы с сервером, этот же объект FormData можно будет отправить на сервер как есть. А пока наша цель — собрать данные и убедиться, что они правильные.

У каждого поля есть методы и свойства, которые сообщают результат встроенной проверки:

console.log(email.validity.valueMissing);    // false — поле не пустое

checkValidity()
Возвращает true / false. У формы проверяет все её поля сразу.
reportValidity()
То же, но ещё и показывает пользователю всплывающую подсказку браузера.

Объект с флагами причин: valueMissing (пусто при required), typeMismatch (не email/url), patternMismatch (не подошёл pattern), rangeUnderflow / rangeOverflow (меньше min / больше max), tooShort / tooLong, customError.
validationMessage
Текст ошибки на языке браузера пользователя. У одного человека он русский, у другого английский — управлять им нельзя.

Вручную объявляет поле невалидным с вашим сообщением. Пустая строка "" снимает ошибку.

Аналогия из жизни

Встроенная валидация — как охранник на входе в торговый центр: он смотрит на очевидное (есть ли билет, не пустой ли пропуск), но не знает правил вашего магазина. Он не скажет «Вам нужен именно таджикский номер с кодом +992» и не объяснит причину отказа на понятном вам языке и в нужном месте страницы. Для этого нужна собственная проверка.

Чего не хватает встроенной валидации

  • Тексты ошибок — на языке и в стиле браузера, их не оформить по дизайну сайта.
  • Один пузырёк за раз — человек видит только первую ошибку, а не все сразу.
  • Сложные правила — «пароли совпадают», «телефон только таджикский» требуют своего кода.
  • Живая проверка по ходу ввода — «красиво» без своего JavaScript не получится.
Нюансы

1) minlength и maxlength проверяются только когда значение вводит человек. Если записать input.value = "a" из JavaScript, флаг tooShort не сработает. 2) Все проверки браузера и ваш JS на странице легко обойти (достаточно открыть DevTools), поэтому на настоящем сайте данные проверяют ещё и на сервере. Проверка в браузере — это удобство для человека, а не защита.

Поэтому на практике делают так: ставят базовые атрибуты (required, type) ради подсказок мобильной клавиатуры, а саму проверку и тексты ошибок пишут в JavaScript и отключают браузерные пузырьки атрибутом novalidate на форме:

<form id="reg" novalidate>
  <input name="email" type="email" required>
</form>

05 Регулярные выражения для новичков

Регулярное выражение (regex, «регэксп») — это короткий шаблон, который описывает, как должна выглядеть строка. «Только цифры», «начинается с +992 и дальше девять цифр», «латинские буквы и подчёркивание» — всё это записывается одной строчкой. Для проверки форм это незаменимый инструмент.

Аналогия из жизни

Портной снимает мерки и вырезает ткань по лекалу: деталь либо точно ложится на лекало, либо нет. Регулярное выражение — лекало для текста. Вы описываете форму один раз, а компьютер прикладывает к ней любую строку и отвечает «подходит» или «не подходит».

const onlyDigits = /^\d+$/;          // между слэшами — шаблон

console.log(onlyDigits.test("12345"));  // true  — подходит
console.log(onlyDigits.test("12a45"));  // false — есть буква
console.log(onlyDigits.test(""));       // false — пусто (нужна хотя бы одна цифра)

Регулярное выражение записывается между двумя слэшами /.../. Метод .test(строка) возвращает true, если строка подходит под шаблон, иначе — false. Теперь разберём «буквы» этого языка.

Алфавит регулярок: всего несколько символов

\sПробельный символ: пробел, таб, перевод строки/\s/ подходит к «a b»

Читаем регулярку по частям

Номер телефона в Таджикистане: +992 и девять цифр. Разберём шаблон слева направо:

const phone = /^\+992\d{9}$/;

console.log(phone.test("+992927771234"));    // true
console.log(phone.test("+99292777123"));     // false — только 8 цифр
console.log(phone.test("+9929277712345"));   // false — 10 цифр, лишняя
console.log(phone.test("927771234"));        // false — нет кода страны

Якоря ^ и $: самая частая ошибка

Без ^ и $ регулярка ищет подходящий кусочек внутри строки — и пропускает мусор вокруг:

const bad  = /\d{4}/;      // «где-то в строке есть 4 цифры подряд»
const good = /^\d{4}$/;    // «вся строка — ровно 4 цифры»

console.log(bad.test("abc1234xyz"));   // true  ← ✖ пропустили мусор
console.log(good.test("abc1234xyz"));  // false ← так правильно
console.log(good.test("1234"));        // true

Флаги и замена: чистим ввод

После закрывающего слэша можно ставить флаги: i — не различать большие и маленькие буквы, g — искать все совпадения, а не только первое. С методом replace это удобный способ почистить телефон от пробелов и дефисов:

const raw = "+992 92 777-12-34";
const clean = raw.replace(/[\s-]/g, "");   // убираем все пробелы и дефисы
console.log(clean);                        // +992927771234

console.log(/^tj$/i.test("TJ"));           // true — регистр не важен из-за флага i
console.log("a1b22c333".replace(/\D/g, ""));  // 122333 — оставили только цифры

Что нужно знать про регулярки
  • Якоря. Проверяете «вся строка такая» — ставьте ^ и $. Ищете «содержит» — не ставьте.
  • Не угадывайте, проверяйте. Регулярка — это код. Прогоните её на 5–10 примерах: подходящих и нет (в разделе про ИИ мы сделаем это системно).
  • Не усложняйте. Идеального выражения для email не существует, а «идеальные» занимают три строки, и никто их не понимает. Достаточно простой проверки формата. Что адрес реально существует, проверяют письмом с кодом, а не регуляркой.
  • Кириллица и \w. Шаблон \w (буквы, цифры, «_») понимает только латиницу. Для русских и таджикских букв пишите диапазоны явно и проверяйте на реальных именах.

06 Своя валидация: функции-валидаторы и тексты ошибок

Теперь у нас есть всё, чтобы написать собственную проверку. Рецепт простой и работает для любой формы:

  1. Один валидатор на поле. Это функция, которая принимает значение и возвращает текст ошибки — или пустую строку "", если всё хорошо.
  2. Собираем в объект. { fullName: validateName, email: validateEmail, ... } — по ключу видно, какой валидатор к какому полю.
  3. Показываем ошибки. Текст — в <span> под полем, а само поле помечаем красной рамкой и атрибутом aria-invalid.
  4. Не отправляем, пока есть хоть одна ошибка.

Шаг 1: валидатор — это функция «значение → текст ошибки»

function validateEmail(value) {
  const email = value.trim();                       // убираем пробелы по краям
  if (email === "") return "Введите email";
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
    return "Похоже, в адресе ошибка. Пример: madina@mail.tj";
  }
  return "";                                        // пустая строка = ошибок нет
}

console.log("[" + validateEmail("") + "]");
console.log("[" + validateEmail("madina@") + "]");
console.log("[" + validateEmail("  madina@mail.tj ") + "]");

Функция только проверяет и ничего не знает про страницу. Поэтому её легко тестировать (мы только что вызвали её с тремя примерами) и легко использовать повторно — на любой странице и с любым дизайном. Правило «функция считает, другая функция показывает» вы уже встречали на уроке 5.

Аналогия из жизни

Контролёр на входе в метро. Он не бежит за вами — он стоит у турникета и смотрит на билет. Если что-то не так, он называет причину («приложите карту», «не хватает денег»). Валидатор — тот же контролёр: на выходе либо «проходите» (""), либо понятная причина отказа.

Какие тексты ошибок писать

Плохо

«Ошибка!», «Неверное значение», «Invalid input», «Поле заполнено неверно». Человек не понимает, что не так и как исправить.

Хорошо

«Введите номер в формате +992 и 9 цифр», «Пароль — минимум 8 символов», «Пароли не совпадают». Сказано, чего ждём, и сразу виден пример.

  • Говорите на «вы» и спокойно: не «Ты ввёл неправильно», а «Проверьте, пожалуйста, email».
  • Называйте правило, а не только факт ошибки: «минимум 2 буквы» полезнее, чем «слишком коротко».
  • Показывайте ошибку рядом с полем, а не одним окном alert вверху страницы.
  • Пустое обязательное поле и неверный формат — это разные сообщения: «Введите email» и «Неверный формат email».

Шаг 2: проверяем все поля сразу

Когда валидаторов несколько, удобно держать их в объекте и пройти циклом. На выходе — объект ошибок: в нём есть ключи только у невалидных полей. Пустой объект — всё хорошо.

const validators = {
  fullName: (v) => (v.trim().length < 2 ? "Введите имя (минимум 2 буквы)" : ""),
  age: (v) => (Number(v) >= 16 ? "" : "Курс с 16 лет"),
};

function validateAll(data) {
  const errors = {};
  for (const field in validators) {
    const message = validators[field](data[field]);
    if (message) errors[field] = message;
  }
  return errors;
}

console.log(JSON.stringify(validateAll({ fullName: "Мадина", age: "19" })));   // {}
console.log(JSON.stringify(validateAll({ fullName: "М", age: "15" })));

Каждое поле получает «место для ошибки» — пустой <span> рядом. При ошибке мы пишем в него текст, при её отсутствии — стираем. Всегда используйте textContent, а не innerHTML: ввод пользователя нельзя вставлять в страницу как HTML.

function showError(name, message) {
  const input = form.elements[name];
  const box = form.querySelector(`[data-error="${name}"]`);
  box.textContent = message;                               // пустая строка стирает ошибку
  input.classList.toggle("invalid", message !== "");       // красная рамка
  input.setAttribute("aria-invalid", message ? "true" : "false");  // для читалок экрана
}

  event.preventDefault();
  let firstBad = null;
  for (const name in validators) {
    const message = validators[name](form.elements[name].value);
    showError(name, message);
    if (message && !firstBad) firstBad = form.elements[name];

  if (firstBad) {
    firstBad.focus();                 // ставим курсор в первое ошибочное поле
    return;                           // дальше не идём — форма не отправляется

Типичные ошибки
  • Забыли trim() — « » (пробелы) считается непустым именем.
  • Сравниваем строку как число — "5" < "16" сравнит строки по символам. Сначала Number(...).
  • Не стираем старую ошибку — человек исправил поле, а красный текст остался. Поэтому showError всегда вызывается и для валидных полей — с пустой строкой.
  • Показываем ввод через innerHTML — открывает дыру для XSS. Только textContent.
  • Проверка только в браузере — для настоящего сайта нужна ещё и серверная.

07 Живая валидация: проверяем, пока человек печатает

Проверка только при нажатии «Отправить» работает, но неудобно: человек заполнил десять полей и узнаёт об ошибке в самом первом. Живая валидация подсказывает сразу. Для неё нужны три события:

input
Срабатывает на каждое изменение значения: нажали клавишу, вставили текст, стёрли символ.
change
Срабатывает, когда значение поменялось и поле потеряло фокус (для чекбокса и списка — сразу при выборе).
blur
Поле потеряло фокус — человек ушёл в другое поле. Не всплывает (в отличие от focusout).
Аналогия из жизни

Хороший официант в чайхоне не перебивает вас на полуслове: «Нет, плова уже нет!» Он ждёт, пока вы закончите говорить, и только потом поправляет. Так и форма: не ругайтесь на поле, пока человек не закончил его вводить, иначе первая же буква email вызовет красное «Неверный email».

Правило «тронуто / не тронуто» (touched)

  1. Пока человек не покидал поле — ошибку не показываем, даже если значение пока неверное.
  2. Когда сработал blur — поле считается «тронутым»: проверяем и показываем ошибку.
  3. С этого момента на каждый input перепроверяем: как только человек исправил, ошибка исчезает сразу.
  4. При нажатии «Отправить» «трогаем» все поля сразу и показываем все ошибки.

Правило «пароли совпадают» зависит от двух полей, поэтому проверять нужно при изменении любого из них. Частая ошибка — подписаться только на второе поле: человек поправил первый пароль, а красная ошибка у второго осталась.

Типичные ошибки
  • Ругаемся слишком рано. Красная ошибка после первой буквы раздражает. Используйте «touched».
  • Проверяем только на change. Тогда человек видит ошибку только после ухода из поля — это уже не «живая» проверка. Основное событие — input.
  • Забыли проверку при отправке. Человек может нажать «Отправить», вообще не заходя в поле: живая валидация дополняет проверку на submit, а не заменяет её.
  • Блокируем кнопку без объяснения. Заблокированная кнопка «Отправить» без подсказки, чего не хватает, — плохой интерфейс. Лучше показывать ошибки и оставить кнопку активной.

09 Практика на уроке: форма регистрации с живой валидацией

Соберём всё вместе в одну форму — такую, какую вы увидите на любом сайте. Мы строим регистрацию на курс: имя, email, пароль и повтор пароля.

Правила нашей формы
  • Имя — минимум 2 символа без пробелов по краям. Ошибка: «Имя — минимум 2 буквы».
  • Email — простой формат что-то@что-то.что-то. Ошибка: «Введите email в формате name@mail.tj».
  • Пароль — минимум 8 символов, затем минимум одна цифра. Ошибки: «Пароль — минимум 8 символов» и «Добавьте хотя бы одну цифру».
  • Повтор пароля — совпадает с паролем. Ошибка: «Пароли не совпадают».
  • Ошибки появляются после ухода из поля (blur), дальше обновляются на каждый ввод (input).
  • При отправке проверяются все поля сразу, курсор встаёт в первое ошибочное, а при успехе выводится «Регистрация: имя, email» (пароль в логи не пишем — никогда!).

План работы

  1. Разметка. Форма с novalidate, у каждого поля — label, name и пустой span.error под ним (data-error="имя поля").
  2. Валидаторы. Функции «значение → текст ошибки», собранные в объект validators (раздел 6).
  3. Показ ошибок. showError — текст, красная рамка, aria-invalid.
  4. Живая проверка. Словарь touched, обработчики blur и input (раздел 7).
  5. Отправка. Обработчик submit: «трогаем» все поля, проверяем, фокус на первое ошибочное или успех (раздел 2).

Разметку, стили и общий «каркас» (шаги 1, 3) мы даём готовыми. Ваша работа — два этапа.

const form = document.querySelector("#reg");
const touched = {};

const validators = {
  fullName(value) {
    return value.trim().length < 2 ? "Имя — минимум 2 буквы" : "";
  },
  email(value) {
    return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value.trim()) ? "" : "Введите email в формате name@mail.tj";
  },
  password(value) {
    if (value.length < 8) return "Пароль — минимум 8 символов";
    if (!/\d/.test(value)) return "Добавьте хотя бы одну цифру";
    return "";
  },
  confirm(value) {
    return value === form.elements.password.value ? "" : "Пароли не совпадают";
  },
};

function showError(name, message) {
  const input = form.elements[name];
  form.querySelector(`[data-error="${name}"]`).textContent = message;
  input.classList.toggle("invalid", message !== "");
  input.setAttribute("aria-invalid", message ? "true" : "false");
}

function validateField(name) {
  const message = validators[name](form.elements[name].value);
  showError(name, message);
  return message === "";
}

for (const name of Object.keys(validators)) {
  const input = form.elements[name];
  input.addEventListener("blur", () => {
    touched[name] = true;
    validateField(name);
  });
  input.addEventListener("input", () => {
    if (touched[name]) validateField(name);
  });
}

form.elements.password.addEventListener("input", () => {
  if (touched.confirm) validateField("confirm");
});

form.addEventListener("submit", (event) => {
  event.preventDefault();
  let firstBad = null;
  for (const name of Object.keys(validators)) {
    touched[name] = true;
    if (!validateField(name) && !firstBad) firstBad = form.elements[name];
  }
  if (firstBad) {
    firstBad.focus();
    return;
  }
  const data = Object.fromEntries(new FormData(form));
  console.log(`Регистрация: ${data.fullName}, ${data.email}`);
});
