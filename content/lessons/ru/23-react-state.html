Props, списки и keys, useState

Вы уже умеете создавать компоненты и собирать из них страницу. Но страница, которая не меняется, — это просто красивая картинка. Сегодня мы научим компоненты принимать данные (props), выводить списки из массива, помнить состояние (useState) и реагировать на пользователя. Именно на этих четырёх вещах держится интерфейс любого сайта на React — от корзины интернет-магазина до чата.

  • Передавать данные в компонент через props, использовать children, деструктуризацию и значения по умолчанию
  • Выводить список из массива через .map() и объяснить, зачем нужен key и почему индекс в роли ключа ломает список
  • Хранить изменяемые данные в useState и обновлять их через setter, в том числе функциональным способом
  • Никогда не менять состояние «на месте»: добавлять, удалять и обновлять элементы массивов и объектов через spread, filter и map
  • Обрабатывать события (onClick, onChange, onSubmit) и делать управляемые поля ввода
  • Показывать и прятать части интерфейса: &&, тернарный оператор, ранний return
Как работать с этой страницей

Блоки кода с вкладками App.jsx и style.css — это мини-проекты React прямо в браузере: слева код, справа результат, внизу консоль. Меняйте код и нажимайте ▶ Запустить. Им нужен интернет — React подгружается из сети. В задачах под кодом есть строка // ---- проверка (не менять) ----: это маленький «робот-тестировщик», который после запуска сам нажимает кнопки и вводит текст, а потом пишет результат в консоль — по нему задача проверяется автоматически. В настоящем проекте такой блок не нужен, и трогать его не надо. Подсказки спрятаны под замочком 🔒: сначала пробуйте сами.

И ещё одна важная вещь. В реальном проекте на Vite React в консоли браузера ругается на ошибки, например «Each child in a list should have a unique key». Здесь, в учебной песочнице, работает «боевая» (production) сборка React, и этих предупреждений нет. Поэтому ошибки с ключами и состоянием мы будем ловить по результату, а не по красным строкам. Это даже полезнее: так вы учитесь видеть баг глазами.

01 Props: данные в компонент

Компонент — это функция, которая возвращает кусок интерфейса (на прошлом уроке вы создавали их в Vite). Одна и та же функция должна уметь рисовать разные карточки: про самбусу, про курутоб, про шакароб. Для этого ей нужны входные данные. В React они называются props — от слова «properties», свойства.

Аналогия из жизни

Меню в чайхоне. Рамка, шрифт и расположение строки — это компонент: они одинаковые для всех блюд. А «Самбуса — 5 сомони» и «Курутоб — 35 сомони» — это props: у каждого блюда свои. Типографии не нужно печатать новый бланк для каждого блюда — меняется только то, что вписано в строки.

Props передают как атрибуты в HTML. Внутри компонента они приходят одним объектом в первом аргументе функции:

function DishCard(props) {
  return <div>{props.name} — {props.price} сомони</div>;
}

// props = { name: "Самбуса", price: 5 }
<DishCard name="Самбуса" price={5} />

Обратите внимание на запись значений: строки можно писать в кавычках (name="Самбуса"), а всё остальное — числа, булевы значения, массивы, объекты, функции — в фигурных скобках (price={5}). Фигурные скобки здесь означают: «внутри — обычное JavaScript-выражение».

Props
Объект с данными, который родитель передаёт ребёнку. Родитель пишет их как атрибуты, ребёнок получает как аргумент функции.
Односторонний поток
Данные идут только сверху вниз: от родителя к ребёнку. Ребёнок не может переписать props своего родителя.
children
Особый prop: всё, что написано между открывающим и закрывающим тегами компонента.

Props нельзя менять

Props доступны компоненту только для чтения. Компонент должен вести себя как чистая функция: получил данные — нарисовал по ним интерфейс, но сами данные не трогает. Если компоненту нужно что-то изменять — это уже не props, а состояние (useState, раздел 04).

Частая ошибка

Попытка «подправить» props внутри компонента: props.price = props.price * 2. В режиме разработки React сразу выдаст ошибку, а в боевой сборке изменение может «тихо» сломать другие места. Нужно значение посчитать в новой переменной: const total = price * 2;

children — вложенное содержимое

Компоненты можно вкладывать друг в друга, как обычные HTML-теги. Всё, что вы написали между <Panel> и </Panel>, придёт в компонент в prop children. Вы сами решаете, где его вывести.

// children — всё, что написали МЕЖДУ открывающим и закрывающим тегом
function Panel({ title, children }) {
  return (
    <section className="card">
      <h3 style={{ margin: "0 0 6px" }}>{title}</h3>
      {children}
    </section>
  );
}

export default function App() {
  return (

Подарочная коробка. Сама коробка (рамка, бантик, надпись) — это компонент Panel. Что лежит внутри — children. Одну и ту же коробку можно использовать для конфет, для книги, для платка. Коробке неважно, что внутри, — её дело красиво это упаковать.

02 Деструктуризация, значения по умолчанию и rest

Писать props.name, props.price, props.city в каждой строке утомительно. Вы уже знаете из урока про объекты, как это сокращается: деструктуризация. В React её используют почти везде — прямо в скобках параметров функции.

// было
function StudentCard(props) {
  return <p>{props.name}, {props.age} лет</p>;
}

// стало
function StudentCard({ name, age }) {
  return <p>{name}, {age} лет</p>;
}

Значения по умолчанию

Если родитель не передал prop, внутри будет undefined. Чтобы подставить запасное значение, используйте знак = в деструктуризации — как в параметрах обычной функции (урок 5).

// Значения по умолчанию — прямо в деструктуризации props
function Button({ label = "Нажми", color = "gray" }) {
  return (
    <button style={{ background: color, color: "white", border: 0, borderRadius: 8, marginRight: 8 }}>
      {label}
    </button>
  );
}

export default function App() {
  return (
    <div>
      <Button label="Купить" color="green" />
      <Button label="Отмена" />
      <Button />
    </div>
  );
}

Ловушка

Значение по умолчанию срабатывает только для undefined. Если передали null, 0 или пустую строку "", будет использовано именно это значение. Для null в JavaScript есть оператор ?? — вы знакомы с ним по уроку про условия. Разберём это в задаче 2.3.

Rest и spread: «раздать остальные props»

Бывает, что компонент сам использует один-два prop, а все остальные должен передать вложенному тегу — например, <input>. Здесь работают знакомые три точки:

  • { label, ...rest } в параметрах — собирает все остальные props в объект rest;
  • <input {...rest} /> в JSX — раздаёт этот объект как набор атрибутов.
// ...rest собирает «все остальные» props, а {...rest} раздаёт их дальше
function Field({ label, ...rest }) {
  return (
    <label style={{ display: "block", margin: "6px 0" }}>
      {label}: <input {...rest} />
    </label>
  );
}

export default function App() {
  return (
    <div>
      <Field label="Имя" placeholder="Мадина" />
      <Field label="Пароль" type="password" placeholder="не менее 8 знаков" />
      <Field label="Возраст" type="number" min="14" max="99" />
    </div>
  );
}

Аналогия из жизни

Маршрутка в Душанбе. Водитель берёт плату за проезд (это label — то, что нужно ему), а вашу просьбу «остановите у Зелёного базара» и сумку (это rest) он не оставляет себе, а просто передаёт дальше. Так и компонент: берёт, что ему нужно, а остальное пересылает дальше без разбирательств.

Совет

Используйте {...rest} осознанно. Если раздавать «всё подряд», в тег может попасть prop, который он не понимает, и это сложно отлаживать. Для простых компонентов лучше явно перечислять нужные props.

03 Списки: .map() и key

Данные на сайте почти всегда приходят списком: товары в каталоге, сообщения в чате, студенты в группе. Писать <li> для каждого элемента вручную нельзя — длина списка заранее неизвестна. В React список рисуют так: берут массив и превращают каждый его элемент в кусок JSX методом .map(). С map вы познакомились на уроке про массивы — он возвращает новый массив, и React умеет выводить массив из JSX-элементов.

// Список из массива: .map() превращает каждый элемент в <li>
const lessons = ["HTML и CSS", "JavaScript", "React Lite"];

export default function App() {
  return (
    <ul>
      {lessons.map((lesson) => (
        <li key={lesson}>{lesson}</li>
      ))}
    </ul>
  );
}

  2. map превращает каждую строку в элемент. Для "JavaScript" получается <li>JavaScript</li>.

  4. Всё это записано в фигурных скобках { ... } — внутри JSX это «вставка JavaScript».

Зачем нужен key

Каждому элементу списка нужно дать особый prop key — уникальный «паспорт» элемента. По ключу React узнаёт, какой именно элемент изменился, добавился или исчез, и перерисовывает только нужное. Без ключей он не может отличить «удалили второй элемент» от «изменили содержимое второго и третьего».

Аналогия из жизни

Гардероб в чайхоне или театре. Вы сдаёте куртку и получаете номерок. Гардеробщик не запоминает ваше лицо и не смотрит на цвет куртки, а ищет по номеру. Если номерки выдавать «по порядку в очереди» (первый, второй, третий) и первый человек уйдёт, все остальные внезапно получат чужие номерки. Хороший номерок принадлежит человеку, а не месту в очереди. Именно так работают ключи.

Ключ должен быть:

  • уникальным среди соседей (в одном списке), но не обязательно на всей странице;
  • стабильным: у одного и того же элемента при каждой перерисовке один и тот же ключ;
  • взятым из данных: id из базы, уникальный артикул или логин — а не случайное число.

04 useState: компонент, который помнит

Props приходят снаружи и не меняются. Но на странице есть данные, которые меняются от действий пользователя: сколько раз нажали «лайк», что написано в поле, открыто ли меню. Эти данные называются состоянием (state). Для него в React есть хук useState.

Сначала посмотрим, почему обычной переменной недостаточно. Запустите пример и понажимайте кнопку:

// Так НЕ работает: обычная переменная не заставляет React перерисовать экран.
// Нажмите кнопку несколько раз и сравните экран с консолью.
export default function App() {
  let count = 0;

  function handleClick() {
    count = count + 1;
    console.log("count в памяти:", count);
  }

  return (
    <div>
      <p>На экране: {count}</p>
      <button onClick={handleClick}>+1</button>
    </div>
  );
}

В консоли число растёт, а на экране всегда ноль. Две причины:

  1. React перерисовывает компонент, только когда его об этом «попросили». Простое изменение переменной ему не видно.
  2. При каждой перерисовке функция компонента выполняется заново с нуля, и let count = 0 снова становится нулём. Обычные переменные внутри компонента не переживают перерисовку.

Нужно место, где значение живёт между перерисовками, и способ сообщить React «значение изменилось, перерисуй». Это и делает useState:

import { useState } from "react";

export default function App() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Вы нажали {count} раз</p>
      <button onClick={() => setCount(count + 1)}>Нажми меня</button>
    </div>
  );
}

Начальное значение
Аргумент useState(0). Используется только при первом показе компонента. При следующих перерисовках React отдаёт уже сохранённое значение.
Текущее значение
Первый элемент пары — count. Это обычная переменная, которую можно читать в JSX.

Функциональное обновление

Когда новое значение зависит от старого («прибавить 1»), безопасно передавать в сеттер функцию: setCount((c) => c + 1). React сам подставит в c самое свежее значение. Почему это важно? Внутри одного обработчика переменная count — это «снимок» значения на момент перерисовки. Три вызова setCount(count + 1) подряд превращаются в три раза «поставить 0 + 1» — и счётчик вырастет только на 1.

// count сейчас 0
setCount(count + 1);  // поставить 0 + 1
setCount(count + 1);  // поставить 0 + 1  (count всё ещё 0 в этом «снимке»)
setCount(count + 1);  // поставить 0 + 1  → итог: 1

// функциональная запись
setCount((c) => c + 1);  // 0 → 1
setCount((c) => c + 1);  // 1 → 2
setCount((c) => c + 1);  // 2 → 3  → итог: 3
Частая ошибка

Ожидать, что сразу после setCount(5) переменная count станет равна 5. Она изменится только при следующей перерисовке. Если нужно «прямо сейчас» работать с новым значением, положите его в отдельную переменную: const next = count + 1; setCount(next); console.log(next);

Правила хуков

Хуки вызывают только на верхнем уровне компонента — не внутри if, циклов и вложенных функций — и только в компонентах (функциях с именем с заглавной буквы). Так React не теряет порядок хранимых значений.

Хранить только необходимое

Если значение можно вычислить из другого состояния — не заводите под него отдельное. В задаче 4.2 число лайков вычисляется из флага liked: два значения, которые легко рассинхронизировать, превращаются в одно.

05 Главное правило: не менять состояние «на месте»

Состояние-массив и состояние-объект — самое частое место для ошибок новичков. Правило одно: никогда не меняйте состояние напрямую — всегда передавайте в сеттер новую копию. React сравнивает старое и новое значение «по ссылке». Если вы изменили тот же самый массив и передали его обратно, для React ничего не изменилось — он пропускает перерисовку.

Аналогия из жизни

Электронная очередь в банке. Если оператор молча зачеркнёт строчку в старом талоне, табло в зале этого не заметит. Чтобы все увидели изменение, нужно выдать новый талон и повесить его на табло. Новая копия массива — это новый талон: он и сообщает React «смотри, тут что-то поменялось».

Запустите пример и нажмите кнопку. В консоли «Лук» есть, а на экране его нет:

Ловушка

Spread делает поверхностную копию. Если внутри объекта лежит вложенный объект или массив (user.address.city), его нужно скопировать тоже: { ...user, address: { ...user.address, city: "Хуҷанд" } }. Поэтому в состоянии стараются хранить данные «плоскими».

Совет

Если сомневаетесь, не мутирую ли я состояние, посмотрите на метод. Мутируют: push, pop, shift, unshift, splice, sort, reverse. Не мутируют (возвращают новое): map, filter, slice, concat, spread. Для сортировки сначала сделайте копию: [...items].sort(...).

Тогда при каждой перерисовке все ключи новые, React считает, что все элементы заменены, и пересоздаёт их с нуля: поля теряют фокус и введённый текст. Идентификатор нужно создавать один раз — при создании данных (например, когда пользователь добавляет задачу), и хранить его вместе с данными.

Управляемое поле (controlled input)

В обычном HTML значением поля владеет браузер. В React принято иначе: значение живёт в состоянии, а поле только показывает его и сообщает об изменениях. Такое поле называется управляемым. Для этого нужны два атрибута:

  • value={name} — что показывать;

Формы: onSubmit и preventDefault

Форма по умолчанию при отправке перезагружает страницу. Состояние при этом сбрасывается — это ровно то, чего мы не хотим. Поэтому в начале обработчика onSubmit вызывают event.preventDefault() — знакомый вам приём из урока про формы.

import { useState } from "react";

export default function App() {
  const [text, setText] = useState("");
  const [sent, setSent] = useState("");

  function handleSubmit(event) {
    event.preventDefault(); // не даём браузеру перезагрузить страницу
    setSent(text);
    setText("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={text} onChange={(e) => setText(e.target.value)} placeholder="Ваше сообщение" />{" "}
      <button>Отправить</button>
      <p>Отправлено: {sent || "—"}</p>
    </form>
  );
}

08 Условный рендер: показать или спрятать

Интерфейс постоянно «ветвится»: у гостя одна кнопка, у вошедшего другая; пока данные грузятся — крутилка, потом список; корзина пустая — подсказка, не пустая — товары. Вывеска на магазине: «Открыто» или «Закрыто». Это тернарный оператор: всегда висит одна из двух табличек. А вот табличка «Скидка!» висит только если скидка есть — это &&. Если скидки нет, нет и таблички, а не табличка «Скидки нет».

Ловушка: «0 && …» рисует ноль

Оператор && возвращает левую часть, если она ложная. false, null, undefined React не показывает, но число 0 показывает как 0. Поэтому {items.length && <List />} при пустом списке выведет на странице цифру 0. Сравнивайте явно: {items.length > 0 && ...}.

09 ИИ-блок: ИИ объясняет ошибки React — а мы проверяем

Две ошибки React новички видят чаще всего: «я нажимаю, а экран не меняется» и «список ведёт себя странно после удаления». ИИ объясняет их быстро и убедительно. Но убедительно — не значит верно. Ваша задача сегодня — взять объяснение ИИ и проверить его на собственном коде: запустить, поломать, починить и убедиться, что причина названа правильно.

Правила курса, которые здесь особенно важны

1. Сначала 15 минут пробуете сами: вспомните разделы 04–06 этого урока. 2. Только потом идёте к ИИ. 3. Шаг 4 (бонус). Общий счётчик: поднимаем состояние

А если нужен счётчик «понравилось N из M» над списком? Карточки не могут рассказать об этом соседям, а App не может заглянуть в состояние карточки. Решение — поднять состояние вверх: App хранит, какие курсы лайкнуты, а карточка получает liked и функцию onToggle через props. // Шаг 4 (бонус). Поднимаем состояние: App знает, какие курсы лайкнуты, и считает общий счётчик
import { useState } from "react";

const courses = [
  { id: 1, title: "HTML и CSS" },
  { id: 2, title: "JavaScript" },
  { id: 3, title: "React Lite" },
];

// onToggle — это prop-ФУНКЦИЯ: карточка вызывает её, когда нажали на сердечко
function CourseCard({ title, liked, onToggle }) {
  return (
    <div className="card">
      <b>{title}</b>{" "}
      <button onClick={onToggle}>{liked ? "♥ Нравится" : "♡ Лайк"}</button>
    </div>
  );
}

export default function App() {
  const [likedIds, setLikedIds] = useState([]);

  function toggle(id) {
    setLikedIds(likedIds.includes(id) ? likedIds.filter((x) => x !== id) : [...likedIds, id]);
  }

  return (
    <div>
      <h3>Понравилось: {likedIds.length} из {courses.length}</h3>
      {courses.map((course) => (
        <CourseCard
          key={course.id}
          title={course.title}
          liked={likedIds.includes(course.id)}
          onToggle={() => toggle(course.id)}
        />
      ))}
    </div>
  );
}

✓ Шпаргалка урока

  • Props: данные идут от родителя к ребёнку как атрибуты, приходят объектом: function Card({ name, price }). Props только для чтения. Строки — в кавычках, остальное — в { }.

  • По умолчанию и rest: { label = "Нажми" } срабатывает только для undefined; для null — ??. { a, ...rest } собирает остальное, <input {...rest} /> раздаёт.
  • Списки: items.map((x) => <Item key={x.id} … />). С { } после стрелки нужен return. Фильтр — filter перед map.
  • key: уникальный и стабильный, из данных (id). Не index для изменяемых списков (ломаются поля ввода и состояние строк) и не Math.random().
  • useState: const [x, setX] = useState(начальное). Начальное значение — только при первом показе. Обычная переменная экран не обновит. Хуки — только на верхнем уровне компонента.
  • Функциональное обновление: setX((x) => x + 1), когда новое значение зависит от старого. Вычисляемое не храним в состоянии.
  • Не мутируем: добавить [...arr, x], удалить arr.filter(...), изменить arr.map(...), объект { ...obj, k: v }. Нельзя: push, splice, obj.k = v, sort без копии.
  • События: onClick={fn} — передаём функцию, не вызываем: onClick={() => remove(id)}. Форма: onSubmit + event.preventDefault().
  • Управляемое поле: value={text} + onChange={(e) => setText(e.target.value)}; у чекбокса — checked и e.target.checked.
  • Условный рендер: cond && <A /> («или ничего»), cond ? <A /> : <B /> («одно или другое»), ранний return для особых случаев. 0 && … рисует 0 — сравнивайте: n > 0 && ….
  • Поднятие состояния: общее состояние живёт в ближайшем общем родителе, а детям отдаём значение и функцию-обработчик через props.
