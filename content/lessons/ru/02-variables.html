01 Переменные: let, const и почему не var

Переменная — это именованное место в памяти, куда программа кладёт значение, чтобы потом достать его по имени. Вместо того чтобы писать число 25 в десяти местах, вы записываете его один раз и дальше пользуетесь именем.

let price = 25;
console.log(price);        // → 25

price = 30;                // новое значение
console.log(price);        // → 30
console.log(price * 2);    // → 60
Аналогия из жизни

Камера хранения на автовокзале в Душанбе. У каждой ячейки есть номер — это имя переменной. Внутри лежит вещь — это значение. Вы можете открыть ячейку и положить туда другую вещь (let), а можете запереть её так, что менять содержимое нельзя (const).

Как объявить переменную

let
Переменная, значение которой можно менять: баланс, счётчик, имя пользователя.
const
Переменная, которую нельзя переприсвоить: курс валюты, название академии, адрес сайта. Это вариант по умолчанию.
var
Старый способ из эпохи до 2015 года. Работает, но ведёт себя неожиданно. В новом коде не используем.
Правило курса

Начинайте с const. Если позже выяснится, что значение должно меняться, — замените на let. Так по коду сразу видно, что может измениться, а что нет.

const academy = "Ilmhona";   // не меняется
let students = 12;            // будет меняться

students = 13;                // пришёл новый студент
console.log(academy, students);   // → Ilmhona 13

Что будет, если изменить const

JavaScript остановит программу и покажет ошибку. Это не поломка, а защита: вы сами сказали, что значение не должно меняться.

const rate = 10.95;
console.log("Курс:", rate);

rate = 11;   // ✖ TypeError: Assignment to constant variable.
console.log("Новый курс:", rate);

Обратите внимание: строка с "Новый курс" не выполнилась. После ошибки программа останавливается. Умение читать текст ошибки — один из главных навыков программиста: TypeError — «тип ошибки», после двоеточия — понятное описание.

Объявить и присвоить — разные вещи

  • Объявление — слово let или const и имя. Делается один раз.
  • Присваивание — знак =. Можно делать много раз (для let).
  • У const значение нужно задать сразу при объявлении: const x; — ошибка.
  • У let можно объявить без значения: let result; — внутри будет undefined («не определено»). Про него поговорим в разделе о типах.
let result;                 // объявили, значения пока нет
console.log(result);        // → undefined

result = 100;               // присвоили
console.log(result);        // → 100

Почему не var

У var три неприятные особенности. Вы будете встречать его в старых учебниках и в ответах ИИ, поэтому важно понимать, в чём проблема.

1. «Протекает» из фигурных скобок. Код в { } — это блок. Переменная let остаётся внутри блока, а var выходит наружу:

{
  var oldWay = "var видно снаружи";
  let newWay = "let живёт только внутри";
  console.log(newWay);        // → let живёт только внутри
}

console.log(oldWay);          // → var видно снаружи

{
  let newWay = "let живёт только внутри";
}

console.log(newWay);   // ✖ ReferenceError: newWay is not defined

2. Позволяет объявить то же имя дважды — и вы можете случайно перезаписать чужую переменную, даже не заметив:

var city = "Душанбе";
var city = "Худжанд";      // JavaScript молчит, хотя имя уже занято
console.log(city);         // → Худжанд

let city = "Душанбе";
let city = "Худжанд";      // ✖ SyntaxError: Identifier 'city' has already been declared
console.log(city);

3. «Поднимается»: var можно использовать до строки с объявлением — получите undefined вместо понятной ошибки. С let и const JavaScript честно скажет, что вы поторопились.

console.log(a);   // → undefined (странно, но без ошибки)
var a = 5;
console.log(a);   // → 5

console.log(b);   // ✖ ReferenceError: Cannot access 'b' before initialization
let b = 5;
Вывод

Ошибка, которую JavaScript показывает сразу, — это хорошо: её легко найти. var прячет ошибки, let и const их показывают. Поэтому: только const и let.

02 Типы данных и typeof

Значения бывают разных типов. Число 25 и текст "25" выглядят похоже, но для JavaScript это совершенно разные вещи: числа можно умножать, а текст — склеивать и показывать. Тип определяет, что со значением можно делать.

Аналогия из жизни

На базаре есть мясной ряд, фруктовый ряд и ряд с посудой. Нон нельзя взвесить на весах для чая и нельзя налить в пиалу. У каждого товара свой «ряд» — свой тип, и от него зависит, что с ним делают.

Пять основных типов

ТипЧто этоПримеры
stringТекст — всегда в кавычках"Салом", 'Ilmhona', "25"
numberЧисло — целое или дробное, одного типа25, 3.14, -7
booleanЛогическое «да/нет»: только два значенияtrue, false
null«Пусто» — намеренно записанное отсутствие значенияnull

Узнать тип значения помогает оператор typeof. Он возвращает строку с названием типа:

console.log(typeof "Салом");     // → string
console.log(typeof 25);          // → number
console.log(typeof 3.14);        // → number  (дробные — тоже number)
console.log(typeof true);        // → boolean
console.log(typeof undefined);   // → undefined

typeof работает и с переменными — он смотрит на значение внутри:

const dish = "курутоб";
const price = 35;
const isSpicy = false;

console.log(dish, typeof dish);       // → курутоб string
console.log(price, typeof price);     // → 35 number
console.log(isSpicy, typeof isSpicy); // → false boolean
Кавычки меняют тип

25 — число, а "25" — строка из двух символов. Если число пришло в кавычках, считать с ним как с числом пока нельзя (про это — в разделах 5 и 6).

console.log(typeof 25);     // → number
console.log(typeof "25");   // → string
console.log(typeof true);   // → boolean
console.log(typeof "true"); // → string — это просто текст из четырёх букв

null и undefined: в чём разница

Аналогия из жизни

Вы пришли в камеру хранения. undefined — ячейка есть, но в неё ещё ничего не положили («не задано»). null — в ячейке лежит записка «здесь намеренно пусто» («значение задано: ничего»).

let phone;                 // объявили, но не присвоили
console.log(phone);        // → undefined

let nickname = null;       // мы сами решили: ника нет
console.log(nickname);     // → null

Обычно undefined появляется «сам» (JavaScript говорит: «тут пусто, потому что вы ничего не положили»), а null программист записывает осознанно: «сейчас значения нет».

Странность typeof null

typeof null возвращает "object", хотя null — отдельный тип. Это известная ошибка, которая появилась в JavaScript в 1995 году и осталась навсегда: исправление сломало бы миллионы старых сайтов. Запомните как факт и не удивляйтесь — ИИ в ответах нередко путает именно это место.

console.log(typeof null);       // → object  (!)
console.log(typeof undefined);  // → undefined
console.log(null === undefined);// → false — «строго равно»: это разные значения (подробнее в разделе 6)

Тип у переменной не закреплён

В JavaScript переменная может хранить значение любого типа и менять его. Это называют динамической типизацией. Удобно, но требует внимания: переменная, в которой было число, вдруг оказывается строкой — и посчитать уже не получится.

let value = 100;
console.log(typeof value);   // → number

value = "сто";
console.log(typeof value);   // → string

value = true;
console.log(typeof value);   // → boolean

Ещё два типа — только знакомство

  • bigint — очень большие целые числа, пишутся с буквой n на конце: 12345678901234567890n. Обычный number точен лишь до 9 007 199 254 740 991. Вам это понадобится редко.
  • symbol — уникальный «идентификатор», создаётся командой Symbol("id"). В этом курсе не потребуется.
console.log(typeof 123n);             // → bigint
console.log(typeof Symbol("id"));     // → symbol

Есть ещё «составной» тип object — для списков и объектов. Его мы разберём на уроках 6 и 7, а пока в нашем списке всего пять основных примитивных типов.

03 Строки и шаблонные литералы

Строка — это текст. Её пишут в кавычках, и кавычки бывают трёх видов:

const a = "двойные кавычки";
const b = 'одинарные кавычки';
const c = `обратные кавычки — шаблонная строка`;

console.log(a);
console.log(b);
console.log(c);

Двойные и одинарные — одно и то же, выберите один стиль и держитесь его. Если внутри текста нужны такие же кавычки, их «экранируют» обратной косой чертой:

console.log("Он сказал: \"Салом!\"");     // → Он сказал: "Салом!"
console.log('Сумма: 5 сомони\nИтого: 10');  // \n — перенос строки

Склейка строк через +

Знак + между строками их склеивает. Это называется конкатенация:

const name = "Мадина";
console.log("Салом, " + name + "!");   // → Салом, Мадина!

Работает, но с несколькими значениями быстро превращается в кашу из кавычек и плюсов — и легко забыть пробел.

Шаблонные литералы

Строка в обратных кавычках `…` позволяет вставлять значения прямо в текст через ${ }. Внутри скобок можно писать любые выражения.

const name = "Мадина";
const age = 19;
const price = 25;

console.log(`Салом, ${name}!`);                     // → Салом, Мадина!
console.log(`${name}, вам ${age} лет`);              // → Мадина, вам 19 лет
console.log(`Три самбусы стоят ${price * 3} сомони`);// → Три самбусы стоят 75 сомони
console.log(`Через год вам будет ${age + 1}`);       // → Через год вам будет 20
Аналогия из жизни

Шаблонная строка — как бланк поздравительного письма с пропусками: «Дорогой(ая) ______, поздравляем с ______!». Бланк один, а пропуски вы заполняете для каждого получателя. В JavaScript пропуски — это ${ }.

Ещё одно удобство: шаблонная строка может занимать несколько строк — переносы сохранятся как есть.

const student = "Фарход";
const grade = 5;

console.log(`Ведомость
Студент: ${student}
Оценка: ${grade}`);

Строка — это ещё и набор команд

У каждой строки есть свойства и команды, которые записываются через точку. Сейчас нам хватит нескольких — как они устроены внутри, узнаем на уроках про функции и объекты.

const city = "  Душанбе  ";

console.log(city.length);              // → 11 — количество символов (с пробелами!)
console.log(city.trim());              // → Душанбе — убрали пробелы по краям
console.log(city.trim().toUpperCase()); // → ДУШАНБЕ
console.log(city.trim().toLowerCase()); // → душанбе
console.log("Салом"[0]);               // → С — первый символ (счёт идёт с нуля)
console.log("Салом"[4]);               // → м — пятый символ
  • .length — длина строки (без скобок: это свойство);
  • .toUpperCase() / .toLowerCase() — заглавные / строчные;
  • .trim() — убирает пробелы с начала и конца;
  • [0], [1] … — символ по номеру; нумерация начинается с нуля.
Частая ошибка

Забыть обратные кавычки: "Привет, ${name}" в обычных кавычках выведет текст дословно — вместе с ${name}. Подстановка работает только в `…`.

const name = "Далер";
console.log("Привет, ${name}");   // → Привет, ${name}  (не сработало!)
console.log(`Привет, ${name}`);   // → Привет, Далер

Оператор % — «остаток» — проще всего понять на манты. 17 манты разложили по 5 штук на тарелку: получилось 3 полные тарелки (это Math.floor(17 / 5)), а 2 манты остались — это и есть 17 % 5. const manti = 17;
const plates = 5;

console.log(10 % 2);   // → 0 — чётное
console.log(7 % 2);    // → 1 — нечётное

Округление: Math.round, floor, ceil

Деление часто даёт дробь. Для округления есть три команды, которые начинаются с Math.:

console.log(Math.round(2.5));  // → 3 — до ближайшего целого
console.log(Math.round(2.4));  // → 2
console.log(Math.floor(2.9));  // → 2 — всегда вниз
console.log(Math.ceil(2.1));   // → 3 — всегда вверх

Сокращённая запись: +=, ++ и компания

Менять значение переменной нужно постоянно: прибавить к балансу, увеличить счётчик. Для этого есть короткие формы:

let balance = 100;

balance = balance + 20;   // длинная запись
balance += 20;            // то же самое, коротко
console.log(balance);     // → 140

balance -= 40;            // balance = balance - 40
balance *= 2;             // balance = balance * 2
console.log(balance);     // → 200

let visitors = 0;
visitors++;               // увеличить на 1
visitors++;
console.log(visitors);    // → 2
visitors--;               // уменьшить на 1
console.log(visitors);    // → 1

Знаки ++ и -- можно писать перед переменной и после. Если вы просто увеличиваете число отдельной строкой, разницы нет. Но если значение ещё и используется в этой же строке — разница есть:

let a = 5;
console.log(a++);   // → 5  — сначала отдали старое значение, потом увеличили
console.log(a);     // → 6

let b = 5;
console.log(++b);   // → 6  — сначала увеличили, потом отдали
console.log(b);     // → 6
Совет

Пока вы учитесь, используйте ++ и -- только отдельной строкой — visitors++;. Так не придётся гадать, какое значение получится.

Сравнения дают boolean

Знаки >, <, >=, <=, === (равно) и !== (не равно) сравнивают значения и возвращают true или false. Условия if, которые на этом строятся, мы будем изучать на уроке 3.

console.log(5 > 3);        // → true
console.log(5 < 3);        // → false
console.log(10 >= 10);     // → true
console.log(7 === 7);       // → true
console.log(7 !== 7);       // → false

Infinity и NaN

В математике на ноль делить нельзя. JavaScript не падает, а возвращает особое значение:

console.log(1 / 0);     // → Infinity — «бесконечность»
console.log(-1 / 0);    // → -Infinity
console.log(0 / 0);     // → NaN — «не число» (Not a Number)

NaN появляется, когда арифметика не получилась: например, умножили текст на число. Запомните три свойства NaN:

  • по типу это всё равно number: typeof NaN → "number";
  • оно «заразное»: любое действие с NaN тоже даёт NaN;
  • NaN не равно даже самому себе. Проверять надо командой Number.isNaN(x).
console.log("abc" * 2);              // → NaN
console.log(NaN + 5);                // → NaN — заразилось
console.log(NaN === NaN);            // → false (!)
console.log(Number.isNaN(NaN));      // → true
console.log(Number.isNaN("abc"));    // → false — это строка, не NaN
Дробные числа и деньги

Компьютер хранит дроби в двоичном виде, и некоторые десятичные дроби записываются неточно. Это не баг JavaScript — так работают почти все языки.

console.log(0.1 + 0.2);            // → 0.30000000000000004
console.log(0.1 + 0.2 === 0.3);    // → false

Что делать с деньгами: считать в наименьших единицах — в дирамах (1 сомони = 100 дирамов), то есть в целых числах, и делить на 100 только при показе. А красивый вывод с двумя знаками даёт .toFixed(2) — но помните: он возвращает строку, а не число.

const total = 0.1 + 0.2;
console.log(total.toFixed(2));          // → 0.30
console.log(typeof total.toFixed(2));   // → string — это уже текст!

console.log((10 + 20) / 100);           // → 0.3 — считали в дирамах (10 и 20), потом разделили

05 Явное приведение типов

Приведение типов — превращение значения из одного типа в другой. Оно бывает явным (вы сами просите: «сделай из этого число») и неявным (JavaScript делает это сам, не спрашивая — разберём в следующем разделе). Сначала учимся делать это осознанно.

Аналогия из жизни

Обменный пункт. Вы приходите с долларами, а нужны сомони: сумма «по сути» та же, но форма другая. Для каждой пары валют есть своя касса: String() — «сделать текстом», Number() — «сделать числом», Boolean() — «сделать да/нет». Но обмен бывает неудачным: «абракадабру» в число не обменяешь — получите NaN.

В строку: String()

console.log(String(123));         // → "123"
console.log(String(true));        // → "true"
console.log(String(null));        // → "null"
console.log(String(undefined));   // → "undefined"
console.log(typeof String(123));  // → string

В число: Number()

Самое важное преобразование. В реальной работе числа часто приходят как текст: из поля ввода, из ответа сервера. Пробелы по краям Number() убирает, а вот лишний текст внутри — нет.

console.log(Number("42"));        // → 42
console.log(Number("3.14"));      // → 3.14
console.log(Number("  7  "));     // → 7    — пробелы по краям отбрасываются
console.log(Number("12px"));      // → NaN  — внутри есть лишние символы
console.log(Number("abc"));       // → NaN
console.log(Number(""));          // → 0    — пустая строка даёт ноль (!)
console.log(Number(true));        // → 1
console.log(Number(false));       // → 0
console.log(Number(null));        // → 0
console.log(Number(undefined));   // → NaN

В логическое значение: Boolean()

Любое значение можно превратить в true или false. Правило простое: «пустые» значения дают false, все остальные — true. «Пустых» (их называют falsy) всего шесть основных:

  • false — сам по себе;
  • 0 (и -0);
  • "" — пустая строка;
  • null;
  • undefined;
  • NaN.
console.log(Boolean(0));            // → false
console.log(Boolean(""));           // → false
console.log(Boolean(null));         // → false
console.log(Boolean(undefined));    // → false
console.log(Boolean(NaN));          // → false

console.log(Boolean(1));            // → true
console.log(Boolean(-5));           // → true  — любое число, кроме нуля
console.log(Boolean("Салом"));      // → true
console.log(Boolean(" "));          // → true  — пробел это уже символ!
console.log(Boolean("0"));          // → true  — строка "0" не пустая
console.log(Boolean("false"));      // → true  — и это тоже просто текст
Ловушки Boolean

"0" и "false" — непустые строки, поэтому true. А пустая строка "" и число 0 — false. Это место, где ошибаются и новички, и ИИ.

Куда приходят строки в реальных проектах

const answer = prompt("Сколько вам лет?");   // пользователь ввёл 19
console.log(typeof answer);                   // → string — всегда строка!

06 Неявное приведение: главные ловушки

Если в выражении встречаются значения разных типов, JavaScript сам приводит их к общему виду — и не предупреждает. Иногда это удобно, но чаще становится источником странных ошибок. Ваша задача — понимать правила и уметь предсказывать результат.

Правило 1: «+» с текстом — это склейка

Если хотя бы одна сторона + — строка, JavaScript превращает вторую в строку и склеивает.

console.log("5" + 3);        // → 53   — не 8!
console.log(3 + "5");        // → 35
console.log("Итого: " + 100);// → Итого: 100
console.log("5" + true);     // → 5true
console.log("5" + null);     // → 5null
Аналогия из жизни

Знак + работает как клей. Рядом два числа — он складывает. Рядом хоть один текст — клеит: «5» и «3» превращаются в «53», как номера на бирках. Остальные знаки (-, *, /) клеить не умеют — они только считают.

Правило 2: остальные арифметические знаки превращают в числа

console.log("5" - 3);        // → 2
console.log("5" * "2");      // → 10
console.log("10" / "2");     // → 5
console.log("abc" * 2);      // → NaN — превратить в число не получилось

Правило 3: boolean, null и undefined в вычислениях

console.log(true + 1);       // → 2    — true становится 1
console.log(false + 1);      // → 1    — false становится 0
console.log(null + 1);       // → 1    — null становится 0
console.log(undefined + 1);  // → NaN  — undefined становится NaN

Порядок слева направо

Выражение вычисляется по шагам слева направо. Пока слева числа — они складываются, а как только в цепочке появилась строка — дальше идёт склейка:

console.log(1 + 2 + "3");    // → 33   — сначала 1 + 2 = 3, потом "3" + "3"
console.log("1" + 2 + 3);    // → 123  — сначала "1" + 2 = "12", потом "12" + 3
console.log(1 + 2 + 3);      // → 6

Унарный плюс: короткая запись Number()

Плюс перед значением без левой части превращает его в число — так же, как Number(). Это можно увидеть в чужом коде, а вот своём лучше писать явно.

console.log(+"7");           // → 7
console.log(+"");            // → 0
console.log(+"abc");         // → NaN
console.log(typeof +"7");    // → number
console.log("b" + "a" + +"a" + "a");   // → baNaNa  — известная шутка про NaN

Сравнения: == и ===

Есть два способа проверить равенство. Двойное == «нестрогое» — приводит типы и поэтому ведёт себя странно. Тройное === «строгое» — сравнивает без приведения: значения равны, только если и значение, и тип совпадают.

console.log(5 == "5");        // → true   — привело строку к числу
console.log(5 === "5");       // → false  — разные типы
console.log(0 == "");         // → true   (!)
console.log(0 == false);      // → true   (!)
console.log("0" == false);    // → true   (!)
console.log(null == undefined);   // → true
console.log(null === undefined);  // → false
console.log(null == 0);       // → false  — вот такая непоследовательность
Правило курса

Всегда пишите === и !==. Нестрогое == не используем — оно не стоит запоминания всех его странностей.

Сравнение строк — по буквам

Две строки сравниваются посимвольно, как слова в словаре, а не как числа. Поэтому «10» оказывается «меньше» «9»: первая цифра 1 меньше, чем 9.

console.log("10" > "9");     // → false (!)  — строки сравниваются по символам
console.log("10" > 9);       // → true       — одно из значений число, значит сравнивает как числа
console.log(Number("10") > Number("9"));  // → true — надёжный способ
Как защититься

Не надеяться на «авось» неявного приведения. Получили данные снаружи (поле формы, prompt, ответ сервера) — сразу превратите их в нужный тип через Number(), и дальше работайте уже с числами. Явное лучше неявного: его видно в коде, и оно предсказуемо.

07 ИИ-блок: анатомия промпта и «ловим ИИ на ошибке»

ИИ-помощник отвечает ровно на тот вопрос, который вы ему задали. Расплывчатый вопрос — расплывчатый ответ, который к тому же может содержать ошибку. Поэтому в этом курсе у нас два навыка: правильно спрашивать (промпт) и проверять ответ (запустить и сверить).

Правила работы с ИИ в нашем курсе

1. Сначала 15 минут пробуете сами — и только потом идёте к ИИ. 2. Не вставляете в работу код, который не можете объяснить строчка за строчкой. 3. Всегда просите объяснение, а не только код. 4. Анатомия промпта: четыре обязательных части

Хороший промпт — это не длинный текст, а структура. Запомните порядок: контекст → задача → ограничения → формат ответа. Пятый пункт — проверка — мы добавляем, когда нужен ответ, которому нельзя слепо доверять (то есть почти всегда).

ЧастьЧто писатьПример для этого урока

Аналогия из жизни

Заказ такси. «Отвези меня» — водитель не понимает, куда ехать. «Из Сино в аэропорт, багаж большой, без платной дороги, остановитесь у зала вылета» — это контекст, задача, ограничение и формат в одном предложении. Чем точнее заказ, тем меньше шансов приехать не туда. ИИ — тот же водитель: он не читает мысли.

Ограничения: без if, циклов и функций. Если используешь новый термин — объясни его одной фразой. Формат ответа: сначала правило в одном предложении, потом 4 коротких примера кода, в комментарии у каждого — результат. Проверка: в конце дай 2 выражения, на которых я могу ошибиться. Ответы не пиши — я проверю в консоли сам.

Чем сильный промпт лучше: ИИ не гадает, какой у вас уровень, не использует незнакомые вам конструкции, отвечает в удобной форме и сам даёт вам материал для самопроверки.

Собираем свой шаблон промпта

Каждый раз писать структуру с нуля долго. Сделайте свой шаблон — заготовку, которую вы будете копировать и заполнять. Это ваш первый артефакт курса: он пойдёт в конспект по промптам, а потом — в личную шпаргалку, которую сдают на уроке 21.

  1. Скопируйте заготовку ниже в свой конспект (файл или заметки).
  2. Заполните «постоянные» поля один раз: в «Контексте» напишите свой уровень и стек («чистый JavaScript, без библиотек, новичок»). Это будет одинаково в каждом промпте.
  3. Придумайте свою «любимую» строку в «Проверке»: например, «покажи, что выведет консоль» или «назови 2 крайних случая». Её вы тоже оставите навсегда.
  4. Протестируйте шаблон на задаче из урока: заполните поля и отправьте ИИ. Если ответ вас не устроил — уточните, в какой из четырёх частей не хватило деталей, и поправьте шаблон.
Контекст: [кто я, что уже умею, над чем работаю — например: «новичок, учу чистый JavaScript, знаю let/const и типы»] Задача: [одно конкретное действие — объясни / проверь / дай 5 задач] Ограничения: [что нельзя использовать, что обязательно; «новые термины объясняй одной фразой»] Формат ответа: [как оформить: сначала правило, потом примеры; сколько примеров; без таблиц] Проверка: [что ещё: «назови 2 места, где я могу ошибиться», «покажи, что выведет консоль»]
Хорошие рабочие промпты по этой теме

Из шпаргалки курса: «Вот код: [код]. Объясни построчно, что происходит и почему результат такой. Не переписывай код — только объясни.» И второй: «Дай 5 задач на [тема] уровня новичка, от простой к сложной, без решений.» Сверяйте объяснение с тем, что реально выводит консоль, а задачи — на соответствие теме и отсутствие готовых ответов.

Как читать ответ ИИ: проверяем, а не верим

ИИ пишет уверенно — даже когда ошибается. На теме типов это особенно заметно: неявное приведение и странности вроде typeof null он нередко пересказывает неверно. Поэтому у вас есть простой алгоритм:

  1. Прогнозируйте. Прочитали объяснение ИИ — запишите, какой результат должен получиться.
  2. Запускайте. Скопируйте пример в консоль и посмотрите, что выведется на самом деле.
  3. Сверяйте. Совпало — отлично. Не совпало — ошибся либо ИИ, либо вы. Разберитесь, кто именно: в этом и есть обучение.
  4. Переспрашивайте. Покажите ИИ реальный вывод: «в консоли получилось X, а ты говорил Y — объясни расхождение».
Консоль — главный судья

Спорный вопрос «кто прав: я, ИИ или учебник» решает не мнение, а запуск кода. Если консоль и ИИ расходятся — прав консоль.

Работа с ИИ и конспект по промптам

Задание на «ловлю ошибок»

Выберите любые 3 задачи из 10. Для каждой отправьте ИИ промпт по вашему шаблону: «объясни, как это решается, и что выведет консоль». Затем запустите код из ответа и сверьте с вашим результатом. В конспекте запишите для каждой из трёх задач:

  • какой промпт вы отправили (текстом);
  • краткое содержание ответа ИИ (2–3 предложения);
  • где ИИ ошибся — или, если не ошибся, что именно вы проверили, чтобы убедиться;
  • что вы исправили или уточнили вторым промптом.

Если ИИ не ошибся ни разу — это нормально, но тогда нужны доказательства: что именно вы запустили и сверили. Ответ «ИИ был прав, потому что так сказал ИИ» не засчитывается.

✓ Шпаргалка урока

  • Переменная — именованная ячейка со значением. const — по умолчанию, let — если значение меняется, var — не используем (протекает из блока, молчит о повторном объявлении, «поднимается»).
  • Имена: латиница, camelCase, не с цифры, регистр важен; константы-настройки — UPPER_CASE.
  • Типы: string, number, boolean, null, undefined (+ bigint, symbol). typeof возвращает строку. typeof null → "object" — историческая странность; typeof NaN → "number".
  • undefined — «значения ещё нет», null — «значения намеренно нет».
  • Строки: шаблонные литералы `Салом, ${name}`; .length, .trim(), .toUpperCase(), s[0]. Подстановка работает только в обратных кавычках.
  • Операторы: + - * / % **; сокращения +=, -=, ++, --; Math.round/floor/ceil для округления.
  • NaN — «не число», заразен, NaN !== NaN, проверка — Number.isNaN(). Infinity — результат деления на ноль.
  • Деньги считаем в целых дирамах; 0.1 + 0.2 !== 0.3; toFixed() возвращает строку.
  • Явное приведение: String(), Number() ("" → 0, лишний текст → NaN), parseInt/parseFloat читают число из начала строки, Boolean().
  • Falsy: false, 0, "", null, undefined, NaN. Всё остальное — true, включая "0" и "false".
  • Неявное приведение: "5" + 3 → "53" (строка с + — склейка); "5" - 3 → 2; true + 1 → 2; null + 1 → 1; undefined + 1 → NaN; 1 + 2 + "3" → "33".
  • Сравнение: всегда === и !==. Строки сравниваются по символам: "10" > "9" → false.
  • Промпт: контекст → задача → ограничения → формат ответа (+ проверка). Ответ ИИ — гипотеза: прогнозируй, запускай, сверяй, переспрашивай. Консоль — главный судья.
