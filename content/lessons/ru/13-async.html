Асинхронный JavaScript

Когда вы открываете сайт, он не замирает, пока загружаются картинки, курс валют или список товаров. Страница живёт, а данные «приезжают» позже. Это асинхронность: JavaScript умеет не ждать у плиты, а заниматься другими делами, пока готовится ответ. Сегодня разберём, как это устроено, и научимся писать такой код без путаницы.

  • Читать код с колбэками и понимать, чем плох «ад колбэков»
  • Создавать промисы и строить цепочки then / catch / finally
  • Писать async / await с try / catch
  • Предсказывать порядок вывода: стек, микрозадачи, макрозадачи (event loop)

01 Синхронно и асинхронно. setTimeout

До сегодняшнего дня весь наш код был синхронным: JavaScript выполнял строки строго по порядку, одну за другой, и следующая не начиналась, пока не закончилась предыдущая.

console.log("1. Открыли приложение");
console.log("2. Посчитали сумму");
console.log("3. Показали результат");

Но в реальных программах есть дела, которые занимают время: запрос на сервер, загрузка картинки, таймер, ответ пользователя. Если ждать каждое из них, пока оно закончится, страница «зависнет». Поэтому такие дела запускают и не ждут: когда результат будет готов, JavaScript вернётся к нему. Это и есть асинхронный код.

Аналогия из жизни

Вы пришли в чайхону и заказали плов. Официант не стоит рядом с котлом, пока рис не дойдёт, — он принимает заказы у других столов. Когда плов готов, повар зовёт официанта, и тот несёт блюдо вам. Синхронный официант стоял бы у котла 40 минут и не обслужил никого. Асинхронный — запустил готовку и пошёл дальше.

setTimeout — «сделай это позже»

Самый простой способ получить асинхронность — функция setTimeout(функция, миллисекунды). Она говорит браузеру: «через столько-то миллисекунд вызови эту функцию», а сама сразу возвращается. 1000 мс = 1 секунда.

console.log("Заказали плов");

setTimeout(() => {
  console.log("Плов готов!");
}, 500);

console.log("Официант идёт к другому столу");

Обратите внимание на порядок: «Официант идёт…» появилось раньше «Плов готов!», хотя написано ниже. Функцию внутри setTimeout мы передаём, а не вызываем: она сработает потом. Такая функция называется колбэком (callback — «перезвони мне») — подробнее о них в следующем разделе.

Нулевая задержка тоже асинхронна

Самый частый сюрприз: даже setTimeout(…, 0) не выполняет функцию сразу. Он ставит её в очередь на «после того, как закончится весь текущий код».

console.log("A");
setTimeout(() => console.log("B (с нулевой задержкой)"), 0);
console.log("C");
  1. A — обычная строка, выводится сразу.
  2. setTimeout — функция «отложена» в сторону. Дальше JavaScript идёт, не оглядываясь.
  3. C — выводится сразу.
  4. Весь код закончился, и только теперь JavaScript достаёт отложенную функцию и выводит B.

Аргументы и отмена

setTimeout возвращает число — номер таймера. По нему таймер можно отменить через clearTimeout, пока он не сработал.

const timerId = setTimeout(() => console.log("Это не выведется"), 300);
console.log("Таймер запущен, номер есть:", typeof timerId);

clearTimeout(timerId);
console.log("Таймер отменили");

setInterval — «повторяй каждые N мс»

setInterval работает так же, но вызывает функцию снова и снова, пока вы его не остановите через clearInterval. Если забыть остановить — таймер будет тикать вечно (в этой странице выполнение прервётся через 8 секунд).

let left = 3;

const id = setInterval(() => {
  console.log("Осталось:", left);
  left--;

  if (left === 0) {
    clearInterval(id);   // останавливаем, иначе будет тикать вечно
    console.log("Поехали!");
  }
}, 200);
Частая ошибка

Вызвать функцию вместо того, чтобы передать её. setTimeout(sayHi(), 1000) — скобки запускают функцию прямо сейчас, а в таймер уходит то, что она вернула (то есть ничего). Нужно setTimeout(sayHi, 1000) или setTimeout(() => sayHi(), 1000).

function sayHi() {
  console.log("Салом!");
}

setTimeout(sayHi(), 1000);   // ✖ «Салом!» выведется мгновенно, а не через секунду
console.log("Конец кода");

02 Callback: «перезвони, когда будет готово»

Мы уже передавали функции в map и filter. Функция, которую передают в другую функцию «на потом», называется колбэком. Раньше колбэки вызывались сразу, внутри цикла. А в асинхронном коде колбэк вызывается, когда работа закончится.

function loadPrice(dish, callback) {
  console.log("Спрашиваем цену:", dish);
  setTimeout(() => {
    const price = dish === "плов" ? 35 : 10;
    callback(price);            // «перезваниваем» с результатом
  }, 300);
}

loadPrice("плов", (price) => {
  console.log("Цена плова:", price, "сомони");
});

console.log("Пока ждём ответ, можно заняться другими делами");
Аналогия из жизни

Вы заказываете торт в кондитерской и оставляете свой номер: «Позвоните, когда будет готов». Номер — это колбэк. Вы идёте по делам, а кондитер сам позвонит. Вам не нужно стоять у витрины и спрашивать каждые пять минут.

Колбэк с ошибкой: договорённость «error-first»

Асинхронная работа может не получиться: нет сети, нет такого товара, неверный пароль. Поэтому по традиции первым аргументом колбэк получает ошибку (или null, если всё хорошо), а вторым — результат.

function findStudent(id, callback) {
  setTimeout(() => {
    if (id !== 1) {
      callback(new Error("студент не найден"));   // ошибка — первый аргумент
      return;
    }
    callback(null, "Мадина");                      // успех — ошибки нет
  }, 200);
}

findStudent(1, (error, name) => {
  if (error) {
    console.log("Ошибка:", error.message);
    return;
  }
  console.log("Нашли:", name);
});

findStudent(7, (error, name) => {
  if (error) {
    console.log("Ошибка:", error.message);
    return;
  }
  console.log("Нашли:", name);
});

Ад колбэков (callback hell)

Что, если шаги зависят друг от друга: сначала найти пользователя, потом его заказы, потом адрес доставки? Каждый следующий шаг приходится вкладывать в колбэк предыдущего. Получается «лесенка», которая уезжает вправо.

function step(name, callback) {
  setTimeout(() => {
    console.log("Готово:", name);
    callback();
  }, 100);
}

step("нашли пользователя", () => {
  step("загрузили заказы", () => {
    step("узнали адрес", () => {
      step("посчитали доставку", () => {
        console.log("Всё готово!");
      });
    });
  });
});

Всего четыре шага, а код уже трудно читать. А если добавить обработку ошибок на каждом уровне — получится настоящий лабиринт. Именно эту проблему решили промисы, о которых мы поговорим чуть позже: те же шаги выстраиваются в ровную цепочку.

Колбэки

Вложенность растёт вправо. Ошибки нужно проверять на каждом уровне вручную. Код сложно менять.

Промисы и async/await

Шаги идут друг за другом ровной колонкой. Ошибки ловит одно место — catch или try/catch.

Частая ошибка

Писать код после асинхронного вызова и ждать, что результат уже есть. Колбэк ещё не сработал, а строка ниже уже выполнилась.

let price;

setTimeout(() => {
  price = 35;
}, 200);

console.log("Цена плова:", price);   // ✖ undefined — таймер ещё не сработал

Всё, что зависит от результата, нужно делать внутри колбэка (или, как мы увидим дальше, после await).

03 Как это работает: event loop

JavaScript однопоточный: у него одни руки, он делает одно дело за раз. Как же тогда таймеры и запросы «идут сами»? Ждёт их не JavaScript, а браузер. Когда таймер сработал, браузер кладёт ваш колбэк в очередь, а специальный механизм — event loop (цикл событий) — достаёт его оттуда, когда JavaScript освободится.

Аналогия из жизни

Представьте один кассовый аппарат в магазине на Шохмансуре. Кассир (стек вызовов) обслуживает одного покупателя за раз. Остальные стоят в очередях. Но очередей две: у «быстрой кассы» стоят те, кто с одной покупкой (микрозадачи — промисы), а в обычной очереди — все остальные (макрозадачи — таймеры). Кассир закончил с покупателем, и сначала обслуживает всю быструю кассу, и только потом берёт одного человека из обычной очереди.

Схема

Call Stack
Стек вызовов. Здесь работает JavaScript. Пока в стеке есть код, всё остальное ждёт.
Макрозадача
Колбэк таймера setTimeout / setInterval, обработчик клика и подобное. За один «круг» выполняется только одна.
Микрозадача
Колбэки .then / .catch / .finally, продолжение после await, queueMicrotask. После каждой макрозадачи выполняются все, пока очередь не опустеет.

Разбор по шагам

console.log("1");

setTimeout(() => console.log("2"), 0);

Promise.resolve().then(() => console.log("3"));

console.log("4");
  1. Синхронный код. В стек попадает console.log("1") — выводится 1.
  2. setTimeout. Таймер передан браузеру. Через 0 мс его колбэк ляжет в очередь макрозадач. Выполнен он будет не сейчас.
  3. Promise.resolve().then(…). Промис уже выполнен, поэтому колбэк then сразу ложится в очередь микрозадач.
  4. Синхронный код. console.log("4") — выводится 4. Стек опустел.
  5. Микрозадачи. Event loop видит, что очередь микрозадач не пуста, и выполняет колбэк — выводится 3.
  6. Макрозадача. Теперь очередь микрозадач пуста, и можно взять одну макрозадачу — колбэк таймера: выводится 2.

Итог: 1, 4, 3, 2. Запомните правило: синхронный код → микрозадачи (промисы) → макрозадачи (таймеры).

Микрозадачи вклиниваются после каждой макрозадачи

Если в макрозадаче создали промис, его колбэк выполнится сразу после неё, ещё до следующей макрозадачи из очереди.

setTimeout(() => {
  console.log("таймер 1");
  Promise.resolve().then(() => console.log("промис внутри таймера 1"));
}, 0);

setTimeout(() => console.log("таймер 2"), 0);

Порядок: таймер 1, промис внутри таймера 1, таймер 2. Микрозадача, рождённая таймером 1, успела раньше, чем «обычная очередь» дошла до таймера 2.

Частая ошибка

Думать, что setTimeout(fn, 0) сработает «сразу». На самом деле он сработает только когда закончится весь текущий код и все микрозадачи. А если текущий код занят тяжёлым циклом, таймер будет ждать, пока цикл не завершится: setTimeout гарантирует «не раньше, чем через N мс», а не «ровно через N мс».

Совет: как предсказывать порядок

Идите по коду сверху вниз и раскладывайте строки по трём «корзинам»: 1. выполняется сразу, 2. в микрозадачи (then, await), 3. в макрозадачи (setTimeout; у кого задержка меньше — тот раньше). Потом читайте: корзина 1 → корзина 2 → корзина 3. Если внутри колбэка появилась новая корзина-2 или корзина-3, повторите то же самое.

04 Promise: обещание результата

Промис (Promise — «обещание») — это объект, который представляет результат асинхронной работы, которого пока нет, но который будет: либо значение, либо ошибка. Вместо вложенных колбэков мы получаем объект, на который можно «подписаться» методами then и catch.

Аналогия из жизни

Вы оплатили доставку и получили чек с номером заказа. Это ещё не товар, но обещание: «товар будет». У обещания три состояния: ждём (заказ в пути), выполнено (курьер привёз) или отказ (товара нет на складе). Чек вы держите в руках сразу, а привезут позже — или отменят.

Три состояния промиса

pending
«Ожидает». Начальное состояние: результата ещё нет.
fulfilled
«Выполнен». Работа закончилась успешно, у промиса есть значение. Вызывается колбэк из then.
rejected
«Отклонён». Что-то пошло не так, у промиса есть причина (ошибка). Вызывается колбэк из catch.

Важно: из pending промис переходит в другое состояние один раз и навсегда. Выполненный промис нельзя «отклонить» позже.

Создание промиса

Промис создают через new Promise. В конструктор передают функцию с двумя параметрами: resolve (вызвать при успехе) и reject (вызвать при ошибке).

const orderPlov = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve("Плов готов!");     // успех: передаём значение
  }, 300);
});

orderPlov.then((result) => {
  console.log("Получили:", result);
});

console.log("Промис создан, ждём…");

function buyTicket(balance) {
  return new Promise((resolve, reject) => {
    if (balance >= 3) {
      resolve("Билет куплен");
    } else {
      reject(new Error("Недостаточно сомони"));
    }
  });
}

buyTicket(10)
  .then((text) => console.log(text))
  .catch((error) => console.log("Ошибка:", error.message));

buyTicket(1)
  .then((text) => console.log(text))
  .catch((error) => console.log("Ошибка:", error.message));

then, catch, finally

  • .then(onSuccess) — выполнится, когда промис выполнен;
  • .catch(onError) — выполнится, когда промис отклонён (или где-то выше по цепочке случилась ошибка);
  • .finally(fn) — выполнится в любом случае: «прибраться» после работы (убрать индикатор загрузки).
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

console.log("Показываем «Загрузка...»");

wait(300)
  .then(() => console.log("Данные пришли"))
  .catch(() => console.log("Ошибка"))
  .finally(() => console.log("Прячем «Загрузка...»"));

Функция wait здесь — полезная заготовка. Она возвращает промис, который выполняется через заданное время. Мы будем использовать её в уроке постоянно.

Цепочки промисов

Главная сила промисов: then возвращает новый промис. Поэтому then можно соединять в цепочку, а значение, которое вернул один then, попадает в следующий.

Promise.resolve(5)
  .then((n) => {
    console.log("Получили:", n);
    return n * 2;               // это значение уйдёт дальше
  })
  .then((n) => {
    console.log("Удвоили:", n);
    return n + 1;
  })
  .then((n) => {
    console.log("Прибавили 1:", n);
  });

Если колбэк then возвращает промис, цепочка подождёт его завершения и только потом пойдёт дальше. Так выстраиваются последовательные шаги, и пирамида колбэков из прошлого раздела превращается в ровную колонку:

const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

function step(name) {
  return wait(100).then(() => console.log("Готово:", name));
}

step("нашли пользователя")
  .then(() => step("загрузили заказы"))
  .then(() => step("узнали адрес"))
  .then(() => step("посчитали доставку"))
  .then(() => console.log("Всё готово!"));

Ошибки в цепочке

Если в любом звене случилась ошибка (reject или throw), цепочка пропускает все следующие then и «проваливается» в ближайший catch. Один catch в конце ловит ошибки всех шагов. А если catch вернул значение — цепочка снова считается успешной и идёт дальше.

Promise.resolve("шаг 1")
  .then((v) => {
    console.log(v, "выполнен");
    throw new Error("шаг 2 сломался");
  })
  .then(() => console.log("этот then пропущен"))
  .catch((error) => {
    console.log("Поймали:", error.message);
    return "запасной вариант";
  })
  .then((v) => console.log("Цепочка продолжилась:", v));
Частая ошибка: забыли return в then

Если в колбэке then нет return, следующий then получит undefined. А если внутри then запускается новый асинхронный шаг и его не вернули — цепочка не подождёт его.

Promise.resolve(100)
  .then((price) => {
    price * 2;                      // ✖ посчитали, но не вернули
  })
  .then((result) => {
    console.log("Результат:", result);   // → undefined
  });

Несколько промисов сразу

Бывает, что нужно загрузить несколько независимых вещей. Если ждать их по очереди — потеряем время. Лучше запустить все сразу.

  • Promise.all([…]) — ждёт все. Возвращает массив результатов в том же порядке, что и в запросе. Если хотя бы один промис отклонён — отклоняется целиком;
  • Promise.allSettled([…]) — ждёт все и никогда не отклоняется: для каждого сообщает status ("fulfilled" или "rejected") и value / reason;
  • Promise.race([…]) — результат (или ошибка) самого быстрого.
const wait = (ms, value) => new Promise((resolve) => setTimeout(() => resolve(value), ms));

Promise.all([
  wait(300, "курсы валют"),
  wait(100, "погода"),
  wait(200, "новости"),
]).then((results) => {
  console.log("Всё загружено:", results.join(", "));   // порядок как в запросе
});

Promise.race([wait(300, "медленный"), wait(100, "быстрый")])
  .then((winner) => console.log("Первым пришёл:", winner));

05 async / await: промисы без цепочек

Цепочки then лучше пирамиды, но всё равно читаются не как обычный код. В JavaScript есть синтаксис, который делает асинхронный код похожим на синхронный: async / await. Под капотом это те же промисы, просто записанные удобнее.

async
Слово перед функцией. Такая функция всегда возвращает промис, а внутри неё можно использовать await.
await
«Подожди результат промиса». Работает только внутри async-функции. Приостанавливает эту функцию, но не всю программу.
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// было: цепочка then
function checkoutThen() {
  return wait(100)
    .then(() => console.log("then: корзина открыта"))
    .then(() => wait(100))
    .then(() => console.log("then: оплата прошла"));
}

// стало: async / await
async function checkout() {
  await wait(100);
  console.log("await: корзина открыта");
  await wait(100);
  console.log("await: оплата прошла");
}

checkoutThen().then(() => checkout());

Код с await читается сверху вниз, как обычный синхронный: «подождали, вывели, подождали, вывели». Результат промиса можно просто положить в переменную:

const wait = (ms, value) => new Promise((resolve) => setTimeout(() => resolve(value), ms));

async function showPrice() {
  console.log("Спрашиваем цену...");
  const price = await wait(200, 35);      // await «достаёт» значение из промиса
  console.log("Цена плова:", price, "сомони");
  return price * 2;
}

showPrice().then((double) => console.log("Две порции:", double));
console.log("showPrice() запущена и вернула промис");
Аналогия из жизни

Вы стоите в очереди за лепёшкой. await — это «встал в очередь и ждёшь свою порцию». Но остальные дела на улице (весь остальной код программы) не остановились: ждёте только вы, одна функция. Как только лепёшка готова, вы продолжаете с того места, где остановились.

Ошибки: try / catch / finally

Если промис отклонён, await бросает ошибку на том месте, где вы его ждали. Ловим её обычным try / catch, который вы уже знаете. finally выполняется в любом случае.

const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function loadStudent(id) {
  await wait(100);
  if (id <= 0) {
    throw new Error("неверный номер студента");
  }
  return "Студент №" + id;
}

async function main() {
  try {
    console.log(await loadStudent(5));
    console.log(await loadStudent(0));      // здесь будет ошибка
    console.log("эта строка не выполнится");
  } catch (error) {
    console.log("Ошибка:", error.message);
  } finally {
    console.log("Загрузка завершена");
  }
}

main();

Последовательно или параллельно

Каждый await ждёт, пока завершится предыдущий шаг. Если шаги независимы — это пустая трата времени: две загрузки по 200 мс подряд займут 400 мс. Запустите оба промиса сразу и ждите их вместе через Promise.all — получится 200 мс.

const wait = (ms, value) => new Promise((resolve) => setTimeout(() => resolve(value), ms));

async function sequential() {
  console.log("--- последовательно ---");
  const a = await wait(200, "курсы");        // ждём 200 мс
  const b = await wait(200, "новости");      // потом ещё 200 мс
  console.log("получили:", a, b);
}

async function parallel() {
  console.log("--- параллельно ---");
  const [a, b] = await Promise.all([wait(200, "курсы"), wait(200, "новости")]);   // 200 мс вместе
  console.log("получили:", a, b);
}

sequential().then(parallel);
Частые ошибки

1. await вне async-функции — синтаксическая ошибка. 2. Забыть await: вместо значения вы получите сам промис. 3. Забыть try / catch: ошибка «вылетит» наружу как необработанная.

const wait = (ms, value) => new Promise((resolve) => setTimeout(() => resolve(value), ms));

async function main() {
  const price = wait(100, 35);         // ✖ без await
  console.log("Цена:", price);          // → Цена: Promise {…}, а не 35
}

main();

await и event loop

Всё, что идёт после await, — это продолжение функции в виде микрозадачи. Код до первого await выполняется синхронно, а остаток «встаёт в очередь» микрозадач:

async function main() {
  console.log("1. до await (синхронно)");
  await null;
  console.log("3. после await (микрозадача)");
}

main();
console.log("2. после вызова main() (синхронно)");

ЗАДАЧА 5.5

Повторить попытку

сложная

Сервер иногда «падает». Напишите async function retry(fn, times): она вызывает fn до times раз. Если попытка неудачна — выводит попытка N: сообщение и пробует снова. Если все неудачны — выбрасывает последнюю ошибку. Функция flaky специально ломается дважды.

const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

let calls = 0;
async function flaky() {
  calls++;
  await wait(50);
  if (calls < 3) {
    throw new Error("сбой " + calls);
  }
  return "данные";
}

// async function retry(fn, times) { ... }

успех: данные
Подсказка 1

Цикл for (let i = 1; i <= times; i++), а внутри — try { return await fn(); } catch (error) { … }.

Подсказка 2

В catch: выведите `попытка ${i}: ${error.message}`. Если i === times, сделайте throw error — иначе цикл просто перейдёт к следующей попытке.

07 Практика на уроке: имитация загрузки данных

Настоящих серверов у нас пока нет (до них доберёмся на следующем уроке), поэтому создадим «ненастоящий» — функции, которые отвечают с задержкой, как реальные запросы. Это стандартный приём: так проверяют интерфейс до того, как готов сервер.

Шаг 1. База данных и вспомогательные функции

Шаг 2. Функции «запросов»

Каждая функция ждёт и возвращает данные. Если пользователя нет — отклоняет промис с ошибкой. Так себя ведёт настоящий сервер: чаще всего он отвечает за 100–500 мс, а иногда отвечает «ошибка».

Выстройте их в плоскую цепочку и выведите результат каждого шага. Добавьте один catch в конце и проверьте, что он срабатывает, если заставить один шаг отклониться.
  4. Три загрузки одновременно. Три «запроса» с разной задержкой (курс сомони, погода в Душанбе, расписание группы). Запустите через Promise.all, выведите результаты и общее время (Date.now() до и после — оно должно быть около самой долгой задержки, а не суммы).
  5. async / await с ошибкой. Напишите async function loadProfile(id), которая «грузит» профиль 300 мс и для номера больше 100 бросает ошибку. Вызовите её для трёх номеров, ошибки ловите через try / catch / finally.
  6. Лист прогнозов. Придумайте три собственных фрагмента кода со смесью console.log, setTimeout и Promise.then. Над каждым запишите комментарием свой прогноз порядка вывода, затем запустите и сверьте. Если не угадали — одной строкой объясните, в чём была ошибка.

✓ Шпаргалка урока

  • Синхронный код идёт по строкам. Асинхронный запускает работу и не ждёт: результат приходит позже.
  • setTimeout(fn, мс) — выполнить один раз позже; setInterval — повторять; остановка — clearTimeout / clearInterval. Передаём функцию, а не её вызов.
  • Callback — функция, которую вызовут «потом». Колбэк «error-first»: (error, result). Много вложенных колбэков — «ад колбэков».
  • Promise: pending → fulfilled / rejected, меняется один раз. Создание: new Promise((resolve, reject) => …).
  • then / catch / finally: then возвращает новый промис, значение уходит по цепочке (нужен return); ошибка пропускает then до ближайшего catch; finally — всегда.
  • Promise.all — все вместе (порядок как в запросе, одна ошибка — всё отклонено); allSettled — отчёт по каждому; race — самый быстрый.
  • async функция всегда возвращает промис. await ждёт результат только внутри async; ошибки ловим try / catch / finally. Независимые шаги — через Promise.all.
  • Event loop: сначала весь синхронный код → все микрозадачи (then, после await, queueMicrotask) → одна макрозадача (setTimeout) → снова микрозадачи.
  • С ИИ: сначала сами, потом промпт по формуле. Объяснение ИИ про порядок вывода — всегда проверяем запуском.
