01 Как JavaScript работает в браузере

Страница состоит из трёх языков, и у каждого своя работа. Вы уже знаете два из них:

Аналогия из жизни

Представьте чойхону. HTML — это здание: стены, столы, кухня. CSS — интерьер: ковры, свет, расстановка столов. А JavaScript — официант и повара: они принимают заказ, несут чай, пересчитывают счёт. Здание без людей красивое, но пустое. Сайт без JavaScript — то же самое.

Внутри каждого браузера есть «двигатель», который понимает JavaScript: в Chrome и Edge он называется V8, в Firefox — SpiderMonkey, в Safari — JavaScriptCore. Вам не нужно ничего устанавливать, чтобы JavaScript заработал: он уже есть в вашем браузере. Именно поэтому мы начинаем с браузера, а Node.js — программу для запуска JS вне браузера — подключим позже, на уроке 17.

Как JavaScript читает код

  • Сверху вниз, строка за строкой. Как вы читаете рецепт: сначала первый шаг, потом второй.
  • Одна команда — одно действие. Команды (их называют «инструкциями») принято заканчивать точкой с запятой ;.
  • Регистр важен. console и Console для JavaScript — два разных слова.
  • Если на какой-то строке случилась ошибка, код ниже не выполнится. Браузер остановится и напишет сообщение в консоль.

Самая первая команда, которую вы выучите, — console.log. Она «печатает» значение в консоль. Попробуйте: нажмите «Запустить», потом поменяйте текст и запустите снова.

console.log("Салом, JavaScript!");
console.log("Я учусь программировать в MakeFirstStep");

Проверьте на практике, что порядок важен. Строки выполняются сверху вниз, и результат в консоли идёт в том же порядке:

console.log("Первый шаг");
console.log("Второй шаг");
console.log("Третий шаг");

А вот что бывает, когда на середине программы — ошибка. Третья команда обращается к несуществующему слову, и четвёртая уже не выполняется:

console.log("Шаг 1: всё хорошо");
console.log("Шаг 2: всё хорошо");
console.log(шаг3);
console.log("Шаг 4: сюда мы не дойдём");
Частая ошибка

Думать, что JavaScript «понимает, что вы имели в виду». Нет: он делает ровно то, что написано, буква в букву. Лишний пробел в кавычках, заглавная буква вместо маленькой, забытая скобка — и вместо результата вы получите красное сообщение. Это нормально: ошибки встречаются у всех программистов каждый день, а читать их — отдельный навык, который мы сегодня начнём тренировать.

02 Подключаем скрипт: inline, внешний файл, defer

Чтобы браузер выполнил JavaScript, код нужно «положить» на страницу с помощью тега <script>. Есть два способа.

Способ 1. Код прямо в HTML (inline)

<body>
  <h1>Моя страница</h1>

  <script>
    console.log("Салом из inline-скрипта!");
  </script>
</body>

Удобно для короткой проверки, но в настоящих проектах так не делают: HTML превращается в кашу, а код нельзя использовать на другой странице.

Способ 2. Отдельный файл (внешний скрипт)

Это основной способ. Код лежит в файле script.js рядом с index.html, а в HTML вы только ссылаетесь на него через атрибут src — точно так же, как <link href="style.css"> подключает CSS.

<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Первый скрипт</title>
  <link rel="stylesheet" href="style.css">
  <script src="script.js" defer></script>
</head>
<body>
  <h1>Салом, JavaScript!</h1>
</body>
</html>

console.log("Салом из script.js!");
Аналогия из жизни

Inline-скрипт — это записка, приклеенная прямо к стене. Внешний файл — это полка с папками: на стене висит только ярлык «см. папку script.js», а все документы лежат в папке, и их можно открыть из любой комнаты (с любой страницы).

src
Адрес файла со скриптом. script.js — рядом с HTML, js/script.js — в подпапке js, ../script.js — на уровень выше.
Закрывающий тег
Всегда нужен: <script src="..."></script>. Записать как <script src="..." /> нельзя — страница сломается.
defer
Атрибут «подожди». Браузер скачивает файл параллельно с чтением страницы, но запускает его только после того, как весь HTML прочитан.

Где держать тег script

Помните схему из прошлого раздела: браузер читает HTML сверху вниз. Если скрипт стоит выше элемента, к которому обращается, то в момент запуска такого элемента ещё нет. Посмотрите на живом примере. В трёх местах мы просим у страницы заголовок h1 (как это работает, разберём на уроке 8 — пока важно только слово null — «ничего нет»).

<script>
  console.log("скрипт ВЫШЕ заголовка:", document.getElementById("title"));
</script>

<h1 id="title">Салом, MakeFirstStep!</h1>

<script>
  console.log("скрипт НИЖЕ заголовка:", document.getElementById("title"));
</script>

// файл script.js в этой песочнице запускается после всей страницы, как с defer
console.log("script.js (как defer):", document.getElementById("title"));

Первый скрипт увидел null: заголовка на странице ещё не было. Второй и третий — нашли <h1#title>. Отсюда три рабочих правила:

ВариантКак выглядитКогда использовать
defer в <head><script src="script.js" defer></script>Наш выбор на курсе. Подключение видно сразу вверху файла, а выполнение — после загрузки страницы.
В конце <body><script src="script.js"></script> перед </body>Старый, но рабочий способ. Часто встречается в чужом коде.
В <head> без defer<script src="script.js"></script>Обычно ошибка: скрипт запускается, когда страницы ещё нет, и не находит элементов.

Есть ещё атрибут async: он запускает скрипт сразу, как только скачал, не дожидаясь страницы и других скриптов. Так подключают счётчики аналитики. Для наших программ он не подходит: порядок запуска не гарантирован. А type="module" (уроки 17–18) ведёт себя как defer автоматически.

Частые ошибки при подключении
  • Скрипт «не работает», в консоли пусто. Проверьте путь в src: skript.js и script.js — разные файлы. На сервере регистр тоже важен: Script.js ≠ script.js.
  • В консоли красная строка «Failed to load resource: 404». Браузер не нашёл файл: он лежит в другой папке или назван иначе.
  • Файл называется script.js.txt. На Windows расширения по умолчанию скрыты — включите их (Проводник → Вид → Показать → Расширения имён файлов).
  • Изменил код, а в браузере всё по-старому. Файл не сохранён (белая точка у вкладки в VS Code) или браузер показывает старую копию: обновите страницу с очисткой кэша — Ctrl + Shift + R (Windows) или Cmd + Shift + R (macOS).
  • Если у тега есть src, то код внутри него игнорируется. Нужно одно из двух: либо src, либо код внутри.

03 Консоль: log, warn, error, table

Консоль — это окно «чата» между вами и браузером. Туда программа пишет сообщения, а вы читаете. Программисты на JavaScript проводят в консоли половину рабочего времени: проверяют значения, ищут ошибки, пробуют команды.

Аналогия из жизни

Консоль — как окошко на кухне чойхоны, через которое повар передаёт сообщения залу. «Заказ готов» (log), «рис заканчивается» (warn), «казан сломан, плов не будет» (error). Посетитель этого окошка не видит — только вы, разработчик.

console.log — печатаем значение

В скобках можно писать текст, числа и даже вычисления. Текст всегда берётся в кавычки: двойные "..." или одинарные '...' — без разницы, главное, чтобы открывающая и закрывающая были одинаковые.

console.log("Это текст");          // строка — в кавычках
console.log('Одинарные тоже можно');
console.log(2026);                 // число — без кавычек
console.log(7 * 8);                // JavaScript сам посчитает: 56
console.log(100 - 35);             // 65

Чем отличается "5" от 5? В кавычках — текст (строка), без кавычек — число. Для человека одинаково, а для программы нет. Подробно разберём на следующем уроке, пока достаточно запомнить: кавычки = текст.

Арифметика: что умеет JavaScript

ЗнакЧто делаетПримерРезультат
+сложение12 + 820

*умножение5 * 630

Порядок действий такой же, как в школьной математике: сначала умножение и деление, потом сложение и вычитание, а скобки меняют порядок. Дробная часть в JavaScript пишется через точку: 2.5, а не 2,5.

console.log(10 + 5 * 2);     // умножение первым: 10 + 10
console.log((10 + 5) * 2);   // скобки первыми: 15 * 2
console.log(10 / 4);         // 2.5
console.log(17 % 5);         // остаток: 17 = 3 * 5 + 2

Несколько значений в одном log

Через запятую в console.log можно передать сколько угодно значений: консоль выведет их в одну строку через пробел. Это очень удобно: подпись слева, значение справа.

console.log("Курутоб:", 35, "сомони");
console.log("Два чайника по 12 сомони:", 2 * 12);
console.log("Хуш омадед", "в", "MakeFirstStep");

Текст можно и склеивать знаком +. Но осторожно: пробелы между словами придётся ставить самим — внутри кавычек.

console.log("Урок " + 1 + ": старт курса");
console.log("MakeFirstStep" + " " + "2026");
console.log("MakeFirstStep" + "2026");     // без пробела — слиплось
Совет

В обычном тексте иногда нужны сами кавычки. Если внутри слова есть апостроф или кавычка, возьмите кавычки другого вида: "It's a plov" или 'Он сказал "Салом"'. Для переноса строки внутри текста есть символ \n. Остальное узнаем позже.

warn, error, info, table

У консоли есть разные «голоса». В настоящей консоли браузера они выглядят по-разному: warn — жёлтая строка, error — красная, info — обычная с иконкой, а table рисует таблицу.

console.log("Обычное сообщение");
console.info("Информация: курс начался");
console.warn("Предупреждение: осталось мало риса");
console.error("Ошибка: казан сломан");
console.table(["самбуса", "курутоб", "чой"]);
Как это выглядит у вас в браузере

В окне запуска на этой странице всё выводится простыми строками, чтобы вы могли сравнивать результат с эталоном. В настоящей консоли warn будет жёлтым, а error — красным с кнопкой раскрытия, откуда вызвано сообщение. console.table нарисует настоящую таблицу со столбцами «index» и «Value» — откройте консоль на своей странице и посмотрите. Таблицы особенно полезны, когда выводите много однотипных данных (с массивами и объектами познакомимся на уроках 6 и 7).

МетодКогда использовать

console.info()То же, что log, но «по смыслу» — справочная информация.
console.warn()Что-то подозрительное, но программа может работать дальше.

Консоль как калькулятор

В DevTools консоль можно использовать и напрямую: напечатали выражение, нажали Enter — получили результат, без console.log. Стрелка ↑ достаёт предыдущую команду, Shift + Enter переносит строку, не выполняя команду. Удобно проверять мелочи: 2 ** 10, 17 % 5, "a" + "b".

Читаем сообщение об ошибке

Красная строка — не приговор, а подсказка. В ней всегда три части:

  1. Вид ошибки — SyntaxError (нарушены правила записи: не хватает скобки, кавычки), ReferenceError (используете слово, которого JavaScript не знает).
  2. Описание — например, Console is not defined («Console не определено») или missing ) after argument list («после аргументов не хватает )»).
  3. Место — имя файла и номер строки, например script.js:3. В настоящей консоли это ссылка: клик открывает именно эту строку.

Научитесь читать эти три части — и половина ошибок будет решаться за минуту. Окно запуска на этой странице тоже подсказывает: под красной строкой появляется строка с пояснением на русском.

console.log("Открываем чойхону");
console.log("Добавьте закрывающую кавычку);
console.log("Закрываем чойхону");
Частые опечатки новичков
  • consol.log, console.lg, console.Log — опечатка в слове.
  • Забытая кавычка или скобка: console.log("Салом).
  • Разные кавычки в начале и в конце: "Салом'.
  • Текст без кавычек: console.log(Салом) — JavaScript решит, что Салом — команда.
  • Русские буквы вместо латинских в слове console (внешне те же с и о, а для программы — другие). Если «всё правильно, а не работает» — перепишите слово заново.
  • Забытая запятая между значениями или лишняя точка.

Вкладка Elements: живая страница

Вы уже видели её, когда разбирались с CSS. Слева — дерево HTML, справа — стили выбранного элемента. Но теперь у неё появляется новый смысл: это то, что реально лежит на странице в данный момент, а не то, что было в файле. Когда JavaScript меняет страницу, вы увидите изменения именно здесь.

  • Двойной клик по тексту — меняете его прямо на странице. Двойной клик по атрибуту или значению стиля — тоже.

  • Изменения живут до перезагрузки. Файл на диске не меняется — это «репетиция» на копии страницы.

Вкладка Console: сообщения и команды

Вкладка Sources: файлы и точки останова

Слева дерево файлов сайта: index.html, style.css, script.js. Откройте script.js — в середине вы увидите свой код. Поиск файла по имени: Ctrl/Cmd + P.

05 Окна: alert, prompt, confirm

Консоль видна только разработчику. Но иногда нужно поговорить с пользователем: показать сообщение, спросить имя, получить «да» или «нет». У браузера для этого есть три встроенных окна. Они «модальные»: пока окно открыто, страница заморожена, и ничего другого нажать нельзя.

Запускать эти примеры придётся у себя

Код на этой странице работает внутри изолированной «песочницы» браузера, и она запрещает модальные окна: alert, prompt и confirm здесь просто игнорируются. Поэтому следующие блоки — только для чтения. Скопируйте их в свой script.js (после настройки среды в разделе 6) и попробуйте на своей странице.

alert — показать сообщение

alert("Салом, MakeFirstStep!");

Окно с текстом и одной кнопкой «OK». Ничего не возвращает: просто показывает и ждёт.

prompt — спросить у пользователя

prompt("Как вас зовут?");                // окно с полем ввода
prompt("В каком вы городе?", "Душанбе"); // второй аргумент — значение по умолчанию

Показывает окно с полем ввода и кнопками «OK» и «Отмена». Что вернёт prompt:

  • если нажали OK — то, что ввели, всегда как строку (даже если вы набрали число);
  • если нажали «Отмена» или Esc — специальное значение null («ничего»).

confirm — спросить «да или нет»

confirm("Вы точно хотите удалить заказ?");

Окно с вопросом и кнопками «OK» и «Отмена». Возвращает true («да»), если нажали OK, и false («нет»), если «Отмена». Что делать с этим ответом — выбирать, когда мы научимся условиям (урок 3).

Используем ответ сразу, без переменных

Переменных мы пока не знаем (это урок 2), но ответ prompt уже можно использовать — вставив один вызов внутрь другого. Сначала JavaScript выполняет то, что внутри скобок, а потом использует результат.

alert("Салом, " + prompt("Как вас зовут?") + "!");
  1. Выполняется внутренний вызов: открывается окно «Как вас зовут?», вы вводите «Мадина».
  2. prompt возвращает строку "Мадина".
  3. Склеивается "Салом, " + "Мадина" + "!".
  4. Внешний alert показывает Салом, Мадина!.

Ловушка: prompt возвращает строку

Если спросить у пользователя два числа и сложить ответы знаком +, получится склейка, а не сумма: "7" + "5" даёт "75". Чтобы превратить строку в число, используйте функцию Number(...). Эту «ловушку» можно проверить даже здесь, без окон — подставим вместо ответов пользователя готовые строки:

console.log("7" + "5");                    // склейка строк
console.log(Number("7") + Number("5"));    // превратили в числа и сложили

alert(Number(prompt("Первое число")) + Number(prompt("Второе число")));
Аналогия из жизни

Это как анкета в банке: вы пишете цифры от руки, а оператор вводит их в компьютер. Пока цифры только на бумаге (в строке), считать с ними нельзя. Сначала нужно «ввести» (Number(...)), а потом складывать.

Почему в настоящих проектах это почти не используют
  • Окна блокируют всю страницу, выглядят одинаково на всех сайтах и пугают пользователя.
  • Их нельзя оформить в стилях сайта: красить, анимировать, перетаскивать.
  • Браузер позволяет пользователю включить «Не показывать больше диалоги», после чего код тихо перестаёт работать.
  • Вместо них на сайтах используют формы, модальные окна из HTML и уведомления — этому мы научимся в модулях 2 и 3.

Зато для обучения и быстрой проверки идей alert и prompt идеальны: ничего не нужно верстать.

Аналогия из жизни

Чат — как консультант в магазине: расскажет и посоветует, но не покупает за вас. Автодополнение — как подсказки такси-навигатора: быстро, но если слепо следовать им, можно заехать в тупик. Агент — как водитель, которому вы дали адрес: довезёт, но если вы сами дорогу не знаете, не заметите, что он поехал странным маршрутом.

Где ИИ ошибается в JavaScript чаще всего

  • Выдумывает команды. Предлагает метод или функцию, которых нет в JavaScript (например, console.print), — звучит убедительно, а в консоли красная ошибка.
  • Путает языки. Подсовывает конструкции из Python или другого языка, потому что «похоже».
  • Неверно предсказывает вывод. Уверенно пишет «этот код выведет 4», а он выводит 22. ИИ не запускает ваш код — он угадывает.
  • Решает не ту задачу. Вы просили одно, а он решил похожее, да ещё добавил лишнее.
  • Использует устаревшие приёмы или слишком сложные решения, которые вы не сможете объяснить.

Проверьте сами: ИИ-ассистент мог бы сказать «"2" + 2 даст 4». Запустите и убедитесь, кто прав — консоль или ИИ:

console.log("2" + 2);   // ИИ мог бы уверенно ответить: 4
console.log(2 + 2);     // а это уже правда 4

Вывод: консоль — последняя инстанция. Любой ответ ИИ про код проверяется запуском.

Правила работы с ИИ на курсе

  1. Сначала пробуешь сам 15 минут — только потом спрашиваешь ИИ.
  2. Не вставляешь код, который не можешь объяснить строчку за строчкой.
  3. На проверке ДЗ преподаватель может попросить объяснить любую строку.
  4. Промпт всегда содержит: контекст, задачу, ограничения и нужный формат ответа.
  5. ИИ пишет черновик — ты проверяешь логику, имена и крайние случаи.
  6. Copilot включаем на практике и выключаем на контрольных заданиях.
  7. Контрольные на уроках 6 и 18 выполняются полностью без ИИ.

Чего не делаем на курсе
  • Не просим «сделай ДЗ за меня» и не сдаём код, который не можем объяснить.
  • Не вставляем в чат пароли, ключи и личные данные.
  • Не принимаем Tab от Copilot, не прочитав подсказку.
  • Не доверяем ИИ в вопросе «что выведет этот код» — запускаем и смотрим.

✓ Шпаргалка урока

  • Роли: HTML — что на странице, CSS — как выглядит, JavaScript — что происходит. JS уже встроен в браузер (движок V8 в Chrome и Edge).
  • Как читается код: сверху вниз, строка за строкой. Регистр важен. Ошибка на строке — остальное не выполняется.
  • Подключение: <script src="script.js" defer></script> в <head> — наш стандарт. Закрывающий тег обязателен. Без defer скрипт в <head> запускается раньше страницы. Inline — только для проверок. Если есть src, код внутри тега игнорируется.
  • Пустая консоль? Проверьте путь в src, регистр букв, расширение файла (.js, а не .js.txt), сохранён ли файл, вкладку Network (200 или 404), обновление без кэша: Ctrl/Cmd + Shift + R.
  • Консоль: console.log(...) — несколько значений через запятую выводятся через пробел; warn — предупреждение, error — ошибка, table — таблица. Текст в кавычках, числа без. Арифметика: + - * / % **, скобки, дробная часть — через точку.

  • Строки и числа: "7" + "5" — это "75", а Number("7") + Number("5") — это 12. + рядом с текстом склеивает, - и * работают с числами.
