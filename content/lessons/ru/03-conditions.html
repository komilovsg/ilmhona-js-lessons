01 Операторы сравнения

Любое решение в программе начинается с вопроса: «этот возраст больше восемнадцати?», «пароль совпал?», «хватает ли денег?». Вопрос в JavaScript задаётся оператором сравнения, а ответ всегда один из двух: true («да») или false («нет»). Это тип boolean, который вы уже знаете из урока про типы данных.

const price = 35;
const balance = 120;

Частая ошибка: один знак «=»

Один знак = — это присваивание («положи значение в переменную»), а не сравнение. Вопрос «равно ли?» задаёт ===. Перепутать их очень легко, поэтому читайте вслух: = — «станет», === — «равно ли».

let score = 5;
console.log(score === 7);  // → false: просто вопрос, score не меняется
score = 7;                  // присваивание: теперь в score лежит 7
console.log(score === 7);  // → true

Сравнение строк: по алфавиту, но с оговорками

Строки сравниваются «по словарю», буква за буквой. Но компьютер сравнивает не буквы, а их внутренние номера (коды) в таблице Unicode. Поэтому есть два подвоха: заглавные буквы «меньше» строчных, а числа-строки сравниваются как текст, а не как числа.

console.log("Аня" < "Бахтиёр");  // → true: «А» стоит в алфавите раньше «Б»
console.log("а" < "Б");          // → false: строчная «а» в таблице после заглавной «Б»
console.log("Z" < "a");          // → true: все заглавные идут раньше строчных
console.log("10" < "9");         // → true: как текст «1» раньше «9», как в словаре
console.log(10 < 9);             // → false: а вот как числа
Аналогия из жизни

Номера маршруток на остановке в Душанбе. Если читать их как числа, «9» идёт раньше «10». Но если сложить таблички в алфавитном порядке, как папки в шкафу, то «10» окажется перед «9»: сравнивается первая цифра, а она у «1» меньше. Строки в JavaScript сравниваются именно как таблички в шкафу, а числа — как числа.

Сравнение разных типов

Когда с одной стороны > или < стоит строка, а с другой число, JavaScript превращает строку в число (вы видели это в уроке про приведение типов) и только потом сравнивает.

console.log("10" > 9);        // → true: строка "10" стала числом 10
console.log("abc" > 1);       // → false: "abc" стало NaN, а любое сравнение с NaN даёт false
console.log(NaN === NaN);      // → false: NaN не равно даже самому себе
console.log(null > 0);        // → false
console.log(null === 0);       // → false
console.log(null >= 0);       // → true — странность языка, к ней вернёмся в следующем разделе

02 Строгое и нестрогое равенство

В JavaScript два вида «равно». Они выглядят похоже, но ведут себя совершенно по-разному.

  • === — строгое равенство. Сравнивает и значение, и тип. Если типы разные — сразу false, без попыток что-то преобразовать.
  • == — нестрогое равенство. Если типы разные, сначала пытается привести значения к общему типу, и только потом сравнивает.
console.log(5 === 5);     // → true: число и число
console.log(5 === "5");   // → false: число и строка, типы разные
console.log(5 == "5");    // → true: == превратило строку "5" в число и сравнило
Аналогия из жизни

Строгое === — это охранник на входе в университет: проверяет паспорт полностью — и имя, и документ. Нестрогое == — это добрый знакомый: «Ну, вы похожи на Фархода, проходите». Иногда он угадывает, но иногда пропускает не того. В коде мы хотим предсказуемости, поэтому охранник лучше.

Правило курса

Всегда пишем === и !==. Единственное, что стоит запомнить про ==: умение прочитать его в чужом коде и понимание, почему оно опасно. Если нужно сравнить число из формы со строкой — преобразуйте явно: Number(input) === 5. Явное лучше неявного: код читается однозначно.

Так плохо

Работает «случайно» и ломается, когда пользователь введёт пустую строку.

}
Так хорошо

const answer = "";
if (answer !== "" && Number(answer) === 0) {
  console.log("Ответ — ноль!");  // не выведется
}

03 Истинные и ложные значения (truthy / falsy)

Условие не обязано быть сравнением. В if можно положить любое значение, и JavaScript сам превратит его в true или false. Это то самое неявное приведение к boolean, о котором шла речь в уроке про типы.

Всего восемь «ложных» значений, остальное — истина

Значения, которые превращаются в false, называют falsy («ложноватые»). Запомните основные пять — они встречаются каждый день:

Falsy значениеЧто это
falseсамо ложное значение
0 (а также -0, 0n)число ноль
""пустая строка
null«намеренно пусто»
undefined«значение не задано»
NaN«не число»

Всё остальное — truthy («истинное»): любое ненулевое число (включая отрицательные), любая непустая строка, включая "0" и "false". Проверить любое значение можно через Boolean(...) или двойное отрицание !!:

console.log(Boolean(0));         // → false
console.log(Boolean(""));        // → false
console.log(Boolean(null));      // → false
console.log(Boolean(NaN));       // → false

console.log(Boolean(1));         // → true
console.log(Boolean(-5));        // → true: отрицательное число — тоже истина
console.log(Boolean("Мадина"));  // → true
console.log(Boolean(" "));       // → true: пробел — это символ, строка не пустая!
console.log(Boolean("0"));       // → true: строка "0" не пустая
console.log(Boolean("false"));   // → true: строка с текстом false — просто текст
Аналогия из жизни

Пустой стакан, пустой кошелёк, пустое место на остановке — это «нет». А кошелёк, в котором лежит одна монета, — уже «есть», пусть и немного. Но обратите внимание на одну странность: 0 — это «пусто», а строка "0" — «есть», ведь в ней лежит символ-цифра.

Как это используется

Самая частая причина смотреть на truthy/falsy — проверка «задал ли пользователь значение вообще»:

const username = "";   // пользователь ничего не ввёл

if (username) {
  console.log("Добро пожаловать, " + username);
} else {
  console.log("Введите имя");
}
Ловушка: ноль — тоже честное значение

Проверка if (value) считает ложью и «не задано», и настоящий 0. Если ноль для вас допустим (скидка 0%, баланс 0 сомони, оценка 0), проверка if (discount) сработает неверно.

const discount = 0;   // скидка 0% — это нормальное значение

if (discount) {
  console.log("Скидка:", discount + "%");
} else {
  console.log("Скидки нет");   // ✖ ошибка логики: 0% тоже скидка
}

// правильно: спрашиваем именно «задано ли значение»
if (discount !== undefined) {
  console.log("Скидка:", discount + "%");
}

04 Логические операторы: &&, ||, !

Одного вопроса часто мало. «Можно в клуб, если вам 18 или больше и у вас есть паспорт». Чтобы объединять вопросы, используют три логических оператора:

&& — «и»
Истина, только если оба условия истинны.

Аналогия из жизни

Чтобы подняться на канатную дорогу, нужен билет и хорошая погода (&&). Попасть в чойхону можно или через главный вход, или через дворик (||). Знак «не» — это табличка «Не работает»: она переворачивает ответ.

Приоритет и скобки

Порядок выполнения такой же, как в математике: сначала !, затем &&, потом ||. Как умножение идёт раньше сложения, так «и» идёт раньше «или». Чтобы не гадать и не путать читателя, в сложных условиях ставьте скобки.

const isStudent = true;
const hasCard = false;
const isWeekend = false;

// без скобок: сначала &&, потом ||
console.log(isStudent || hasCard && isWeekend);     // → true
// со скобками: порядок меняется
console.log((isStudent || hasCard) && isWeekend);   // → false

Закон «не» (законы де Моргана)

Условие «не (А или Б)» означает то же самое, что «не А и не Б». И наоборот: «не (А и Б)» — это «не А или не Б». Это помогает упрощать запутанные условия.

const isClosed = false;
const isFull = true;

// «Можно войти, если НЕ (закрыто ИЛИ мест нет)»
console.log(!(isClosed || isFull));     // → false
// то же самое: «НЕ закрыто И НЕ заполнено»
console.log(!isClosed && !isFull);     // → false

Короткое замыкание и возвращаемые значения

Здесь начинается самое интересное. Операторы && и || на самом деле возвращают не true / false, а одно из значений, которые сравнивают. И делают это «лениво», слева направо, останавливаясь как только ответ понятен. Это называется короткое замыкание.

  • a || b — берёт первое истинное значение. Если истинных нет — вернёт последнее.
  • a && b — берёт первое ложное значение. Если ложных нет — вернёт последнее.
console.log(0 || 10);                  // → 10: 0 ложь, идём дальше
console.log("Алиша" || "гость");       // → Алиша: первое значение уже истинное, дальше не смотрим
console.log(null || undefined || "запасной"); // → запасной

console.log(1 && 2 && 3);                // → 3: все истинны, вернули последнее
console.log(1 && 0 && 3);                // → 0: остановились на первом ложном
console.log(null && "не дойдём");        // → null
Аналогия из жизни

|| — это проверка запасных вариантов: «пойдём в чойхону у дома, а если закрыто — в соседнюю, а если и она закрыта — домой». Берём первый вариант, который сработал. && — это цепочка проверок в аэропорту: паспорт, билет, багаж. Как только одна проверка не пройдена — дальше не пускают, и мы знаем, на чём остановились.

Этим пользуются на практике. Значение по умолчанию:

const nickname = "";                          // пользователь ничего не ввёл
const shown = nickname || "Гость";            // если пусто — подставляем «Гость»
console.log("Привет,", shown);                // → Привет, Гость

И безопасное «сделай только если»: правая часть && вычисляется лишь тогда, когда левая истинна.

const isAdmin = true;
isAdmin && console.log("Открываем панель администратора");  // выполнится
const isGuest = false;
isGuest && console.log("Это сообщение не появится");        // правая часть даже не вычислялась

Оператор ?? — «если пусто» только для null и undefined

У || есть недостаток, который вы уже видели: он считает ложью 0 и пустую строку. Для значений по умолчанию это часто неудобно: громкость 0 — это честная настройка, а не «значение не задано». Оператор ?? («нулевое слияние») подставляет запасное значение только если слева null или undefined.

const volume = 0;                 // пользователь выключил звук

console.log(volume || 50);        // → 50 ✖ выключенный звук включился сам
console.log(volume ?? 50);        // → 0  ✔ ноль сохранён

let theme;                        // настройка не задана (undefined)
console.log(theme ?? "светлая");  // → светлая

05 Условный оператор if / else if / else

Теперь, когда мы умеем задавать вопросы, научим программу выбирать путь. Для этого служит оператор if («если»).

const temperature = 35;

if (temperature > 30) {
  console.log("Жарко, берите воду");
}
console.log("Программа продолжается");

Код в фигурных скобках выполняется, только если условие в круглых скобках истинно. Если ложно — блок просто пропускается, и программа идёт дальше.

else — «в остальных случаях»

const balance = 8;
const fare = 3;   // проезд в маршрутке

if (balance >= fare) {
  console.log("Проезд оплачен");
} else {
  console.log("Недостаточно средств");
}

else if — несколько вариантов

Если вариантов больше двух, между if и else добавляют сколько угодно else if. Условия проверяются сверху вниз, до первого истинного; остальные уже не проверяются.

const score = 72;

if (score >= 86) {
  console.log("Оценка: 5");
} else if (score >= 71) {
  console.log("Оценка: 4");
} else if (score >= 56) {
  console.log("Оценка: 3");
} else {
  console.log("Оценка: 2");
}
Аналогия из жизни

Светофор на проспекте Рудаки. Водитель проверяет по порядку: красный? — стоим. Нет? Жёлтый? — готовимся. Нет? Значит, зелёный — едем. Как только один пункт подошёл, остальные водитель уже не рассматривает. Так работает цепочка if / else if / else.

Порядок условий важен

Раз выполняется только первая подходящая ветка, условия нужно ставить от самых строгих к самым мягким. Если поставить score >= 56 первым, то и 90 баллов получит оценку «3» — ведь 90 тоже больше 56.

const score = 90;

if (score >= 56) {
  console.log("Оценка: 3");     // сработает уже здесь
} else if (score >= 71) {
  console.log("Оценка: 4");     // никогда не дойдём
} else if (score >= 86) {
  console.log("Оценка: 5");     // и сюда тоже
}

Составные условия и вложенность

Внутри условия можно использовать &&, || и !. А внутрь блока — класть другие if. Но много уровней вложенности трудно читать: чаще проще объединить условия через &&.

const hour = 14;
const isWorkDay = true;

if (isWorkDay && hour >= 9 && hour < 18) {
  console.log("Офис открыт");
} else {
  console.log("Офис закрыт");
}
Совет: фигурные скобки и ранние проверки

Если в блоке всего одна строка, скобки можно не писать, но делать так не стоит: при добавлении второй строки легко забыть скобки и получить ошибку. Всегда пишите { }. Кроме того, сложные проверки удобнее ставить «снизу вверх»: сначала самый исключительный случай (score > 100, «некорректный ввод»), а затем обычные.

06 Тернарный оператор ? :

Когда нужно просто выбрать одно из двух значений, конструкция if / else занимает слишком много места. Для таких случаев есть сокращённая запись — тернарный оператор. Он единственный в JavaScript с тремя частями («тернарный» значит «тройной»).

const age = 20;

// длинная запись
let status1;
if (age >= 18) {
  status1 = "взрослый";
} else {
  status1 = "ребёнок";
}

// короткая запись: условие ? значение_если_да : значение_если_нет
const status2 = age >= 18 ? "взрослый" : "ребёнок";

console.log(status1);   // → взрослый
console.log(status2);   // → взрослый
Аналогия из жизни

Табличка на двери чойхоны: «Открыто / Закрыто». Хозяин одним взглядом на часы выбирает, какой стороной повесить табличку. Тернарный оператор делает ровно это: по условию выбирает одно из двух готовых значений.

Где он удобен

Результат тернарного оператора — значение, поэтому его можно вставить прямо в шаблонную строку или в аргумент console.log:

const items = 0;
console.log(`В корзине: ${items === 0 ? "пусто" : items + " шт."}`);

const hour = 7;
console.log("Чойхона:", hour >= 9 && hour < 22 ? "открыта" : "закрыта");

Цепочка тернарных операторов

Тернарные операторы можно соединять, это заменяет else if. Работает, но уже с двумя уровнями читать трудно.

const temp = 22;
const feel = temp >= 30 ? "жарко"
           : temp >= 15 ? "тепло"
           : "прохладно";
console.log(feel);   // → тепло
Перебор

Вложенные тернарные операторы в одну строку — головная боль для читателя.

const x = a ? b ? 1 : 2 : c ? 3 : d ? 4 : 5;
Честный if / else

Если вариантов больше двух или условия сложные — берите if / else if или switch.

let label;
if (temp >= 30) {
  label = "жарко";
} else if (temp >= 15) {
  label = "тепло";
} else {
  label = "прохладно";
}
Не для действий, а для значений

Тернарный оператор нужен, чтобы получить значение. Если вам нужно выполнить разные действия (вывести одно, сохранить другое), используйте обычный if. Выражение вроде cond ? console.log("a") : console.log("b") работает, но читается плохо.

07 Конструкция switch

Если нужно сравнить одну и ту же переменную со многими конкретными значениями, цепочка из десяти else if получается громоздкой. Для этого придумали switch («переключатель»).

const day = 3;

switch (day) {
  case 1:
    console.log("Понедельник");
    break;
  case 2:
    console.log("Вторник");
    break;
  case 3:
    console.log("Среда");
    break;
  default:
    console.log("Другой день");
}
  1. Вычисляется выражение в скобках после switch — здесь day.
  2. Значение сравнивается строго (как ===) с каждым case сверху вниз.
  3. Находится первое совпадение — и код выполняется с этого места вниз.
  4. break выходит из switch. Если break нет — выполнение продолжается дальше.
  5. default — «ничего не подошло», аналог else. Его пишут в конце.
Аналогия из жизни

Меню в чойхоне: официант слышит «курутоб» и идёт прямо к нужной строчке меню, а не читает все блюда по порядку. default — это «такого блюда у нас нет». А если забыть break, то официант принесёт и курутоб, и всё, что записано ниже в меню.

Забыли break: «проваливание» (fall-through)

Самая известная ловушка switch. Без break JavaScript находит нужный case и выполняет всё, что ниже, пока не встретит break или конец switch.

const n = 2;

switch (n) {
  case 1:
    console.log("Один");
  case 2:
    console.log("Два");
  case 3:
    console.log("Три");
  default:
    console.log("Неизвестно");
}
// выведет: Два, Три, Неизвестно — всё, что ниже совпавшего case

Полезное проваливание: несколько case — одно действие

Бывает и полезная сторона. Если у нескольких значений действие одинаковое, их можно записать подряд, а break поставить только после общего кода:

const month = 4;

switch (month) {
  case 12:
  case 1:
  case 2:
    console.log("Зима");
    break;
  case 3:
  case 4:
  case 5:
    console.log("Весна");
    break;
  case 6:
  case 7:
  case 8:
    console.log("Лето");
    break;
  case 9:
  case 10:
  case 11:
    console.log("Осень");
    break;
  default:
    console.log("Такого месяца нет");
}

Сравнение строгое

switch сравнивает значения как ===, без приведения типов. Поэтому число 1 и строка "1" — разные значения:

const choice = "1";   // строка, как из поля формы

switch (choice) {
  case 1:
    console.log("Число один");
    break;
  case "1":
    console.log("Строка «1»");
    break;
  default:
    console.log("Не нашли");
}
Когда что выбиратьИнструмент
Один вопрос «да / нет»if / else
Выбрать одно из двух значенийтернарный оператор
Диапазоны («от 71 до 85»), сложные условияif / else if
Одна переменная сравнивается с конкретными значениями (1, 2, 3 или "+", "-")switch
Совет

Всегда пишите default, даже если «этого не может быть». Пользователь, опечатка или данные из сети рано или поздно подкинут неожиданное значение, и вы сразу узнаете об этом по сообщению, а не по тихому сбою.

ИИ-подсказка

Copilot — это не учитель, а очень быстрый и очень самоуверенный напарник. Он видит ваш код и угадывает, что вы собираетесь написать дальше. ✓ Шпаргалка урока

  • Сравнение: > < >= <= возвращают true / false. Один = — присваивание, а не сравнение. Строки сравниваются по таблице Unicode: «Z» меньше «a», а "10" < "9".
  • === и !== — строгое сравнение (значение и тип). == приводит типы и ведёт к сюрпризам (0 == "", null == undefined). В коде пишем только ===; NaN не равно никому.
  • Falsy: false, 0, "", null, undefined, NaN. Всё остальное — truthy, включая "0", " ", "false". Ноль — настоящее значение: проверяйте !== undefined, когда ноль допустим.
  • Логика: && — и, || — или, ! — не. Приоритет: !, потом &&, потом ||; сомневаетесь — ставьте скобки.
  • Короткое замыкание: || возвращает первое истинное, && — первое ложное (или последнее значение цепочки). nick || "Гость" — значение по умолчанию. ?? заменяет только null и undefined: 0 ?? 50 даёт 0.
  • if / else if / else: условия проверяются сверху вниз до первого истинного, от строгих к мягким. Всегда с фигурными скобками.
  • Тернарный оператор: условие ? если_да : если_нет — для выбора одного из двух значений. Цепочки из двух уровней и больше лучше писать через if.
  • switch: строгое сравнение с case, break обязателен (иначе «проваливание» вниз), default — для всего остального. Подряд идущие case без break — одно действие на несколько значений.
  • Copilot: Tab — принять, Esc — отклонить, Ctrl/Cmd + I — inline chat. Помогает с рутиной и объяснением, мешает учиться, если принимать подсказки не думая. Сначала сами с выключенным Copilot, потом он как рецензент. Проверяйте границы (> и >=), ноль и забытые break.
