Поле поиска, под ним — карточки товаров. Запрос уходит с задержкой (debounce), пока идёт загрузка — индикатор, если ничего не нашли — понятное сообщение.

Сложность примерно равная: у товаров больше логики поиска, у погоды — разбор вложенного ответа, у пользователей — зависимые запросы. 02 Требования: MVP и бонусы

MVP — минимальная версия, которая уже работает от начала до конца. Сначала делаем её полностью, и только потом украшения. Проект без MVP не получит высокой оценки, сколько бы бонусов в нём ни было.

MVP — обязательно для всех вариантов

Бонусы — после MVP

  • Скелетоны вместо слова «Загрузка…» (серые блоки под карточки).
  • Кэш последних запросов: тот же запрос второй раз не ходит в сеть.
  • Таймаут запроса через Promise.race или AbortController со своим сообщением.
  • История поиска или избранное в localStorage.
  • Автоповтор при ошибке: до трёх попыток с паузой.
  • Тёмная тема с сохранением выбора.
  • Пагинация или кнопка «Показать ещё» (limit и skip у dummyjson).
Совет

Бонус ценится, только если вы можете объяснить каждую его строку. Один простой кэш, который вы понимаете, лучше трёх «магических» кусков из чата с ИИ.

04 Декомпозиция: разбиваем проект вместе с ИИ

Проект с API опаснее первого: появились сеть, ожидание и ошибки, которые не воспроизводятся «по заказу». Поэтому план особенно важен. Идея та же, что на уроке 12: сначала шаги, потом код, и у каждого шага — видимый результат. Но теперь в плане должны быть отдельные шаги на каждое состояние (loading, error, empty) и на «рискованные» места: первый запрос, гонка ответов, сборка.

Аналогия из жизни

Поездка маршруткой из Душанбе в Худжанд: нужно заранее знать остановки, время в пути и запасной вариант, если дорогу перекроют. «Поеду как-нибудь» — путь в никуда. План с запасным вариантом — это ваши состояния error и «Повторить».

ИИ-блок: большая задача — непонятно, с чего начать

ИИ хорошо предлагает список шагов, но порядок, лишнее и оценку времени проверяете вы. Составляйте запрос по формуле курса: контекст → задача → ограничения → формат ответа → проверка.

05 Разминка 1. Состояния запроса и ошибки сети

Любой запрос в сеть живёт в одном из четырёх состояний: idle (ещё не просили), loading (ждём), success (получили, и данные могут быть как с содержимым, так и пустыми) и error (не получилось). Главное правило: всё это лежит в одном объекте state, а страница рисуется из него, как и в проекте №1.

const state = {
  status: "loading",   // "idle" | "loading" | "success" | "error"
  items: [],           // данные (при success)
  error: "",           // текст ошибки (при error)
};

// для каждого статуса — свой «экран»
const screens = {
  idle: "Введите запрос",
  loading: "Загрузка...",
  success: "Показываем данные",
  error: "Что-то пошло не так",
};
console.log(screens[state.status]);

Чтобы тренироваться без интернета, мы будем подменять сервер своей функцией: она тоже возвращает Promise и отвечает с задержкой — точь-в-точь как fetch, но каждый раз одинаково.

const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// «сервер» отвечает через 20 мс; на запрос "error" падает
async function fakeApi(query) {
  await wait(20);
  if (query === "error") throw new Error("Сеть недоступна");
  return [`${query} 1`, `${query} 2`];
}

async function main() {
  console.log("запрос...");
  const items = await fakeApi("плов");
  console.log("получили:", items.join(", "));
  try {
    await fakeApi("error");
  } catch (err) {
    console.log("ошибка:", err.message);
  }
}

Настоящий fetch: что нужно проверить после ответа

fetch устроен хитро: он «падает» (отклоняет промис) только если вообще не удалось связаться с сервером — нет сети, не найден домен.   if (!response.ok) {                                      // 2. 404 / 500 — тоже ошибка
    throw new Error(`HTTP ${response.status}`);

  return await response.json();                            // 3. ждём разбор JSON
}

06 Разминка 2. Debounce, кэш и таймаут

Если отправлять запрос на каждую нажатую букву, сервер получит десятки лишних обращений, а экран будет мигать. Debounce решает это: функция срабатывает только когда пользователь замолчал на заданное время. Каждый новый вызов сбрасывает таймер и запускает новый.

function debounce(fn, ms) {
  let timer;
  return (...args) => {
    clearTimeout(timer);                           // отменили прошлый таймер
    timer = setTimeout(() => fn(...args), ms);     // запустили новый
  };
}

const search = debounce((q) => console.log("запрос:", q), 30);
search("п");
search("пл");
search("плов");      // сработает только этот вызов, через 30 мс
Аналогия из жизни

Типичные вопросы и о чём на них сказать

Что такое async/await и чем отличается от then?
Это тот же Promise, но код читается сверху вниз. await «ставит функцию на паузу» до ответа, не блокируя страницу.
Почему нужен response.ok? Разве fetch не упадёт на 404?
Нет: fetch отклоняется только при сетевой проблеме. Ответ 404/500 — «успешный», потому что сервер ответил. Статус нужно проверять самому.
Зачем await response.json(), это же уже ответ?
Заголовки пришли, а тело ответа читается отдельно и тоже асинхронно.
Что такое debounce и зачем он здесь?
Функция срабатывает после паузы. Без него каждая буква — запрос: лишняя нагрузка и «мигающий» экран.
Что такое гонка ответов и как ты её решил?
Ответ на старый запрос может прийти позже ответа на новый и затереть его. Решение: номер запроса (применяем только свежий) или AbortController.
Как у тебя устроены состояния?
Один объект state со status, items, error; render рисует из него. Нет набора флагов, которые могут противоречить друг другу.
Что в api.js, что в ui.js, и почему так?
В api.js только сеть, в ui.js только DOM, main.js связывает. Так каждую часть можно менять и проверять отдельно.
Что делает npm run build и что лежит в dist?
Vite собирает модули в готовые для хостинга файлы. В Git dist не кладут: его можно пересобрать.
Где ты использовал ИИ? Объясни эту строку.

retry: повторяем при сбое

сложная

12 Разбор: где ИИ сэкономил время, а где увёл в сторону

Это AI-блок урока: после двух проектов важно не просто «пользоваться ИИ», а знать его настоящую цену. Часто кажется, что ИИ ускорил работу, а потом вы час искали баг в чужом, непонятном коде. Бывает наоборот: ИИ за три минуты объяснил то, на что вы потратили бы вечер. Чтобы отличать одно от другого, нужны не ощущения, а записи.

Правила курса, которые мы сейчас проверяем

№1: сначала 15 минут сам, потом ИИ. №2: код, который не можешь объяснить построчно, не вставляем. №5: ИИ пишет черновик — ты проверяешь логику, имена и крайние случаи. Разбор покажет, где вы эти правила соблюдали, а где нет.

Аналогия из жизни

Навигатор в машине. На незнакомой трассе в Согдийскую область он экономит часы. Но если слепо ехать, куда он говорит, можно оказаться на закрытой дороге. Хороший водитель знает, куда ему нужно, и сверяет подсказки со знаками. ИИ — тоже навигатор: цель и проверка остаются на вас.
