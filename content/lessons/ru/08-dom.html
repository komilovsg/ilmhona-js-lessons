DOM: поиск и изменение элементов

До сих пор JavaScript жил в консоли: мы считали, фильтровали и выводили текст. Сегодня он выходит на страницу. Каталог товаров, корзина, список задач, оценки в личном кабинете — всё это на настоящих сайтах рисует JavaScript, который находит нужное место на странице и меняет его. Сегодня вы соберёте страницу, в которой весь контент создаётся из массива.

  • Объяснить, что такое DOM и чем он отличается от HTML-файла
  • Находить элементы через querySelector и querySelectorAll
  • Менять текст, разметку, классы, атрибуты и data-*
  • Создавать элементы через createElement, вставлять их и удалять
  • Рисовать список карточек из массива объектов и очищать его
  • Делить работу с ИИ: он пишет разметку и стили, вы — логику
Как работать с этой страницей

В этом уроке много песочниц. В каждой три вкладки: index.html (разметка), style.css (стили, если есть) и script.js (ваш код). Нажмите ▶ Запустить или Ctrl + Enter — ниже появится живая страница, а под ней консоль. Задачи проверяются по тому, что вы вывели через console.log, поэтому оставляйте строки с выводом на месте. Подсказки спрятаны: сначала попробуйте сами.

Одно правило песочницы: ваша разметка стоит в <body> не одна — после неё браузер добавляет служебные <script>. Поэтому мы всегда кладём содержимое в одну обёртку или ищем элементы по селектору, а не считаем детей у body.

01 Что такое DOM

Вы пишете HTML — это обычный текст в файле. Когда браузер открывает страницу, он читает этот текст и строит из него дерево объектов. Это дерево называется DOM — Document Object Model, «объектная модель документа». Каждый тег превращается в объект, у которого есть свойства (текст, классы, размеры) и методы. Именно с этими объектами работает JavaScript.

Аналогия из жизни

HTML-файл — это напечатанное меню в папке. DOM — это накрытый стол в чойхоне, который строится по этому меню. Официант (JavaScript) может поставить на стол ещё одну самбусу, убрать пустую пиалу или поменять чай. Напечатанное меню в папке от этого не меняется. Обновили страницу — стол накрывается заново по меню.

Вот простая страница и дерево, которое из неё получается:

<body>
  <h1>Меню</h1>
  <ul class="menu">
    <li>Самбуса</li>
    <li>Курутоб</li>
  </ul>
</body>
document
Корень всего дерева и «входная дверь» в страницу. Через него вы ищете элементы: document.querySelector(...).
Элемент
Объект, соответствующий тегу: <h1>, <li>, <div>. Именно их мы будем искать, менять, создавать и удалять.
Родитель и дети
<ul> — родитель двух <li>. Два <li> — соседи (siblings).
Текстовый узел
Кусочек текста внутри элемента. Пробелы и переносы строк между тегами — тоже текстовые узлы.

Как посмотреть DOM своими глазами

Откройте любой сайт, нажмите F12 и перейдите на вкладку Elements. Это и есть живой DOM: вы видите дерево, можете кликать по элементам, менять текст двойным щелчком, перетаскивать теги — и страница реагирует сразу. Сам файл при этом не меняется. Выделенный в Elements элемент доступен в консоли как $0.

Ходим по дереву

У каждого элемента есть «стрелки» к соседним узлам. Они пригодятся, когда один элемент найден и нужно добраться до соседей:

СвойствоЧто даёт
el.parentElementродитель
el.childrenвсе дети-элементы (список, у него есть .length)
el.firstElementChild / el.lastElementChildпервый и последний ребёнок
el.nextElementSibling / el.previousElementSiblingследующий и предыдущий сосед
 
<ul class="menu">
  <li>Самбуса</li>
  <li>Курутоб</li>
  <li>Шакароб</li>
</ul>

// body.firstElementChild — первый элемент нашей разметки, то есть <ul>
const menu = document.body.firstElementChild;

console.log(menu.tagName);                      // UL
console.log(menu.children.length);              // 3
console.log(menu.firstElementChild.textContent); // Самбуса
console.log(menu.lastElementChild.textContent);  // Шакароб

const second = menu.children[1];                 // дети лежат как в массиве: 0, 1, 2
console.log(second.textContent);                 // Курутоб
console.log(second.previousElementSibling.textContent); // Самбуса
console.log(second.parentElement.tagName);       // UL

textContent — это текст внутри элемента. Подробнее про него — в третьем разделе, пока просто пользуйтесь.

Частая ошибка: childNodes вместо children

Есть похожее свойство childNodes. Оно возвращает все узлы, включая пробелы и переносы строк между тегами. Поэтому «детей» оказывается больше, чем вы видите глазами. Для работы с элементами используйте children и семейство ...ElementChild, ...ElementSibling.

const box = document.createElement("div");
box.innerHTML = `
  <p>Один</p>
  <p>Два</p>
`;

console.log(box.children.length);    // → 2 — два абзаца
console.log(box.childNodes.length);  // → 5 — два абзаца и три «пустых» текстовых узла

02 Поиск элементов: querySelector

Чтобы что-то изменить на странице, сначала нужно это «что-то» найти. Для поиска в современном JavaScript почти всегда хватает двух методов. Главное: в них вы пишете обычный CSS-селектор — тот же, что в файле стилей. Новый язык учить не нужно.

document.querySelector(селектор)
Возвращает первый подходящий элемент. Если ничего не нашлось — null.
document.querySelectorAll(селектор)
Возвращает список всех подходящих элементов (NodeList). Если ничего нет — пустой список, не null.
<h1 id="title">Чайхона «Сомон»</h1>
<ul class="menu">
  <li class="item">Курутоб</li>
  <li class="item">Оши палав</li>
  <li class="item hot">Шакароб</li>
</ul>

const title = document.querySelector("#title");        // по id
const first = document.querySelector(".item");         // по классу — первый из трёх
const hot = document.querySelector(".item.hot");       // два класса сразу
const all = document.querySelectorAll(".item");        // все три

console.log(title.textContent);   // Чайхона «Сомон»
console.log(first.textContent);   // Курутоб
console.log(hot.textContent);     // Шакароб
console.log(all.length);          // 3
Аналогия из жизни

Вы стоите на Зелёном базаре и говорите: «Найдите мне самую первую палатку с курагой» — это querySelector. А «Покажите все палатки с курагой» — это querySelectorAll. Селектор — это то, как вы описываете палатку: по номеру (#id), по вывеске (.class) или по типу (li).

Какие селекторы можно писать

СелекторЧто находит

".menu li"<li> внутри .menu (на любой глубине)

Совет

Если не уверены, правильный ли селектор, проверьте его в DevTools: на вкладке Elements нажмите Ctrl + F и вставьте селектор. Браузер подсветит найденное и покажет, сколько совпадений.

NodeList: похож на массив, но не массив

querySelectorAll возвращает NodeList. У него есть .length, к элементам можно обратиться по индексу, его можно перебирать через for...of и forEach. Но методов map, filter и reduce у него нет. Если нужны — превращаем в настоящий массив:

const box = document.createElement("div");
box.innerHTML = `<p class="n">10</p><p class="n">20</p><p class="n">30</p>`;

const nodes = box.querySelectorAll(".n");

console.log(nodes.length);         // → 3
console.log(nodes[1].textContent); // → 20

nodes.forEach(p => console.log("p:", p.textContent));   // forEach есть

const numbers = Array.from(nodes).map(p => Number(p.textContent)); // map — только у массива
// то же самое: [...nodes].map(...)
console.log(numbers);              // → [10, 20, 30]

Ищем не по всей странице, а внутри элемента

Метод querySelector есть не только у document, но и у любого элемента. Тогда поиск идёт только внутри него. Это важно, когда на странице много одинаковых карточек и нужно достать цену именно из этой карточки:

<div class="card"><span class="name">Шапка</span> — <span class="price">60</span></div>
<div class="card"><span class="name">Шарф</span> — <span class="price">45</span></div>

const cards = document.querySelectorAll(".card");

for (const card of cards) {
  const name = card.querySelector(".name").textContent;   // ищем только внутри card
  const price = card.querySelector(".price").textContent;
  console.log(name + ": " + price);
}

Есть и старые методы: getElementById("title"), getElementsByClassName, getElementsByTagName. Они работают, и вы встретите их в чужом коде, но querySelector универсальнее — достаточно помнить один способ.

Частая ошибка: элемент не найден (null)

Если querySelector ничего не нашёл, он возвращает null. А у null нет ни textContent, ни других свойств — получаем самую знаменитую ошибку DOM. Причин обычно три: опечатка в селекторе, забытая точка или решётка ("item" вместо ".item"), либо скрипт запустился раньше, чем элемент появился на странице.

const price = document.querySelector(".price"); // на странице такого элемента нет → null
console.log(price);                              // → null
console.log(price.textContent);                  // ✖ TypeError: Cannot read properties of null

Про третью причину: в настоящем проекте подключайте скрипт с атрибутом defer — тогда он выполняется после того, как браузер построил всё дерево. В песочницах урока это уже сделано за вас.

<body>
  <ul id="list"></ul>
  <script src="script.js" defer></script>
</body>
Привычка на всю жизнь

Найденные элементы кладите в переменные один раз в начале скрипта: const list = document.querySelector("#list");. Не ищите один и тот же элемент по десять раз — код станет короче, а браузер быстрее.

03 Меняем содержимое: textContent и innerHTML

Элемент найден. Теперь можно прочитать то, что внутри него, и заменить. Для этого у каждого элемента есть два главных свойства. Они похожи, но делают разное — и разница важна не только для красоты, но и для безопасности.

textContent — только текст

Читает и записывает обычный текст. Любые < и > считаются просто символами, теги не создаются. Быстро и безопасно.

innerHTML — текст и разметка

Читает и записывает HTML-строку. Теги внутри превращаются в настоящие элементы. Мощно, но опасно, если в строке чужой текст.

<h2 id="dish">Загрузка…</h2>
<div id="box">Старое содержимое</div>

const dish = document.querySelector("#dish");
const box = document.querySelector("#box");

dish.textContent = "Оши палав";            // заменили текст
console.log(dish.textContent);              // Оши палав

box.innerHTML = "<b>Цена:</b> 35 сомони";   // тег <b> станет настоящим элементом
console.log(box.children.length);           // 1 — внутри появился <b>
console.log(box.innerHTML);                 // <b>Цена:</b> 35 сомони
console.log(box.textContent);               // Цена: 35 сомони — только текст, без тегов
Аналогия из жизни

Представьте, что вы заказываете торт с надписью. textContent — это когда кондитер пишет на торте ровно то, что вы сказали, даже если вы продиктовали странные значки. innerHTML — когда вы даёте кондитеру инструкцию: «поставь здесь украшение, а вот тут сделай жирную надпись». Он выполнит инструкцию буквально. Если инструкцию написал посторонний человек — он может заставить кондитера сделать что угодно.

Читаем и пишем

  • el.textContent — прочитать весь текст внутри элемента (включая вложенные теги, но без самих тегов).
  • el.textContent = "новый текст" — заменить всё содержимое одним текстом.
  • el.innerHTML — прочитать содержимое вместе с тегами, как строку.
  • el.innerHTML = "<b>жирный</b>" — заменить содержимое, разобрав строку как HTML.

Есть ещё innerText: он учитывает CSS и не показывает скрытый текст. Для обычной работы берите textContent — он проще и предсказуемее.

Почему innerHTML опасен

Допустим, на вашем сайте пользователь пишет комментарий, а вы вставляете его на страницу через innerHTML. Если вместо «Отличный курс!» он напишет специально подготовленный тег <img> со скрытым кодом — браузер создаст этот элемент и выполнит чужой код на страницах других посетителей. Такая атака называется XSS и входит в число самых распространённых в вебе.

Правило безопасности

Всё, что пришло от пользователя, из формы, из адресной строки или от внешнего API, вставляйте через textContent. innerHTML — только для разметки, которую написали вы сами (или ИИ, и вы её проверили). Посмотрите, как выглядит разница:

const comment = "Круто! <b>Пять звёзд</b>";      // представим, что это ввёл пользователь

const safe = document.createElement("div");
safe.textContent = comment;          // текст остался текстом
console.log(safe.children.length);   // → 0 — никаких тегов не появилось

const risky = document.createElement("div");
risky.innerHTML = comment;           // строка разобрана как HTML
console.log(risky.children.length);  // → 1 — появился настоящий тег <b>

Ловушка: += для innerHTML

Запись list.innerHTML += "<li>…</li>" выглядит как «добавить в конец», но на самом деле браузер сносит весь список и собирает заново. Все ранее найденные элементы в ваших переменных теряют связь со страницей.

const list = document.createElement("ul");
list.innerHTML = "<li>Нон</li>";

const first = list.firstElementChild;     // запомнили первый пункт
list.innerHTML += "<li>Чой</li>";         // «добавили» второй

console.log(list.children.length);             // → 2
console.log(first === list.firstElementChild); // → false — это уже другой, новый элемент!
console.log(list.contains(first));             // → false — старый пункт выброшен

В разделе 5 вы узнаете, как добавлять элементы без такого побочного эффекта — через createElement и append.

Собираем список строкой

Если разметку пишете вы сами, а данные безопасные (ваш массив, а не ввод пользователя), удобно собирать HTML шаблонными строками и методами массивов, которые вы уже знаете:

console.log(html);   // → <li>Самбуса</li><li>Курутоб</li><li>Шакароб</li>

04 Классы, стили и атрибуты

Внешний вид элемента почти всегда задаётся в CSS. JavaScript не должен красить страницу сам, его работа — включать и выключать готовые классы. Вы пишете в CSS, как выглядит .hot, а в JS только решаете, когда элементу его выдать. Так код остаётся чистым, а дизайн меняется в одном месте.

Аналогия из жизни

Класс — это форма в Илмхоне: бейдж «преподаватель», «студент», «гость». Бейдж один раз придумали, дизайн утвердили. Охранник (JS) не рисует каждому новый бейдж, а просто выдаёт готовый или забирает. Выдать — add, забрать — remove, поменять на противоположный — toggle.

05 Создаём и удаляем элементы

Пока мы только находили и меняли то, что уже написано в HTML. Но у настоящего сайта, например интернет-магазина, список товаров приходит из данных, и разметки под него заранее никто не пишет. Элементы нужно создавать из кода. Это три шага:

  1. Создали — document.createElement("li"). Элемент появился «на складе»: он существует, но на странице его пока не видно.
  2. Настроили — задали текст, классы, атрибуты: li.textContent = "Самбуса", li.classList.add("item").
  3. Вставили — parent.append(li). Только после этого он появляется на странице.
Аналогия из жизни

Бозор. Продавец достаёт товар из мешка (createElement), вешает ценник (настройка) и только потом выкладывает на прилавок (append). Пока товар в мешке, покупатели его не видят. Самая частая ошибка новичка — сделать два первых шага и забыть про прилавок.

Элемент не копируется, а переезжает

Один и тот же элемент не может быть в двух местах дерева. Если вставить уже существующий элемент в другое место, он переедет, а на старом месте исчезнет. Нужна копия — делайте cloneNode(true).

const a = document.createElement("ul");
const b = document.createElement("ul");

const li = document.createElement("li");

console.log(a.children.length, b.children.length);  // → 0 1

a.append(li.cloneNode(true));        // копия остаётся и там, и там
console.log(a.children.length, b.children.length);  // → 1 1

06 Рендер: из массива в карточки

Теперь соединим всё, что вы знаете. В уроках 6 и 7 вы работали с массивами объектов — каталогами товаров, студентов, заказов. Теперь эти данные можно нарисовать. Слово рендер (render) как раз и означает «из данных построить то, что видно на экране». Схема всегда одна и та же:

  1. Данные — массив объектов: const products = [{ title: "Нон", price: 4 }, …]. Это главный источник правды.
  2. Функция-фабрика createCard(product) — получает один объект и возвращает готовый элемент.
  3. Функция рендера render(items) — очищает контейнер и вставляет в него карточки для всего массива.
  4. Вызов render(products) — страница нарисована. Изменили массив — вызвали render снова.
Аналогия из жизни

Оши палав на свадьбе. Рецепт и список гостей — это данные. Повар — функция-фабрика: на входе рис и мясо, на выходе одна порция. А официант — render: проходит по всему списку гостей, ставит порцию перед каждым. Новый гость пришёл — не нужно менять рецепт, просто ещё одна порция по тому же рецепту.

Разбираем render по частям

items.map(createCard)
map передаёт каждый товар в createCard и собирает возвращённые элементы в новый массив.
...cards
Оператор spread из прошлого урока: «высыпает» массив элементов в аргументы replaceChildren(card1, card2, …).
replaceChildren(…)
Сначала убирает всех старых детей, потом вставляет новых. Поэтому повторный render не дублирует карточки.
replaceChildren()
Без аргументов — просто очищает контейнер. Это и есть «кнопка очистки».
Кнопка пока на «честном слове»

Строка clearBtn.onclick = … — первый взгляд на события. Пока запомните её как «когда нажмут на кнопку — сделай это». Полностью события (addEventListener, объект события, делегирование) мы разберём в следующем уроке. Для домашнего задания этой строки достаточно.

Пустое состояние

Что видит пользователь, если по его фильтру ничего не нашлось? Пустую белую страницу — как будто сайт сломался. Хороший рендер всегда обрабатывает пустой массив:

function render(items) {
  if (items.length === 0) {
    const empty = document.createElement("p");
    empty.className = "empty";
    empty.textContent = "Ничего не найдено";
    catalog.replaceChildren(empty);
    return;                              // ранний выход — как в уроке про функции
  }
  catalog.replaceChildren(...items.map(createCard));
}
Две частые ошибки рендера

1. Вставлять карточки, не очистив контейнер: каждый новый render будет дописывать товары к старым, и список будет расти. Используйте replaceChildren.

2. Создавать элемент вне функции или вне цикла: const card = document.createElement(…) один раз и затем много раз append(card). Элемент один — значит, он будет переезжать, и в итоге на странице окажется одна карточка (помните раздел 5).

Тот же рендер строкой

Короткий вариант с шаблонной строкой тоже допустим, если данные ваши и безопасные. Сравните — результат одинаковый:

function render(items) {
  catalog.innerHTML = items
    .map(p => `<article class="card"><h3>${p.title}</h3><p class="price">${p.price} сомони</p></article>`)
    .join("");
}

Если же title может прийти от пользователя или с чужого сервера — только createElement и textContent.

✓ Шпаргалка урока

  • DOM — живое дерево объектов, которое браузер строит из HTML. JavaScript работает с ним через document. Файл HTML при этом не меняется.
  • Навигация: parentElement, children, firstElementChild, lastElementChild, nextElementSibling, previousElementSibling. childNodes считает ещё и пробелы.
  • Поиск: querySelector(sel) — первый элемент или null; querySelectorAll(sel) — NodeList (для map — Array.from). Искать можно внутри элемента: card.querySelector(".price").
  • Текст и разметка: textContent — безопасный текст; innerHTML — разметка, только для своих данных. Чужой текст — всегда textContent. += для innerHTML ломает старые ссылки.
  • Классы: classList.add / remove / toggle / contains. className = затирает всё. Дизайн — в CSS-классах, а не в el.style.
  • Атрибуты: getAttribute / setAttribute / removeAttribute / hasAttribute; свойства value, disabled, hidden; свои данные — data-* и el.dataset.name (всегда строка).
  • Создание: createElement → настроить → append / prepend / before / after. Удаление — el.remove(), очистка — parent.replaceChildren(), копия — cloneNode(true). Элемент не копируется, а переезжает.
  • Рендер: данные (массив) → createCard(item) возвращает элемент → render(items) делает replaceChildren(...items.map(createCard)). Всегда обрабатывайте пустой массив.
  • С ИИ: ИИ пишет HTML и CSS (BEM, без JS и inline-стилей), вы — логику. Проверяйте имена классов, безопасность вставки и выдуманные методы. Не вставляйте код, который не можете объяснить.
