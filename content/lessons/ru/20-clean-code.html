Чистый код, рефакторинг и деплой

Код пишут один раз, а читают — десятки. Через месяц вы сами не поймёте, что имели в виду под x2, а работодатель на собеседовании открывает ваш репозиторий за 30 секунд. Сегодня учимся наводить в коде порядок так, чтобы он не ломался, а потом выкладываем проекты в интернет — чтобы по ссылке их мог открыть любой человек, от мамы до рекрутёра.

  • Давать имена переменным и функциям, которые не нужно расшифровывать
  • Дробить большие функции, убирать вложенность ранним return, не повторяться (DRY)
  • Выносить «магические числа» в константы и отделять расчёты от отображения
  • Проверять код по чек-листу и рефакторить так, чтобы поведение не менялось
  • Собрать проект командой npm run build и настроить переменные окружения без утечки секретов
  • Задеплоить проект на Vercel и GitHub Pages, а советы ИИ-ревью — разделять на полезные и вредные
Как работать с этой страницей

Код с кнопкой ▶ Запустить — живой: меняйте его и смотрите результат в консоли. Блоки с подписью «Терминал» и конфигурационные файлы запускать нельзя — их вы повторите у себя на компьютере. В задачах на рефакторинг поведение кода менять нельзя: проверка сравнивает вывод, поэтому в каждой такой задаче внизу уже есть строки-тесты. Не трогайте их — они ваша страховка. 01 Имена: код читают чаще, чем пишут

Компьютеру всё равно, как назвать переменную: a, x2 или somoniForOnePlov. Но программу читает не только компьютер — её читаете вы через неделю, ваш напарник по проекту и ИИ-помощник. Хорошее имя избавляет от комментария: из него сразу понятно, что это и зачем.

Придётся расшифровывать

  return x * 11;
}
let flag = false;
Читается как текст 
const daysInWeek = 7;

function convertUsdToSomoni(usd) {
  return usd * 11;

Аналогия из жизни

Представьте кухню в чайхоне, где все банки подписаны «Банка 1», «Банка 2», «Банка 3». Повар-новичок положит в плов не зиру, а красный перец. А теперь банки с надписями «Зира», «Соль», «Барбарис» — ошибиться почти невозможно. Имена переменных — это подписи на банках вашей программы.

02 Маленькие функции и ранний возврат

Правило номер один для функций: одна функция — одна задача. Если вы описываете её словом «и» («считает сумму и применяет скидку и печатает чек»), это три функции. Короткая функция проще читать, называть, проверять и использовать в другом месте.

  • Размер. Ориентир — помещается на один экран, 10–20 строк. Не закон, а сигнал: если пролистываете — пора делить.
  • Параметры. Два–три — нормально. Пять и больше — повод подумать, не стоит ли передать объект.
  • Один уровень детализации. Верхняя функция рассказывает «что происходит» (validate → calc → render), а подробности спрятаны в маленьких функциях.
function processOrder(prices) {
  let sum = 0;
  for (const price of prices) {
    sum += price;
  }
  const discount = sum >= 100 ? sum / 10 : 0;
  console.log("К оплате: " + (sum - discount));
}

processOrder([40, 70, 20]);

function calcSum(prices) {
  let sum = 0;
  for (const price of prices) {
    sum += price;
  }
  return sum;
}

function calcDiscount(sum) {
  return sum >= 100 ? sum / 10 : 0;
}

function processOrder(prices) {
  const sum = calcSum(prices);
  const discount = calcDiscount(sum);
  console.log("К оплате: " + (sum - discount));
}

processOrder([40, 70, 20]);

Ранний возврат (guard clauses)

Когда проверки вкладываются друг в друга, получается «стрелка» из скобок: основная логика уехала вправо на три уровня, а в голове приходится держать все условия сразу. Лекарство — ранний возврат: сначала отсекаем плохие случаи и сразу выходим из функции, а основная логика остаётся на одном уровне.

Стрелка из вложенных if 
function getFare(age, hasCard) {
  if (age >= 0) {
    if (hasCard) {
      if (age < 7) {
        return 0;
      } else {
        return 3;
      }
    } else {
      return 5;
    }
  } else {
    return -1;
  }
}
Ранний возврат — плоско 
function getFare(age, hasCard) {
  if (age < 0) return -1;
  if (!hasCard) return 5;
  if (age < 7) return 0;
  return 3;
}

Обе функции возвращают одно и то же, но вторую читаешь сверху вниз как список правил. Заметили? Слово else пропало: после return оно не нужно, функция уже закончилась.

Аналогия из жизни

Контролёр на входе в метро проверяет билет сразу у турникета и не пускает без него. Представьте, что вас пустили внутрь, довезли до конечной — и только там сообщили, что билета не было. Ранний возврат — это турникет в начале функции.

Частая ошибка: забыли return в «охране»

Если в проверке написать только сообщение, а return забыть — функция продолжит работать с плохими данными.

function divide(a, b) {
  if (b === 0) {
    console.log("Делить на ноль нельзя");   // сообщили, но не вышли!
  }
  return a / b;                             // всё равно делим
}

console.log(divide(10, 0));   // → Infinity, а хотели остановиться

03 DRY и магические числа

DRY — Don't Repeat Yourself, «не повторяйся». Скопировали кусок кода три раза — значит, при любой правке придётся найти и исправить все три копии. Одну забудете — получите баг, который проявляется «иногда». Решение то же, что в уроке про функции: одно место, где написано, и много мест, где вызвано.

console.log("Самбуса: " + 5 + " сомони");
console.log("Курутоб: " + 35 + " сомони");
console.log("Шакароб: " + 15 + " сомони");

function printPriceTag(name, price) {
  console.log(`${name}: ${price} сомони`);
}

const menu = [
  { name: "Самбуса", price: 5 },
  { name: "Курутоб", price: 35 },
  { name: "Шакароб", price: 15 },
];

for (const dish of menu) {
  printPriceTag(dish.name, dish.price);
}
Правило трёх

Повторилось второй раз — потерпите. Повторилось в третий — выносите в функцию или данные. Не абстрагируйтесь слишком рано: два похожих куска кода иногда похожи случайно и завтра будут отличаться. Если «общая» функция обрастает параметрами-флагами (isStudent, isSenior, isSpecial…), вы объединили то, что объединять не стоило.

Магические числа

Магическое число — число (или строка) в коде, смысл которого непонятен без объяснений. Что значит * 11? А >= 300? Через месяц не вспомните сами. Лекарство — именованная константа: вынести значение наверх файла и дать ему имя.

Магия 
function deliveryCost(sum) {
  if (sum >= 300) return 0;
  return 25;
}
Константы объясняют смысл 
const FREE_DELIVERY_FROM = 300; // сомони
const DELIVERY_PRICE = 25;      // сомони

function deliveryCost(sum) {
  if (sum >= FREE_DELIVERY_FROM) return 0;
  return DELIVERY_PRICE;
}
  • Константы пишем ЗАГЛАВНЫМИ_С_ПОДЧЁРКИВАНИЕМ и собираем в начале файла — так видно все «настройки» программы.
  • Единицу измерения — в имя или комментарий: TIMEOUT_MS, FREE_DELIVERY_FROM // сомони.
  • Нужно поменять курс или порог — меняете в одном месте.
  • Не магия: 0, 1, -1, 2 в очевидных местах (i % 2, list.length - 1). Выносить их — перебор.
  • Строки-статусы тоже магия: вместо "paid" в десяти местах заведите const STATUS_PAID = "paid" — опечатка в имени константы поймается сразу, в строке — никогда.
Аналогия из жизни

В бозоре табличка «Курс доллара — 11 сомони» висит одна. Если бы продавец каждому покупателю объявлял курс заново «из головы», то в какой-то момент один сказал бы 11, а другой — 10,5. Константа — это табличка, на которую смотрят все.

04 Логика отдельно от отображения. Комментарии

В каждой программе есть две разные работы: считать (логика: отфильтровать товары, посчитать средний балл) и показывать (отображение: собрать HTML, вывести в консоль). Когда они свалены в одну функцию, её нельзя проверить без браузера, нельзя использовать повторно и страшно менять: тронешь вёрстку — сломаешь математику.

Аналогия из жизни

Повар и официант. Повар готовит блюдо — это логика. Официант красиво подаёт — отображение. Если бы повар сам выходил в зал, а официант бегал на кухню помешивать плов, то смена оформления зала замедлила бы кухню. Пусть каждый занимается своим, а передают друг другу готовое блюдо — данные.

Схема: три роли

  1. Функция-расчёт (getAffordableDishes, calcStats): получает данные, возвращает данные. Не трогает DOM, не печатает, не меняет внешние переменные. Её легко проверить через console.log.
  2. Функция-отображение (renderMenu, formatStats): получает готовые данные, строит строку или элементы. Ничего не считает.
  3. «Склейка» (обработчик события, главная функция): вызывает первую, результат отдаёт второй.

05 Рефакторинг: меняем форму, не поведение

Рефакторинг — это улучшение устройства кода без изменения того, что он делает. Для пользователя ничего не поменялось: те же кнопки, те же цифры. Для вас поменялось всё: код стал понятнее и дальше его легче развивать. Главное слово здесь — «без изменения»: если по пути вы нечаянно изменили поведение, это уже не рефакторинг, а новый баг.

Аналогия из жизни

Уборка на кухне чайхоны во время работы: ножи в один ящик, специи по алфавиту, чистые доски. Посетители продолжают получать плов, но повара стали готовить быстрее и реже ошибаться. Нельзя начать уборку и заодно изменить рецепт плова — иначе непонятно, что именно ухудшило вкус.

Безопасный рабочий цикл

  1. Зафиксируйте поведение. Прежде чем что-то менять, запустите код и запишите, что он выводит для нескольких входов — включая граничные (0, пусто, ровно порог). Это ваши «тесты».
  2. Один маленький шаг: переименовали → запустили → вывод тот же. Вынесли константу → запустили → тот же. Не делайте десять правок подряд.
  3. Порядок шагов от простого к сложному: имена → константы → удалить мусор и мёртвый код → ранний возврат → выделить функции → убрать повторы → разделить логику и вывод.
  4. Сломалось — откатитесь к последнему рабочему состоянию. В Git это одна команда; поэтому после каждого удачного шага делаем коммит (урок 19), например rename vars in cart.js.
  5. Две шляпы. Либо вы рефакторите, либо чините баг/добавляете функцию. Одновременно — нельзя. Нашли баг по пути — запишите и вернитесь к нему отдельным коммитом.

Мини-тесты в одну функцию

Для проверки рефакторинга не нужны специальные инструменты. Достаточно маленькой функции, которая сравнивает ответ с ожидаемым:

function check(name, actual, expected) {
  console.log(`${actual === expected ? "OK  " : "FAIL"} ${name}`);
}

const isAdult = age => age >= 18;

check("18 — взрослый", isAdult(18), true);
check("17 — не взрослый", isAdult(17), false);
check("0 — не взрослый", isAdult(0), false);

Чтобы «чистый» не означало «как мне нравится», у нас общий чек-лист из 12 пунктов — полная печатная версия в конце урока. Пункты 1–8 про код, 9–12 про проект. Сейчас нужны первые восемь:

06 Сборка проекта: npm run build

В уроке 17 вы создали проект на Vite и запускали npm run dev. Это режим разработки: Vite отдаёт файлы «как есть», мгновенно обновляет страницу и добавляет подсказки для разработчика. Для настоящего сайта такой режим не годится — код не сжат, лишний, а сервер работает только у вас на ноутбуке. Для публикации нужна сборка (build).

Аналогия из жизни

Режим разработки — это кухня во время готовки: кастрюли, ножи, очистки на столе. Сборка — готовый обед, красиво упакованный в контейнер навынос. Клиенту нужен контейнер, а не вся кухня. Папка dist — это и есть упакованный «контейнер» вашего сайта.

Что делает сборка

  1. Собирает все ваши модули (import/export) в несколько файлов.
  2. Минифицирует: убирает пробелы, комментарии, сокращает имена переменных. Файл становится в несколько раз меньше — страница грузится быстрее.
  3. Выкидывает неиспользуемое (tree shaking): если вы подключили библиотеку, но пользуетесь одной функцией, лишнее не попадёт на сайт.
  4. Добавляет хеш в имена файлов (index-Ab12Cd34.js): изменили код — имя поменялось, и браузер скачает свежую версию, а не возьмёт старую из кэша.
  5. Кладёт результат в папку dist/ — её и отдают на хостинг.
npm install        # если ещё не ставили зависимости
npm run build      # запускает «vite build», результат — в папке dist/
npm run preview    # локальный сервер для готовой сборки: http://localhost:4173

Что лежит в dist/ после сборки небольшого проекта:

dist/
├── index.html                  ← точка входа, ссылки на файлы из assets/
├── favicon.svg                 ← всё из папки public/ копируется как есть
└── assets/
    ├── index-Ab12Cd34.js       ← весь ваш JavaScript, сжатый
    └── index-Ef56Gh78.css      ← весь CSS, сжатый
Три частые ошибки

1. «В dev работает, а в build — нет». Сборка строже: она не прощает битые импорты и опечатки в путях. Всегда запускайте npm run build до деплоя.
2. Регистр букв в именах файлов. На Windows и macOS import "./Header.js" найдёт файл header.js. Но хостинги работают на Linux, где Header.js и header.js — разные файлы: на вашем компьютере всё хорошо, а на Vercel сборка падает. Пишите имена файлов и импорты в точности одинаково.
3. Открыть dist/index.html двойным кликом. Пути в нём начинаются с /assets/… и из файловой системы не находятся — страница будет пустой. Для проверки есть npm run preview.

Windows и macOS

Команды npm одинаковы везде. На Windows запускайте их в PowerShell, «Терминале» VS Code или Git Bash; на macOS — в «Терминале» или во встроенном терминале VS Code (Ctrl + `). Проверьте, что Node установлен: node -v. Если npm run build пишет «vite: command not found» — вы не в папке проекта или не выполнили npm install.

Папку dist в Git не коммитим

Это «производный» файл: его всегда можно получить командой build. В .gitignore (урок 19) должны быть строки node_modules и dist — в шаблоне Vite они уже есть. Хостинг сам запустит сборку из вашего кода.

07 Переменные окружения и секреты

Адрес API на вашем компьютере — один, в «боевой» версии сайта — другой. Размер страницы, название приложения, ключ к сервису погоды — всё это настройки, которые не нужно зашивать в код. Их выносят в переменные окружения — отдельный файл, который читается при запуске и сборке.

Аналогия из жизни

Рецепт плова один, а количество порций зависит от случая: на семью — килограмм риса, на свадьбу — десять. Вы не переписываете рецепт, а меняете «настройку» в записке на двери кухни. Переменные окружения — такая записка: код один, а значения для каждой среды (ваш ноутбук, сайт в интернете) свои.

Как это работает в Vite

Создайте в корне проекта (рядом с package.json) файл .env:

VITE_API_URL=https://dummyjson.com
VITE_PAGE_SIZE=12
VITE_APP_NAME=Лавка MakeFirstStep
DB_PASSWORD=не-попадёт-в-браузер

В коде читаем через import.meta.env:

export const API_URL = import.meta.env.VITE_API_URL;
export const PAGE_SIZE = Number(import.meta.env.VITE_PAGE_SIZE);   // все значения — строки!

console.log(import.meta.env.DB_PASSWORD);   // undefined: без префикса VITE_ переменная скрыта
console.log(import.meta.env.MODE);          // "development" при dev, "production" при build
console.log(import.meta.env.DEV);           // true только в режиме разработки
  • Префикс VITE_ — единственные переменные, которые Vite отдаёт в браузерный код. Остальные остаются невидимыми.
  • Значения — всегда строки. VITE_PAGE_SIZE=12 даёт "12", а VITE_DEBUG=false — строку "false", которая в условии считается истиной! Преобразуйте сами: Number(...), value === "true".
  • После правки .env перезапустите npm run dev — переменные читаются при старте.
  • Встроенные: import.meta.env.MODE, DEV, PROD, BASE_URL.

Главное правило: в браузере нет секретов

Значения VITE_* при сборке подставляются прямо в JavaScript-файл — любой пользователь откроет DevTools → Sources и прочитает их. Поэтому VITE_ — для публичных настроек (адрес API, название, размер страницы). Платёжные ключи, пароли от баз данных, токены с правом записи в такие переменные класть нельзя: для них нужен собственный сервер или серверные функции — это тема следующего курса.

  2. Заведите .env.example — копию .env с пустыми значениями. Он идёт в Git и подсказывает напарнику, какие переменные нужны: VITE_API_URL=

  4. На хостинге значения вводят в панели (Vercel — Settings → Environment Variables, GitHub — Settings → Secrets and variables), а не в репозитории.
  5. Если ключ случайно попал в коммит — считайте его украденным: немедленно отзовите и выпустите новый в сервисе. Удалить коммит недостаточно: история Git и боты, сканирующие GitHub, уже успели его забрать.

08 Деплой: Vercel и GitHub Pages

Деплой — публикация сайта в интернете, чтобы его открывал любой человек по ссылке. Пока проект лежит у вас на ноутбуке, это упражнение. Когда у него есть ссылка — это портфолио. Мы разберём два бесплатных способа для статических сайтов (а ваши проекты на Vite — именно такие).

Аналогия из жизни

Вы испекли самбусу дома — вкусно, но попробуют только родные. Деплой — открыть лоток на базаре: тот же продукт, но теперь у него есть адрес, и к нему могут прийти все. Хостинг — это место на базаре, а ссылка — номер вашего лотка.

Перед деплоем: короткий чек-лист

  • npm run build проходит без ошибок, npm run preview показывает рабочий сайт.
  • Проект лежит в репозитории на GitHub (урок 19), ветка с рабочим кодом отправлена: git push.
  • В репозитории нет .env.local и секретов; есть .env.example.
  • Регистр имён файлов и импортов совпадает.

Способ 1. Vercel

Vercel сам находит Vite, сам собирает проект и после каждого git push обновляет сайт. Для новичка — самый короткий путь.

  1. Откройте vercel.com и войдите через кнопку Continue with GitHub (тариф Hobby бесплатный для личных проектов).
  2. Нажмите Add New… → Project. Vercel покажет ваши репозитории: найдите нужный и нажмите Import (при первом разе разрешите доступ к репозиториям).
  3. На экране настройки проверьте: Framework Preset — Vite (определяется сам), Build Command — npm run build, Output Directory — dist.
  4. Раскройте Environment Variables и добавьте переменные из вашего .env (например, VITE_API_URL) — по одной: имя и значение. Файл .env Vercel из репозитория не читает.
  5. Нажмите Deploy. Через минуту появится адрес вида название-проекта.vercel.app. Это ваша живая ссылка.
  6. Дальше: каждый git push в основную ветку обновляет сайт, а каждая другая ветка получает отдельный адрес-превью — удобно показывать правки до слияния.
git add .
git commit -m "fix price format"
git push
# Vercel сам запустит npm run build и обновит сайт
Если сайт открылся, но данные не грузятся

Откройте DevTools → Network (урок 19). Запрос уходит на undefined/products? Значит, переменная не добавлена в Vercel или у неё нет префикса VITE_. Добавили переменную после деплоя — этого мало: переменные подставляются при сборке, поэтому откройте Deployments → … → Redeploy.

Способ 2. GitHub Pages

Бесплатный хостинг прямо в репозитории (для публичных репозиториев). Адрес — https://ваш-логин.github.io/имя-репозитория/. Обратите внимание на последнюю часть: сайт живёт не в корне, а в подпапке. Поэтому Vite нужно сказать, откуда брать файлы — настройка base.

import { defineConfig } from "vite";

export default defineConfig({

✓ Шпаргалка урока

  • Имена: переменная — существительное, функция — глагол, булево — is/has/can, константа — UPPER_SNAKE. Без data, temp, x1.

  • Комментарий отвечает «почему», а не «что». Закомментированный код — удалять (Git помнит).
