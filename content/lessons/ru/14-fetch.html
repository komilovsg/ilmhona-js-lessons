01 HTTP: как браузер разговаривает с сервером

Клиент — это ваш браузер (или ваш код в нём). Сервер — компьютер, на котором лежат данные. Они общаются по правилам протокола HTTP: клиент шлёт запрос (request), сервер возвращает ответ (response). Всегда по очереди: сервер сам первым не пишет.

Аналогия из жизни

Вы в кафе у Рудаки заказываете через официанта. Запрос: «Принесите (метод) плов (адрес блюда в меню), без моркови (заголовок с пожеланиями)». Ответ: официант возвращается и сначала говорит статус — «Принёс» (200) или «Такого блюда нет» (404) или «Повар заболел» (500), потом ставит на стол тело ответа — сам плов.

Из чего состоит адрес

Адрес ресурса называется URL. В нём несколько частей, и браузер умеет их разбирать с помощью встроенного класса URL.

const url = new URL("https://jsonplaceholder.typicode.com/todos?userId=1&_limit=3");

console.log(url.protocol);               // https:
console.log(url.hostname);               // jsonplaceholder.typicode.com
console.log(url.pathname);               // /todos
console.log(url.searchParams.get("userId"));   // 1  (всегда строка!)

Запрос и ответ

Запрос состоит из четырёх частей, ответ — из трёх. Запомните эту схему: она нужна, чтобы понимать любую документацию к API.

Запрос (клиент → сервер)

Метод (что делать) · URL (где) · заголовки (служебная информация) · тело (данные, если отправляем).

Ответ (сервер → клиент)

Статус (число: как всё прошло) · заголовки (например, тип данных) · тело (сами данные, чаще всего JSON).

Методы: глагол запроса

Метод говорит серверу, что мы хотим сделать. Для работы с данными есть пять основных. Адрес у них может быть один и тот же — отличается только глагол.

POSTСоздать новую записьОформить новый заказда
PUTЗаменить запись целикомПереписать заказ зановода
PATCHИзменить часть записиПоменять только адрес доставкида

Если метод не указан, браузер использует GET. Сегодня мы почти всё время будем получать данные, а к остальным методам придём в разделе 05.

Коды статуса: число, которое сервер говорит первым

Первая цифра кода — это группа. Если запомнить группы, то 90% кодов вы поймёте без справочника.

Заголовки: служебные записки

Content-Type
Какого типа тело. Для JSON это application/json. Есть и у запроса (что мы отправляем), и у ответа (что получили).
Accept
В запросе: «какой формат ответа я понимаю».
Authorization
В запросе: ключ или токен, подтверждающий, кто вы. Без него закрытые API ответят 401. В этом уроке он не нужен — мы берём открытые API.

JSON: язык, на котором говорят API

Данные по сети ходят как текст. Объекты и массивы превращают в текст формата JSON и обратно: JSON.stringify(объект) → строка, JSON.parse(строка) → объект. Правила строже, чем в JS: ключи и строки только в двойных кавычках, никаких комментариев и запятых в конце.

const student = { name: "Мадина", age: 17, courses: ["JS", "CSS"] };

const text = JSON.stringify(student);
console.log(text);                  // это строка
console.log(typeof text);

const back = JSON.parse(text);
console.log(back.name, back.courses.length);
Частая ошибка

Писать JSON «как в JavaScript»: без кавычек у ключей или с одинарными кавычками. Такой текст JSON.parse не принимает и бросает SyntaxError.

const text = "{ name: 'Мадина' }";    // ✖ ключ без кавычек, строка в одинарных

const student = JSON.parse(text);
console.log(student.name);

02 fetch: первый запрос

fetch(url) — встроенная функция браузера для HTTP-запросов. Подключать ничего не нужно. Она возвращает промис (урок 13), поэтому с ней работают через then или, удобнее, через async / await. Попробуем взять одну задачу из учебного сервера jsonplaceholder — он создан специально, чтобы на нём тренироваться:

async function main() {
  const response = await fetch("https://jsonplaceholder.typicode.com/todos/1");
  const todo = await response.json();

  console.log(todo.title);
  console.log("выполнена?", todo.completed);
}

main();

Строк мало, но здесь есть два await, и это не случайность. Давайте разберёмся, зачем.

  1. fetch(url) отправляет запрос. Промис выполнится, как только придёт начало ответа: статус и заголовки.
  2. await даёт нам объект response — это «конверт»: в нём статус и заголовки, а тело ещё может ехать по сети.
  3. response.json() дочитывает тело и превращает JSON-текст в объект. Это тоже промис — поэтому второй await.
Аналогия из жизни

Вы заказали доставку из пекарни. Сначала курьер звонит: «Заказ принят, еду» — это response со статусом. Потом он поднимается к вам с коробкой — это response.json(). Звонок и коробка приходят в разное время, поэтому ждать приходится дважды.

Что есть у response

response.status
Число — код статуса: 200, 404, 500…
response.ok
true, если статус от 200 до 299. Самая полезная проверка — к ней мы вернёмся в разделе 04.
response.headers
Заголовки ответа. Читаются методом get: response.headers.get("content-type").
response.json()
Прочитать тело как JSON → получим объект или массив.
response.text()
Прочитать тело как обычный текст (удобно, если пришёл не JSON).
async function main() {
  const response = await fetch("https://jsonplaceholder.typicode.com/todos/1");

  console.log("статус:", response.status);
  console.log("ok:", response.ok);
  console.log("тип данных:", response.headers.get("content-type"));
}

main();

То же самое через then

Вариант без async / await тоже встречается в чужом коде — вы должны его узнавать. Смысл тот же, только вложенность другая:

fetch("https://jsonplaceholder.typicode.com/todos/1")
  .then((response) => response.json())
  .then((todo) => {
    console.log("Задача:", todo.title);
  });
Частая ошибка

Забыть await перед fetch или перед response.json(). Тогда в переменной окажется не данные, а промис, и все обращения к полям дадут undefined.

async function main() {
  const response = await fetch("https://jsonplaceholder.typicode.com/todos/1");
  const todo = response.json();     // ✖ забыли await — это промис, а не объект

  console.log(todo.title);          // undefined
}

main();

03 Тело ответа: json(), text() и параметры запроса

Серверы отдают данные двух видов: один объект (/users/1) и список (/users — массив). После response.json() вы получаете обычные объекты и массивы JavaScript, а с ними вы уже умеете работать: map, filter, деструктуризация, ?..

const API = "https://jsonplaceholder.typicode.com";

async function main() {
  const response = await fetch(API + "/users");
  const users = await response.json();

  console.log("Пользователей:", users.length);

  const names = users.slice(0, 3).map((user) => user.name);
  console.log(names.join(", "));
}

main();

Вложенные данные

Реальные ответы почти всегда вложенные: у пользователя есть адрес, у адреса — город. Деструктуризация из урока 7 здесь очень кстати:

async function main() {
  const response = await fetch("https://jsonplaceholder.typicode.com/users/1");
  const { name, email, address: { city } } = await response.json();

  console.log(`${name}, ${city}, ${email}`);
}

main();

Параметры запроса: просим только нужное

Скачивать всё подряд — расточительно. Большинство API понимают параметры после знака ?: фильтры, лимиты, поиск. В jsonplaceholder, например, ?_limit=3 вернёт только три записи, а ?userId=2 — только записи второго пользователя.

async function main() {
  const url = "https://jsonplaceholder.typicode.com/todos?userId=2&_limit=3";
  const todos = await (await fetch(url)).json();

  console.log("Получили:", todos.length);
  console.log("Все от пользователя 2:", todos.every((t) => t.userId === 2));
}

main();

Строка await (await fetch(url)).json() — сжатая запись двух шагов. Читается тяжелее, поэтому пока лучше писать по шагам.

json() или text()?

json() ожидает на входе корректный JSON. Если сервер прислал HTML-страницу с ошибкой или пустой ответ, json() бросит SyntaxError. А text() всегда вернёт текст — его можно показать или записать в лог. Чтобы потренироваться без интернета, мы можем создать «поддельный» ответ: конструктор new Response(текст) делает точно такой же объект, как от настоящего сервера.

async function main() {
  const response = new Response(JSON.stringify({ city: "Душанбе", temp: 21 }));

  const data = await response.json();
  console.log(data.city + ": " + data.temp);
}

main();
Частая ошибка

Тело ответа можно прочитать только один раз. Вызвали text() — потом json() уже не сработает: данные «выпиты». Читайте тело один раз и сохраняйте результат в переменную.

async function main() {
  const response = new Response(JSON.stringify({ city: "Душанбе" }));

  const text = await response.text();   // тело прочитано
  const data = await response.json();   // ✖ читаем второй раз

  console.log(text, data);
}

main();

04 Ошибки: 404 — это не ошибка fetch

Это самое неожиданное место для новичков. У запроса может быть два совершенно разных вида неудач — и fetch относится к ним по-разному.

Аналогия из жизни

Вы едете на маршрутке в Рудаки. Сетевая ошибка — маршрутка сломалась по дороге и вы вообще не доехали (нет интернета, неверный адрес сервера, сервер выключен). Ответ с кодом 404 или 500 — вы доехали, зашли в магазин, а продавец говорит «такого товара нет» или «у нас сегодня закрыто». Вы связались с сервером, он ответил — просто не тем, на что вы рассчитывали.

СитуацияЧто делает fetchКак узнать
Нет сети, сервер недоступен, неверный адресПромис отклоняется (ошибка TypeError)Сработает catch
Сервер ответил 404, 500 и т. п.Промис выполняется успешно!Проверить response.ok или response.status

Посмотрите: запрос несуществующей задачи не бросил ошибку. catch молчит, а ok равно false.

async function main() {
  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/todos/99999");
    console.log("запрос дошёл до сервера");
    console.log("статус:", response.status, "ok:", response.ok);
  } catch (error) {
    console.log("сюда мы не попадём");
  }
}

main();

Правильная схема: проверяем ok и сами бросаем ошибку

Чтобы обе неудачи обрабатывались в одном месте, превращаем «плохой статус» в настоящую ошибку:

async function loadTodo(id) {
  const response = await fetch("https://jsonplaceholder.typicode.com/todos/" + id);

  if (!response.ok) {
    throw new Error("HTTP " + response.status);   // 404 → настоящая ошибка
  }
  return response.json();
}

async function main() {
  for (const id of [1, 99999]) {
    try {
      const todo = await loadTodo(id);
      console.log("Нашли:", todo.title);
    } catch (error) {
      console.log("Ошибка:", error.message);
    }
  }
}

main();

Сетевая ошибка: сервера нет вообще

Когда запрос не смог добраться до сервера, fetch отклоняет промис, и catch получает ошибку типа TypeError. Чтобы сымитировать это, возьмём адрес, которого точно не существует (зона .invalid зарезервирована под «несуществующие» адреса):

async function main() {
  try {
    await fetch("https://no-such-server.invalid/data");
    console.log("не дойдём досюда");
  } catch (error) {
    console.log("Сеть недоступна. Тип ошибки:", error.name);
  }
}

main();

Текст самой ошибки в разных браузерах разный (в Chrome — Failed to fetch, в Safari — Load failed), поэтому полагаться на error.message нельзя. Надёжнее смотреть на error.name или просто показать пользователю свой понятный текст.

Ещё одна причина «Failed to fetch» — CORS

Браузер не даёт страницам читать ответы чужих серверов, если те явно не разрешили (заголовок Access-Control-Allow-Origin). Публичные учебные API разрешают всем, поэтому у нас всё работает. Но когда вы запросите «закрытый» сервер, в консоли появится красное сообщение про CORS, а fetch выдаст ту же сетевую ошибку. Это не баг вашего кода: нужно, чтобы владелец сервера разрешил запросы с вашего сайта. Подробнее разберём в следующих уроках.

Когда тело — не JSON

Третья неприятность: сервер ответил, но в теле не JSON (например, HTML-страница «Сервис временно недоступен»). Тогда response.json() бросит SyntaxError. Проверим на поддельном ответе:

async function main() {
  const response = new Response("<html>Сервис временно недоступен</html>", { status: 503 });

  try {
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.log("Не удалось разобрать JSON. Тип ошибки:", error.name);
  }
}

main();
Частая ошибка

Сразу делать response.json() и надеяться на лучшее. Для ответа 404 с пустым телом ({}) код «сработает» и выдаст undefined вместо данных — а настоящая причина (запись не найдена) останется незамеченной.

05 POST, PUT, DELETE: отправляем данные

Чтобы создать или изменить запись, второй аргумент fetch — объект настроек. В нём три главных ключа: method, headers и body.

О нашем учебном сервере

jsonplaceholder — «притворный» сервер: он принимает POST, PUT и DELETE, отвечает как настоящий, но ничего не сохраняет. Создали пост — а при следующем запросе его нет. Для обучения это идеально: нельзя ничего сломать. Настоящие серверы, конечно, данные запоминают.

async function main() {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ title: "Мой первый пост", body: "Салом, мир!", userId: 1 }),
  });

  const created = await response.json();

  console.log("статус:", response.status);   // 201 — Created
  console.log("id:", created.id);            // сервер присвоил номер
  console.log("заголовок:", created.title);  // и вернул то, что мы отправили
}

main();
  1. method: "POST" — сообщаем серверу, что хотим создать запись.
  2. Content-Type: application/json — предупреждаем: «в теле лежит JSON». Без этого сервер может не понять тело.
  3. JSON.stringify(...) — тело запроса должно быть строкой, объект напрямую отправить нельзя.
  4. В ответ сервер вернёт 201 Created и созданную запись — с новым id.

PUT, PATCH и DELETE

Те же настройки, другой метод. Адрес теперь указывает на конкретную запись: /posts/1.

const API = "https://jsonplaceholder.typicode.com";
const json = { "Content-Type": "application/json" };

async function main() {
  // PUT — заменить запись целиком
  let response = await fetch(API + "/posts/1", {
    method: "PUT",
    headers: json,
    body: JSON.stringify({ title: "Новый заголовок", body: "новый текст", userId: 1 }),
  });
  console.log("PUT:", response.status, (await response.json()).title);

  // PATCH — изменить только одно поле
  response = await fetch(API + "/posts/1", {
    method: "PATCH",
    headers: json,
    body: JSON.stringify({ title: "Только заголовок" }),
  });
  console.log("PATCH:", response.status, (await response.json()).title);

  // DELETE — удалить, тело не нужно
  response = await fetch(API + "/posts/1", { method: "DELETE" });
  console.log("DELETE:", response.status);
}

main();
Частая ошибка

Отправить объект без JSON.stringify и без Content-Type. Браузер превратит объект в строку "[object Object]", и данные пропадут по дороге. Сервер при этом может ответить «успешно» (201) — просто с пустой записью. Всегда проверяйте, что вернул сервер, а не только статус.

console.log("со stringify:", JSON.stringify(data));  // ✔ корректный JSON

06 Собираем свою обёртку api.js

Посмотрите, сколько повторяющегося кода мы уже написали: адрес сервера, проверка ok, заголовки, JSON.stringify, response.json(). В большом проекте запросов десятки. Решение — одна функция-обёртка, которая делает всё это за вас. Это и есть ваш артефакт урока: файл api.js. Строим его по шагам, и на каждом шаге код работает.

Шаг 1. Одна функция вместо копипасты

Выносим адрес сервера в константу и учимся собирать полный адрес из пути.

const BASE_URL = "https://jsonplaceholder.typicode.com";

  return response.json();

async function main() {

main();

Шаг 2. Проверка ok и ошибка со статусом

Добавляем главное: плохой статус становится ошибкой. Заодно кладём код статуса прямо в ошибку — вызывающему коду он пригодится (например, показать «Не найдено» вместо «Ошибка»).

const BASE_URL = "https://jsonplaceholder.typicode.com";

async function request(path) {
  const response = await fetch(BASE_URL + path);

  if (!response.ok) {
    const error = new Error("HTTP " + response.status);
    error.status = response.status;      // запоминаем код на ошибке
    throw error;
  }
  return response.json();
}

async function main() {
  try {
    await request("/todos/99999");
  } catch (error) {
    console.log(error.message, "| статус в ошибке:", error.status);
  }
}

main();

Шаг 3. Поддержка POST и других методов

Принимаем второй аргумент options. Если передали body — сами делаем JSON.stringify и ставим заголовок. Теперь тело всегда отправляется правильно.

const BASE_URL = "https://jsonplaceholder.typicode.com";

async function request(path, { method = "GET", body } = {}) {
  const options = { method, headers: {} };

  if (body !== undefined) {
    options.headers["Content-Type"] = "application/json";
    options.body = JSON.stringify(body);
  }

  const response = await fetch(BASE_URL + path, options);

  if (!response.ok) {
    const error = new Error("HTTP " + response.status);
    error.status = response.status;
    throw error;
  }
  return response.json();
}

async function main() {
  const post = await request("/posts", { method: "POST", body: { title: "Салом", userId: 1 } });
  console.log("создан пост номер", post.id);
}

main();

Запись { method = "GET", body } = {} — это деструктуризация параметра со значениями по умолчанию (урок 7). Благодаря = {} функцию можно вызывать и вовсе без второго аргумента.

Шаг 4. Таймаут: не ждём вечно

Если сервер завис, пользователь будет смотреть на «Загрузка…» до бесконечности. Поэтому добавим ограничение по времени. Для этого у fetch есть «кнопка отмены» — AbortController: вызываем controller.abort(), и запрос прерывается с ошибкой AbortError.

const BASE_URL = "https://jsonplaceholder.typicode.com";

async function request(path, { method = "GET", body, timeout = 8000 } = {}) {
  const options = { method, headers: {} };

  if (body !== undefined) {
    options.headers["Content-Type"] = "application/json";
    options.body = JSON.stringify(body);
  }

  const controller = new AbortController();
  options.signal = controller.signal;
  const timer = setTimeout(() => controller.abort(), timeout);   // через timeout мс — отмена

  try {
    const response = await fetch(BASE_URL + path, options);

    if (!response.ok) {
      const error = new Error("HTTP " + response.status);

Шаг 5. Удобные сокращения и итоговый api.js

Остаётся спрятать вызов request за короткими именами. Объект api с методами get, post, put, del (слово delete в JS занято) — и код в проекте читается как предложение. Параметры запроса принимаем объектом и собираем через URLSearchParams.

const BASE_URL = "https://jsonplaceholder.typicode.com";

async function request(path, { method = "GET", body, timeout = 8000 } = {}) {
  const options = { method, headers: {} };

  if (body !== undefined) {
    options.headers["Content-Type"] = "application/json";
    options.body = JSON.stringify(body);
  }

  const controller = new AbortController();
  options.signal = controller.signal;
  const timer = setTimeout(() => controller.abort(), timeout);

  try {
    const response = await fetch(BASE_URL + path, options);

    if (!response.ok) {
      const error = new Error("HTTP " + response.status);
      error.status = response.status;
      throw error;
    }
    return await response.json();
  } catch (error) {
    if (error.name === "AbortError") {
      throw new Error("сервер не ответил за " + timeout + " мс");
    }
    throw error;
  } finally {
    clearTimeout(timer);
  }
}

const api = {
  get(path, params) {
    const query = params ? "?" + new URLSearchParams(params) : "";
    return request(path + query);
  },
  post: (path, body) => request(path, { method: "POST", body }),
  put: (path, body) => request(path, { method: "PUT", body }),
  del: (path) => request(path, { method: "DELETE" }),
};

async function main() {
  const todos = await api.get("/todos", { userId: 2, _limit: 3 });
  console.log("задач:", todos.length);

  const post = await api.post("/posts", { title: "Салом", userId: 1 });
  console.log("создан пост:", post.id);

  try {
    await api.get("/todos/99999");
  } catch (error) {
    console.log("ошибка:", error.message, error.status);
  }
}

main();
Зачем всё это

function fakeFetch(scenario) {
  switch (scenario) {

    case "notfound": return Promise.resolve(new Response("{}", { status: 404 }));

  }
}

✓ Шпаргалка урока

  • HTTP: клиент шлёт запрос (метод + URL + заголовки + тело), сервер отвечает (статус + заголовки + тело). Данные чаще всего в формате JSON.
  • Методы: GET — получить, POST — создать, PUT — заменить, PATCH — изменить часть, DELETE — удалить.
  • Статусы: 2xx успех (200, 201), 3xx перенаправление, 4xx ошибка клиента (404, 401, 403), 5xx ошибка сервера (500).
  • fetch возвращает промис с response (статус и заголовки). Тело читаем отдельно и один раз: await response.json() или text().
  • 404 и 500 — не ошибка fetch. Проверяйте response.ok и сами бросайте ошибку. Сетевая ошибка (нет сети, неверный сервер) — отклонённый промис, TypeError.
  • Шаблон: try { const r = await fetch(url); if (!r.ok) throw new Error("HTTP " + r.status); const data = await r.json(); … } catch (e) { … } finally { … }
  • POST: fetch(url, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(data) }). Тело — всегда строка.
  • URL и параметры: new URL(…) разбирает адрес, new URLSearchParams(объект) собирает строку запроса.
  • api.js: одна функция request — базовый адрес, заголовки, JSON, проверка ok, таймаут через AbortController; сверху — get / post.
  • С ИИ: сначала сами, потом промпт по формуле. Обёртку от ИИ проверяем на плохих ответах: 404, 500, не-JSON, нет сети, таймаут.
