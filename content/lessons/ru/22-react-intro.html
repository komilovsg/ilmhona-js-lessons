Как работать с этой страницей

Примеры на React открываются в песочнице с превью: вкладка App.jsx с кодом, под ней — готовая страница и консоль. Меняйте код и нажимайте ▶ Запустить (или Ctrl + Enter). React подгружается из интернета, поэтому нужен доступ в сеть. В песочнице один файл — компоненты лежат рядом друг с другом; в настоящем проекте на Vite каждый будет в отдельном файле. 01 Зачем React: где ручной DOM начинает мешать

Всё, что вы делали с экраном до сих пор, — это императивный подход: вы пошагово командуете браузеру. «Найди этот элемент. Создай новый. Запиши в него текст. Вставь сюда». Для карточки с заголовком это выглядит так:

<div id="app"></div>

.card { border: 2px solid #1f6feb; border-radius: 12px; padding: 12px 16px; max-width: 280px; }
.card h2 { margin: 0 0 6px; }

const app = document.querySelector("#app");

const card = document.createElement("div");
card.className = "card";

const title = document.createElement("h2");
title.textContent = "JavaScript с нуля";

const info = document.createElement("p");
info.textContent = "24 урока · 8 недель";

const button = document.createElement("button");
button.textContent = "Записаться";

card.append(title, info, button);
app.append(card);

console.log(app.innerHTML);

Тот же результат на React. Сравните: здесь нет ни одного createElement, ни одного querySelector. Вы пишете то, что хотите увидеть, — функция просто «возвращает» разметку.

export default function App() {
  return (
    <div className="card">
      <h2>JavaScript с нуля</h2>
      <p>24 урока · 8 недель</p>
      <button>Записаться</button>
    </div>
  );
}

// автопроверка: печатает разметку, которую построил React
setTimeout(() => console.log(document.getElementById("root").innerHTML), 100);

.card { border: 2px solid #1f6feb; border-radius: 12px; padding: 12px 16px; max-width: 280px; }
.card h2 { margin: 0 0 6px; }

В консоли обеих песочниц — одна и та же разметка. Разница в том, как вы к ней пришли: в первом случае 12 строк команд, во втором — «картинка» того, что нужно.

Аналогия из жизни

Чойхона. Ручной DOM — это когда вы сами идёте на кухню и говорите повару: «Возьми казан. Налей масло. Положи лук. Через пять минут добавь морковь…» На каждый плов — вся инструкция заново. React — это когда вы говорите официанту: «Плов и чай на двоих». Что именно и в каком порядке делать на кухне — забота заведения. Вы описываете результат (так это называется — декларативный подход), а не шаги.

Четыре боли ручного DOM

1. Разметку не видно
Структура страницы спрятана за десятками createElement и append. Чтобы понять, что получится, нужно мысленно «выполнить» код.
2. Легко забыть обновить
Одни и те же данные показаны в нескольких местах. Поменяли в одном — в другом осталось старое, и экран врёт.
3. Нет «своих тегов»
Карточка курса нужна в десяти местах — приходится писать функции-фабрики и склеивать вручную. Нет единого способа сказать «вот мой блок, используй его как обычный тег».
4. Состояние и экран расходятся
В уроке 11 вы решили это функцией render(), которая перестраивает экран целиком. Работает, но при каждом изменении браузер пересоздаёт всё — и теряются фокус в поле ввода, прокрутка и выделение.

Посмотрите на вторую боль вживую. Цена курса показана в двух местах, а обновлена только в одном:

document.body.innerHTML = `
  <p>Курс: <b id="price-top">500</b> сомони</p>
  <p>Итого: <b id="price-total">500</b> сомони</p>`;

let price = 500;
price = 450; // сделали скидку

document.querySelector("#price-top").textContent = price;
// про #price-total забыли

console.log(document.querySelector("#price-top").textContent);
console.log(document.querySelector("#price-total").textContent);

Вверху 450, в «Итого» всё ещё 500. В маленькой странице это видно сразу, в большом приложении с сотней экранов — нет. React устроен так, что экран всегда считается из данных, и «забыть» обновить место просто нечем.

Что такое React

React — библиотека для построения интерфейсов, её создала компания Meta (бывший Facebook), и сейчас она, пожалуй, самая популярная в мире для сайтов и приложений. Ключевая идея: интерфейс — это функция от данных. Данные поменялись — React сам сравнит «было» и «стало» и изменит в DOM только то, что нужно. Всё остальное (маршруты, серверный рендеринг) подключается отдельно: на следующем уровне курса вы встретите Next.js — это фреймворк на основе React.

React нужен не всегда

Лендинг из пяти блоков и пары кнопок прекрасно живёт на чистом HTML, CSS и JS — и загружается быстрее. React окупается там, где много интерактивных экранов, одни и те же блоки повторяются, а данные часто меняются: личные кабинеты, магазины, дашборды, чаты. Мы учим React не вместо JS, а поверх него: всё, что вы знаете про функции, массивы и объекты, пригодится на каждой строке.

02 Мыслим компонентами

Откройте любой сайт и мысленно обведите рамками «кирпичики»: шапка, меню, карточка товара, кнопка, подвал. Это и есть компоненты. Компонент — функция, которая возвращает кусок интерфейса. Раз это функция, вы уже умеете с ней обращаться: объявить один раз, вызвать сколько нужно.

Аналогия из жизни

Конструктор или набор формочек для самбусы. Одну форму вы сделали один раз — и лепите ею хоть сто штук. Страница сайта — это не одна большая лепёшка, а набор готовых деталей: шапка, список курсов, подвал. Нужно поменять подвал — меняете в одном месте, и он обновится на всех страницах.

Страница — это дерево

Компоненты вкладываются друг в друга, как вложенные коробки. Самая внешняя — App, главный компонент приложения. Внутри неё лежат остальные:

App ├─ Header │ ├─ Logo │ └─ Nav ├─ Courses └─ Footer

Как найти границы компонентов

  • Блок повторяется (карточка курса, пункт меню) — почти всегда это отдельный компонент.
  • У блока своя задача («показать шапку», «показать подвал») — отдельный компонент, как отдельная функция в уроке 5.
  • Файл разросся, и в нём не найти нужное — режем на части.
  • Не дробите до пылинок. Тег <h2> компонентом делать незачем. Хорошее правило: если для блока можно придумать понятное имя, оно получится и у компонента.

Первый компонент

Компонент выглядит так же, как функция из урока 5, только он возвращает не число, а разметку. Два правила: имя начинается с большой буквы и использовать его нужно как тег:

function Header() {
  return (
    <header className="top">
      <h1>Ilmhona</h1>
    </header>
  );
}

function Footer() {
  return <footer>© Ilmhona, Душанбе</footer>;
}

export default function App() {
  return (
    <div className="page">
      <Header />
      <main>Здесь будут курсы</main>
      <Footer />
    </div>
  );
}

// автопроверка: печатает разметку, которую построил React
setTimeout(() => console.log(document.getElementById("root").innerHTML.replaceAll("><", ">\n<")), 100);

.page { border: 2px solid #1f6feb; border-radius: 12px; overflow: hidden; }
.top { background: #1f6feb; color: #fff; padding: 4px 16px; }
main { padding: 16px; }
footer { background: #f3f4f6; padding: 8px 16px; color: #6b7280; }

Обратите внимание на три вещи. <Header /> с большой буквы — это наш компонент: React вызывает функцию Header и подставляет результат. <main> с маленькой — обычный тег HTML. App тоже компонент, просто самый главный. Его мы пишем как export default function App(): именно его песочница (и проект Vite) показывает на странице.

Частая ошибка: имя с маленькой буквы

React различает теги и компоненты по первой букве. <header /> — это тег HTML, а <Header /> — ваша функция. Если назвали компонент header или menu, React не найдёт функцию и нарисует пустой тег (а <menu> — вообще настоящий тег HTML). Ошибки не будет — просто пустота на экране, и это самое неприятное.

03 Создаём проект: Vite + React

В уроке 17 вы создавали проект на Vite с шаблоном vanilla. Для React меняется один параметр — шаблон. Всё остальное вам знакомо: npm, package.json, dev-сервер.

Аналогия из жизни

Шаблон проекта — как типовая планировка квартиры. Можно самому класть кирпичи и тянуть проводку (настраивать сборщик вручную), а можно получить дом «под ключ» с готовой проводкой и водой и сразу заселяться — добавлять свою мебель. Vite даёт именно такой «дом под ключ» для React.

Пошаговая инструкция

  1. Откройте терминал в папке для проектов (без кириллицы и пробелов в пути; не в OneDrive/iCloud). Node.js уже установлен с урока 17 — проверьте: node -v.
  2. Создайте проект. Часть -- --template react говорит Vite: «возьми шаблон React». Двойное -- передаёт опцию дальше, в create-vite (мы уже видели это на уроке 17).
  3. Перейдите в папку и установите зависимости — npm install скачает React и Vite в node_modules.
  4. Запустите сервер разработки и откройте адрес из терминала.
npm create vite@latest my-react-app -- --template react
cd my-react-app
npm install
npm run dev

Если вы запустите npm create vite@latest без опций, мастер задаст вопросы: название проекта, фреймворк (выберите React), вариант (JavaScript). В зависимости от версии он может ещё предложить сразу установить зависимости и запустить сервер — можно согласиться, а можно ответить «нет» и выполнить команды вручную, как выше. После npm run dev вы увидите:

&gt; my-react-app@0.0.0 dev
&gt; vite

  VITE v8.3.4  ready in 210 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose

Откройте http://localhost:5173/: вы увидите стартовую страницу React со счётчиком. Измените что-нибудь в src/App.jsx и сохраните — страница обновится сама, без перезагрузки (HMR из урока 17).

Если что-то пошло не так

«npm: command not found» — Node.js не установлен или терминал нужно перезапустить. Ошибка про версию Node — обновите Node.js до LTS. Страница пустая — откройте DevTools (F12) → Console: там написано, в каком файле ошибка (чаще всего опечатка в JSX). Порт занят — Vite сам выберет 5174 и напишет об этом.

04 JSX: похож на HTML, но не HTML

JSX — это способ писать разметку прямо внутри JavaScript. Браузер JSX не понимает: Vite (а в нашей песочнице — встроенный компилятор) превращает каждый тег в вызов функции. Для вас это значит одно: JSX — это JavaScript, а значит, правила у него строже, чем у HTML.

// вы пишете:
const title = <h1 className="big">Салом</h1>;

// сборщик превращает в обычный JS:
const title = jsx("h1", { className: "big", children: "Салом" });
Аналогия из жизни

HTML — это разговорная речь: можно пропустить слово, поставить запятую как угодно, и всё равно поймут. JSX — официальное заявление: каждый тег закрыт, у документа один заголовок, все слова по форме. Зато заявление можно автоматически проверить. Поэтому JSX сразу ругается на опечатку, а браузер молча «догадывается».

Шесть отличий JSX от HTML

Частая ошибка: незакрытый тег

В HTML <input> и <br> закрывать не нужно. В JSX — нужно, иначе компилятор остановится с ошибкой.

<div>
  <input type="text">     {/* ✖ тег не закрыт */}
  <br>                    {/* ✖ и этот тоже */}
</div>

<div>
  <input type="text" />   {/* ✓ */}
  <br />                  {/* ✓ */}
</div>

4. Один корневой элемент

Компонент — это функция, а функция возвращает одно значение. Поэтому два тега рядом вернуть нельзя: их нужно обернуть. Если лишний <div> не нужен, используют фрагмент — пустые теги <>…</>. Он группирует детей, но в итоговом HTML ничего не добавляет.

// ✖ ошибка: "Adjacent JSX elements must be wrapped in an enclosing tag"
return (
  <h2>Расписание</h2>
  <p>Пн, Ср, Пт — 18:00</p>
);

// ✓ с обёрткой
return (
  <div>
    <h2>Расписание</h2>
    <p>Пн, Ср, Пт — 18:00</p>
  </div>
);

// ✓ с фрагментом: лишнего div в HTML не будет
return (
  <>
    <h2>Расписание</h2>
    <p>Пн, Ср, Пт — 18:00</p>
  </>
);

Круглые скобки после return нужны не React, а JavaScript: если после return перейти на новую строку без скобок, JS решит, что возвращать нечего (return;), и вернёт undefined. Скобки — страховка для многострочной разметки.

5. Фигурные скобки: JavaScript внутри разметки

Всё, что внутри { }, — обычное JS-выражение: переменная, арифметика, вызов функции, тернарный оператор ? :. Результат подставляется в разметку. Скобки можно ставить и в тексте, и в значении атрибута.

export default function App() {
  const student = "Мадина";
  const lessons = 24;
  const hour = 19;

  return (
    <div className="box" title={"Студент " + student}>
      <h2>Салом, {student}!</h2>
      <p>Осталось уроков: {lessons - 22}</p>
      <p>Имя в верхнем регистре: {student.toUpperCase()}</p>
      <p>{hour < 20 ? "Занятия ещё идут" : "Занятия закончились"}</p>
    </div>
  );
}

// автопроверка: печатает разметку, которую построил React
setTimeout(() => console.log(document.getElementById("root").innerHTML.replaceAll("><", ">\n<")), 100);

.box { border: 2px dashed #1f6feb; border-radius: 12px; padding: 4px 16px; }
Можно в {…}
Переменные, числа, строки, арифметика, вызовы функций, ? :, &&, ||, методы строк и массивов.
Нельзя в {…}
Инструкции: if, for, const x = …. Это не выражения. Условие внутри разметки пишем через ? : или &&; а if и переменные — выше, перед return.
Комментарий в JSX
{/* вот так */} — это пустое выражение с комментарием внутри. Обычный // … внутри разметки превратится в текст на странице.

Что React рисует, а что нет

Значения true, false, null и undefined React не показывает вообще — на этом построено условное отображение. Но число 0 показывается, и об этом часто забывают.

export default function App() {
  const isOpen = true;
  const messages = 0;

  return (
    <div>
      <p>true: [{true}]</p>
      <p>null: [{null}]</p>
      <p>0: [{0}]</p>
      <p>{isOpen && "Мы открыты"}</p>
      <p>Новых сообщений: {messages && <b>есть</b>}</p>
    </div>
  );
}

// автопроверка: печатает разметку, которую построил React

В последней строке вы ожидали пустоту, а получили 0: выражение 0 && … равно 0, а ноль React рисует. Безопасный вариант — сделать условие настоящим булевым: messages > 0 && … или тернарный оператор.

6. style — это объект

В HTML стиль — строка. В JSX style принимает объект, значит, фигурные скобки получаются двойными: внешние — «здесь JS», внутренние — сам объект. Свойства пишутся в camelCase (backgroundColor), числа без единиц считаются пикселями.

export default function App() {
  const badge = {
    backgroundColor: "gold",
    padding: 8,
    borderRadius: 8,
    fontWeight: "bold",
  };

  return (
    <div>
      <p style={badge}>Новинка</p>
      <p style={{ color: "crimson", fontSize: 20 }}>Скидка 10%</p>
    </div>
  );
}

// автопроверка: печатает разметку, которую построил React
setTimeout(() => console.log(document.getElementById("root").innerHTML.replaceAll("><", ">\n<")), 100);

Для основного оформления всё равно используйте CSS-классы (className + style.css): style пригодится, когда значение вычисляется из данных (ширина полосы прогресса, цвет по условию).

05 App.jsx: экспорт и импорт компонентов

Пока компоненты лежали в одном файле. В реальном проекте так не делают: один компонент — один файл. Это те же модули из урока 17: файл экспортирует функцию, другой файл её импортирует. Для компонентов принято export default.

Структура проекта с компонентами

src/ ├─ main.jsx ├─ App.jsx собирает страницу из компонентов └─ components/ ├─ Header.jsx export default function Header() ├─ CourseCard.jsx export default function CourseCard() └─ Footer.jsx export default function Footer()
  • Имя файла = имя компонента, с большой буквы: Header.jsx, CourseCard.jsx.
  • Расширение .jsx — признак того, что внутри JSX. Vite требует его для файлов с разметкой.
  • Папка components — просто договорённость, чтобы не сваливать всё в src/.

Как это выглядит в файлах

export default function Header() {
  return (
    <header className="top">
      <h1>Ilmhona</h1>
    </header>
  )
}

export default function Footer() {
  return <footer>© Ilmhona, Душанбе</footer>
}

import Header from './components/Header.jsx'
import Footer from './components/Footer.jsx'

export default function App() {
  return (
    <div className="page">
      <Header />
      <main>Здесь будут курсы</main>
      <Footer />
    </div>

Строка import Header from './components/Header.jsx' читается так: «возьми то, что Header.jsx экспортирует по умолчанию, и назови Header». Путь начинается с ./ (рядом с этим файлом), расширение .jsx пишем целиком — как мы договорились на уроке 17. Не было бы export default — импортировать было бы нечего.

Аналогия из жизни

Кухня большого ресторана. Салаты делает холодный цех, горячее — горячий цех, десерты — кондитерский. Каждый цех работает в своём помещении (файле) и отдаёт готовое блюдо (экспорт). Официант-сборщик (App.jsx) ничего не готовит: он берёт блюда из цехов (импорт) и составляет из них заказ на столе. Перепутать цеха нельзя, а новый повар приходит в конкретный цех, а не на всю кухню сразу.

Именованный экспорт тоже работает

// 1) по умолчанию — один компонент на файл (наш выбор)
export default function Header() { … }
import Header from './components/Header.jsx'

// 2) именованный — можно экспортировать несколько штук из файла
export function Header() { … }
import { Header } from './components/Header.jsx'

Главное — чтобы экспорт и импорт совпали по стилю: у export default импорт без скобок, у именованного — со скобками. В этом курсе компоненты экспортируем по умолчанию.

Три типичные ошибки импорта

1) Забыли export default — ошибка «does not provide an export named 'default'». 2) Импортировали без ./: import Header from 'components/Header.jsx' — Vite ищет такой пакет в node_modules и не находит. 3) Назвали компонент в импорте с маленькой буквы: import header from … — получится тег, а не ваш компонент (см. раздел 02).

06 ИИ-блок: переписываем знакомый JS на React

Лучший способ понять новый подход — взять код, который вы уже понимаете, и сравнить его с версией на React. ИИ здесь — переводчик, а вы — проверяющий. Вы знаете оригинал, значит, сразу видите, где перевод неточен.

Правила курса

1) Сначала 15 минут сами: попробуйте переписать блок на JSX без подсказок — в песочнице или в проекте на Vite. 2) Только потом промпт. 3) Не вставляйте в проект код, который не можете объяснить строчку за строчкой. 4) Результат проверяет запуск, а не уверенный тон ИИ.

Переделай в React

Почему плохо: ИИ не знает, где вы учитесь, какие инструменты у вас есть, и выдаст «всё и сразу» — с состоянием, эффектами и сторонними библиотеками, которых мы ещё не проходили. И вы не получите объяснений.

Задача: вот код на чистом JS: [вставьте блок выше]. Перепиши его как один React-компонент App. Ограничения: только разметка и данные. Без useState, useEffect и обработчиков событий. ✓ Шпаргалка урока

  • Ручной DOM — императив: «найди, создай, вставь, обнови». Много кода, легко забыть обновить место, разметки не видно. React — декларатив: описываем, что должно быть на экране, а React сам меняет DOM.
  • Компонент — функция, которая возвращает JSX. Имя с большой буквы, использование как тег: <Header />. Имя с маленькой буквы — это обычный HTML-тег.
  • Страница = дерево компонентов. Режем по смыслу: повторяющийся блок, блок со своей задачей. Один компонент — один файл.
  • Проект: npm create vite@latest my-app -- --template react → cd my-app → npm install → npm run dev.
  • Цепочка запуска: index.html (<div id="root">) → src/main.jsx (createRoot(…).render(<App />)) → src/App.jsx (главный компонент).
  • JSX ≠ HTML: className, htmlFor, все теги закрыты (<br />, <input />), один корень или фрагмент <>…</>, {выражение}, style={{ backgroundColor: "gold" }}, комментарий {/* … */}.
  • В {…} — только выражения: переменные, арифметика, вызовы, ? :, &&. Не рисуются true, false, null, undefined; 0 рисуется — условие n && … пишите как n > 0 && ….
  • Экспорт и импорт: export default function Header() {…} → import Header from './components/Header.jsx'. Путь с ./, расширение .jsx целиком.
  • StrictMode в режиме разработки вызывает компоненты дважды — console.log в компоненте печатается два раза. В собранном сайте так не бывает.
  • ИИ: сначала сами 15 минут; в промпте — контекст, «без useState и событий», формат «таблица строка → строка». Проверяем: имена, className, один корень, style-объект, лишние библиотеки, запуск.
  • Дальше (урок 23): props — параметры компонента, useState — его память, списки и key.
