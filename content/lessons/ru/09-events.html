01 Что такое событие и addEventListener

Пока вы пишете код сверху вниз, он выполняется один раз и заканчивается. Но пользователь делает что-то позже и непредсказуемо: кликает, нажимает клавишу, вводит текст, прокручивает страницу. Браузер замечает каждое такое действие и создаёт событие — сигнал «что-то произошло». Наша задача — заранее сказать: «если случится вот это событие на вот этом элементе — выполни вот эту функцию».

Аналогия из жизни

Над дверью чойхоны висит колокольчик. Пока никто не входит — тишина, официант занят своими делами. Но стоит открыть дверь — колокольчик звенит, и официант идёт встречать гостя. Вы заранее договорились: «зазвенел — иди к двери». Событие — это звон колокольчика, обработчик — действия официанта, а addEventListener — сама договорённость.

Событие
Сигнал от браузера: click, input, submit, keydown… У каждого события есть тип — строка с названием.
Обработчик
Функция, которая выполнится, когда событие случится. Ещё говорят handler или listener («слушатель»).
Подписка
Связка «элемент + тип события + функция». Делается один раз, а срабатывает сколько угодно раз.

Как выглядит подписка

Посмотрим на живом примере. Мы создаём кнопку, подписываемся на клик и «нажимаем» кнопку из кода двумя вызовами click():

document.body.innerHTML = `<button id="buy">Купить</button>`;
const buy = document.querySelector("#buy");

function onBuy() {
  console.log("Спасибо за покупку!");
}

buy.addEventListener("click", onBuy);
console.log("Обработчик навешен, клика ещё не было");

buy.click();   // программный клик — как будто нажали мышкой
buy.click();

Обратите внимание: обработчик не выполняется в момент addEventListener. Он просто запоминается и ждёт. Каждый клик вызывает его заново.

Главная разница видна, когда обработчиков несколько. Свойство onclick хранит одну функцию — следующее присваивание затирает предыдущее. А addEventListener складывает их в список, и они срабатывают в порядке добавления:

document.body.innerHTML = `<button id="b">Кнопка</button>`;
const b = document.querySelector("#b");

b.onclick = () => console.log("onclick №1");
b.onclick = () => console.log("onclick №2");   // затёр первый!

b.addEventListener("click", () => console.log("слушатель №1"));
b.addEventListener("click", () => console.log("слушатель №2"));

b.click();
Частая ошибка: скобки после имени функции

В addEventListener передают саму функцию, а не результат её вызова. Скобки () вызывают функцию прямо сейчас — и обработчиком становится то, что она вернула (обычно undefined).

document.body.innerHTML = `<button id="b">Кнопка</button>`;
const b = document.querySelector("#b");

function hello() {
  console.log("Салом!");
}

b.addEventListener("click", hello());   // ✖ скобки: «Салом!» выведется сразу, один раз
console.log("Клика ещё не было, а салом уже прозвучал");
b.click();   // а на клик никто не отвечает

Если нужно передать в обработчик свои данные, оборачивайте вызов в стрелочную функцию: b.addEventListener("click", () => hello("Мадина")).

Снять обработчик и сработать один раз

Подписку можно отменить: removeEventListener с теми же параметрами. Поэтому функцию нужно хранить в переменной — анонимную стрелку снять не получится, это будет «другая» функция.

document.body.innerHTML = `<button id="b">Талон</button>`;
const b = document.querySelector("#b");

function takeTicket() {
  console.log("Ваш талон выдан");
  b.removeEventListener("click", takeTicket);   // тот же элемент, тип и функция
}

b.addEventListener("click", takeTicket);
b.click();
b.click();   // тишина — обработчик снят
console.log("Второй клик ничего не сделал");

Для случая «сработать один раз» есть короткий путь — третий аргумент с настройками. Браузер сам снимет обработчик после первого срабатывания:

document.body.innerHTML = `<button id="b">Приз</button>`;
const b = document.querySelector("#b");

b.addEventListener("click", () => console.log("Вы получили приз!"), { once: true });

b.click();
b.click();
b.click();

02 Объект события

Когда браузер вызывает ваш обработчик, он передаёт ему один аргумент — объект события. Обычно его называют event, evt или коротко e. В нём лежит всё, что известно о случившемся: какого оно типа, на каком элементе произошло, где была мышь, какая клавиша нажата.

Аналогия из жизни

Диспетчер маршрутки записывает в журнал: «что случилось (посадка), где (остановка «Шохмансур»), во сколько, кто сел». Объект события — такой же журнальный листок. Хотите узнать подробности — загляните в него.

document.body.innerHTML = `<button id="pay" class="btn">Оплатить</button>`;
const pay = document.querySelector("#pay");

pay.addEventListener("click", (event) => {
  console.log("Тип события:", event.type);
  console.log("Элемент:", event.target.id);
  console.log("Тег:", event.target.tagName);
  console.log("Это Event?", event instanceof Event);
});

pay.click();

Мышь и клавиатура

Как «нажать клавишу» из кода? Создаём событие вручную и отправляем его элементу методом dispatchEvent. Так мы будем делать в задачах — для вашего обработчика это выглядит как настоящее нажатие.

document.body.innerHTML = `<input id="field" placeholder="Введите имя">`;
const field = document.querySelector("#field");

field.addEventListener("keydown", (e) => {
  console.log("Нажата клавиша:", e.key);
});

field.dispatchEvent(new KeyboardEvent("keydown", { key: "Enter" }));
field.dispatchEvent(new KeyboardEvent("keydown", { key: "a" }));

document.body.innerHTML = `<div id="map" style="width:300px;height:200px">Карта</div>`;
const map = document.querySelector("#map");

map.addEventListener("click", (e) => {
  console.log(`Клик в точке (${e.clientX}, ${e.clientY})`);
});

map.dispatchEvent(new MouseEvent("click", { clientX: 120, clientY: 45 }));

target и currentTarget: кто сработал и кто слушает

Это два разных свойства, и путаница между ними — одна из самых частых. Пусть внутри кнопки есть значок <b>. Если щёлкнуть по значку, то:

target
Самый глубокий элемент, по которому реально щёлкнули: значок <b>.
currentTarget
Элемент, у которого вызван обработчик: кнопка. Всегда тот, на ком вы написали addEventListener.
document.body.innerHTML = `<button id="cart"><b id="icon">🛒</b> Корзина</button>`;
const cart = document.querySelector("#cart");
const icon = document.querySelector("#icon");

cart.addEventListener("click", (e) => {
  console.log("target:", e.target.tagName);
  console.log("currentTarget:", e.currentTarget.tagName);
});

icon.click();   // щёлкнули по значку внутри кнопки
cart.click();   // щёлкнули по самой кнопке

Пока элемент один, они совпадают. Но как только внутри есть вложенные элементы, target может оказаться «глубже». Это важно: в разделе 06 мы построим на этом целую технику.

А что такое this?

В обычной функции-обработчике this тоже указывает на элемент, на котором висит обработчик — то же, что currentTarget. В стрелочной функции this другой. Чтобы не гадать, всегда используйте event.currentTarget — он работает везде одинаково.

Частая ошибка: свойство не из того события

Набор свойств зависит от типа события. У клика нет клавиши, у нажатия клавиши нет координат мыши. JavaScript не ругается — он просто вернёт undefined, и вы потратите полчаса на поиск «бага».

document.body.innerHTML = `<button id="b">Кнопка</button>`;
const b = document.querySelector("#b");

b.addEventListener("click", (e) => {
  console.log(e.key);        // undefined — клавиши у клика нет
  console.log(e.clientX);    // а координаты есть (0, потому что клик программный)
});
b.click();

Если сомневаетесь, какие свойства есть у события, выведите весь объект: console.log(e) — и посмотрите в DevTools.

04 Действие по умолчанию: preventDefault

У многих событий у браузера есть своё действие по умолчанию. Оно выполнится после ваших обработчиков, если его не остановить:

  • клик по ссылке <a href> — переход на другую страницу;
  • отправка формы — перезагрузка страницы с данными;
  • клик правой кнопкой — контекстное меню;
  • Ctrl + S — окно «Сохранить страницу»;
  • пробел на странице — прокрутка вниз.

Метод event.preventDefault() говорит браузеру: «Не надо, дальше я сам». Ваш код при этом продолжает работать как обычно.

Аналогия из жизни

Вы подходите к турникету на станции, а контролёр говорит: «Стойте, сначала покажите билет». Вы собирались пройти (действие по умолчанию), но вас остановили — и теперь решаете, пустить ли. preventDefault — это поднятая рука контролёра: проход отменён, но всё остальное в зале идёт своим чередом.

document.body.innerHTML = `<a id="promo" href="https://example.com/promo">Акция недели</a>`;
const promo = document.querySelector("#promo");

promo.addEventListener("click", (e) => {
  e.preventDefault();                       // остаёмся на странице
  console.log("Переход отменён:", e.defaultPrevented);
});

promo.click();

Главный случай: форма

Отправка формы по умолчанию перезагружает страницу: всё, что JavaScript успел нарисовать, исчезает. Поэтому почти любая форма на современном сайте обрабатывается так: слушаем submit у формы (не click у кнопки!), делаем preventDefault() и работаем с данными сами.

Почему именно submit, а не клик по кнопке? Форму можно отправить клавишей Enter в поле — клика по кнопке при этом не будет, а submit сработает всегда. В наших задачах форму «отправляет» код: он вручную запускает событие submit командой form.dispatchEvent(new Event("submit", { cancelable: true })). Обработчик не заметит разницы, а страница при этом не перезагрузится.

document.body.innerHTML = `
  <form id="order">
    <input id="who" value="Мадина">
    <button>Заказать</button>
  </form>`;
const order = document.querySelector("#order");
const who = document.querySelector("#who");

order.addEventListener("submit", (e) => {
  e.preventDefault();   // без этой строки страница бы перезагрузилась
  console.log("Заказ для:", who.value);
});

order.dispatchEvent(new Event("submit", { cancelable: true }));
who.value = "Фарход";
order.dispatchEvent(new Event("submit", { cancelable: true }));

Частая ошибка: preventDefault «не сработал»

Две типичные причины. Первая — вы повесили обработчик на click кнопки, а форму отправляют ещё и клавишей Enter: слушайте submit. Вторая — preventDefault вызван не во всех ветках: например, внутри if, а при ошибке валидации раньше сработал return. Сначала отмените действие, потом проверяйте.

  console.log("Отправка", i.value);

05 Всплытие и перехват

Что произойдёт, если кнопка лежит внутри карточки, а карточка — внутри списка, и на каждом из них висит свой обработчик клика? Сработают все три — и в очень определённом порядке. Событие не «застревает» на элементе, по которому кликнули: оно путешествует по цепочке родителей.

Аналогия из жизни

Пузырёк воздуха в стакане чая всплывает со дна к поверхности и проходит все слои. Клик по кнопке «всплывает» так же: сначала сообщает о себе кнопке, потом карточке, потом списку, потом body, document. А ещё это похоже на офис в Душанбе: сотрудник сообщает новость начальнику отдела, тот — директору, тот — владельцу.

  1. Погружение (capturing). Событие спускается от document к цели. Обработчики здесь срабатывают только если вы специально попросили: { capture: true }. Нужно редко.
  2. Цель (target). Событие доходит до элемента, по которому кликнули.
  3. Всплытие (bubbling). Событие поднимается обратно вверх до самого document. На этой фазе работают все обычные обработчики.
document.body.innerHTML = `
  <ul id="list">
    <li id="card"><button id="btn">В корзину</button></li>
  </ul>`;

for (const id of ["btn", "card", "list"]) {
  document.getElementById(id).addEventListener("click", (e) => {
    console.log(`сработал ${e.currentTarget.id}, а кликнули по ${e.target.id}`);
  });
}

document.getElementById("btn").click();

stopPropagation: оборвать путь

event.stopPropagation() прекращает всплытие: родители событие не получат. Выглядит соблазнительно, но используйте осторожно. Остановленное событие перестанет доходить и до чужого кода — например, до счётчика аналитики на document, и вы будете долго искать, почему он «пропускает» клики. Лучше обычно проверить в обработчике родителя, куда именно кликнули: event.target === event.currentTarget.

Перехват: { capture: true }

Если третьим аргументом передать true или { capture: true }, обработчик сработает на фазе погружения — раньше, чем у самой цели. Так можно «встретить» событие до того, как оно дойдёт вниз.

document.body.innerHTML = `<div id="wrap"><button id="btn">Кнопка</button></div>`;
const wrap = document.querySelector("#wrap");
const btn = document.querySelector("#btn");

wrap.addEventListener("click", () => console.log("wrap: всплытие"));
wrap.addEventListener("click", () => console.log("wrap: перехват"), { capture: true });
btn.addEventListener("click", () => console.log("button: цель"));

btn.click();

Порядок: сначала перехват у wrap (спуск вниз), потом сама кнопка, потом всплытие у wrap.

06 Делегирование событий

Допустим, у вас список из 50 дел, и у каждого — кнопка «Удалить». Первая мысль: пройти циклом и повесить обработчик на каждую кнопку. Это работает, но есть три проблемы:

  • Много обработчиков. 50 кнопок — 50 слушателей в памяти. А если строк 5000?
  • Новые элементы «глухие». Пользователь добавил дело — у новой кнопки обработчика нет, потому что цикл отработал раньше.
  • Лишняя работа. Каждый элемент нужно подписывать и, при удалении, отписывать.

Решение использует всплытие из прошлого раздела. Клик по любой кнопке всё равно всплывёт до общего родителя — списка. Значит, достаточно одного обработчика на родителе: он узнаёт, кто именно был целью, и решает, что делать. Это называется делегированием — родитель принимает события «по доверенности» за всех детей.

Аналогия из жизни

В Ilmhona нет охранника у двери каждой аудитории — есть один администратор на ресепшене. Все вопросы идут к нему: «Где аудитория 3?», «Кто сегодня ведёт?». Когда открывают новую аудиторию, нанимать нового охранника не нужно — администратор уже в курсе. Так и с делегированием: один «администратор» (родитель) обслуживает всех, в том числе тех, кто появится позже.

Два подхода рядом

Обработчик на каждый элемент 
for (const btn of list.querySelectorAll("button")) {
  btn.addEventListener("click", remove);
}
// новые кнопки — без обработчика
Один на родителе 
list.addEventListener("click", (event) => {
  const btn = event.target.closest("button");
  if (!btn) return;
  remove(btn);
});
// работает и для будущих кнопок

Новый инструмент: closest

Проблема: event.target — это самый глубокий элемент, по которому кликнули. Если в кнопке лежит значок <span>, целью будет значок, а не кнопка. Нужно «подняться» от цели к нужному элементу. Для этого есть метод element.closest(selector): он проверяет сам элемент, затем родителя, затем родителя родителя — и возвращает первый подходящий под CSS-селектор. Если такого нет — null.

document.body.innerHTML = `
  <ul id="list">
    <li class="item"><button class="del"><span class="icon">✕</span></button></li>
  </ul>`;
const icon = document.querySelector(".icon");

console.log(icon.closest("button").className);   // del — поднялись на 1 уровень
console.log(icon.closest("li").className);       // item — на 2 уровня
console.log(icon.closest(".icon") === icon);     // true — сначала проверяется сам элемент
console.log(icon.closest("table"));              // null — такого предка нет

Ещё один инструмент: data-атрибуты

Как узнать, какую именно кнопку нажали — «удалить» или «в избранное»? И в какой строке? Не по тексту же кнопки угадывать. Для таких меток в HTML есть атрибуты data-*: вы сами придумываете имя, а в JS читаете через element.dataset.

document.body.innerHTML = `<li data-id="42" data-user-name="Мадина"><button data-action="remove">✕</button></li>`;
const li = document.querySelector("li");
const btn = document.querySelector("button");

console.log(li.dataset.id);          // "42" — всегда строка!
console.log(li.dataset.userName);    // data-user-name → userName (camelCase)
console.log(btn.dataset.action);     // "remove"
console.log(Number(li.dataset.id) + 1);   // 43 — число делаем сами

Шаблон делегирования

  1. Один обработчик на общего родителя — список, таблицу, меню.
  2. Найдите нужный элемент: const btn = event.target.closest("button[data-action]");
  3. Ничего не нашли — выходим: if (!btn) return; (клик мимо кнопок).
  4. Проверьте, что кнопка внутри вашего списка: if (!list.contains(btn)) return; Нужна, когда списки вложены друг в друга.
  5. Поднимитесь к строке: const li = btn.closest("li");
  6. Решайте по dataset: if (btn.dataset.action === "remove") li.remove();
document.body.innerHTML = `
  <ul id="list">
    <li data-id="1">Нон <button data-action="remove"><span>✕</span></button></li>
    <li data-id="2">Чой <button data-action="remove"><span>✕</span></button></li>
  </ul>`;
const list = document.querySelector("#list");

list.addEventListener("click", (event) => {
  const btn = event.target.closest("button[data-action]");
  if (!btn || !list.contains(btn)) return;
  const li = btn.closest("li");
  if (btn.dataset.action === "remove") {
    console.log("Удаляю №" + li.dataset.id);
    li.remove();
  }
});

list.querySelector("span").click();   // кликнули по значку внутри кнопки — работает!
console.log("Осталось:", list.children.length);

// добавим новый пункт позже — обработчик не нужен
const newLi = document.createElement("li");
newLi.dataset.id = 3;
newLi.innerHTML = `Лагман <button data-action="remove"><span>✕</span></button>`;
list.append(newLi);
newLi.querySelector("button").click();
console.log("Осталось:", list.children.length);

1. Используют event.target вместо closest. Клик по значку внутри кнопки даёт цель-значок — и проверка target.tagName === "BUTTON" не срабатывает.

07 ИИ-блок: как описать баг

«Кнопка не работает» — самая частая фраза начинающих программистов. И самая бесполезная: ни человек, ни ИИ не поймут, что именно сломалось. События — отличная тренировка, потому что баги в них всегда одного типа: «ожидал, что при клике будет X, а происходит Y (или ничего)». Научитесь описывать такой баг — и получите точный ответ от ИИ, а ещё чаще найдёте причину сами, пока пишете описание.

Правила курса про ИИ — напоминаем

1) Сначала 15 минут пробуете сами. 2) Не вставляете код, который не можете объяснить строчка за строчкой — на проверке ДЗ преподаватель вправе спросить про любую строку. 3) В промпте всегда: контекст → задача → ограничения → формат ответа → проверка.

Шпаргалка урока

  • Событие — сигнал от браузера. Обработчик — функция, которую мы передаём (без скобок!): el.addEventListener("click", handler).
  • Обработчиков может быть много, они срабатывают в порядке добавления. Снять: removeEventListener (нужна та же функция). Один раз: { once: true }. Свойство onclick хранит только один обработчик — не используем.
  • Обработчик получает event: type, target (где случилось), currentTarget (где висит обработчик), key, clientX/Y, target.value.
  • Частые события: click, input (каждая буква), change (значение зафиксировано), keydown, submit, DOMContentLoaded. У флажка читаем checked, у поля и списка — value (строка).
  • Из кода: el.click(), el.dispatchEvent(new Event("input", { bubbles: true })), form.dispatchEvent(new Event("submit", { cancelable: true })). Ручные события по умолчанию не всплывают.
  • event.preventDefault() отменяет действие браузера: переход по ссылке, перезагрузку при submit, Ctrl + S. Формы слушаем по submit, а не по клику на кнопку.
  • Всплытие: событие идёт от цели вверх по родителям (button → li → ul → body). target не меняется, currentTarget меняется. Погружение — { capture: true }, нужно редко.
  • stopPropagation() прерывает всплытие — используйте осторожно; чаще достаточно проверить event.target === event.currentTarget.
  • Делегирование: один обработчик на родителе + event.target.closest("селектор") + if (!el) return. Работает для элементов, добавленных позже. Метки в HTML — data-action, data-id, читаем el.dataset.action.
  • Не всплывают: focus, blur, mouseenter, mouseleave — у родителя слушайте focusin, focusout, mouseover, mouseout.
  • Пользовательский текст в DOM — через textContent, не через innerHTML.
  • С ИИ: баг-репорт = ожидал / получил (ошибка дословно) / минимальный код (до 20 строк) / что пробовал / формат ответа. Проверяйте гипотезы по одной.
