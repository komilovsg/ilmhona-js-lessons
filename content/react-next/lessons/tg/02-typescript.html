TypeScript: аз JavaScript ба навъҳо

Дар охири дарс шумо навъҳои TypeScript-ро мехонед ва менависед: маълумоти тарабхона, таом ва сабадро тавсиф мекунед, қиматҳоро бо рӯйхати вариантҳо маҳдуд месозед, бо null ва undefined дуруст муносибат мекунед, функсияҳо, props, рӯйдодҳо ва useState-ро навъбандӣ менамоед. Дар лоиҳаи «Дастархон» файлҳои types.ts, data.ts ва панҷ компоненти навъбандишуда пайдо мешаванд, ва барои ҳар хатои сурхи компилятор нақша хоҳед дошт: хондан, фаҳмидан, бе any ислоҳ кардан.

  • Фаҳмонед, ки TypeScript чиро мегирад, ки JavaScript намегирад ва чаро навъҳо ҳангоми ҷамъбаст нопадид мешаванд
  • Маълумотро тавассути type ва interface тавсиф кунед, майдонҳоро ихтиёрӣ ва «танҳо барои хондан» гардонед
  • Қиматҳоро бо union- ва literal-навъҳо маҳдуд кунед, навъро бо санҷиш танг намоед ва аз as const навъ ҳосил кунед
  • Бо null ва undefined бехатар кор кунед (?., ??, санҷиш) ва функсияҳоро навъбандӣ намоед
  • Props, children, коркунандаҳои рӯйдодҳо ва useState-ро дар компоненти React навъбандӣ кунед
  • Хатоҳои маъмули компиляторро ислоҳ кунед ва аз ЗС хоҳед, ки хаторо шарҳ диҳад, на «ба ҳар қиммат ислоҳ кунад»
Ин дарсро чӣ тавр гузаштан лозим аст

Лозим аст: лоиҳаи «Дастархон» аз дарси 1 (онро дар Cursor ё VS Code кушоед), терминал ва тақрибан 3,5 соат. Назарияро (бахшҳои 1–8) қисм-қисм хонед. Блокҳои заминаи торик дар худи саҳифа иҷро мешаванд: навъҳоро дар онҳо компилятори ҳақиқии TypeScript месанҷад, барои ҳамин хатоҳоро фавран бо рақами сатр ва код мебинед. Бахши 9 — «озмоишгоҳ»: 15 хатои маъмули компилятор, ки шумо ислоҳ мекунед. Бахши 10 — амалиёт дар лоиҳа дар компютери шумо, бахши 11 — вазифаи хонагӣ.

Фарз мешавад, ки шумо JavaScript ва асосҳои React-ро медонед: JSX, компонентҳо, props, useState. Дар ин ҷо шумо ба он чизе, ки аллакай медонед, навъҳо илова мекунед. Generics-ро (қавсҳои кунҷдор бо параметри навъ) баъдтар дар курс мефаҳмем, ҳоло танҳо дар ду навишти тайёр вомехӯред: useState<…> ва ChangeEvent<…>. Онҳоро ҳамчун қолаби тайёр хонед. Навъҳои ёрирасон (Partial, Pick ва дигарон) низ баъдтар меоянд, дар ин дарс онҳо нестанд.

01 Навъҳо барои чӣ лозиманд ва TypeScript чист

JavaScript назорат намекунад, ки шумо ба тағйирёбанда чӣ мегузоред. Сатр, рақам, undefined — барои ӯ фарқ надорад, то даме ки код иҷро нашавад. Хато назди корбар, дар бадтарин лаҳза пайдо мешавад. Блокро иҷро кунед:

const price = "45";          // нарх ҳамчун сатр омад, масалан аз майдони форма
const delivery = 10;
console.log("К оплате:", price + delivery);   // 55 интизор будем

const restaurant = { name: "Navruz" };
console.log(restaurant.adress.toUpperCase()); // хатои имлоӣ дар adress

Сатри аввал ба ҷои 55 адади 4510-ро мебарорад: JavaScript сатрро бо рақам часпонд. Дуюм бо TypeError меафтад, аммо танҳо дар лаҳзаи иҷро. TypeScript — ҳамон JavaScript аст, илова бар он навъҳо: қайдҳо дар бораи он, ки кадом қиматҳо раво ҳастанд. Ӯ кодро бе иҷро хонда, ин ҷойҳоро ҳанӯз дар муҳаррир бо ранги сурх нишон медиҳад.

Акнун ҳамон код бо навъҳо. «Запустить»-ро пахш кунед: хатоҳои компиляторро пеш аз иҷрои код мебинед.

const price: number = "45";
const delivery: number = 10;
console.log("К оплате:", price + delivery);

const restaurant = { name: "Navruz" };
console.log(restaurant.adress);

Компилятор дар бораи ду хато хабар медиҳад: Type 'string' is not assignable to type 'number'. (TS2322) ва Property 'adress' does not exist on type '{ name: string; }'. (TS2339). Онҳоро чунин хонед: «сатрро ба ҷое, ки адад интизор аст, гузоштан мумкин нест» ва «ин объект майдони adress надорад». Матни хатоҳо бо забони англисӣ аст ва ин мушкил нест: дар онҳо ҳамон калимаҳо такрор мешаванд ва тезунав онҳоро якбора мешиносед.

Навъҳо танҳо то иҷро зиндаанд

Браузер TypeScript-ро намефаҳмад. Пеш аз оғоз навъҳо бурида мешаванд ва JavaScript-и оддӣ мемонад. Барои ҳамин навъҳо ба корбар чизе намеандозанд: онҳо ба шумо дар навиштани код кумак мекунанд. Илова бар ин онҳо ҳамчун ҳуҷҷат кор мекунанд: аз рӯи навъи функсия фавран маълум аст, ки ба вай чӣ додан лозим ва вай чӣ бармегардонад.

Ролик бо забони англисӣ, субтитрҳоро фаъол кунед (2 дақиқа): TypeScript чист ва барои чӣ лозим аст. Ролики соли 2022, ғояро шарҳ медиҳад; фармонҳо ва танзимотро аз ин дарс гиред.

Монанд аз ҳаёт

Навъҳо мисли санҷиш дар даромадгоҳи фурудгоҳанд. Дар толори интизорӣ ғавғост, аммо дар роҳи ҳавопаймо аз ҳар кас шиноснома ва чиптаро месанҷанд. Хато дар фурудгоҳ ёфт мешавад, на дар ҳаво. JavaScript бе навъҳо ҳамаро роҳ медиҳад ва мушкилиро вақте мебинад, ки ҳавопаймо аллакай парвоз карда истодааст.

Фаҳмиши нодурусти маъмул

1. «TypeScript забони алоҳида аст ва JavaScript-ро иваз мекунад». Не, ин болосохт аст: ҳар JavaScript аллакай TypeScript-и дуруст аст. 2. «Навъҳо дар браузери корбар санҷида мешаванд». Не, танҳо ҳангоми коркард ва ҷамъбаст. 3. «Агар навъҳо мувофиқ омаданд, хато нест». Навъҳо як синфи хатоҳоро дар бораи шакли маълумот мегиранд, аммо хатоҳои мантиқиро не: нархро ба рақами нодуруст зарб кардан мумкин, натиҷа аз рӯи навъ дуруст, аммо аз рӯи маъно нодуруст мешавад. 4. «Навъҳо кори барномаро суст мекунанд». Ба суръати барнома таъсир надоранд, дар коди ниҳоӣ онҳо нестанд.

02 Навъҳои асосӣ ва хулосаи навъҳо

Навъҳое, ки ҳар рӯз лозиманд: string (сатр), number (ҳар адад, бутун ва каср), boolean (true/false). Навъ баъди ном ва ду нуқта навишта мешавад: const name: string = "Navruz".

Хулосаи навъҳо: аксар вақт навъро навиштан лозим нест

Агар шумо фавран қимат диҳед, TypeScript навъро худаш муайян мекунад. Ин хулосаи навъҳо (type inference) номида мешавад. Дар чунин ҷойҳо навъро дастӣ навиштан — садои зиёдатист.

let city = "Душанбе";    // TypeScript қарор дод: city — string
city = "Худжанд";        // мумкин: боз сатр
city = 5;                // хато: адад ба тағйирёбандаи string

const rating = 4.8;      // number
const isOpen = true;     // boolean
console.log(city, rating, isOpen);

Дар let ва const хулоса каме гуногун аст. let city = "Душанбе" навъи string мегирад, чунки қиматро тағйир додан мумкин аст. Аммо const city = "Душанбе" навъи дақиқи "Душанбе" (литерал) мегирад: қимат ҳеҷ гоҳ тағйир намеёбад. Дар бахши 4 мебинед, ки ин барои чӣ лозим аст.

Кай навъро бо даст менависанд

  • Параметрҳои функсияҳо: TypeScript намедонад, ки шумо чӣ медиҳед, барои ҳамин параметрҳоро ҳамеша бояд тавсиф кард (бахши 6).
  • Маълумоте, ки «аз берун» омадааст: ҷавоби API, майдони форма. Шакли онҳоро худатон тавсиф мекунед (бахши 3).
  • Қиматҳои холӣ: массиви холии [] ва қимати null маълумоти кам доранд, барои ҳамин навъро ошкоро нишон медиҳанд.

Массивҳо

Навъи массив — навъи унсур ва қавсҳои мураббаъ: number[] (массиви рақамҳо), string[] (массиви сатрҳо). Агар ба чунин массив унсури навъи дигар гузоред, хато мешавад. Усулҳои map, filter, find навъи унсурҳоро худашон медонанд: дар prices.map((p) => p * 2) параметри p адад аст, навъбандӣ кардани он лозим нест.

const cuisines: string[] = ["плов", "шашлык"];
cuisines.push("самбуса");       // мумкин

const prices: number[] = [45, 8, 12];
const doubled = prices.map((p) => p * 2);   // p — number, doubled — number[]
console.log(cuisines.length, doubled);
Навъи any: дар курс манъ аст

any маънои «ҳар қимат»-ро дорад: компилятор санҷиши ин тағйирёбандаро қатъ мекунад. Ӯ ҳимояеро, ки барояш TypeScript пайваст кардем, хомӯш менамояд ва кодро «сироят» медиҳад: ҳар чизе, ки аз any ҳисоб шудааст, низ any мешавад. Мо any-ро на дар мисолҳои таълимӣ ва на дар лоиҳа менависем. Агар навъи мувофиқ ёфтан нашавад, ин сабаби пурсидан аст: «ба ин ҷо дар асл чӣ меояд?», на таслим шудан.

Курс бо забони русӣ (майи 2025, 4,4 соат), қисм-қисм тамошо кунед. Барои ин дарс: 23:37–33:54 (навъҳои ибтидоӣ, массивҳо), 1:08:16–1:23:35 (union ва функсияҳо), 1:27:17–1:49:43 (интерфейсҳо ва навъҳо, литералҳо, майдонҳои ихтиёрӣ). enums-ро (41:38) гузаред: дар лоиҳаи мо бо танзими erasableSyntaxOnly манъ аст. Синфҳо, декораторҳо ва Angular дар курси мо лозим нестанд.

Монанд аз ҳаёт

Хулосаи навъҳо — мисли фурӯшандаи ботаҷриба дар бозор. Шумо мол мегузоред ба тарозу ва ӯ худаш мефаҳмад: ин пиёз аст, бо килограмм ҳисоб мекунем. Ҳар молро бо даст навиштан лозим нест. Аммо вақте шумо бо телефон фармоиш медиҳед («чизе бифирист»), бе возеҳ кардан намешавад: бояд гуфт, ки чӣ ва чанд. Параметрҳои функсия — ҳамин гуна фармоиши телефонианд.

03 Объектҳо: type, interface, майдонҳои ихтиёрӣ

Маълумот дар барнома — объектҳоянд: тарабхона, таом, ҷойи сабад. Шакли объектро бо номи навъ тавсиф мекунанд. Ҳамин тавр он як маротиба навишта шуда, дар ҳама ҷо истифода мешавад.

type Restaurant = {
  id: number;
  name: string;
  rating: number;
  open: boolean;
  address?: string;        // ? — майдони ихтиёрӣ
  readonly createdAt: number;   // readonly — баъд аз сохтан тағйир додан мумкин нест
};

const navruz: Restaurant = { id: 1, name: "Navruz", rating: 4.8, open: true, createdAt: 2024 };
console.log(navruz.name, navruz.address);   // address шояд undefined бошад
navruz.rating = 4.9;                        // мумкин
navruz.createdAt = 2025;                    // хато: readonly

Чӣ муҳим аст:

  • Майдони address?: string ихтиёрӣ аст: онро нишон надодан мумкин, навъи он — string | undefined. Ҳангоми хондани чунин майдон бояд ба назар гирифт, ки қимат шояд набошад (бахши 5).
  • readonly тағйир додани майдонро баъд аз сохтан манъ мекунад. Ин ҳимоя аз таҳрири тасодуфист.
  • Майдони зиёдатӣ ё бо хатои имлоӣ дар литерали объект низ хато аст: { name: "A", nmae: "B" }-ро компилятор намегузаронад.
  • Объект бо майдонҳои дарунманда ҳамон тавр тавсиф мешавад: type CartItem = { item: MenuItem; qty: number }.

interface ва type: кадомашро интихоб кунем

Шакли объектро ду роҳ тавсиф кардан мумкин аст: type ва interface. Барои объектҳо онҳо қариб баробаранд:

interface Dish {
  id: number;
  title: string;
  price: number;
}

interface Drink extends Dish {   // Drink ҳамаи майдонҳои Dish-ро мегирад ва худиашро илова мекунад
  volumeMl: number;
}

const tea: Drink = { id: 7, title: "Чай", price: 8, volumeMl: 300 };
console.log(tea.title, tea.volumeMl);

Васеъ кардан& (буриши навъҳо)extends

Муттаҳид кардани эълонҳои ҳамномне (такрор — хато)ҳа (declaration merging)

Қоидаи курс: ҳамеша type. Вай ҳар чизеро, ки барои props ва маълумот лозим аст, ба шумули union, медонад, ва як роҳро дар хотир доштан осонтар аст. interface-ро шумо дар коди бегона ва ҳуҷҷатҳои китобхонаҳо вомехӯред: фаҳмидани он лозим, истифодааш ҳатмӣ нест.

Монанд аз ҳаёт

Навъи объект — мисли варақаи фармоиш дар чойхона: «таом (ҳатмӣ), миқдор (ҳатмӣ), хоҳиш (ихтиёрӣ)». Варақаро нодуруст пур кардан (бе таом, бо «миқдор» аз калимаҳо) пешхизмат қабул намекунад. Аммо readonly — мӯҳри «тасдиқ шуд»: баъди он фармоишро таҳрир кардан мумкин нест.

Хатоҳои маъмул

1. Навиштани name?: string «барои эҳтиёт»: он гоҳ ҳама ҷо бояд санҷид, ки ном ҳаст ё не. Майдонро танҳо вақте ихтиёрӣ кунед, ки маълумот дар ҳақиқат бе он низ мешавад. 2. Шакли объектро дар ҳар файл аз нав тавсиф кардан: навъро як маротиба дар types.ts менависанд ва ворид мекунанд. 3. Дар ҷое нуқтавергул ва дар ҷои дигар вергул гузоштан байни майдонҳо: дар навъҳои объектӣ ҳарду кор мекунад, як тарзро интихоб кунед (дар лоиҳа Prettier ҳамаро ба як шакл меорад). 4. Ҳарфи пешванд дар ном: IRestaurant, TRestaurant — одати кӯҳна, мо оддӣ Restaurant менависем.

04 Union, literal-навъҳо ва as const

Аксар вақт қимат на «сатри ихтиёрӣ», балки яке аз якчанд вариант аст: ҳолати фармоиш, навъи ошпазӣ, андозаи порсия. Барои ин дар TypeScript union (муттаҳидшавӣ) ва literal-навъҳо (қиматҳои дақиқ) ҳаст.

type OrderStatus = "new" | "cooking" | "delivering" | "done";   // танҳо ин 4 сатр

let status: OrderStatus = "new";
status = "cooking";        // мумкин
status = "ready";          // хато: чунин вариант нест

type Id = number | string;  // union аз навъҳо: адад ё сатр
const id: Id = 42;
console.log(status, id);

Чунин навъ аз оддӣ string беҳтар аст: хатои имлоии "cookng" ба хатои компилятор табдил меёбад, на ба хатои хомӯш. Муҳаррир ҳатто ҳангоми навиштан вариантҳоро пешниҳод мекунад.

Танг кардани навъ (narrowing)

Бо қимати union коре кардан мумкин нест, ки ба ҳамаи вариантҳо мувофиқ набошад. Аввал бояд санҷид, ки кадом вариант дар пеш аст. Баъд аз санҷиш TypeScript навъро дар дохили шоха «танг мекунад».

function showPrice(price: number | string): string {
  // price.toFixed(2) дар ин ҷо хато мебуд: string toFixed надорад
  if (typeof price === "string") {
    return price;                  // дар дохили if — ин string аст
  }
  return price.toFixed(2) + " сомони";   // дар ин ҷо number монд
}
console.log(showPrice(45));
console.log(showPrice("по запросу"));

Union бо нишона: «ё ин, ё он»

Вақте вариантҳо — объектҳо бо майдонҳои гуногунанд, ба ҳар кадом майдони умумии нишона бо литерал мегузоранд. Аз рӯи нишона TypeScript мефаҳмад, ки дар пеш кадом вариант аст. Ҳолатҳои боркунии маълумотро ҳамин тавр тавсиф мекунанд (дар дарси 5 ин лозим мешавад):

type LoadState =
  | { status: "loading" }
  | { status: "error"; message: string }
  | { status: "ok"; count: number };

function describe(state: LoadState): string {
  if (state.status === "error") return "Ошибка: " + state.message;   // дар ин ҷо message ҳаст
  if (state.status === "ok") return "Найдено: " + state.count;       // дар ин ҷо count ҳаст
  return "Загрузка…";                                                // loading монд
}
console.log(describe({ status: "ok", count: 3 }));
console.log(describe({ status: "error", message: "нет сети" }));
console.log(describe({ status: "loading" }));

as const: рӯйхати қиматҳо як маротиба

Фарз кунем, ошпазиҳо дар массив нигоҳ дошта мешаванд ва худи ҳамон онҳоро ҳамчун навъ истифода бурдан лозим аст. Рӯйхатро дар ду ҷо такрор кардан хатарнок аст: дар як ҷо илова кардед ва дар дигар фаромӯш кардед. Роҳи ҳал — as const («ин доимист ҳисоб кун»): массив «танҳо барои хондан» мешавад ва унсурҳояш литералҳои дақиқ. Навъро аз қимат ҳосил кардан мумкин аст:

const CUISINES = ["плов", "шашлык", "самбуса"] as const;

// typeof CUISINES — навъи худи массив, [number] — «навъи ҳар унсури он»
type Cuisine = (typeof CUISINES)[number];   // "плов" | "шашлык" | "самбуса"

const favorite: Cuisine = "плов";
const wrong: Cuisine = "суши";              // хато: чунин вариант нест
console.log(favorite, CUISINES.length);

Навишти (typeof CUISINES)[number]-ро ҳоло ҳамчун дастури тайёр хонед: «навъи унсури массив». Ошпазӣ ба массив илова шуд — навъ худаш нав шуд, ва .map аз рӯи CUISINES ҳамон қиматҳоро барои тугмаҳои филтр медиҳад. Дар лоиҳа шумо айнан ҳамин тавр мекунед.

Хатоҳои маъмул

1. Ҳолатро ҳамчун string эълон кардан: хатоҳои имлоӣ гирифта намешаванд. 2. Усули қимати union-ро бе санҷиш даъват кардан: Property 'toFixed' does not exist on type 'string | number'. (TS2339). Навъро бо санҷиш танг кунед. 3. Бо варианти вуҷуднадошта муқоиса кардан: This comparison appears to be unintentional… (TS2367) — эҳтимол, хатои имлоӣ. 4. enum истифода бурдан: дар лоиҳа erasableSyntaxOnly фаъол аст, union аз литералҳо ҳамин корро бе коди зиёдатӣ мекунад.

Монанд аз ҳаёт

Union-и литералҳо — менюи интихоби маҳдуд. Дар чойхона шумо «чойи сиёҳ» ё «чойи сабз»-ро интихоб мекунед, аммо «чойи мирриху» пешхизмат қабул намекунад: чунин банд нест. Танг кардан — мисли саволи пешхизмат «бо лиму мехоҳед?» пеш аз овардани истакон: то ҷавобро надонад, на яке ва на дигареро оварда наметавонад.

05 null, undefined ва қиматҳои ихтиёрӣ

Сабаби аз ҳама маъмули афтидани барномаҳои JavaScript — Cannot read properties of undefined. Қимати «нест» ду хел аст: undefined («муайян нашуд», майдони гузошташуда ё find, ки унсурро наёфт, ҳамин тавр рафтор мекунанд) ва null («ихтиёран холӣ»). Дар реҷаи strict TypeScript онҳоро навъҳои алоҳида ҳисоб мекунад: ба string null гузоштан мумкин нест. Агар «холӣ» имконпазир бошад, онро дар навъ бояд навишт: string | null.

const dishes = [
  { id: 1, title: "Плов", note: "без острого" },
  { id: 2, title: "Чай" },
];

const found = dishes.find((d) => d.id === 2);   // навъ: объект | undefined
// console.log(found.title);    // хато: 'found' is possibly 'undefined'

if (found) {
  console.log(found.title);     // дар дохили if қимат ҳатман ҳаст
}

let selected: string | null = null;   // «ҳоло чизе интихоб нашудааст»
selected = "Navruz";
console.log(selected);

Агар шумо фавран пул мебароред ва нигоҳ намекунед, ки касе пушти растаа ҳаст ё не, нохуш мешавад. Санҷиши if (фурӯшанда) — нигоҳ ба растаа пеш аз баровардани ҳамён аст.

function lineTotal(price: number, qty: number): number {

const double = (n: number) => n * 2;   // тирӣ: натиҷаи number худаш хулоса шуд

  • Параметрҳо бе навъ дар реҷаи strict — хато: Parameter 'price' implicitly has an 'any' type. (TS7006) (дар деструктуризатсия: Binding element 'name' implicitly has an 'any' type. (TS7031)).
  • Даъват бо шумораи нодурусти аргументҳо — Expected 2 arguments, but got 1. (TS2554).
  • Навъи нодурусти аргумент — Argument of type 'string' is not assignable to parameter of type 'number'. (TS2345).
  • Параметрҳои ихтиёриро дар охири рӯйхат мегузоранд.
  • void — «чизеро бармегардонад». Маъмулан барои коркунандаҳо ва колбэкҳо.

Навъи функсия: барои колбэкҳо

Функсияро ба функсияи дигар ё ба компонент додан мумкин аст. Навъи чунин параметр «шакл»-и функсияро тавсиф мекунад: чӣ мегирад ва чӣ бармегардонад. Онро чун тир менависанд: (id: number) => void. Дар React onSelect ва onChange-ро ҳамин тавр тавсиф мекунанд.

type OnPick = (id: number) => void;

function renderButtons(ids: number[], onPick: OnPick): void {
  for (const id of ids) {
    onPick(id);       // ҳар тугмаро «пахш мекунем»
  }
}

renderButtons([1, 2, 3], (id) => console.log("выбран:", id));   // id — number худаш хулоса шуд

Диққат диҳед: дар тири дохили даъват параметри id-ро навъбандӣ кардан лозим нашуд. TypeScript навъро аз OnPick мегирад. Чунин хулосаро шумо дар React пайваста мебинед.

Монанд аз ҳаёт

Навъи функсия — мисли дархости маршрутка: «мусофирро (адад) қабул мекунад, мерасонад, чизеро бармегардонад». Ҳар ронандаи ҳамин хатсайр мувофиқ аст. Агар дар дархост «рақами хатро қабул мекунад» навишта бошад, ва шумо бо сатри «автобус» омада бошед, диспетчер фавран мегӯяд: мувофиқ нест.

07 TypeScript дар React: props, children, рӯйдодҳо, useState

Дар React ҳама чиз ҳамон аст, танҳо навъҳо ба компонентҳо татбиқ мешаванд. Компонент — функсия аст: параметраш объекти props, натиҷааш JSX. Барои ҳамин бояд props-ро навъбандӣ кард.

Props: навъ дар паҳлӯи компонент

import type { Restaurant } from './types'

type RestaurantCardProps = {
  restaurant: Restaurant
  onSelect: (id: number) => void   // колбэк: падар id мегирад

  • Навъи натиҷаи компонентро наменависем: TypeScript худаш хулоса мекунад. Навишти кӯҳнаи React.FC-ро дар коди нав истифода намебаранд.
  • Навъи Restaurant — навъ аст, барои ҳамин он тавассути import type ворид мешавад (дар лоиҳа verbatimModuleSyntax фаъол аст).

children

Ҳар чизе, ки байни тегҳои компонент менависед (<Section>…</Section>), ба prop-и children меояд. Навъи он — ReactNode: «ҳар чизе, ки React тасвир карда метавонад» (сатр, адад, унсур, массиви унсурҳо, null).

Рӯйдодҳо

Коркунандаи рӯйдод навъи худро дорад: барои onChange-и майдони вурудӣ ин ChangeEvent<HTMLInputElement> аст. Дар қавсҳои кунҷдор нишон дода шудааст, ки рӯйдод дар кадом унсур рух додааст (ин дастрасӣ ба event.target.value медиҳад). Агар коркунанда бевосита дар JSX навишта шавад, навъ худаш хулоса мешавад ва навиштани он лозим нест:

import type { ChangeEvent } from 'react'

type SearchBoxProps = {
  value: string
  onChange: (value: string) => void
}

export default function SearchBox({ value, onChange }: SearchBoxProps) {
  // коркунанда, ки ба функсия бароварда шудааст: навъи рӯйдодро худамон менависем
  function handleChange(event: ChangeEvent<HTMLInputElement>) {
    onChange(event.target.value)
  }
  return <input value={value} onChange={handleChange} placeholder="Найти ресторан" />
  // ҳамин мантиқ дар JSX: onChange={(e) => onChange(e.target.value)} — навъи e хулоса шудааст
}

Рӯйдодҳои маъмули дигар: MouseEvent (клик), FormEvent (фиристодани форма), KeyboardEvent. Агар навъро намедонед — коркунандаро бевосита дар JSX нависед ва курсорро ба параметр оред: муҳаррир навъро нишон медиҳад.

useState

Агар қимати ибтидоӣ худаш гӯё бошад, навъ хулоса мешавад: useState(0) — адад, useState('') — сатр. Вақте ҳолат шояд «холӣ» бошад ё қиматҳоро аз рӯйхат қабул кунад, навъро дар қавсҳои кунҷдор нишон медиҳанд: useState<Restaurant | null>(null). Бе қавсҳо TypeScript мешуморид, ки ҳолат ҳамеша null аст, ва ба он тарабхона гузоштанро иҷозат намедод.

const [query, setQuery] = useState('')                         // хулоса шуд: string
const [selected, setSelected] = useState<Restaurant | null>(null)   // «ҳоло интихоб нашудааст»
const [cuisine, setCuisine] = useState<Cuisine | null>(null)         // ошпазӣ аз рӯйхат ё «ҳама»

Ролик бо забони англисӣ, субтитрҳоро фаъол кунед (51 дақиқа, июли 2026). Аз 14:07 тамошо кунед: навъбандии useState, баъд 25:12–36:53: компонентҳо, props ва навъҳои воридшуда, ва 44:49: функсияҳо ҳамчун props. Сатрҳои оид ба React.FC ва «JSX.Element»-ро дар он гузаред: мо бе онҳо менависем.

Хатоҳои маъмул ва матни онҳо

(TS2322). 3. children-ро дар навъи props фаромӯш кардед: Property 'children' does not exist on type 'IntrinsicAttributes & SectionProps'. (TS2322). 4. Сатри майдони вурудиро ба ҷое додед, ки адад интизор аст: Argument of type 'string' is not assignable to parameter of type 'SetStateAction<number>' — қимати event.target.value ҳамеша сатр аст, адад аз он ошкоро сохта мешавад (Number(...)).

Монанд аз ҳаёт

Props — фармоиш дар чойхона, ки аз рӯи варақа тартиб дода шудааст: миз, таом, миқдор. Колбэки onSelect — занг ба пешхизмат: «миз 5 палав интихоб кард». 08 Блоки ЗС: тарҷумони хатоҳои TypeScript

Матнҳои хатоҳои TypeScript аксар вақт дароз ва бо забони англисианд. Ин барои агенти зеҳни сунъӣ кори беҳтарин аст: шарҳ додани гуфтаҳои компилятор. Аммо агент васваса дорад, ки «ба ҳар қиммат ислоҳ кунад»: ӯ any, as, ! ё // @ts-ignore мегузорад ва хато нопадид мешавад. Мушкил мемонад, шумо онро дигар намебинед. Мақсади мо — хаторо фаҳмидан ва ҳалро худамон интихоб кардан.

Қоидаҳои кор бо хатоҳои навъ

1. Аввал шарҳ, баъд ислоҳ: хоҳиш кунед, ки хаторо тарҷума кунад ва сабабро нишон диҳад. 2. Хаторо пурра нусха кунед, бо коди TSxxxx ва роҳ то файл, илова бар ин 10–20 сатри атроф. 3. Ду варианти ҳал ва шарҳи фарқи онҳоро хоҳед. 4. Қуфлзаниро манъ кунед: бе any, as, !, @ts-ignore, бе хомӯш кардани strict. 5. Баъди ислоҳ npm run typecheck-ро иҷро кунед: агент шояд хаторо ба ҷои дигар гузаронида бошад.

Ду дархости ба агентро муқоиса кунед (формула: контекст → вазифа → маҳдудиятҳо → шакли ҷавоб → санҷиш).

исправь ошибки TypeScript в проекте

Ограничения: без any, as, ! и @ts-ignore; не отключай правила в tsconfig. Формат ответа: «что значит ошибка» (2–3 предложения), затем таблица «вариант — что изменить — когда подходит». Проверка: после моего выбора внеси правку и запусти npm run typecheck, покажи вывод целиком.

Дархости хуб ба агент ҳама чизро медиҳад, то шарҳ диҳад: хатои пурра, ҷой, маҳдудиятҳо ва шакли дилхоҳ. Дархости бад интихоби «чӣ тавр компиляторро хомӯш кунем»-ро ба агент мемонад, ва роҳи аз ҳама тез — айнан қуфлзанӣ.

Навъҳоеро, ки агент навиштааст, чӣ тавр санҷем

  1. Қуфлзанӣ. Дар код any, as (ба ҷуз as const), ! баъди қиматҳо, @ts-ignore, @ts-expect-error бе сабаб нест. Санҷиши зуд: grep -rnE "\bany\b|@ts-ignore|@ts-expect-error" src.
  2. Навъҳои аз ҳад васеъ. Барои ҳолат ё ошпазӣ — union аз литералҳо, на string. Барои объектҳо — type-и худӣ, на object ё {}.
  3. Такрори навъҳо. Навъи тарабхона як маротиба дар types.ts тавсиф шудааст. Агар агент нусхаи дуюмро дар компонент сохта бошад — ин сабаби муттаҳид кардан аст.
  4. Майдонҳои ихтиёрӣ. Ҳар ? бо маълумот шарҳ дода мешавад: оё он «барои он ки компилятор шикоят накунад» пайдо нашудааст.
  5. Props. type XxxProps-и алоҳида, children: ReactNode, колбэкҳо бо имзои дақиқ, на Function ҳаст.
  6. Услуби кӯҳна. React.FC, enum, пешванди I дар номҳои навъҳо, propTypes нест.
  7. Санҷиш бо иҷро. npm run typecheck, npm run lint, npm run build бе хато ва ҷадвали холии Console дар браузер.
