Ҳукҳои махсус ва суръати кор

Дар охири дарс «Дастархон» маълумотро тавассути ҳуки худии useFetch<T> бор мекунад, сабадро тавассути useLocalStorage<T> дар браузер нигоҳ медорад (он аз навсозии саҳифа мегузарад) ва бо таъхир тавассути useDebounce<T> ҷустуҷӯ мекунад. Шумо ҷаласаро дар React DevTools Profiler сабт мекунед, аз нав кашидани нолозими феҳристро меёбед, онҳоро бо ёрии memo, useMemo ва useCallback бартараф мекунед ва натиҷаро бо мемоизатсияи худкори React Compiler муқоиса мекунед. Ва шумо мефаҳмед, ки мемоизатсия кай лозим аст ва кай он танҳо кодро мураккаб мекунад.

  • Мантиқи дорои ҳолат ва эффектҳоро ба ҳуки худии useЧтоТо баровардан ва шарҳ додан, ки чаро ҳар даъвати ҳук ҳолати худро мегирад
  • Дженерикҳоро дар сатҳи ҳадди ақал истифода баред: <T> дар функсияҳо ва навъҳо, маҳдудияти extends, баровардани навъ, навъи возеҳ дар қавсҳои кунҷдор
  • useFetch<T>, useLocalStorage<T> ва useDebounce<T>-ро бо вобастагиҳои софдилона, тозакунӣ ва санҷиши маълумот тавассути type guard нависед
  • Ҷаласаро дар React DevTools Profiler сабт кунед, рендерҳои нолозимро ёбед ва ҷавоб диҳед, ки чаро компонент аз нав кашида шуд
  • memo, useMemo ва useCallback-ро танҳо дар ҷое истифода баред, ки таъсири онҳо андоза карда шудааст, ва шарҳ диҳед, ки чаро устувории истинодҳо вайрон мешавад
  • React Compiler-ро дар шохаи алоҳида фаъол кунед, санҷед, ки он кор мекунад, ва натиҷаро бо мемоизатсияи дастӣ муқоиса кунед
Ин дарсро чӣ тавр гузаштан лозим аст

Лозим аст: лоиҳаи dastarkhon баъд аз машқи дарси 5 (тарабхонаҳо аз API-и таълимӣ тавассути fetch меоянд, дар App се эффект), терминал бо ду тиреза (API ва сервери dev), браузер бо васеъкунии React DevTools (онро дар дарси 1 насб карда будед) ва тақрибан 3,5 соат. Бахшҳои 1–7 — назария бо майдончаҳои зинда: коди дар замина торик навишташударо тағйир додан ва иҷро кардан мумкин аст, ва дар вазифаҳо бояд тавре кард, ки натиҷа бо «Натиҷаи интизоршаванда» мувофиқ шавад. Бахши 8 — дар бораи агенти ИИ, бахши 9 — машқ дар лоиҳа, бахши 10 — вазифаи хонагӣ.

Фарз мешавад, ки шумо JavaScript, асосҳои useState, useEffect ва useRef-ро медонед ва инро, ки эффект маълумотро чӣ тавр бор мекунад (дарси 5), модели рендерро аз дарси 3 (компонент — функсияи тоза, компонентҳои фарзанд бо падар якҷоя рендер мешаванд) ва навъҳои union-ро аз дарси 2. Ҳар чизе, ки аз ин зиёд лозим аст, дар ин ҷо шарҳ дода мешавад: дженерикҳо, мемоизатсия ва кор бо Profiler.

01 Ҳуки худӣ: функсияе, ки ҳукҳои дигарро даъват мекунад

Дар дарси 5 шумо эффекти боркунӣ, эффекти тугмаи тез ва эффекти ҳаракати саҳифаро навиштед, ва ҳар се дар App мехобанд. Компонент калон мешавад: ӯ ҳам интерфейсро мекашад, ҳам медонад, ки ба шабака чӣ тавр баромадан лозим, ҳам ба тирезаи браузер обуна мешавад. Лоиҳаи оянда ҳамин боркуниро талаб мекунад, ва шумо эффектро пурра нусха мекунед. Нусхабардории мантиқи дорои ҳолат — сабаби асосии ҳуки худӣ аст.

Ҳуки худӣ (custom hook) — функсияи оддие, ки ҳукҳои дигарро даъват мекунад (useState, useEffect, useRef, ҳукҳои бегона). Дар React барои ин ягон имкони нав нест, шумо танҳо ба мантиқ ном медиҳед ва онро аз компонент берун мебароред. Ҳук ду аломат дорад:

  1. Ном бо use оғоз мешавад (useToggle, useFetch). Ин ороиш нест: аз рӯи префикс линтер мефаҳмад, ки дар дохил ҳукҳо даъват мешаванд, ва ба функсия қоидаҳои ҳукҳоро татбиқ мекунад (дарси 4).
  2. Дар дохил ҳукҳо даъват мешаванд. Функсияи formatPrice(n) бе ҳукҳо — танҳо функсия аст, ба он префикс лозим нест. Аммо useToggle бе як ҳуки ягона дар дохил — хатои тарҳрезӣ аст: онро бо номи дигар номед.

«Пеш» ва «баъд»-ро дар оддитарин мисол муқоиса кунед. Ду гузариш дар як компонент як ҷуфти «ҳолат + функсия»-ро такрор мекунанд:

function Filters() {
  const [openOnly, setOpenOnly] = useState(false)
  const [delivery, setDelivery] = useState(false)

  return (
    <div>
      <button onClick={() => setOpenOnly((v) => !v)}>Открытые: {String(openOnly)}</button>
      <button onClick={() => setDelivery((v) => !v)}>Доставка: {String(delivery)}</button>
    </div>
  )
}

import { useState } from 'react'

export function useToggle(initial = false) {
  const [on, setOn] = useState(initial)

  function toggle() {
    setOn((value) => !value)
  }

  return [on, toggle] as const
}

// в компоненте
const [openOnly, toggleOpenOnly] = useToggle()
const [delivery, toggleDelivery] = useToggle()

Ҳар даъвати ҳук ҳолати худро мегирад

Муҳимтарин чизе, ки дар бораи ҳукҳои худӣ бояд фаҳмид: ҳук код тақсим мекунад, на ҳолатро. Ду сатри useToggle() дар як компонент (ё дар ду компоненти гуногун) ду useState-и мустақил месозанд. Аз дарси 4 дар хотир доред: React ҳолати компонентро ҳамчун рӯйхати «ҷойҳо» аз рӯи тартиби даъвати ҳукҳо нигоҳ медорад. Ҳуки худӣ танҳо ҷойҳои худро ба ин рӯйхат мегузорад. Агар лозим бошад, ки ду компонент як қимати ягонаро бубинанд, ҳолатро ба боло мебаранд (дарси 4) ё ба Context мебароранд (дарси 8), на ин ки дар ҳук пинҳон кунанд.

import { useState } from "react";

function useToggle(initial = false) {
  const [on, setOn] = useState(initial);
  function toggle() {
    setOn((value) => !value);
  }
  return [on, toggle];
}

export default function App() {
  const [a, toggleA] = useToggle(false);
  const [b, toggleB] = useToggle(true);
  return (
    <div>
      <button onClick={toggleA}>A: {String(a)}</button>
      <button onClick={toggleB}>B: {String(b)}</button>
    </div>
  );
}

«A»-ро пахш кунед: танҳо A тағйир меёбад. Ҳар даъват useState-и худро дорад, ва қиматҳои аввалия дар онҳо гуногунанд.

Аз ҳук чиро баргардонидан: кортеж ё объект

Агар ду қиматро бо тартиби «классикӣ» (қимат ва функсия) баргардонед, кортеж ва as const-ро истифода баред: он гоҳ TypeScript навъи дақиқи readonly [boolean, () => void]-ро мебарорад, ва коди даъваткунанда худаш ҳангоми деструктуризатсия ном медиҳад ([openOnly, toggleOpenOnly]), мисли useState. Бе as const навъ массиви (boolean | (() => void))[] мешуд, ва деструктуризатсия union-и бефоидаро медод. Агар қиматҳо се ва зиёдтар бошанд ё табиати гуногун дошта бошанд, объект-ро баргардонед ({ state, retry }): номҳо фавран намоёнанд, тартиб муҳим нест. Худи ҳамин тавр useFetch дар бахши 3 сохта мешавад.

Кай берун бурдан лозим аст ва кай не

  • Берун баред, агар мантиқ ҳолат ё эффект дошта бошад ва дар ду ҷо лозим бошад (ё компонент бе он ба таври назаррас соддатар ва хонотар мешуд).
  • Берун набаред коди «барои эҳтиёт»: ҳуки як даъвати як ҳолат бе эффект — файли зиёдатӣ аст. Се сатри монанд аз абстраксияи пешвақтӣ беҳтар аст.
  • Дар ҳук пинҳон накунед он чиро, ки бояд дар компонент намоён бошад: масалан, JSX. Ҳук маълумот ва функсияҳоро бармегардонад, ва нишонагузориро компонентҳо мекашанд.
  • Аз рӯи маъно ном диҳед, на аз рӯи татбиқ: useDebounce, на useTimeoutState.
Монанд аз ҳаёт

Ҳук — мисли дастури палав дар корти чойхона. Дастур барои ҳамаи ошпазҳо як аст, аммо дег барои ҳар ошпаз ҷудо: ду ошпаз аз рӯи як корт мепазанд ва ду палави гуногун мегиранд. Дастурро ба ошхонаи дигар ҳар қадар нусха кардан мумкин аст, аммо дегии умумӣ барои ду ошхона — ин аллакай «ҳолатро ба боло бардоштан» аст.

Хатоҳои маъмул

1. Ҳукро бе use номидан (toggle()): линтер дар дохили он қоидаҳои ҳукҳоро намесанҷад, ва барои хонанда нофаҳмо аст, ки ин ҳук аст. 2. Ҳукро дар шарт ё баъд аз return-и барвақт даъват кардан: дар консол Rendered more hooks than during the previous render, дар линтер react-hooks(rules-of-hooks). 3. Интизор шудан, ки ду компонент бо як ҳуки ягона як ҳолатро мебинанд: он барои ҳар кадом ҷудо аст. 4. Массивро бе as const баргардонидан ва дар деструктуризатсия ба ҷои қимат ва функсия union гирифтан. 5. Ҳукро «барои ҳолати эҳтимолӣ» сохтан — баъд аз аввалин иваз маълум мешавад, ки он дар як ҷо истифода мешавад.

ВАЗИФАИ 1.1

Худро санҷед: ҳукҳои худӣ

осон

Ду компоненти гуногун useToggle()-ро даъват мекунанд. Вақте ки яке аз онҳо қиматро иваз кунад, чӣ мешавад?

  1. Қимат дар компоненти дуюм низ тағйир меёбад: ҳук умумӣ аст
  2. Компоненти дуюм чизеро намефаҳмад: ҳар даъвати ҳук ҳолати худро дорад
  3. React хато медиҳад: ҳукро аз ду ҷо даъват кардан мумкин нест
  4. Ҳарду компонент аз нав кашида мешаванд, аммо қиматҳо собит мемонанд

Ҳук танҳо кодро тақсим мекунад. Ҳолат дар ҷойҳои компоненти мушаххас нигоҳ дошта мешавад, бинобар ин ҳар даъват ҳолати худро дорад. Ҳолати умумиро ба падар мебаранд ё ба Context мегузоранд.

Аз ин чиро ҳамчун ҳуки худӣ бо номи useЧтоТо тартиб додан мумкин аст?

  1. Функсияи formatPrice(n), ки рақамро ба сатри «45 сомонӣ» табдил медиҳад
  2. Компоненти Rating, ки JSX-ро бармегардонад
  3. Функсияе, ки дар дохил useState ва useEffect-ро даъват мекунад ва қиматро барои компонент бармегардонад
  4. Собити CUISINES бо рӯйхати ошхонаҳо

Ҳук — функсияест, ки ҳукҳои дигарро даъват мекунад. Функсияи оддӣ бе ҳукҳо ҳук нест, ва компонент JSX-ро бармегардонад ва бо ҳарфи калон номида мешавад.

Барои чӣ return [on, toggle] as const-ро ба ҷои return [on, toggle] навиштан лозим аст?

  1. То ки навъ кортежи readonly [boolean, () => void] шавад, на массиви қиматҳои union
  2. То ки ҳук тезтар кор кунад
  3. То ки массивро деструктуризатсия кардан мумкин набошад
  4. Ин талаботи ҳатмии React аст

Бе as const TypeScript (boolean | (() => void))[]-ро мебарорад, ва баъд аз деструктуризатсия on ва toggle як union доранд. Бо as const мавқеъҳо навъҳои худро мегиранд.

02 TypeScript: дженерикҳо дар ҳадди ақал

Ҳукҳои useFetch ва useLocalStorage бо маълумоти навъҳои гуногун кор мекунанд: тарабхонаҳо, хӯрокҳо, сабад. Агар unknown нависед, коди даъваткунанда қимате мегирад, ки бо он ҳеҷ кор кардан мумкин нест. Агар any нависед, санҷиши навъҳо нест мешавад. Барои чунин ҳолатҳо дар TypeScript дженерикҳо (generics) ҳастанд: параметри навъ, ки ҳангоми истифода гузошта мешавад. Шумо онҳоро аллакай дидаед: useState<Cuisine | null>(null), Array<T> ва LoadState<T>-и худатон аз дарси 5. Акнун навиштани дженерикҳои худиро меомӯзем.

Функсия бо параметри навъ

Фарз мекунем, ки функсияи «элементи аввали массив» лозим аст. Барои сатрҳо, рақамҳо ва тарабхонаҳо он як ва ҳамон аст. Параметри навъи T-ро дар қавсҳои кунҷдор баъд аз номи функсия менависанд: ин «тағйирёбандаи навъ» аст, мисли параметри функсия — тағйирёбандаи қимат.

function first<T>(items: T[]): T | undefined {
  return items[0]
}

const name = first(['Navruz', 'Rohat']) // T = string, тип name: string | undefined
const rating = first([4.8, 4.5]) // T = number
const none = first<string>([]) // T указан явно: пустой массив ничего не подсказывает

Ба ду роҳи додани T диққат диҳед. Аксар вақт TypeScript онро худаш аз рӯи аргументҳо мебарорад (first(['Navruz', 'Rohat'])), ва навиштани қавсҳои кунҷдор лозим нест. Навъи возеҳ (first<string>([])) дар он ҷо лозим аст, ки баровардан аз чизе имкон надорад: массиви холӣ, useState<User | null>(null), useLocalStorage<CartItem[]>(…).

Маҳдудият: T extends

Дар дохили функсия бо T-и «луч» дар бораи он ҳеҷ чиз маълум нест, бинобар ин ба майдонҳо муроҷиат кардан мумкин нест. id лозим аст? Навъро маҳдуд кунед: T extends { id: number } маънои «ҳар гуна навъе, ки майдони ададии id дорад»-ро дорад. Ҳам Restaurant, ҳам MenuItem мувофиқ аст, аммо сатр мувофиқ нест:

function findById<T>(items: T[], id: number): T | undefined {
  return items.find((item) => item.id === id)
}

function findById<T extends { id: number }>(items: T[], id: number): T | undefined {
  return items.find((item) => item.id === id)

Навъи дженерикӣ ва қимати пешфарз

Навъҳо низ параметрдор мешаванд. Шумо аллакай LoadState<T>-ро навиштаед; инак боз як қолаби маъмул, «натиҷаи амал». Параметри дуюм E = string қимати пешфарз дорад: агар онро нишон надиҳед, хато сатр мешавад.

type Result<T, E = string> =
  | { ok: true; value: T }
  | { ok: false; error: E }

function parsePrice(text: string): Result<number> {
  const n = Number(text)
  return Number.isNaN(n) ? { ok: false, error: 'цена не число' } : { ok: true, value: n }
}

const result = parsePrice('45')
if (result.ok) {
  console.log(result.value + 1) // здесь result.value: number
} else {
  console.log(result.error) // здесь result.error: string
}

Қоидаи «дар ҳадди ақал»

Дженерикҳоро ба муаммо табдил додан осон аст. Барои курс чор усул кифоя аст: функсия бо <T>, маҳдудияти extends, навъи дженерикӣ (Result<T>, LoadState<T>) ва навъи возеҳ дар қавсҳо, вақте ки баровардан аз ӯҳда набаромад. <T>-ро насозед, агар навъ дар функсия як маротиба истифода шавад ва ба ҷое баргардонда нашавад: unknown ё навъи мушаххас кифоя аст. Ва ҳаргиз <T = any> нанависед: ин ҳамон any бо як қадами иловагӣ аст (бахши 8).

Монанд аз ҳаёт

Дженерик — ин нон бо ҷои холӣ барои пур. Шакли хамир як аст, ва пурро шумо ҳангоми фармоиш интихоб мекунед: гӯшт, каду, картошка. extends — ин шарти «нон бо чизе, ки пухтан мумкин аст»: рег ба пур намегузоранд. Ва пури «номаълум» unknown — ин бастаи мӯҳршуда аст: то онро накушоед ва насанҷед, хӯрдан мумкин нест.

03 useFetch<T>: боркунии маълумот дар ҳуки худӣ

Дар дарси 5 боркунии тарабхонаҳо бевосита дар App буд: ҳолати load, ҳисобкунаки attempt, эффект бо AbortController, функсияи retry. Ин тақрибан 20 сатр аст, ки ба ҳар экрани бо маълумот лозим мешавад (меню, фармоишҳо, профил). Онҳоро дар як ҳуки useFetch<T> ҷамъ мекунем: он суроға ва функсияи санҷиши ҷавобро мегирад, ва ҳолати LoadState<T> ва функсияи «Такрор»-ро бармегардонад.

Имзо: ҳук чиро қабул ва бармегардонад

Ҳук намедонад, ки маҳз чиро бор мекунад, бинобар ин навъи натиҷа T ба ӯ аз коди даъваткунанда лозим аст. Аммо as T навиштан мумкин нест (бахши 2): санҷиши маълумотро ҳук ҳамчун аргумент, бо функсияи parse мегирад. Навъи он (data: unknown) => T ҳамзамон ба TypeScript мегӯяд, ки T ба чӣ баробар аст, бинобар ин қавсҳои кунҷдор ҳангоми даъват лозим нестанд:

function useFetch<T>(url: string, parse: (data: unknown) => T): {
  state: LoadState<T>
  retry: () => void
}

Боркунӣ: қимати ҳосилшуда ба ҷои setState дар эффект

Дар дарси 5 қоида буд: «боркунӣ» дар дохили эффект гузошта намешавад. Аммо вақте ки суроға иваз мешавад (масалан, тарабхонаи дигарро интихоб карданд), чӣ кор кардан лозим? Дархости нав рафт, ва дар экран ҷавоби кӯҳна ҳанӯз ҳаст. Ҳук инро чунин ҳал мекунад: ҳар ҷавоб якҷоя бо калиди дархост (суроға ва рақами кӯшиш) нигоҳ дошта мешавад. Агар калиди ҷавоби нигоҳдошташуда ба ҷорӣ баробар набошад, пас ҷавоб «бегона» аст ё ҳанӯз наомадааст, ва ҳолат — loading аст. Ин дар рендер ҳисоб карда мешавад, на нигоҳ дошта мешавад.

import { useCallback, useEffect, useState } from 'react'
import { errorMessage, fetchJson, isAbortError } from '../api'
import type { LoadState } from '../types'

type Result<T> = { key: string; state: LoadState<T> }

export function useFetch<T>(url: string, parse: (data: unknown) => T) {
  const [attempt, setAttempt] = useState(0)
  const [result, setResult] = useState<Result<T> | null>(null)
  const key = `${url}#${attempt}`

  useEffect(() => {
    const controller = new AbortController()
    fetchJson(url, parse, controller.signal)
      .then((data) => setResult({ key, state: { status: 'success', data } }))
      .catch((error: unknown) => {
        if (isAbortError(error)) return
        const state: LoadState<T> = {
          status: 'error',
          message: errorMessage(error),
        }
        setResult({ key, state })
      })
    return () => controller.abort()
  }, [url, parse, key])

  const retry = useCallback(() => setAttempt((n) => n + 1), [])

  // ответ относится к другому запросу или ещё не пришёл: показываем загрузку
  const state: LoadState<T> =
    result !== null && result.key === key
      ? result.state
      : { status: 'loading' }

  return { state, retry }
}

Ҳукро қисм ба қисм таҳлил кунед, ҳамаи онҳо ба шумо аз дарси 5 шиносанд. Эффект бо шабака ҳамоҳанг мешавад: контроллер дар дохил сохта мешавад, тозакунӣ abort()-ро даъват мекунад, AbortError хомӯшона нодида гирифта мешавад. Вобастагиҳо софдилона: суроға, функсияи санҷиш ва калид. «Такрор» — ин зиёд шудани attempt аст: калид иваз мешавад, эффект аз нав оғоз мешавад, ва ҳолат худаш loading мешавад, зеро калиди ҷавоб дигар мувофиқ намеояд. Функсияи retry ба useCallback печонида шудааст: ҳук функсияро ба берун бармегардонад, ва истиноди устувор ба коди даъваткунанда кор меояд (бахши 5).

Дом: функсияи санҷиш бояд устувор бошад

parse ба вобастагиҳои эффект дохил мешавад. Агар тирро бевосита ба даъват гузаронед, он ҳангоми ҳар рендер нав мешавад (дарси 5: функсияҳои бадани компонент ҳамеша нав ҳастанд), ва эффект бори дигар ва бори дигар аз нав оғоз мешавад:

const { state } = useFetch('/api/restaurants', (data) => parseRestaurants(data))

Ҷавоб меояд, ҳолат тағйир меёбад, компонент рендер мешавад, тири нав сохта мешавад, эффект вобастагии навро мебинад, дархостро бекор мекунад ва дархости навро мефиристад. Дар экран ҳама чиз муқаррарӣ менамояд, ва дар Network дархостҳо беохир мераванд. Мо санҷидем: дар панҷ сония чунин даъват ба ҷои ду 10 дархост фиристод (ду ҳамчун натиҷаи StrictMode). Ҳалли он оддӣ аст: функсияеро гузаронед, ки берун аз компонент эълон шудааст (parseRestaurants дар api.ts меистад). Линтер чунин хаторо нишон намедиҳад, бинобар ин қоидаро дар AGENTS.md навиштан ва дар ревью санҷидан лозим аст.

Монанд аз ҳаёт

Калиди дархост — ин рақами ҷевон дар гардероб аст. Шумо куртаро супоридед ва рақами №17-ро гирифтед. Вақте ки гардеробчӣ бо курта бармегардад, рақамро муқоиса мекунад: агар №17 бошад, курта аз они шумост, ва агар дар дасташ рақами меҳмони пештара бошад, ӯ онро ба шумо намедиҳад, балки мегӯяд «ҳанӯз меҷӯям». То он даме ки курта нест, шумо «боркунӣ»-ро мебинед, ва ҳеҷ кас парчами алоҳидаи «мечӯем»-ро нигоҳ намедорад.

Хатоҳои маъмул

1. Тир дар аргументи parse: дархостҳо давр мезананд. 2. as T баъд аз response.json() ба ҷои санҷиш: сервер метавонад ҳар чизро фиристад, ва компилятор намефаҳмад. 3. Се ҳолати алоҳидаи data, loading, error ба ҷои union: омезишҳои номумкин имкон доранд (боркунӣ тамом шуд, ва на маълумот ҳаст, на хато). 4. setLoad({ status: 'loading' }) дар эффект ҳангоми иваз шудани суроға: рендери иловагӣ ва огоҳии set-state-in-effect. 5. abort()-и фаромӯшшуда: ҳангоми зуд иваз шудани суроға дар экран метавонад ҷавоб ба дархости кӯҳна пайдо шавад.

04 useLocalStorage<T> ва useDebounce<T>

Боз ду ҳук аз нақшаи дарс ду вазифаи маъмулро ҳал мекунанд. Якум: қиматро дар браузер нигоҳ доштан, то ки он аз навсозӣ гузарад (сабад, мавзӯи интихобшуда, филтри охирин). Дуюм: ба ҳар пахши клавиша вокуниш нишон надодан, балки интизор шудан, ки корбар ворид карданро тамом кунад.

localStorage: пеш аз ҳук чиро донистан лозим аст

localStorage — захираи хурди «калид → сатр» дар браузер: 5–10 МБ барои сайт, маълумот баъд аз пӯшидани варақа мемонад. Аз ин чор қоида барои ҳук бармеояд:

  1. Танҳо сатрҳо нигоҳ дошта мешаванд. Объектҳо ва массивҳоро тавассути JSON.stringify ба сатр табдил медиҳанд ва тавассути JSON.parse бозхонӣ мекунанд.
  2. Ба хондашуда бовар кардан мумкин нест. Корбар ё версияи дигари сайти шумо метавонист ҳар чизро нависад. JSON.parse any-ро бармегардонад: онро ҳамчун unknown қабул кунед ва бо type guard санҷед (дарси 5).
  3. Дастрасӣ метавонад вайрон шавад. Дар реҷаи хусусӣ, ҳангоми хомӯш будани маълумоти сайт ё ҳангоми пур шудани квота getItem ва setItem истисно мепартоянд. Ҳарду даъватро ба try/catch мепечонанд, ва барнома бе нигоҳдорӣ кор карданро идома медиҳад.
  4. Рамзҳои махфиро нагузоред. Ҳар скрипти саҳифа захираро мехонад: токенҳои дастрасӣ ва маълумоти шахсиро дар он нигоҳ доштан хатарнок аст.

useLocalStorage<T>

Ҳук мисли useState рафтор мекунад, аммо қимати аввалияро аз захира мегирад ва ҳар тағйиротро баргашта менависад. Хондан як маротиба, ҳангоми сохтани ҳолат иҷро мешавад: барои ин ба useState функсия (оғозиши танбалона) мегузаронанд, на натиҷаи даъват: он гоҳ localStorage як маротиба хонда мешавад, на ҳангоми ҳар рендер. Навиштан — эффекти ҳақиқӣ аст: ҳамоҳангсозӣ бо системаи беруна, захираи браузер.

import { useEffect, useState, type Dispatch, type SetStateAction } from 'react'

export function useLocalStorage<T>(
  key: string,
  initialValue: T,
  isValid: (value: unknown) => value is T,
): [T, Dispatch<SetStateAction<T>>] {
  const [value, setValue] = useState<T>(() => {
    try {
      const raw = localStorage.getItem(key)
      if (raw === null) return initialValue
      const parsed: unknown = JSON.parse(raw)
      return isValid(parsed) ? parsed : initialValue
    } catch {
      return initialValue
    }
  })

  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value))
    } catch {
      // квота исчерпана или приватный режим: работаем без сохранения
    }
  }, [key, value])

  return [value, setValue]
}

Се тафсилоти навъҳо. isValid: (value: unknown) => value is T — type guard ҳамчун параметр: дар дохили ҳук T ҳеҷ ҷо оварда намешавад, балки бо санҷиш тасдиқ мешавад. Dispatch<SetStateAction<T>> — навъи сеттери useState: он ҳам қимат, ҳам функсияи «аз пештара ба оянда»-ро қабул мекунад, бинобар ин коди даъваткунанда бо ҳук мисли useState кор мекунад. Навъи возеҳ ҳангоми даъват: useLocalStorage<CartItem[]>('cart', [], isCartItems). Мо санҷидем, ки бе қавсҳои кунҷдор TypeScript мекӯшад T-ро аз қимати аввалия барорад ва ба номувофиқӣ бо guard эътироз мекунад.

Яке дигар маҳдудият: калиди key доимӣ ҳисоб карда мешавад, зеро хондан як маротиба иҷро мешавад, ва иваз шудани калид аз нав чизеро намехонад. Ҳамоҳангсозии байни варақаҳо (рӯйдоди storage) дар ин ҷо татбиқ нашудааст.

useDebounce<T>

Дебаунс (debounce) — «хомӯширо интизор шудан». То он даме ки қимат аз як маротиба дар N миллисония зудтар тағйир меёбад, ҳеҷ чиз намешавад, ва баъд аз N мс пас аз тағйири охирин амал кор мекунад. Барои ҳук ин қимат бо таъхир аст: корбар «nav» менависад, ба query ҳар ҳарф фавран меафтад, ва ба debouncedQuery танҳо «nav» баъд аз 250 мс пас аз клавишаи охирини пахшшуда. Татбиқ — ин эффект бо таймер ва тозакунӣ аст (дарси 5): ҳар қимати нав таймери пештараро бекор мекунад.

import { useEffect, useState } from 'react'

export function useDebounce<T>(value: T, delayMs: number): T {
  const [debounced, setDebounced] = useState(value)

  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delayMs)
    return () => clearTimeout(id)
  }, [value, delayMs])

  return debounced
}

Ин дар лоиҳае, ки танҳо шаш тарабхона дорад, барои чӣ? Ҷавоби ҳалол: имрӯз барои ҳеҷ, филтронӣ фаврист. Ҳук вақте лозим аст, ки ҳар тағйирот серверро дархост кунад (ҷустуҷӯ аз рӯи API, дарси 10) ё ҳисобкунии аз нав вазнинро оғоз кунад. Ҳоло мо усулро дар майдони ҷустуҷӯи воқеӣ машқ мекунем, ва дар дарси 10 он ба таври мақсаднок кор меояд. Бо useDeferredValue омехта накунед: ин ҳуки дарунсохт кашидани рӯйхати вазнинро ба таъхир меандозад ва таймер бо миллисонияҳо надорад, яъне барои кам кардани дархостҳо ба сервер мувофиқ нест.

Монанд аз ҳаёт

Дебаунс — мисли пешхизмат дар чойхона, ки назди миз меистад, то шумо фармоишро номбар мекунед: «палав, ва боз лағмон... ва чой... ва самбуса». Ӯ баъд аз ҳар калима ба ошхона намедавад, балки таваққуфро интизор мешавад ва танҳо баъд бо фармоиш меравад. Ва localStorage — дафтарчаи рӯи пештахта: бозгашти шуморо интизор мешавад, аммо ҳар кӣ ба пештахта наздик шавад, онро хонда ва навишта метавонад, бинобар ин шиноснома ба он ҷо намегузоранд.

Хатоҳои маъмул

1. Захираро бевосита дар бадани компонент хондан: хондан ҳангоми ҳар рендер иҷро мешавад. ВАЗИФАИ 4.1

Худро санҷед: захира ва дебаунс

миёна

Барои чӣ дар useLocalStorage хондани захира ба useState бо функсияи useState(() => …) гузаронида мешавад, на бо қимат?

  1. То ки код кӯтоҳтар менамояд
  2. То ки хондан ва таҳлили JSON як маротиба ҳангоми сохтани ҳолат иҷро шавад, на ҳангоми ҳар рендер
  3. То ки хатои QuotaExceededError-ро давр занем
  4. То ки қиматро бевосита тағйир додан мумкин бошад

Оғозиши танбалона функсияро танҳо ҳангоми рендери аввал даъват мекунад. Бе он getItem ва JSON.parse баъд аз ҳар пахши клавиша кор мекарданд, ҳарчанд натиҷаи онҳо як маротиба истифода мешавад.

Дар захира сатри {"bad":1} ҳаст, ва ҳук массиви CartItem[]-ро интизор аст. Чӣ бояд шавад?

  1. Барнома меафтад: маълумот нодуруст аст
  2. Ҳук ин маълумотро ҳамчун CartItem[] бармегардонад
  3. Санҷиши isValid false-ро бармегардонад, ҳук қимати аввалияро мегирад
  4. Ҳук тамоми localStorage-ро тоза мекунад

Маълумоти захира боэътимод нест. Type guard шакли онҳоро месанҷад, ва ҳангоми номувофиқӣ ҳук ба қимати аввалия бармегардад. Барнома кор карданро идома медиҳад.

  1. Таймери қимати пештараро бекор мекунад, то ки танҳо таймери охирин кор кунад
  2. Таймерро тез мекунад
  3. Қиматро аз ҳолат тоза мекунад
  4. Ҳеҷ чиз: таймер худаш бекор мешавад

Бе тозакунӣ ҳар қимат таймери худро оғоз мекард, ва ҳама онҳо ба навбат кор мекарданд. Тозакунӣ «бисёр таймерҳо»-ро ба як таймери охирин табдил медиҳад.

05 Суръати кор: memo, useMemo ва useCallback

Дар дарси 3 шумо фаҳмидед: вақте ки ҳолати компонент тағйир меёбад, React ин компонент ва ҳамаи наслҳои онро аз нав даъват мекунад, ҳатто агар props-и онҳо собит монда бошанд. Одатан ин арзон аст, ва чизе барои оптимизатсия нест. Аммо чунин мешавад, ки компоненти фарзанд вазнин аст (шашсад корти тарабхона, ҷадвали калон), ва падар бо сабаби номарбут аз нав кашида мешавад: клики «В корзину» набояд феҳристро аз нав ҳисоб кунад. Барои чунин ҳолатҳо се абзор ҳаст.

Пеш аз гирифтани онҳо се қадамро аз арзон ба гаронтар гузаред:

  1. Сохторро ислоҳ кунед. Ҳолатро поёнтар, ба компоненти хурде, ки ба он лозим аст, фароварда баред. Қисми вазнинро тавассути children гузаронед: падар бо ҳолат аз нав кашида мешавад, ва унсури тайёри аз children-ро React истифода мебарад (дарси 3). Аксар вақт ин кифоя аст.
  2. Андоза кунед. Profiler-ро кушоед (бахши 6): рендер чанд миллисония арзиш дорад ва кӣ бе сабаб аз нав кашида шуд. Агар кори иловагӣ нест ё он ҳиссаҳои миллисонияро ишғол мекунад, истед.
  3. Мемоизатсияро нуқтавӣ кунед ва бори дигар андоза кунед. Мемоизатсия — ин кэш аст, ва кэш нарх дорад: код мураккабтар мешавад, вобастагиҳоро софдилона бояд пеш бурд, ва вобастагии нодуруст маълумоти кӯҳнаро медиҳад.

memo: рендерро гузарондан, агар props собит бошанд

memo(Component) компонентро чунин мепечонад: вақте ки падар аз нав кашида шуд, React props-и навро бо пештара ба навбат тавассути Object.is (муқоисаи сатҳӣ) муқоиса мекунад. Агар ҳама баробар бошанд, компонент якҷоя бо тамоми дарахти поёнӣ гузаронида мешавад. Муқоиса аз рӯи истинод меравад, на аз рӯи мундариҷа (дарси 5): адади 3 ба 3 баробар аст, ва ду объекти {} ҳамеша гуногунанд.

import { memo } from 'react'

function RestaurantList({ restaurants, onSelect }: RestaurantListProps) {
  // …
}

export default memo(RestaurantList)

Акнун муҳимтарин: массиви нав, объект ё функсия дар бадани падар — ин истиноди нав ҳангоми ҳар рендер аст. Агар чунин қиматро ба компоненти memo гузаронед, муқоиса намегузарад ва мемоизатсия кор намекунад. Бинобар ин memo қариб ҳеҷ гоҳ танҳо намешавад: ба вай истинодҳои устувор лозиманд.

useMemo: натиҷаи ҳисобкуниро ба ёд гирифтан

useMemo(() => ҳисобкунӣ, [вобастагиҳо]) натиҷаро байни рендерҳо нигоҳ медорад ва онро танҳо вақте аз нав ҳисоб мекунад, ки ақаллан як вобастагӣ тағйир ёфта бошад (муқоиса низ тавассути Object.is). Он дар се ҳолат лозим аст: ҳисобкунӣ воқеан гарон аст (дар консол console.time 1 мс ва зиёдтарро барои як амал нишон медиҳад), натиҷа ба компоненти memo ҳамчун prop гузаронида мешавад (истиноди устувор лозим аст), ё натиҷа худаш вобастагии ҳуки дигар аст.

  [restaurants, cuisine, debouncedQuery],
)

Ҳисобкунӣ дар дохили useMemo бояд тоза бошад: React дар реҷаи dev-и StrictMode онро ду маротиба даъват мекунад. Кэш — ишора аст, на кафолат: React метавонад онро партояд, бинобар ин код бояд бе он низ кор кунад (агар қиматро ҳатман нигоҳ доштан лозим бошад, ин useState ё useRef аст).

useCallback: функсияро ба ёд гирифтан

useCallback(fn, [вобастагиҳо]) ҳамин чиз барои функсияҳо: то даме ки вобастагиҳо тағйир наёфтаанд, ҳамон функсияро бармегардонад. Ин useMemo(() => fn, deps) дар навиштаи кӯтоҳ аст. Ҳуҷҷатгузории React се ҳолатро номбар мекунад: функсия ба компоненти memo меравад, функсия — вобастагии ҳуки дигар (масалан, эффект) аст, ё шумо ҳуки худиро менависед, ки функсияҳоро бармегардонад, то ки коди даъваткунанда оптимизатсия карда тавонад (retry дар useFetch ҳамин тавр сохта шудааст).

const handleSelect = useCallback((id: number) => {
  setSelectedId(id)
}, []) // setSelectedId — сеттер useState: ссылка на него стабильна и в зависимости не нужна

Хабари хуш: сеттери useState ва dispatch-и редюсер аллакай устуворанд. Агар onSelect={setSelectedId}-ро бевосита гузаронед, шумо истиноди устуворро бе ягон useCallback мегиред. Тири печонанда onSelect={(id) => setSelectedId(id)} устувориро вайрон мекунад: шумо инро дар машқ дар Profiler мебинед.

Се қоидаи мемоизатсия

  • Вобастагиҳо софдилона. Линтери exhaustive-deps онҳоро мисли барои useEffect месанҷад. Вобастагии гузаштагӣ қимати кӯҳнаро медиҳад: аз рендери иловагӣ бадтар.
  • Як гиреҳи заиф занҷирро мешиканад. Агар аз се props ду устувор ва як нав бошад, memo кор намекунад. Ҳар чизеро, ки ба prop меравад, бояд мемоизатсия кард, ё қиматҳои примитивиро гузаронд.
  • Ҳама ҷо нагузоред. useMemo атрофи амали арзон (ҷамъи ду адад) аз худи амал гаронтар аст: React қиматро нигоҳ медорад ва вобастагиҳоро муқоиса мекунад.
Монанд аз ҳаёт

Мемоизатсия — мисли омодасозии палав барои тамоми рӯз дар чойхона. Агар меҳмонон бисёр бошанд ва фармоиш такрор шавад, омодагӣ соатҳоро сарфа мекунад. Аммо барои як меҳмоне, ки чой фармудааст, омодагӣ кардан нодонист: аз сарфа бештар қувва сарф мешавад. Ва омодагӣ вайрон мешавад: агар хом-ашёро иваз карданро фаромӯш кунанд (вобастагии гузаштагӣ), меҳмонон палави дирӯзаро мегиранд.

Хатоҳои маъмул

1. memo бе props-и устувор: компонент ҳамоно рендер мешавад, ва код мураккаб шуд. 2. useCallback барои функсияе, ки ба компоненти оддӣ (на memo) ё onClick-и тег меравад: маъно надорад. 3. Вобастагиҳо бо гузаштаҳо ё шарҳи «disable lint»: қимати кӯҳна. 4. Объект ё массив дар useMemo, ки аз объекти нав дар вобастагиҳо сохта мешавад: кэш ҳар рендер тоза мешавад. Дар Oxlint ин аз огоҳӣ намоён аст: React hook useMemo depends on `restaurants`, which changes every render. 5. Натиҷаи useMemo-ро тағйир додан: он барои ҳамаи рендерҳо умумӣ аст. 6. Бе андозагирӣ оптимизатсия кардан: шумо намедонед, ки кӯмак кард ё зарар расонд.

Худро санҷед: мемоизатсия

миёна

RestaurantList ба memo печонида шудааст, аммо ҳангоми клики «В корзину» ҳамоно рендер мешавад. Эҳтимолан чӣ нодуруст аст?

  1. Компонентро боз як маротиба ба memo печонидан лозим аст
  2. Компонент барои memo хеле хурд аст
  3. Ба он prop-е гузаронида мешавад, ки ҳангоми ҳар рендери падар нав аст: массив аз filter ё тири коркардкунанда
  4. Сабад ҳамеша тамоми феҳристро аз нав мекашад, ва бо ин ҳеҷ кор кардан мумкин нест

memo props-ро аз рӯи истинод муқоиса мекунад. Массиви нав ё функсия ҳангоми ҳар рендери падар ба пештара баробар нест, бинобар ин гузаронидан кор намекунад. useMemo ва useCallback лозиманд (ё бевосита гузаронидани сеттер).

Пеш аз илова кардани memo ва useMemo чӣ кор кардан лозим аст?

  1. Ҳамаи компонентҳои лоиҳаро барои эҳтиёт ба memo печонидан
  2. Дар Profiler андоза кардан, ки маҳз чӣ аз нав кашида мешавад ва ин чӣ қадар арзиш дорад, ва аввал кӯшиш кардан сохторро соддатар кунед (ҳолатро фуровардан, children-ро истифода бурдан)
  3. StrictMode-ро хомӯш кардан
  4. useState-ро бо useReducer иваз кардан

Мемоизатсия нарх дорад. Аввал андозагирӣ ва ҳалҳои сохторӣ, баъд кэши нуқтавӣ ва андозагирии такрорӣ.

Кадом ду гузаронидан ба компоненти memo истиноди устувор ба коркардкунандаро медиҳанд? (Дар компонент const [id, setId] = useState(0) ҳаст)

  1. onSelect={setId}: сеттери useState устувор аст
  2. onSelect={(next) => setId(next)}: тир як маротиба сохта мешавад
  3. onSelect={function (next) { setId(next) }}: функсияи оддӣ аз нав сохта намешавад
  4. onSelect={handleSelect}, ки дар он const handleSelect = useCallback((next: number) => setId(next), [])

Тир ва ифодаи function дар бадани компонент ҳангоми ҳар рендер аз нав сохта мешаванд. Сеттери useState ва функсияи аз useCallback бо вобастагиҳои софдилона устуворанд.

душвор

import { memo, useMemo, useState } from "react";

const RESTAURANTS = [
  { id: 1, name: "Navruz", open: true },
  { id: 2, name: "Rohat", open: false },
  { id: 3, name: "Samarkand", open: true },
];

const OpenList = memo(function OpenList({ items }) {
  console.log("рендер списка:", items.length);
  return (
    <ul>
      {items.map((r) => (
        <li key={r.id}>{r.name}</li>
      ))}
    </ul>
  );
});

export default function App() {
  const [count, setCount] = useState(0);

  // TODO: результат filter должен быть одним и тем же между рендерами
  const open = RESTAURANTS.filter((r) => r.open);

  return (
    <div>
      <button id="inc" onClick={() => setCount(count + 1)}>+1</button>
      <p>Кликов: {count}</p>
      <OpenList items={open} />
    </div>
  );
}

// автопроверка: стенд нажимает «+1» дважды

08 Блоки ИИ: мантиқро ба ҳук баровардан ва бо Profiler санҷидан

Хоҳиши «мантиқи боркуниро ба ҳук бароваред» безарар менамояд, аммо маҳз дар ҳукҳо агентҳо аксар вақт коде менависанд, ки дар намоиш кор мекунад ва дар ҳаёт вайрон мешавад. Инак ҷавоби маъмул ба чунин хоҳиш:

export function useFetch<T = any>(url: string, options: RequestInit = {}) {
  const [data, setData] = useState<T | null>(null)
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState<any>(null)

  useEffect(() => {
    setLoading(true)
    fetch(url, options)
      .then((res) => res.json())
      .then((json) => setData(json as T))
      .catch((e) => setError(e))
      .finally(() => setLoading(false))
  }, [url, options])

  return { data, loading, error }
}

Дар ин ҷо қариб ҳама чизе, ки дар дарс гуфта шуд, ҷамъ омадааст: T = any ва error: any санҷиши навъҳоро хомӯш мекунанд; options = {} — объекти нав ҳангоми ҳар даъват, он дар вобастагиҳост, ва дархостҳо давр мезананд (бахши 3); санҷиши response.ok нест; json as T — ваъда бе санҷиш; AbortController нест, пас рақобати дархостҳо имкон дорад; се ҳолати алоҳида омезишҳои номумкинро иҷозат медиҳанд; setLoading(true) дар эффект меистад. Дархости хуб ин камбудиҳоро пешакӣ манъ мекунад ва далел металабад.

Формулаи промпт: контекст → вазифа → маҳдудиятҳо → формат → санҷиш

Барои ҳукҳо маҳдудиятҳо оид ба навъҳо ва истинодҳо муҳиманд: чиро ҳамчун any қабул кардан мумкин нест, кадом қиматҳо бояд устувор бошанд, натиҷаро бо чӣ санҷидан. Ва хоҳиши мисоли истифода агентро водор мекунад, ки нишон диҳад, ҳук дар коди даъваткунанда чӣ тавр кор мекунад.

ВАЗИФАИ 8.2

readStored-и агентро ислоҳ кунед

душвор

Агент readStored<T>-ро бо овардани as T навишт. Барои маълумоти вайроншуда дар калиди cart функсия ба ҷои массив объектро бармегардонад, ва барнома меафтад. Ислоҳ кунед: функсия ҳамчун параметри дуюм type guard-и isValid: (value: unknown) => value is T-ро мегирад, ва ҳангоми санҷиши номуваффақ ё хатои таҳлил null-ро бармегардонад. Даъватҳо аллакай бо шакли нав навишта шудаанд.

// стенд: «localStorage» в виде объекта
const store: Record<string, string> = {
  cart: '{"oops":true}',
  saved: '[{"title":"Плов","qty":2},{"title":"Чай","qty":1}]',
};

type Line = { title: string; qty: number };

function isLines(value: unknown): value is Line[] {
  return (
    Array.isArray(value) &&
    value.every(
      (v) =>
        typeof v === "object" && v !== null &&
        "title" in v && typeof v.title === "string" &&
        "qty" in v && typeof v.qty === "number"
    )
  );
}

// код агента: приведение типа без проверки
function readStored<T>(key: string): T | null {
  const raw = store[key];
  return raw === undefined ? null : (JSON.parse(raw) as T);
}

const cart = readStored("cart", isLines) ?? [];
const saved = readStored("saved", isLines) ?? [];
console.log("cart:", cart.length);
console.log("saved:", saved.length);
Натиҷаи интизоршаванда
cart: 0
saved: 2
Ишора 1

Параметри isValid: (value: unknown) => value is T-ро илова кунед. Натиҷаи JSON.parse-ро ба тағйирёбандаи навъи unknown гузоред ва онро танҳо баъд аз санҷиш баргардонед.

Ишора 2

const parsed: unknown = JSON.parse(raw); return isValid(parsed) ? parsed : null; try/catch-ро фаромӯш накунед: барои JSON-и нодуруст null-ро баргардонед.

    import { useCallback, useEffect, useState } from 'react'
import { errorMessage, fetchJson, isAbortError } from '../api'
import type { LoadState } from '../types'

type Result<T> = { key: string; state: LoadState<T> }

export function useFetch<T>(url: string, parse: (data: unknown) => T) {
  const [attempt, setAttempt] = useState(0)
  const [result, setResult] = useState<Result<T> | null>(null)
  const key = `${url}#${attempt}`

  useEffect(() => {
    const controller = new AbortController()
    fetchJson(url, parse, controller.signal)
      .then((data) => setResult({ key, state: { status: 'success', data } }))
      .catch((error: unknown) => {
        if (isAbortError(error)) return
        const state: LoadState<T> = {
          status: 'error',
          message: errorMessage(error),
        }
        setResult({ key, state })
      })
    return () => controller.abort()
  }, [url, parse, key])

  const retry = useCallback(() => setAttempt((n) => n + 1), [])

  // ответ относится к другому запросу или ещё не пришёл: показываем загрузку
  const state: LoadState<T> =
    result !== null && result.key === key ? result.state : { status: 'loading' }

  return { state, retry }
}

    import { useEffect, useState, type Dispatch, type SetStateAction } from 'react'

export function useLocalStorage<T>(
  key: string,
  initialValue: T,
  isValid: (value: unknown) => value is T,
): [T, Dispatch<SetStateAction<T>>] {
  const [value, setValue] = useState<T>(() => {
    try {
      const raw = localStorage.getItem(key)
      if (raw === null) return initialValue
      const parsed: unknown = JSON.parse(raw)
      return isValid(parsed) ? parsed : initialValue
    } catch {
      return initialValue
    }
  })

  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(value))
    } catch {
      // квота исчерпана или приватный режим: работаем без сохранения
    }
  }, [key, value])

  return [value, setValue]
}

    import { isRecord } from './api'

function isCartItem(value: unknown): value is CartItem {
  if (!isRecord(value) || !isRecord(value.item)) return false
  const { item, qty } = value
  return (
    typeof qty === 'number' &&
    typeof item.id === 'number' &&
    typeof item.restaurantId === 'number' &&
    typeof item.title === 'string' &&
    typeof item.price === 'number'
  )
}

export function isCartItems(value: unknown): value is CartItem[] {
  return Array.isArray(value) && value.every(isCartItem)
}

    import { useEffect, useState } from 'react'

export function useDebounce<T>(value: T, delayMs: number): T {
  const [debounced, setDebounced] = useState(value)

  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delayMs)
    return () => clearTimeout(id)
  }, [value, delayMs])

  return debounced
}

  • useFetch<T>(url, parse): эффект бо AbortController ва тозакунӣ, ҷавоб бо калиди дархост нигоҳ дошта мешавад, loading дар рендер ҳисоб карда мешавад, retry дар useCallback. Функсияи parse берун аз компонент эълон мешавад, вагарна дархостҳо давр мезананд.
  • useLocalStorage<T>: оғозиши танбалонаи useState(() => …), JSON.parse ҳамчун unknown ва санҷиши guard, try/catch ҳангоми хондан ва навиштан, навиштан дар эффект. Рамзҳои махфиро дар захира намегузоранд.
  • useDebounce<T>: таймер дар эффект ва clearTimeout дар тозакунӣ. Барои дархостҳо ба сервер ва ҳисобкуниҳои вазнин лозим аст; барои кашидан useDeferredValue ҳаст.
  • Тартиби оптимизатсия: сохтор (ҳолатро фуровардан, children), андозагирӣ дар Profiler, мемоизатсияи нуқтавӣ, андозагирии такрорӣ. memo props-ро аз рӯи истинод муқоиса мекунад; массиви нав, объект ё функсия онро мешикананд. Сеттери useState устувор аст, тири печонанда не. useMemo қиматро кэш мекунад, useCallback — функсияро; вобастагиҳо софдилона.
  • Profiler: сабт, диаграммаи коммитҳо, Flamegraph ва Ranked, ранги хокистарӣ — «рендер нашуд», «Record why each component rendered» сабабро шарҳ медиҳад. Рақамҳои dev зиёд нишон дода мешаванд: «пеш» ва «баъд»-ро дар як компютер муқоиса кунед.
  • React Compiler 1.0: плагини ҷамъбаст, мемоизатсияро дар коди тоза худаш ҷойгир мекунад; дар Vite 8: babel-plugin-react-compiler, @rolldown/plugin-babel ва reactCompilerPreset(). Дар «Қоидаҳои React» кор мекунад; андозагириҳоро иваз намекунад ва эффектҳои нолозимро хориҷ намекунад. Дар лоиҳаи асосии курс фаъол нест (шаклҳо дар React Hook Form дар дарси 7).
  • Лоиҳаи 1 «Дастархон»: дар src/hooks се ҳук, сабад дар localStorage нигоҳ дошта мешавад, ҷустуҷӯ бо таъхир, феҳрист мемоизатсия шудааст. Минбаъд: шаклҳо ва равзанаҳои модалӣ дар React Hook Form ва Zod (дарси 7), Context (дарси 8).
ВАЗИФАИ 11.1

Ман воқеан мавзӯъро фаҳмидам

осон

Танҳо онро қайд кунед, ки бе ишора карда метавонед.

  • Метавонам мантиқи дорои ҳолат ва эффектро ба ҳуки худӣ бароварда, шарҳ диҳам, ки чаро ҳар даъват ҳолати худро мегирад
  • Метавонам функсияи дженерикӣ ва навъи дженерикӣ нависам, маҳдудияти extends-ро илова кунам ва шарҳ диҳам, ки навъи возеҳ кай лозим аст
  • Метавонам useFetch<T>-ро бо санҷиши ҷавоб тавассути parse нависам ва шарҳ диҳам, ки чаро parse бояд устувор бошад
  • Метавонам useLocalStorage<T>-ро бо оғозиши танбалона, санҷиши маълумот ва try/catch нависам
  • Метавонам useDebounce<T>-ро бо тозакунии таймер нависам
  • Метавонам ҷаласаро дар Profiler сабт кунам ва сабаби рендерро хонам
  • Метавонам шарҳ диҳам, ки memo, useMemo ва useCallback кай лозиманд ва чаро истиноди prop бояд устувор бошад
  • Метавонам React Compiler-ро дар лоиҳа дар Vite фаъол кунам ва санҷам, ки он кор мекунад
  • Метавонам ҳуки аз ҷониби агент навишташударо аз рӯи рӯйхати бахши 8 санҷам
