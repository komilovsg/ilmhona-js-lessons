Эффекты, рефы и загрузка данных

К концу урока каталог «Дастархона» будет получать рестораны не из файла, а с настоящего локального API: со скелетоном загрузки, понятной ошибкой и кнопкой «Повторить», с отменой лишних запросов, фокусом на поиске по клавише «/» и прокруткой к меню выбранного ресторана. Вы будете понимать, зачем нужен каждый useEffect в проекте, и уметь удалить тот, который не нужен.

  • Объяснить эффект как синхронизацию с внешней системой и расставить зависимости по подсказке линтера, не отключая его
  • Писать очистку (cleanup) для таймеров, подписок и запросов и объяснить, почему в режиме разработки эффект запускается дважды
  • Находить и удалять лишние эффекты: производные данные, сброс состояния по key, реакцию на клик
  • Использовать useRef для DOM (фокус, прокрутка) и для значений, которые не должны вызывать перерисовку
  • Загружать данные через fetch и AbortController с состояниями loading, error и success, описанными union-типом
  • Типизировать ответ API через unknown и type guard, сужать ошибку в catch и не использовать any

01 useEffect: синхронизация с внешним миром и зависимости

Компонент во время рендера только считает JSX (урок 3: чистая функция). Но приложению нужно и «грязное»: поставить заголовок вкладки, запросить данные по сети, подписаться на клавиатуру, запустить таймер. Всё это называют эффектами: работа, которая выходит за пределы вычисления разметки. Хук useEffect говорит React: «после того как покажешь экран, выполни эту функцию».

Не думайте об эффекте как о «событии жизненного цикла» (componentDidMount из старых туториалов). Правильная модель: эффект синхронизирует компонент с внешней системой (сетью, таймером, DOM, браузерным API) по текущим значениям props и состояния. Если значения изменились, синхронизацию нужно повторить. Какие значения нужны эффекту, говорит массив зависимостей.

import { useEffect } from 'react'

type PageTitleProps = { city: string }

export default function PageTitle({ city }: PageTitleProps) {
  useEffect(() => {
    document.title = `Дастархон · ${city}` // внешняя система: вкладка браузера
  }, [city]) // повторять, когда city изменился

  return null
}

Главное правило: зависимости вы не выбираете, их диктует код. Каждое «реактивное» значение (prop, состояние, переменная или функция, созданные в теле компонента), которое читается внутри эффекта, обязано быть в массиве. Забыть его значит получить эффект, который работает со «старым» значением. Проверяет это линтер: Oxlint из урока 1 содержит правило react-hooks/exhaustive-deps.

src/Bad.tsx:6:25: warning react-hooks(exhaustive-deps): React Hook useEffect has missing dependencies: 'query', and 'n'
  help: Either include it or remove the dependency array.

Не отключайте это предупреждение комментарием // eslint-disable: оно почти всегда указывает на реальную ошибку. Вместо этого поменяйте код. Есть четыре стандартных выхода:

  1. Значение нужно эффекту — добавьте его в зависимости. Эффект станет перезапускаться, и это правильно: данные изменились.
  2. Значение не меняется (константа, функция без замыканий) — вынесите его за пределы компонента, и в зависимости оно не попадёт.
  3. Эффекту нужно лишь «предыдущее состояние» — используйте функциональное обновление setCount((c) => c + 1): само count читать не придётся.
  4. Эффект должен прочитать свежее значение, но не перезапускаться из-за него — отделите «событие» от эффекта через useEffectEvent (ниже).

Объекты и функции в зависимостях

Объект, созданный в теле компонента, при каждом рендере новый, даже если поля те же. Если такой объект в зависимостях, эффект будет запускаться после каждого рендера. Создавайте объект внутри эффекта и зависьте от простых значений.

type Options = { city: string; onlyOpen: boolean }

function Catalog({ city, onlyOpen }: Options) {
  const options = { city, onlyOpen } // новый объект при каждом рендере

  // Плохо: options каждый раз другой, эффект запускается после каждого рендера
  useEffect(() => {
    load(options)
  }, [options])

  // Хорошо: объект собирается внутри, зависимости — простые значения
  useEffect(() => {
    load({ city, onlyOpen })
  }, [city, onlyOpen])
}

Устаревшее замыкание (stale closure)

Каждый рендер создаёт свою копию функций и значений (урок 3: состояние — снимок). Эффект с пустым массивом «запоминает» значения первого рендера навсегда. Классическая ловушка: счётчик в setInterval.

import { useEffect, useState } from "react";

export default function App() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1); // count здесь всегда 0: замыкание первого рендера
    }, 200);
    return () => clearInterval(id);
  }, []);

  return <p>Секунд: {count}</p>;
}

Счёт доходит до 1 и застывает: каждый тик выполняет setCount(0 + 1). Исправляется функциональным обновлением: setCount((c) => c + 1) берёт актуальное значение у React, и зависимость от count не нужна.

useEffectEvent: событие внутри эффекта

Иногда эффект должен прочитать свежее значение, но не перезапускаться при его смене. Пример: при подключении к чату показываем уведомление в текущей теме оформления. Смена темы не должна переподключать чат. С React 19.2 для этого есть useEffectEvent: функция, которая внутри эффекта всегда видит свежие props и состояние, но сама зависимостью не считается.

import { useEffect, useEffectEvent } from 'react'

type ChatProps = { roomId: string; theme: 'light' | 'dark' }

export default function Chat({ roomId, theme }: ChatProps) {
  // свежая theme внутри, но в зависимости её добавлять не нужно
  const onConnected = useEffectEvent(() => {
    showToast('Подключено', theme)
  })

  useEffect(() => {
    const connection = createConnection(roomId)
    connection.on('connected', onConnected)
    connection.connect()
    return () => connection.disconnect()
  }, [roomId]) // перезапуск только при смене комнаты

  return null
}

Вызывать такую функцию можно только изнутри эффектов, а передавать её другим компонентам нельзя. Если сомневаетесь, сначала попробуйте одно из первых трёх решений выше: useEffectEvent нужен редко.

Аналогия из жизни

Эффект — это маршрутка с табличкой «Рудаки — Сино». Табличка (зависимость) говорит, по какому маршруту едем. Сменился маршрут — водитель разворачивается и едет по новому. Пустой массив зависимостей — как маршрутка, которая навсегда осталась на старой табличке: пассажиры давно едут в другое место, а она всё возит по прежнему маршруту.

Типичные ошибки

1. Пустой [] «чтобы не повторялось», хотя эффект читает props: получаете устаревшие данные. 2. Комментарий, отключающий линтер, вместо исправления кода. 3. Объект или функция из тела компонента в зависимостях: эффект запускается после каждого рендера. 4. Эффект без массива вообще и setState внутри: бесконечный цикл рендеров, в консоли Maximum update depth exceeded или зависание вкладки. 5. Считать эффект «обработчиком события»: реакцию на клик нужно писать в onClick (раздел 3).

средняя

Эффект читает prop city и состояние onlyOpen. Какой массив зависимостей правильный?

  1. Ничего, это просто другая запись
  2. Быстрее выполняется
  3. Берёт актуальное значение у React, поэтому count не нужно читать и добавлять в зависимости
  4. Запрещено в эффектах

Функциональное обновление получает последнее состояние от React, а не из замыкания. Так исчезает и устаревшее значение, и лишняя зависимость.

02 Очистка эффекта и двойной запуск в StrictMode

Эффект часто что-то «включает»: таймер, подписку, соединение, запрос. Функция, которую эффект возвращает, — это очистка: она «выключает» то, что включил эффект. React вызывает её в двух случаях: перед следующим запуском эффекта (при смене зависимостей) и при удалении компонента. Порядок при смене зависимостей всегда такой: очистка со старыми значениями, потом новый эффект с новыми.

useEffect(() => {
  function handleResize() {
    setWidth(window.innerWidth)
  }
  window.addEventListener('resize', handleResize) // включили
  return () => window.removeEventListener('resize', handleResize) // выключили
}, [])

Хорошая очистка — зеркало настройки: addEventListener и removeEventListener, setInterval и clearInterval, connect и disconnect, fetch и abort (раздел 5). Без очистки подписки копятся: после десяти показов компонента на каждое событие срабатывают десять обработчиков.

Почему эффект запускается дважды

Проект создан из шаблона Vite, и в main.tsx приложение обёрнуто в StrictMode (урок 3: он вызывает компоненты дважды). Он делает ещё одно: в режиме разработки после первого показа компонента сразу выполняет очистку и запускает эффект заново. Это проверка на прочность: React имитирует «ушли и вернулись» и смотрит, не сломается ли что-то. В продакшн-сборке двойного запуска нет.

отключились: Общий
подключились: Общий

Если у эффекта есть правильная очистка, пара «запуск — очистка — запуск» выглядит так же, как один запуск. Если вы видите баг только из-за двойного вызова (два запроса, два подключения, дублированные записи), это не баг StrictMode, а недостающая очистка. Не боритесь с ним флагами в useRef: починить нужно эффект.

Ролик на русском (11 минут, август 2024): порядок запуска эффекта и очистки. Модель из ролика верна и для React 19.

Аналогия из жизни

Эффект — это аренда самоката. Взяли самокат (подписались), покатались, вернули на стоянку (очистка). Если не вернуть, через неделю вся стоянка пуста, а у вас во дворе десять самокатов. StrictMode — как проверка при выдаче: сразу «вернуть и взять снова», чтобы убедиться, что возврат работает.

Типичные ошибки

1. Нет очистки у setInterval, addEventListener и подписок. 2. Очистка не зеркальна: removeEventListener получает другую функцию, чем addEventListener, и ничего не удаляет (обработчик нужно объявить один раз внутри эффекта). 3. Флаг «уже запускался» в useRef, чтобы скрыть двойной запуск: в продакшн-сборке это ничего не изменит, а баг останется. 4. Ожидать, что очистка вызывается только при удалении компонента: она вызывается и при каждой смене зависимостей.

04 useRef: DOM и значения вне рендера

Ref — это «коробочка» { current: … }, которую React хранит между рендерами. В отличие от состояния, запись в ref.current не вызывает перерисовку. Поэтому у ref две работы: держать ссылку на элемент DOM (чтобы сфокусировать поле или прокрутить к блоку) и хранить значение, которое нужно запомнить, но не показывать (идентификатор таймера, предыдущее значение).

Ref на элемент DOM

В TypeScript тип узла указывают в угловых скобках, а начальное значение всегда null: пока компонент не показан, элемента ещё нет. React 19 требует начальное значение явно (useRef() без аргумента даёт ошибку). Когда элемент появится, React запишет его в ref.current, а при удалении вернёт null. Поэтому перед использованием проверяйте на null.

import { useRef } from 'react'

export default function SearchField() {
  const inputRef = useRef<HTMLInputElement>(null)

  function handleClick() {
    inputRef.current?.focus() // current может быть null
  }

  return (
    <div>
      <input ref={inputRef} placeholder="Найти ресторан" />
      <button onClick={handleClick}>В поиск</button>
    </div>
  )
}

Ref как «хранилище значения»

Таймер нужно остановить кнопкой, а идентификатор из setInterval живёт между рендерами. Если хранить его в состоянии, каждый запуск вызовет лишнюю перерисовку, хотя на экране ничего не меняется. Ref подходит лучше.

  const [seconds, setSeconds] = useState(0);
  const timerRef = useRef(null); // хранит id таймера, но не показывается на экране

  function start() {
    if (timerRef.current !== null) return; // уже идёт
    timerRef.current = setInterval(() => setSeconds((s) => s + 1), 1000);
  }

    clearInterval(timerRef.current);
    timerRef.current = null;

Правило

Не читайте и не записывайте ref.current во время рендера (кроме первой инициализации): иначе компонент перестаёт быть чистым (урок 3). Меняйте ref в обработчиках событий и в эффектах. Ещё одна важная вещь: фокус и прокрутку лучше делать в обработчике события (handleClick). Эффект нужен только тогда, когда элемент должен появиться после рендера: например, прокрутка к блоку, содержимое которого меняется после выбора.

Аналогия из жизни

Состояние — это меню на стене чойхоны: изменилось, и все видят новое. Ref — блокнот официанта в кармане: он записал, какому столу что нести, но стену менять не нужно. Блокнот помогает работе, а зал его не видит. Ref на DOM — номерок на столе: по нему официант находит нужный стол, не обходя весь зал.

1. Показывать ref.current на экране: интерфейс не обновится, потому что перерисовки нет. средняя

  3. Зависимости. Нет пустого [] при чтении props, нет объектов из тела компонента, нет комментариев «disable lint».
  4. Очистка. У каждого таймера, подписки и запроса есть зеркальное действие. Проверьте в StrictMode: после двойного запуска ничего не дублируется.
  5. Запрос. Проверка response.ok, unknown и type guard вместо as и any, AbortError не показывается как ошибка, async не передан прямо в useEffect.

const server = createServer(async (req, res) => {
  const url = new URL(req.url ?? '/', 'http://localhost')
  // ?delay=2000 замедляет ответ, ?fail=1 отвечает ошибкой 500
  const delay = Number(url.searchParams.get('delay') ?? 600)
  await new Promise((resolve) => setTimeout(resolve, delay))

  const send = (status, body) => {
    res.writeHead(status, {
      'Content-Type': 'application/json; charset=utf-8',
    })
    res.end(JSON.stringify(body))
  }

  if (url.searchParams.get('fail') === '1') {
    return send(500, { message: 'Сервер временно недоступен' })
  }

  const path = url.pathname
  if (path === '/api/restaurants') {
    return send(200, restaurants)
  }
  const menuMatch = path.match(/^\/api\/restaurants\/(\d+)\/menu$/)
  if (menuMatch) {
    const id = Number(menuMatch[1])
    if (!restaurants.some((r) => r.id === id)) {
      return send(404, { message: 'Ресторан не найден' })
    }
    return send(
      200,
      menu.filter((item) => item.restaurantId === id),
    )
  }
  send(404, { message: 'Такого адреса нет' })
})
