01 Что такое React и зачем он нужен

Когда вы пишете интерфейс руками, вы командуете браузеру по шагам: «найди элемент, поменяй текст, добавь класс, вставь новый блок». Чем больше экран, тем больше таких команд, и тем легче забыть одну из них. Экран и данные расходятся, и появляются баги вроде «в корзине 3 товара, а на значке написано 2».

React меняет подход. Вы описываете, как должен выглядеть экран при данных: «если товаров 3, покажи три строки и цифру 3». Дальше React сам сравнивает новый результат со старым и точечно обновляет DOM. Короткая формула, которую стоит запомнить: UI = функция(состояние).

Аналогия из жизни

В чойхоне вы говорите официанту: «Хочу плов и чай». Вы не объясняете, как резать морковь и сколько варить рис. Это декларативный подход, и React работает так же: вы заказываете результат («экран с тремя блюдами»), а как до него добраться, решает кухня. Ручной DOM похож на приготовление самому: каждый шаг на вашей совести.

Попробуйте: тот же интерфейс на React

Это живая песочница. Нажимайте на кнопки, затем поменяйте текст и снова запустите. Двоеточия после имён в коде (name: string) — это типы TypeScript. Пока их достаточно узнавать и читать, подробно мы разберём типы в уроке 2.

}

      <Card name="Samarkand" cuisine="самбуса" />

}

React — это библиотека, а не фреймворк

React отвечает только за одно: за то, как выглядит интерфейс при данных. Страницы и адреса, глобальное состояние, запросы к серверу, формы, тесты в React не входят: для каждого есть отдельный инструмент. Поэтому курс устроен так: сначала сам React и TypeScript, потом по одному подключаем нужное (формы, Redux Toolkit, RTK Query, React Router, тесты), а в уроках 15–24 переходим на Next.js, где многое уже собрано в одно целое.

Типичные заблуждения

1. «React — это фреймворк». Нет, это библиотека для интерфейса; роутинг и данные вы выбираете сами. 2. «React сам делает сайт быстрым». Нет, он удобен для поддержки больших интерфейсов, а скорость зависит от вашего кода. 3. «React и Next.js — одно и то же». Next.js — фреймворк, построенный на React. 4. «Надо выучить весь JavaScript до React». Нужна база из прошлых курсов, остальное доучивается по ходу.

ЗАДАЧА 1.1

Проверь себя: идея React

лёгкая

Что значит, что React «декларативный»?

  1. Код в нём нужно объявлять в начале файла
  2. Вы описываете, как выглядит экран при данных, а обновление DOM делает React
  3. Он работает только с заранее объявленными типами
  4. Он не использует JavaScript, только разметку

Декларативный подход: «вот результат при таких данных». Императивный (ручной DOM): «вот шаги, как к нему прийти».

В приложении на React пользователь нажал кнопку, и число в корзине должно измениться. Что делает обработчик?

  1. Находит элемент document.querySelector и меняет его textContent
  2. Перезагружает страницу
  3. Вызывает setState с новым значением, а React сам перерисует экран
  4. Меняет файл компонента

Обработчик меняет состояние. Компонент вызывается заново с новыми данными и возвращает новое описание экрана.

Проверь себя: что выбрать

лёгкая

Вы делаете закрытую панель для администратора ресторана: вход по паролю, поисковики её не индексируют. Какой старт разумнее для обучения и прототипа?

  1. Vite + React + TypeScript: SPA без сервера, проще понять основы
  2. Create React App, потому что он самый свежий
  3. Ничего: React нельзя запускать без сервера
  4. Только Next.js, потому что без него React не работает

  1. Next.js не требует знать React
  2. Next.js даёт роутинг по папкам и серверный рендеринг из коробки

  4. В Next.js первая страница может прийти с сервера уже готовым HTML

Next.js построен на React и поэтому требует его знания. Какой вариант быстрее, зависит от задачи: у SPA проще хостинг, у Next.js лучше первая загрузка и индексация.

03 Проверяем Node.js и создаём проект

Все инструменты курса (Vite, TypeScript, Prettier, позже Next.js) работают на Node.js. Vite 8 требует Node.js 20.19+ или 22.12+. На 28 октября 2026 года долгосрочную поддержку (LTS) имеют линейки 22 и 24, берите свежую LTS с nodejs.org.

  1. Проверьте версии. Откройте терминал (в Cursor: Ctrl + `) и выполните: 
    node -v
npm -v
git --version
    Нужно увидеть v22.12 и выше (или v24.x), версию npm и версию Git. Если версия Node ниже или команда не найдена, установите LTS с nodejs.org и перезапустите терминал.
  2. Выберите папку для проектов. Путь без кириллицы и пробелов, не внутри OneDrive или iCloud. Перейдите в неё командой cd.
  3. Создайте проект. 
    npm create vite@latest dastarkhon -- --template react-ts
    Если мастер задаст вопросы: на «Which linter to use?» выберите Oxlint (почему, объясним в разделе 5), на «Install with npm and start now?» ответьте No: установку сделаем сами.
  4. Установите зависимости и запустите. 
    cd dastarkhon
npm install
npm run dev
    В терминале появится адрес http://localhost:5173/. Откройте его в браузере: вы увидите стартовую страницу Vite со счётчиком. Нажмите на кнопку, потом измените любой текст в src/App.tsx и сохраните: страница обновится без перезагрузки (это HMR). Остановить сервер: Ctrl + C.
  5. Откройте проект в редакторе: cursor . или «File → Open Folder».
Если сломалось

«You are using Node.js 18.x. Vite requires Node.js version 20.19+ or 22.12+. Please upgrade your Node.js version.» Версия Node слишком старая: поставьте LTS и перезапустите терминал. «npm: command not found»: Node.js не установлен или терминал не перезапущен. Порт занят: Vite сам выберет 5174 и напишет адрес в терминале. «Target directory "dastarkhon" is not empty»: папка уже существует, выберите другое имя или удалите её. Страница пустая: откройте DevTools (F12), вкладку Console: там указан файл и строка ошибки.

04 Структура проекта: файл за файлом

Откройте проект и найдите эти файлы. Каждый из них вам придётся трогать или хотя бы понимать.

dastarkhon/ ├─ index.html единственная HTML-страница SPA, в ней <div id="root"> ├─ package.json зависимости и команды (scripts) ├─ vite.config.ts настройки Vite, подключён плагин React ├─ tsconfig.json точка входа: ссылается на два файла ниже ├─ tsconfig.app.json настройки TypeScript для кода в src/ ├─ tsconfig.node.json настройки TypeScript для vite.config.ts ├─ .oxlintrc.json правила линтера ├─ public/ файлы «как есть»: favicon и т. п. └─ src/ ├─ main.tsx точка входа: запускает React ├─ App.tsx корневой компонент └─ index.css глобальные стили

Как запускается приложение

Браузер открывает index.html. В нём тег <script type="module" src="/src/main.tsx"> подключает точку входа. Вот она целиком:

import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import './index.css'
import App from './App.tsx'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
createRoot
Говорит React: «вот элемент #root, управляй всем, что внутри него».
.render(…)
Показывает в этом корне компонент App и всё его дерево.
StrictMode
Помощник для разработки: в dev-режиме выполняет компоненты и эффекты дважды, чтобы вскрыть скрытые баги. На сайте для пользователей этого двойного запуска нет.
!
Восклицательный знак после getElementById('root') читается так: «поверь мне, TypeScript, элемент существует». Без него strict-режим потребует проверить, что он не null. Подробно про такие знаки в уроке 2.

Три файла tsconfig

TypeScript читает настройки из tsconfig*.json. Файлов три, потому что в проекте два разных мира: код приложения (src/) работает в браузере, а vite.config.ts запускается в Node.js. У них разные окружения, поэтому свои настройки. Главные флаги в tsconfig.app.json:

ФлагЧто даёт
"jsx": "react-jsx"JSX компилируется без import React в каждом файле
"moduleResolution": "bundler"Импорты ищутся так, как это делает сборщик Vite
"verbatimModuleSyntax": trueТипы нужно импортировать явно: import type { Foo } from './types'
"erasableSyntaxOnly": trueЗапрещает конструкции, которые не стираются при удалении типов, например enum
"noUnusedLocals", "noUnusedParameters"Неиспользуемые переменные и параметры становятся ошибкой
"noEmit": truetsc только проверяет типы, файлы не создаёт: собирает Vite

Strict-режим. В шаблоне нет строки "strict": true, потому что в современных версиях TypeScript (6 и выше) он включён по умолчанию. Мы проверили это на практике: в проекте на TypeScript 7.0 неописанный параметр функции даёт ошибку TS7006: Parameter 'x' implicitly has an 'any' type. Для наглядности вы добавите строку "strict": true в конфиг сами, в практике.

Важно: Vite не проверяет типы

Vite только вырезает типы из кода и запускает его, а проверка идёт отдельно: командой tsc -b и в редакторе. Поэтому npm run dev может работать при ошибках типов. Команда npm run build (tsc -b && vite build) сначала проверяет типы, и с ошибкой сборка остановится.

Реальные ошибки, которые вы увидите

Их тексты на английском, и это нормально: читайте их целиком, код ошибки (TS1484) пригодится для поиска.

src/Bad.tsx(1,20): error TS1484: 'ReactNode' is a type and must be imported using a type-only import when 'verbatimModuleSyntax' is enabled.
src/Bad.tsx(3,6): error TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled.

Первая: ReactNode — тип, его нужно импортировать как import type { ReactNode } from 'react' (или import { type ReactNode } from 'react'). Вторая: в файле использован enum, вместо него берут объект с as const или union-тип (про них в уроке 2).

Ролик на русском (сентябрь 2025), начинается с создания проекта и разбирает структуру. Автор выбирает шаблон на JavaScript, поэтому у него main.jsx, а у вас main.tsx: логика одна и та же. Если шаблон спросит про линтер, берите Oxlint.

Аналогия из жизни

Проект — это бозор. index.html — ворота, через которые входят все. main.tsx — администратор, который открывает рынок и ставит первый прилавок (App). package.json — список поставщиков (пакетов), а tsconfig — правила рынка, которые проверяет контролёр: что можно ставить на прилавок, а что нельзя.

ЗАДАЧА 4.1

Проверь себя: читаем проект

средняя

Что делает команда npm run build в этом шаблоне?

  1. Только запускает dev-сервер
  2. Только форматирует код Prettier
  3. Сначала проверяет типы командой tsc -b, и только если ошибок нет, собирает приложение через Vite
  4. Загружает проект на GitHub

В package.json: "build": "tsc -b && vite build". Знак && означает «вторую команду запускай, только если первая прошла успешно».

Ошибка TS1484: 'ReactNode' is a type and must be imported using a type-only import. Как её исправить?

  1. Написать import type { ReactNode } from 'react'
  2. Выключить TypeScript в проекте
  3. Заменить тип на any
  4. Удалить файл tsconfig.app.json

Флаг verbatimModuleSyntax требует явно помечать импорт типов. Это помогает сборщику: импорт типов полностью стирается из итогового кода.

Почему npm run dev может запуститься, хотя в коде есть ошибка типа?

  1. Потому что TypeScript в Vite не установлен
  2. Потому что Vite только стирает типы и запускает код, а проверку типов выполняет tsc отдельно
  3. Потому что dev-режим всегда игнорирует ошибки
  4. Потому что ошибки типов не бывают в React

Поэтому проверяйте типы редактором и командой npm run typecheck (её добавим в практике) и всегда запускайте npm run build перед коммитом.

Что из React 19 вам сразу бросится в глаза

ref — обычный prop. Раньше компонент, который принимает ref, нужно было оборачивать в forwardRef. Теперь достаточно взять ref из props:

import { useRef } from "react";

function SearchInput({ placeholder, ref }) {
  return <input placeholder={placeholder} ref={ref} />;
}

export default function App() {
  const inputRef = useRef(null);
  return (
    <div>
      <SearchInput placeholder="Найти ресторан" ref={inputRef} />
      <button onClick={() => inputRef.current?.focus()}>В поиск</button>
    </div>
  );
}

Context без .Provider. Вместо <ThemeContext.Provider value="dark"> пишем <ThemeContext value="dark">. Старая запись пока работает, но будет объявлена устаревшей. Подробности в уроке 8.

Удалено. propTypes и defaultProps у функциональных компонентов (проверку props теперь делает TypeScript, значения по умолчанию задаются в параметрах), ReactDOM.render (вместо него createRoot, как в вашем main.tsx), строковые refs и устаревший Context. Если ИИ или старый туториал предлагает такой код, это сигнал: пример устарел.

TypeScript и React 19. useRef теперь всегда требует начальное значение (useRef(null)), а ref-callback не должен возвращать значение неявно: пишем ref={(el) => { node = el }}, а не ref={(el) => (node = el)}. Тексты ошибок в таких случаях сами подскажут исправление.

Безопасность: держите зависимости свежими

В декабре 2025 команда React закрыла критическую уязвимость в серверных компонентах (удалённое выполнение кода без авторизации). Исправления вышли в 19.0.1, 19.1.2 и 19.2.1. Шаблон Vite сегодня ставит 19.3.x, где она закрыта; в SPA серверных компонентов нет, но привычка важна: npm install свежего шаблона, а не копирование старого package.json, и регулярно npm outdated. В Next.js (уроки 15–24) это критично.

Аналогия из жизни

Версии React 19.x — как обновления маршруток на линии: маршрут (основной принцип «UI = функция от состояния») прежний, но добавили кондиционер (useEffectEvent), безналичную оплату (Actions) и убрали старые сиденья, которые ломались (propTypes, ReactDOM.render). Ездить по-старому можно, пока не наступит момент, когда сиденья нет.

ЗАДАЧА 6.1

Проверь себя: React 19

средняя

Туториал советует ReactDOM.render(<App />, document.getElementById('root')). Что делать в React 19?

  1. Использовать как есть, всё работает
  2. Использовать createRoot(...).render(...) из react-dom/client: ReactDOM.render удалён
  3. Заменить render на propTypes
  4. Ничего: в Vite этот код подставляется автоматически

ReactDOM.render удалён в 19.0. Ваш main.tsx уже использует createRoot. Туториал, где этого нет, написан для React 17 и старше.

Какие утверждения о React 19 верны? Выберите два.

  1. Компонент может принять ref как обычный prop, без forwardRef
  2. Хуки теперь можно вызывать внутри условий
  3. propTypes у функциональных компонентов больше не проверяются, вместо них используют TypeScript
  4. React Compiler встроен в React и включён всегда

Правила хуков не изменились (use можно вызывать в условии, но это отдельный хук). Compiler — отдельный необязательный инструмент сборки.

Промпт: от «почисти» к понятной задаче

Формула промпта: контекст → задача → ограничения → формат ответа → проверка. Сравните два запроса на уборку стартового шаблона.

почисти проект
Контекст: проект Vite 8 + React 19 + TypeScript (strict), создан из шаблона react-ts. В корне лежит AGENTS.md, прочитай его. Задача: сначала только ПЛАН, код не пиши. Какие файлы стартового шаблона нужно удалить или изменить, чтобы осталась чистая заготовка: App.tsx выводит заголовок «Дастархон», а стили лежат в одном src/index.css. Ограничения: не трогай tsconfig*.json, vite.config.ts и package.json, не добавляй зависимости. Формат ответа: таблица «файл — удалить / изменить / оставить — причина в одну строку». Проверка: после моего подтверждения выполни npm run build и npm run lint и покажи вывод целиком.

Хороший промпт отвечает на вопросы «где мы», «что именно», «чего не трогать», «как выглядит ответ» и «как проверить». Плохой оставляет их агенту, и агент отвечает наугад: может удалить конфиги, добавить зависимость или переписать половину файлов.

Как проверять код, который написал агент

  1. Типы. Нет any, as unknown as, // @ts-ignore. Если ошибка типа «исчезла» такой ценой, она не исправлена.
  2. Эффекты. Нужен ли useEffect вообще? Полный ли массив зависимостей? Есть ли очистка? (Подробно в уроке 5.)
  3. Списки. У каждого элемента key из id, а не из индекса.
  4. Устаревший код. Нет ReactDOM.render, propTypes, forwardRef в новом коде, шаблонов Create React App.
  5. Зависимости. Агент добавил пакет? Проверьте, что он существует, нужен и поддерживается. Выдуманные названия пакетов — реальная проблема.
  6. Секреты. Ни ключей, ни токенов в коде. Всё, что имеет префикс VITE_, попадёт в браузер и станет публичным.

  8. Проверка. npm run build, npm run lint, страница в браузере и пустая вкладка Console.

ЗАДАЧА 9.1

Проверь себя: решения проекта

лёгкая

Почему проект 1 мы начинаем на Vite, а не сразу на Next.js?

  1. Потому что Next.js устарел
  2. Чтобы сначала понять сам React (состояние, хуки, данные, роутинг) без серверной части, а затем увидеть, что именно добавляет фреймворк
  3. Потому что на Next.js нельзя использовать TypeScript
  4. Потому что Vite умеет серверный рендеринг лучше

Next.js построен на React и требует его знания. Курс идёт от простого к сложному: SPA (уроки 1–14), потом фреймворк (15–24).

В каком порядке подключаются слои данных в «Дастархоне»?

  1. Сначала локальное состояние и хуки, затем Redux Toolkit, затем RTK Query, затем роутинг
  2. Сначала RTK Query, потом всё остальное
  3. Всё сразу в уроке 1
  4. Роутинг первым, потому что без него нет страниц

Каждый инструмент решает задачу, которую вы уже почувствовали руками: сначала useState и useReducer, потом общее состояние, потом серверные данные, потом страницы.
